# 학생 결과 화면과 교과목·분반 관리자

2026-09-16 · Visual Studio 확장 0.5.0 / VS Code 확장 0.5.0 / 기존 SQLite 모델 재사용.
실제 운영 서버·학생 명단·DB는 변경하지 않았다. 서버 업데이트와 확장 설치는 별도다.

## 1. 학생: 무엇을 확인하면 되는가

이전의 긴 결과 로그 대신 다음 순서로 표시한다.

1. **어느 과제·어느 제출인가**: 과제명, 최신/과거 제출 구분, 접수번호.
2. **현재 판단**: 자동채점 총점 기준 충족 / 수정 필요 / 채점 대기 / 공개 대기 / 처리 오류.
3. **점수**: 큰 글씨의 점수와 총점 달성률. 채점 진행률을 추정하는 막대가 아니다.
4. **다음 할 일**: 수정·저장·재제출, 공개 대기 또는 교수자 문의.
5. **항목별 결과**: 수정 필요 항목 먼저, 충족 항목 다음. 점수·배점·공개된 피드백 표시.
6. **추가 피드백**: 파일·행과 진단 최대 5건을 먼저 표시. 전체 진단·소스 식별값은 펼쳐서 복사.

### 판단 기준

| 상황 | 표시 및 해석 |
| --- | --- |
| 공개된 점수가 유효한 양수 만점과 동일 | 자동채점 총점 기준 충족. 보고서·설계 설명·기한 등 별도 요구사항은 학생이 확인 |
| 공개된 점수가 만점 미만, 0점 포함 | 수정 필요. 실패 항목과 공개 피드백을 확인한 뒤 다시 제출 |
| 접수/대기/실행 중 | 점수 미공개. 제출은 접수되었지만 완성 여부 판단은 아직 불가 |
| graded | 채점 완료 · 결과 공개 대기. 숨겨진 점수·항목·진단은 표시하지 않음 |
| 채점 환경 오류 또는 검증 거절 | 코드의 정답/오답으로 단정하지 않고 교수자 확인 안내 |
| 점수 누락·범위 오류·0점 만점, 만점과 감점 항목이 충돌 | 결과 확인 필요. 완료로 처리하지 않음 |
| 총점만 공개 | 항목별 판정 미제공을 명시. 없는 테스트 결과나 통과 기준을 만들어내지 않음 |

이는 UI 요약 정책이며 서버 채점 배점이나 합격선을 변경하지 않는다. **자동채점 만점은 교과목 수료나
교수자의 최종 평가 완료를 의미하지 않는다.** 비공개 테스트의 내용·정답은 추가로 조회하거나 공개하지 않는다.

### IDE별 사용

- **Visual Studio 2022/2026**: 과제 창 상단의 `내 제출 결과`에서 마지막 접수의 자동 갱신 결과를
  확인한다. 직접 과거 이력을 열면 `과거 제출 기록`으로 구분한다. 새 제출 접수 시 이전 직접 조회
  결과를 지워서 이전 만점을 새 제출의 결과로 혼동하지 않도록 한다. 접수 후 자동 확인은 기존처럼
  최대 2분이며, 종료 후 `최신 결과 확인`으로 다시 조회한다.
- **VS Code**: `채점 결과 보기`나 제출 이력의 결과 조회 시 읽기 전용 결과 탭을 연다. 결과 로그는
  보조 기록으로 유지하되 기본 결과 표시는 요약 탭이다. 이 탭은 조회 시점의 결과이며 자동 갱신 화면은
  아니다. 새로운 제출 후에는 다시 결과를 조회해야 한다.
- 공용 PC에서 로그아웃·주소 변경·재로그인 시 결과 화면을 정리한다. 새 결과 파일이나 성적을
  디스크에 저장하지 않는다. 토큰 저장 정책과 서버 인증은 변경하지 않았다.
- 밝음/어두움 등 IDE 테마 자원을 사용하고 색상 없이도 상태 문구로 판별하도록 한다.

## 2. 관리자 접속

교수자 웹 기능이 활성화된 서버에서 다음 주소를 사용한다. 아래는 **업데이트 후 접속 경로**이며
이번 작업에서 해당 도메인에 배포하거나 접속 시험한 것이 아니다.

- 전체 교과목: [관리자 페이지](https://ai.cbchoi.info:20010/instructor/admin)
- COME2201 분반: [COME2201 관리](https://ai.cbchoi.info:20010/instructor/admin/subjects/come2201)
- COME3105 분반: [COME3105 관리](https://ai.cbchoi.info:20010/instructor/admin/subjects/come3105)

기존 `/instructor` 화면에도 `관리자 · 교과목·분반` 링크를 추가했다.
기능이 꺼져 있다면 사용 중인 설정 CSV에 `instructor_assignment_web_enabled,true`를 한 번만
설정하고 서버를 정상 재시작한다. [교수자 웹 시작·인증 안내](instructor-web-mvp.md)를 따른다.

로그인은 기존 `instructor` 계정과 서버의 `platform-instructor-token`을 사용한다. 학생 비밀번호나
수령 코드는 관리자 인증에 사용할 수 없다. **새 개인별 관리자/교수자 역할은 만들지 않았다.**
공유 운영자 계정은 전체 등록 수업에 접근하므로 개별 교수자에게 권한이 분리되는 서비스로 안내하면 안 된다.

## 3. 교과목 → 학기 → 분반 관리

1. 관리자 페이지에서 교과목 코드를 선택한다.
2. 학년도·학기별로 나뉜 분반 현황을 확인한다.
3. 해당 분반 행의 **학생 관리**, **과제 등록·관리**, **학생별 결과·코드 확인**, **분반 설정·QR**로 이동한다.
4. **이 교과목에 분반 추가**에서 학년도·학기·분반을 확인하고 새 수업을 등록한다.
5. 새 분반에 학생과 과제를 등록하고 검증한 뒤 운영 상태로 전환한다.

`교과목 코드 + 학년도 + 학기 + 분반` 조합은 중복 등록할 수 없다. 분반 이름은 `01`, `02`처럼
일관되게 사용한다. 내부 `course_key`와 학생 접속 주소는 별도로 생성한다. 분반별 학생·인증·과제·
제출·QR은 기존 수업 경계로 분리된다. 다른 분반의 학생·비밀번호·과제는 자동 복사하거나 옮기지 않는다.

기존 `come2201`, `come3105` 주소는 보존한다. 학기·분반 정보가 비어 있는 기존 수업은
`기존 수업 · 학기·분반 정보 보완 필요`로 표시하며 분반 설정에서 정보를 채운다.
학생용 수업 선택·로그인·과제 선택 화면에도 수업명·학년도·학기·분반을 표시한다.

## 4. 관리자 집계 의미

- 수강 중: 해당 분반 수강과 학생 계정이 모두 활성인 학생 수.
- 등록: 비활성 수강을 포함한 등록 수. 전체 교과목 카드의 수강 수는 사람 수가 아닌 **수강 건수**다.
- 활성 과제: bundle 과제 릴리스 중 활성인 수. CLI Git 제출과 비활성 릴리스는 이 요약에 포함하지 않는다.
- 기대 셀: 활성 학생 수 × 활성 과제 릴리스 수.
- 상태: 각 학생·과제의 **최신 제출만** 계산한다. 재제출은 기존 상태를 대체하고 건수를 늘리지 않는다.
- 기준 충족: 공개된 유효 총점이 만점인 최신 제출 수. 총점 기준 집계이며 사람 수나 수료율이 아니다.
- 수정 필요: 공개된 총점이 만점 미만. 채점·공개 대기와 인프라 오류는 별도 구분한다.
- 미제출: 기대 셀 중 접수된 제출이 없는 수. 공개 전·마감 전일 수 있으며 지각이나 기한 위반 판정이 아니다.
- 오류 / 확인 필요: 거절·채점 실패와 점수 누락·불명확 상태를 따로 표시한다.

하나의 SQLite 읽기 스냅샷에서 집계하며 전체 학생×과제 행렬을 메모리에 만들지 않는다.
백그라운드 실시간 갱신 대신 `현황 새로고침`으로 읽는다. 과목/분반 생성은 기존 검증·CSRF·Origin·
중복 방지 절차를 그대로 사용한다. 이번 기능 자체를 위한 새 DB 스키마나 데이터 초기화는 없다.

## 5. 설치와 현장 시험

- VS Code: `extensions/vscode/autograde-vscode-0.5.0.vsix`를 생성했다. `VSIX에서 설치`로 시험한다.
  Marketplace 게시·서명은 수행하지 않았으며 패키징 시 기존 LICENSE 파일 누락 경고가 있다.
  공개 배포 전 라이선스와 게시 정보를 운영자가 확정해야 한다.
- Visual Studio: Windows에서 `extensions/visualstudio/build.ps1`로 0.5.0 VSIX를 생성한다.
  macOS compile-only DLL은 설치 파일이 아니다.
- 합성 자료의 관리자 화면·결과 HTML은 브라우저에서 배치와 가독성을 확인했다.
  실제 IDE Webview/WPF 렌더링, 좁은 도구 창·고대비·키보드 조작, VS2022/2026 설치는 현장 확인이 필요하다.

인수 순서:

1. 시험 수업 한 교과목에 `01`, `02` 분반을 만들고 같은 학번을 각각 등록한다.
2. 한 분반의 학생 비활성화/암호 변경이 다른 분반의 수강·인증을 바꾸지 않는지 확인한다.
3. 만점·감점·0점·공개 대기·채점 오류 제출로 학생 결과 화면을 확인한다.
4. 과거 만점 제출을 열고 새 오답을 제출해 이전 만점이 새 제출의 결과처럼 표시되지 않는지 확인한다.
5. 재제출 후 관리자 집계가 `대기 → 기준 충족/수정 필요`로 바뀌되 기대 셀 수는 유지되는지 확인한다.
6. 로그아웃·다른 학생 로그인 후 이전 결과 탭/카드가 사라지는지 확인한다.
7. 비로그인/학생 토큰으로 관리자 주소 접근 시 차단되는지 확인한다.

## 6. 이번 검증 기록

- Python 전체 회귀: **966개 통과, 7개 환경 조건으로 건너뜀** (Windows/MSVC 2개, 사용 가능한 JDK 부재 5개).
- VS Code: **138개 통과**, 0.5.0 VSIX 패키징 성공. 결과 화면 모듈이 실제 패키지에 포함됨을 확인.
- C# 공통 모듈: **117개 통과**. Python의 Visual Studio 연동 시험에서도 호출하므로 합산하지 않는다.
- Visual Studio WPF/VSSDK compile-only: **경고 0, 오류 0**.
- 합성 데이터로 결과 HTML과 관리자 분반 화면을 브라우저에서 확인했다. 관리자 표의 긴 헤더
  줄바꿈을 줄이기 위해 상태 열을 묶고, 설명은 펼치기 영역으로 이동했다.
- 실제 운영 서버 배포, 실제 학생 계정 사용, Marketplace 업로드, IDE 설치는 수행하지 않았다.
