# IDE에서 Autograde 서버 자동 검색

학교 DNS, DHCP, 공유기, hosts, 방화벽 또는 기존 Nginx 설정을 수정하지 않고 같은 실습실의 Autograde 서버를 찾습니다. 서버의 접속 주소를 알려 주는 안내 프로그램과 IDE의 검색·선택 화면을 사용합니다. 원격 서버를 안내하려면 실습실의 교수자 PC에서 안내 프로그램을 실행해도 됩니다.

실제 로그인·과제·자료·제출 요청은 기존 HTTPS 서버로 갑니다. 안내 프로그램은 인증, 채점, 프록시, DNS 서버 또는 학생 데이터 저장소가 아닙니다.

## 동작과 신뢰 범위

1. 안내 프로그램이 선택한 네트워크 인터페이스에서 `_autograde._tcp.local.` 서비스를 알립니다.
2. IDE가 해당 서비스의 PTR, SRV, TXT 레코드를 찾습니다.
3. IDE는 기관 ID와 API·포털 주소를 로컬에 등록된 신뢰 기관 목록과 정확하게 대조합니다. 임의로 도착한 새로운 기관 주소는 로그인 대상으로 승인하지 않습니다.
4. 학생이 목록에서 서버를 선택하면 일반 DNS와 HTTPS 인증서 검증으로 서버를 확인한 뒤 기존 연결 설정을 적용합니다.
5. 기관 연결 정보만 학생 작업 폴더 밖에 유지합니다. 공용 실습실의 코드, 자료 캐시, IDE 사용자 데이터 및 로그인 정보는 기존 세션 종료 정리 대상입니다. 공개 기관 정보에 학생 학번, 수령 코드, 비밀번호, 토큰을 넣지 않습니다.

LAN 응답 자체는 신뢰 증거가 아닙니다. TLS 검증을 생략하거나 최초 응답자의 인증서를 자동 신뢰하지 않습니다. 안내 패킷에 수신한 IP를 강제로 사용하는 방식도 쓰지 않습니다. 특히 교수자 PC에서 다른 곳의 서버를 안내할 때, 그 서버의 도메인이 교수자 PC의 IP를 가리키는 A/AAAA 레코드를 발표하지 않습니다.

## 안내 프로그램 준비

Autograde 저장소와 Python 가상환경을 준비한 뒤 저장소 루트에서 실행합니다. 자동 검색 의존성은 별도 선택 항목이므로 서버의 기본 실행에는 필요하지 않습니다.

```sh
python -m pip install -e '.[discovery]'
python -m autograde.server_discovery \
  --config config/ide/discovery-advertiser.example.json --check
```

`python`은 서버 또는 안내용 가상환경의 Python입니다. Mac에서 저장소의 `.venv`를 사용한다면 `.venv/bin/python`으로 실행할 수 있습니다. 설치 후에는 `autograde-discovery` 명령도 사용할 수 있습니다.

`--check`는 JSON만 검증합니다. 네트워크 소켓, 데이터베이스, 학교 DNS 또는 서버 설정을 변경하지 않습니다. 설정 예제:

```json
{
  "schema": "autograde.discovery-advertiser.v1",
  "institutionId": "autograde",
  "displayName": "Autograde 수업 서버",
  "apiUrl": "https://ai.cbchoi.info:20000",
  "portalUrl": "https://ai.cbchoi.info:20010"
}
```

다른 기관은 예제를 복사해 사용하고 IDE에도 같은 기관 ID와 주소를 신뢰 기관으로 배포합니다. API와 포털 주소는 현재 서버 구조에 맞게 서로 다른 HTTPS origin이어야 합니다. 주소에 계정 정보, 경로, 쿼리, 토큰을 넣을 수 없습니다. 인증서와 일치하는 DNS 호스트 이름을 사용하며 IP 주소는 이 자동 검색 버전의 광고 대상으로 지원하지 않습니다.

표시 이름은 UTF-8 기준 63바이트 이내이고 점, 역슬래시, 제어 문자를 제외합니다. 같은 실습실에서 같은 표시 이름의 안내 프로그램이 이미 실행 중이면 두 번째 실행은 오류로 종료합니다. 기관 ID와 접속 주소가 같은 안내 프로그램을 여러 PC에서 중복 실행할 필요는 없습니다.

## Mac의 신뢰 기관 목록

기본 IDE는 현재 Autograde 서버를 신뢰 목록으로 제공합니다. 기관을 추가하거나 다른 주소를 사용하려면 운영자가 `config/ide/discovery-profile.example.json`을 편집해 아래 사용자별 파일로 배포합니다.

```text
~/Library/Application Support/Autograde IDE/institution-discovery.json
```

```json
{
  "schema": "autograde.ide-discovery.v1",
  "trustedServers": [
    {
      "institutionId": "autograde",
      "displayName": "Autograde 수업 서버",
      "apiUrl": "https://ai.cbchoi.info:20000",
      "portalUrl": "https://ai.cbchoi.info:20010"
    }
  ]
}
```

파일은 32 KiB 이하의 일반 파일이어야 합니다. 파일과 바로 위 `Autograde IDE` 폴더는 해당 Mac 사용자 소유이며, 폴더 권한은 `0700`, 파일 권한은 `0600`을 사용합니다. 심볼릭 링크는 허용하지 않습니다. 운영자가 파일을 배포한 뒤 IDE를 새로 시작합니다. 신뢰 기관 목록은 LAN 응답으로 추가하거나 갱신하지 않습니다.

학생이 등록된 기관을 선택하면 `selectedInstitutionId`만 저장합니다. 해당 값은 `trustedServers`에 있는 기관 ID여야 합니다. 이 파일은 학생 코드·로그인 정보를 포함하지 않으며 공용 실습의 삭제 대상 폴더 밖에 있습니다. 기관을 다시 선택해도 서명된 IDE 앱 내부 설정을 덮어쓰지 않습니다.

## Mac에서 실행

Mac의 시스템 설정에서 현재 실습실 Wi-Fi 또는 Ethernet의 IPv4 주소를 확인합니다. 아래 `192.168.50.20`은 **안내 프로그램을 실행하는 Mac의 주소**로 교체합니다. 원격 Autograde 서버의 IP를 넣는 자리가 아닙니다.

```sh
python -m autograde.server_discovery \
  --config config/ide/discovery-advertiser.example.json \
  --interface 192.168.50.20
```

`--interface`는 필수입니다. VPN을 포함한 모든 네트워크로 자동 발표하지 않고 지정한 IPv4 인터페이스만 사용합니다. macOS가 로컬 네트워크 접근을 묻는 경우 안내 프로그램과 IDE에 허용해야 검색할 수 있습니다. 학교 장비의 설정을 변경하는 단계는 없습니다.

정상 실행하면 `advertising` 이벤트와 공개 기관 주소가 표시됩니다. 터미널의 `Ctrl+C`로 종료하면 이 프로세스가 등록한 안내를 철회하고 소켓을 닫습니다. 시험 실행은 `--duration 60`을 추가하면 60초 뒤 자동 종료합니다. 별도의 서버나 Nginx 프로세스를 종료하지 않습니다.

## IDE 사용과 Mac 확인 절차

1. 같은 실습실 네트워크의 Mac에서 안내 프로그램을 실행합니다.
2. 수정된 Autograde IDE를 실행하고 학습 홈의 서버 검색 화면에서 목록을 확인합니다.
3. `Autograde 수업 서버`를 선택하여 API·포털 주소를 확인합니다. 기존 로그인 중에는 서버를 자동 전환하지 않습니다.
4. 연결 확인 후 새 수령 코드로 로그인하고 과제 또는 자료를 내려받습니다.
5. 시험용 파일을 작성하고 필요한 내용은 서버 저장 또는 내보내기로 보관합니다.
6. 공용 실습 종료를 선택하거나 IDE를 정상 종료합니다. 실행기의 `session-cleaned` 결과와 학생 작업 폴더·사용자 데이터 정리를 확인합니다.
7. 다시 실행하여 기관 연결 정보는 남고 이전 학생의 파일·로그인 정보가 나타나지 않는지 확인합니다.
8. 안내 프로그램을 종료하고 다시 검색하면, 캐시 만료 후 검색 결과에서 사라져야 합니다. 이미 선택한 기관 설정과 원격 서버의 가용성은 별개의 상태입니다.

검증 항목에는 미등록 기관, 주소 불일치, 잘못된 TXT, 중복 응답, 안내 중단, HTTPS 실패, 취소 및 검색 중 반복 클릭도 포함합니다. 자동 검색 결과를 적용해도 기존 세션 종료 정리와 다음 실행 시 잔여 학생 파일 복구 정리를 생략하지 않습니다.

## 검색되지 않을 때

- **서버가 다른 VLAN에 있음:** 같은 실습실의 교수자 PC에서 원격 서버의 공개 주소를 안내할 수 있습니다. 그 주소로 실제 HTTPS 접속도 가능해야 합니다.
- **무선 AP 격리·멀티캐스트 차단:** 기관 접속 설정 또는 기존 주소 입력을 사용합니다. 검색 프로그램이 학교 보안 정책이나 방화벽을 우회하지 않습니다.
- **검색은 되지만 접속 불가:** 실제 서버 포트, 주소 해석, HTTPS 인증서와 기존 서버의 정상 실행을 확인합니다. 검색이 포트를 열어 주지는 않습니다.
- **알 수 없는 기관:** 운영자가 IDE에 배포한 신뢰 기관 ID·API·포털 주소와 안내 설정을 비교합니다. 패킷의 기관 이름만 보고 승인하지 않습니다.
- **인터페이스 변경:** Wi-Fi/Ethernet 주소가 변경되면 안내 프로그램을 종료하고 새 IPv4 주소로 실행합니다.
- **여러 네트워크에 동시 연결:** 현재 IDE의 IPv4 검색 질의는 기본 인터페이스를 사용합니다. Wi-Fi·Ethernet·VPN을 동시에 사용하는 환경에서 다른 인터페이스의 서버가 검색되지 않으면 기존 주소 입력을 사용합니다. 인터페이스별 검색 선택은 후속 작업입니다.
- **Windows/WSL2:** 이번 우선 검증 대상은 Mac입니다. WSL2의 NAT 네트워크에서는 자동 검색이 전달되지 않을 수 있으므로 Windows 호스트 실행기의 발견 결과 전달을 별도로 검증해야 합니다. 자동으로 WSL 설정이나 방화벽을 변경하지 않습니다.
- **`.local` 주소 사용:** 자동 발견과 HTTPS 인증서 신뢰는 별개입니다. 사설 CA를 사용하는 기관은 클라이언트의 인증서 신뢰를 별도로 구성해야 합니다. 기본 예제는 기존의 정상 HTTPS 도메인을 사용합니다.

브라우저에서 포트가 없는 `https://classroom.local` 주소를 직접 여는 기능은 이 모듈의 범위가 아닙니다. IDE가 발견한 실제 포트를 대신 사용하므로 학생의 주소 입력을 줄일 수 있습니다.

## 프로토콜과 구현 경계

| 레코드 | 값 |
| --- | --- |
| PTR | `_autograde._tcp.local.` → 기관 표시 이름의 서비스 인스턴스 |
| SRV | API DNS 호스트 이름과 실제 TCP 포트 |
| TXT `v` | `1` |
| TXT `institution` | 기관 ID |
| TXT `portal` | 별도 학생 포털 HTTPS origin |

TXT에 API 호스트·포트를 중복하지 않습니다. 각 TXT 항목은 255바이트 이하, 전체 메타데이터는 1 KiB 이하이며 설정 파일도 8 KiB로 제한합니다. 안내 수명은 30초이고 종료 시 goodbye를 보냅니다. 갑작스러운 전원 중단 때는 네트워크 캐시가 만료될 때까지 이전 안내가 잠시 보일 수 있습니다.

안내 모듈은 기존 CSV, SQLite, Nginx, hosts, DNS, DHCP 또는 운영체제 인증서 저장소를 쓰지 않습니다. 선택된 연결 설정은 서명된 IDE 앱 내부 파일을 덮어쓰지 않는 별도 설정으로 취급합니다.

기술 근거: [DNS-SD RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html), [mDNS RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html), [python-zeroconf API](https://python-zeroconf.readthedocs.io/en/latest/api.html), [WSL 네트워크](https://learn.microsoft.com/en-us/windows/wsl/networking).

## 2026-10-29 Mac 검증 기록

- Mac의 실제 LAN 인터페이스에서 Python 안내 프로그램과 IDE의 Node 검색 모듈을 별도 프로세스로 실행했습니다. 기관 1개를 발견하고 기존 원격 API의 `/healthz`를 정상 인증서 검증으로 확인했습니다. 인증 정보는 전송하지 않았습니다.
- 실제 검색 컨트롤러로 기관을 선택하고 별도 테스트 기관 파일에 선택을 저장했습니다. 네트워크 응답에 포함된 IP를 HTTPS 연결에 주입하지 않았습니다.
- 별도 임시 공간에서 패키징된 Mac IDE를 실행하고 Autograde 확장 활성화를 확인했습니다. 테스트 코드·자료·가짜 인증 파일을 만든 뒤 종료했으며 `session-cleaned`와 학생 영역 삭제를 확인했습니다.
- 같은 기관 파일로 다시 실행했을 때 이전 테스트 코드·인증 파일이 없고 기관 선택은 유지됨을 확인했습니다. 두 번째 종료 후에도 학생 영역이 정리됐습니다.
- 확장 테스트 666개, Mac 실행·정리·패키징 테스트 101개, 안내 프로그램 테스트 45개가 통과했습니다. 실제 학생 로그인·과제 제출은 이번 변경의 원격 시험에 포함하지 않았습니다.
- 화면 제어 도구에서 동일한 이름의 IDE 앱들을 구분하지 못해 실제 IDE 버튼 클릭의 시각적 검증은 완료하지 못했습니다. 선택 메시지·상태 전환·기존 주소 재확인·인증 중 전환 차단은 자동 테스트로 검증했습니다.
- 다른 물리 PC 간 검색, 학교 Wi-Fi 정책, Windows 호스트→WSL2 전달은 별도 현장 검증 대상입니다. Mac 앱은 현재 파일럿용 ad-hoc 서명이며 정식 배포 서명·공증을 대신하지 않습니다.
