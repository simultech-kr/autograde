# 확장 0.5.2: 간결한 화면과 다운로드 장애 진단

## 이번 구현

- Visual Studio 2022/2026: 과제 / 결과 / 기록 탭, 고정 헤더·작업 영역·하단 버튼,
  다운로드 전에는 다운로드, 파일 준비 후에는 폴더 열기·제출을 표시한다.
  설정·폴더 관리·기록 복원·항목별 채점 피드백은 펼쳐서 확인한다.
- VS Code: 사이드바 상단의 상시 아이콘을 새로고침·로그아웃으로 줄였다.
  과제를 펼치면 다운로드를 선택할 수 있고, 추가 기능은 `…` 메뉴에 있다.
  결과는 기존 전용 결과 화면을 유지한다. Visual Studio와 같은 3탭 UI로 바꾸지는 않았다.
- 두 확장: 다운로드 단계, 정형 오류 코드, 문의번호(전체 UUID), 서버 전달 상태,
  복구 안내와 정제된 진단 복사. 수락을 취소하거나 기존 코드를 덮어쓰지 않는다.
- 서버: SQLite schema 12, 과제 세션으로 인증하는
  `POST /v1/assignments/{id}/download-diagnostics`, 시도·단계별 기록과 중복/역순 방어.
- 교수자: 기존 **학생별 결과·코드 확인 / 제출·채점 현황** 표의
  **응답 준비 / 다운로드 진단** 열에서 학생별 상태와 문의번호·이력을 펼쳐 본다.
  수업·분반은 기존 수업 선택을 사용하며 다른 수업의 진단을 함께 반환하지 않는다.
- 기존 다운로드 횟수는 ‘서버 응답 준비’로 표시한다. 이는 PC 저장 완료 횟수가 아니다.
- VS Code에서 응답 헤더 수신 후 본문 수신 도중 타임아웃이 해제되던 처리를 수정했다.

## 학생이 오류를 만났을 때

1. 수락 완료 메시지와 파일 준비 완료를 구분한다. 실패해도 수락을 다시 할 필요는 없다.
2. Visual Studio는 **과제 → 다운로드 상세 · 문의번호**를 연다.
   VS Code는 실패 때 열린 진단 화면 또는 사이드바 **… → 다운로드 진단 · 문의번호**를 연다.
3. 단계·원인·복구 안내에 따라 폴더/공간/접속을 확인한다. 인증 만료일 때만 새 코드로 로그인한다.
4. 해결되지 않으면 **진단 정보 복사**로 교수자에게 전달한다. 비밀번호·수령 코드는 보내지 않는다.
5. ‘파일 준비 완료 · IDE 열기 실패’면 다시 받지 말고 기존 폴더를 연다.

진단은 이번 로그인 메모리에만 유지한다. 로그아웃/학생 전환/서버 변경 시 지워진다.
사용자가 직접 복사한 클립보드와 내려받은 파일은 자동 삭제하지 않는다.

## 교수자 확인

`https://<학생 웹 도메인:외부 포트>/courses/<course_key>/instructor/submissions`
또는 수업 관리에서 **학생별 결과·코드 확인**을 선택한다.
직접 API 서버의 `/instructor` Basic 인증 화면도 같은 상태 열을 제공한다.
기존 운영 중인 인증 방식·외부 포트를 유지하며 새 공개 포트를 추가하지 않는다.

표에서 학생·과제를 찾고 다음을 구분한다:

- **다운로드 완료 미확인:** 시도하지 않았거나 구 확장, 통신 단절, 보고 누락일 수 있다.
- **다운로드 진행 보고 / 완료 확인 안 됨:** 마지막 진행 보고 후 5분이면 후자로 표시.
- **다운로드 실패 보고:** 펼쳐서 실패 단계와 코드, 문의번호·확장 버전을 확인.
- **파일 준비 완료 · IDE 열기 실패:** 파일 수신 문제와 구분하여 IDE 열기를 안내.

조회는 수업별 최근 200개 시도로 제한한다. 각 시도의 서버 수신 시각을 표시하며
클라이언트 보고임을 명시한다. 진단을 출석·성적 판단의 근거로 사용하지 않는다.

## 배포 순서

1. 실제 데이터 디렉터리를 백업하고 서버를 정상 종료한다. 운영 데이터 초기화는 하지 않는다.
2. 새 서버 코드를 설치한 뒤 시작한다. 기존 SQLite DB는 추가 테이블을 만드는 schema 12로
   마이그레이션된다. 이전 버전 서버로 즉시 되돌리는 대신 필요하면 검증된 백업으로 복구한다.
3. 교수자 로그인과 기존 학생 과제/제출이 유지되는지 확인한다.
4. VS Code 0.5.2 VSIX를 시험 설치한다. Visual Studio VSIX는 Windows에서
   [개발 안내](../../extensions/visualstudio/DEVELOPMENT.md)에 따라 빌드해야 한다.
5. 시험 계정으로 정상 다운로드, 권한 없는 폴더, 이미 존재하는 폴더, 통신 단절, IDE 열기 실패를
   재현하고 학생 문의번호가 교수자 화면에 나타나는지 확인한다.

구 서버가 진단 API에 404/405를 반환하면 ‘진단 기능 미지원’으로 표시하지만 다운로드는 계속한다.
구 확장은 서버의 파일 준비 완료 보고를 남기지 못한다. 이를 실패로 소급 판정하지 않는다.
진단은 요청당 최대 4 KiB, 시도당 최대 100개 이벤트, 세션당 분당 60개 새 이벤트로 제한한다.
중복 요청은 같은 응답을 반환한다. 수집 실패/잘못된 ACK는 ‘전달됨’으로 표시하지 않는다.

## 설계 대비 후속 범위와 제한

이번 릴리스는 [진단 설계](../architecture/download-troubleshooting.md)의 첫 단계 구현이다.
다음은 아직 구현하지 않았다:

- 오프라인 이벤트 큐의 자동 재전송, 주기적 진행 heartbeat, 진행 바이트·% 표시.
  전송은 각 체크포인트에서 최대 3초를 기다린 후 진행한다. 종료/장애 시 서버 전달을 보장하지 않는다.
- 서버 HTTP 전송 종료 이벤트·프록시 request ID 연결. 현재 상관관계는 클라이언트 시도의 UUID다.
- 모든 단계의 실시간 타임라인. 요청/준비 완료/종료 보고와 실패한 단계를 기록한다.
- 교수자 전용 필터·페이지네이션·동일 장애 묶기·보존 기간 자동 정리·SES 운영 스위치.
- IDE 버전/전송 크기 등 추가 진단 필드. 현재 확장 버전·IDE 종류·OS 계열·원격 환경만 수집한다.

표의 시도 제한을 넘으면 오래된 성공 보고가 목록에서 빠질 수 있다. ‘완료 미확인’은 항상
관측 부족으로 해석해야 한다. 상세 진단 자동 보존 정책은 운영 승인 전이며 자동 삭제하지 않는다.
학생 전체 초기화 도구는 schema 12에서도 대상 수업 진단만 백업 후 제거하도록 확장했다.
이번 개발에서 실제 수업 초기화나 운영 DB 변경은 수행하지 않았다.

## 검증

2026-09-17 로컬 검증: VS Code 자동 테스트 147개 통과, C# 자체 검사 122개 통과,
Visual Studio WPF 컴파일 경고·오류 0개. VS Code 0.5.2 VSIX를 생성했다.
이는 Marketplace 게시나 운영 서버 배포를 의미하지 않는다.

최종 Python 전체 회귀 시험은 **1,023개 통과·7개 건너뜀**(248.51초)이었다.
건너뛴 항목은 Windows/MSVC 전용 2개와 동작 가능한 JDK가 필요한 Java 예제 5개다.
전체 시험 수집 후 추가한 간결한 화면 구조 검사 1개도 별도로 통과했다.
앞선 시험에서 나온 DB 버전 기대값 2건을 수정했으며, C 대량 출력 사례의 일시적
환경 오류는 단독 재시험과 최종 전체 시험에서 재현되지 않았다. 운영 환경의 원인이
해결됐다는 의미는 아니며, 같은 오류가 발생하면 별도 조사가 필요하다.

자동 시험에 포함: 상태/오류 분류·비밀정보 비노출, 중복·역순·다른 세션 거부,
진단 요청 크기·빈도 제한, 서버 수락/응답 준비와 PC 완료 구분,
25명 동시 HTTP 다운로드·진단·제출·채점, C#↔Python 실제 인증·다운로드·진단 보고,
SQLite 마이그레이션·백업/초기화 범위, WPF 컴파일과 테마 자원 연결.

**Windows Visual Studio의 실제 설치·화면 크기·테마 전환·저장/신뢰 확인창은 이 macOS 환경에서
검증하지 못했다.** VS Code의 실제 WSL/원격 창에서도 현장 검증이 필요하다.
자동 시험은 운영 HTTPS/방화벽·인증서·실습실 보안 제품의 검증을 대체하지 않는다.

### 실습실 확인 체크리스트

1. Windows Visual Studio에서 도구 창을 좁게 줄이고 125%·150% 화면 배율로 확인한다.
   과제/결과/기록 탭이 전환되고 결과 영역만 스크롤되며, 하단 버튼이 결과를 가리지 않아야 한다.
   밝음·어두움·고대비 테마에서 선택된 탭, 비밀번호 입력, 오류 상세가 읽혀야 한다.
2. 시험 학생으로 로그인 → 다운로드 → 폴더 열기 → 제출한다. 제출 직후 결과 탭에서
   접수번호와 채점 대기가 구분되고, 완료되면 점수·항목별 피드백을 확인한다.
3. 쓰기 권한 없는 폴더 또는 네트워크 단절로 실패를 재현한다. 학생에게 실패 단계·오류 코드·
   문의번호가 보이고, 서버 전송에 성공한 경우 교수자 화면에 동일 문의번호가 있어야 한다.
4. 다운로드 후 IDE 열기만 취소한다. 파일은 남아 있고 서버에도 다운로드 실패로 표시되지 않아야 한다.
5. 로그아웃 후 다른 학생으로 로그인한다. 앞 학생의 진단·결과가 다시 표시되지 않아야 한다.
   공용 PC에 남은 다운로드 파일과 직접 복사한 클립보드는 별도 정리 정책으로 관리한다.
6. VS Code에서는 같은 절차를 로컬 및 WSL 창에서 각각 확인한다. 추가 기능은 `…` 메뉴,
   다운로드 오류 상세는 별도 진단 화면에서 확인한다.
