# 교수자 등록·평가 안내

## 1. 수업 범위

- 언어: C++17, `main.cpp` 단일 파일
- 문제: 실습 결과 보고서 생성기
- Factory Method: `ReportCreator`의 공통 처리와 구체 제품 생성 분리
- Abstract Factory: 제목·값 제품의 동일 테마 구성
- Singleton: 서비스 인스턴스와 무관한 프로세스 내 공용 일련번호
- 제외: CSV 이스케이프, 파일 저장, 네트워크, 다중 스레드, 임의 문법 오류 입력
- 주차·마감: 미지정. 공개 전에 수업 일정에 맞춰 설정

Factory Method의 제품과 Abstract Factory의 제품군을 구분해 설명합니다. 생성자 비공개와 복사·이동 금지 선언은 시작 코드에 제공되어 있습니다. 해당 선언을 직접 작성했다는 이유로 점수를 별도 부여하지 않습니다.

## 2. 교수자 웹에 신규 과제로 등록

먼저 [내보내기 명령](README.md#웹-업로드-파일-생성)으로 두 ZIP을 생성합니다. 서버는 `evaluation` 필드를 지원하는 현재 코드로 갱신되어 있어야 합니다. DB 마이그레이션이나 새 환경변수는 필요하지 않습니다.

1. 대상 교과목·분반 → **과제 관리 → 새 과제 등록 → 직접 만들기**를 선택합니다.
2. 제목은 `Factory Method · Abstract Factory · Singleton — 실습 결과 보고서 생성기`로 입력합니다. 언어는 C++17, 개발 환경은 실제 실습 환경에 맞춰 선택합니다. 이 소스는 Windows·Linux 전용 API를 사용하지 않습니다.
3. **문제 설명**에 학생용 `README.md` 전체를 붙여 넣습니다. 등록 후 배포되는 README가 이 설명에서 생성되므로 짧은 소개문만 입력하지 않습니다.
4. 수령 시작·마감을 입력합니다. 자세한 피드백을 즉시 제공하려면 결과 공개 방식을 **즉시 공개**로 유지합니다.
5. 학생 배포 자료에 `starter.zip`을 업로드합니다.
6. 교수자 채점 자료에 `grading-private.zip`을 업로드합니다. `tests.json`의 테스트·배점·평가 요소·힌트와 정답·오답 코드가 함께 등록됩니다.
7. 준비 현황에서 테스트 **12개 / 총 100점 / 오답 기대 점수 0점**을 확인합니다. 테스트 편집 화면에서 `학생 공개 평가 요소`와 `학생용 수정 가이드`가 저장되었는지 확인합니다.
8. **현재 저장 버전 검증 시작**을 실행합니다. 정답 100점, 오답 0점과 검증 성공을 확인한 뒤 학생 공개를 실행합니다.

기존 주차 과제의 README·채점 파일·공개본 digest를 덮어쓰지 않습니다. 이미 접수된 제출에 새 채점 기준을 소급 적용하지 않습니다. `assignment.json`은 교수자 참고 파일이며 웹 JSON 전체 업로드 기능을 의미하지 않습니다.

## 3. 기능 자동채점

항목별 배점과 요구사항은 학생 README에 사전 공개합니다. 각 테스트의 배점은 통과 시 전부, 실패 또는 실행하지 못한 경우 0점입니다. 한 항목 안의 일부 명령만 통과한 경우 부분 점수를 계산하지 않습니다. 컴파일은 배점 없는 선행 단계이며, 실패하면 모든 기능 항목은 미검사 상태로 표시됩니다.

| 결과 항목 | 평가 ID | 배점 | 검사 대상 |
| --- | --- | ---: | --- |
| 테스트 1 | F1 | 10 | TEXT 제품 출력 |
| 테스트 2 | F2 | 10 | CSV 제품 출력 |
| 테스트 3 | A1 | 10 | PLAIN 제목·값 |
| 테스트 4 | A2 | 10 | BRACKET 제목·값 |
| 테스트 5 | A3 | 10 | 형식과 테마의 독립 조합 |
| 테스트 6 | S1 | 5 | 반복 접근의 객체 동일성 |
| 테스트 7 | S2 | 10 | 새 서비스 간 누적 번호 공유 |
| 테스트 8 | E1 | 10 | 미지원 형식 거절 |
| 테스트 9 | E2 | 5 | 미지원 테마 거절 |
| 테스트 10 | E3 | 10 | 값 범위와 경계 |
| 테스트 11 | E4 | 5 | 오류 우선순위·상태 보존 |
| 테스트 12 | I1 | 5 | 생성·조회·오류의 교차 실행 |

테스트 1·2·3·4·6·7은 공개 시험입니다. 나머지는 공개 요구사항을 검증하는 비공개 입력이며 별도의 숨은 요구사항은 없습니다.

채점 API의 키는 `case_1`~`case_12`입니다. F1~I1은 학생이 문제·힌트·결과를 연결할 수 있도록 `evaluation` 문장에 포함한 평가 ID입니다.

## 4. 학생 피드백

모든 항목에 결과와 평가 요소를 함께 표시합니다. 실행에 실패한 항목에는 기본 실패 안내와 과제별 힌트를 붙입니다. 미검사 항목은 구체 구현을 틀렸다고 판정하지 않고 컴파일 또는 선행 문제부터 해결하도록 안내합니다.

예: BRACKET의 값 제품이 대괄호를 누락한 경우 테스트 4의 결과는 다음 형태입니다.

```text
테스트 4: 0 / 10, 실패
확인된 현상: 정상 실행되었지만 출력이 요구사항과 다릅니다.
평가 요소: A2 · BRACKET 제품군 — 제목과 값에 각각 대괄호를 적용하는지 확인
수정 가이드: BracketTitle과 BracketValue의 format 결과를 각각 확인
```

이는 피드백 구성 예시입니다. 자동채점은 출력 불일치의 발생 지점을 알려 주지만, 특정 구현이 원인이라고 단정하거나 검사하지 않은 소스 행 번호를 생성하지 않습니다. 학생은 공개 예제로 실제 출력을 확인합니다.

`evaluation`과 `hint`는 비공개 입력의 테스트에서도 학생 공개 정보입니다. 비공개 입력·예상 출력·교수자 정답을 넣지 않습니다. 평가 요소는 짧은 문장으로 작성하며 결과의 기존 길이 제한을 적용받습니다.

VS Code·Visual Studio는 기존 `feedback`·`hint` 표시를 사용합니다. 이번 평가 요소 표시를 위해 새 인증 절차나 확장 전용 필드는 추가하지 않습니다. 기존 상세 결과 화면을 지원하는 확장이 전제입니다.

## 5. 패턴 구조 코드 검토

기능 100점은 다음 구조를 증명하지 않습니다. 학생이 고정 `main`이나 검사 코드를 변경해 결과를 하드코딩할 수 있으므로 제출 소스를 함께 확인합니다. 자동 점수와 구조 검토 결과는 구분해 기록합니다.

| 기준 | 확인할 소스 | 충족 조건 |
| --- | --- | --- |
| Factory Method | `ReportCreator::render`, 구체 Creator | 공통 흐름에서 가상 `createReport`를 호출하며 구체 Creator가 대응 제품을 생성함 |
| 제품 인터페이스 | `Report`, 제품 구현 | 호출자가 구체 출력 제품 대신 공통 인터페이스를 사용하고 가상 소멸자를 유지함 |
| Abstract Factory | `ThemeFactory`, 구체 Factory, `ReportService` | 동일 Factory에서 제목·값 제품을 얻고 선택 이후에는 추상 인터페이스로 조합함 |
| Singleton | `Sequence` | 접근마다 같은 단일 객체 참조, 비공개 생성자, 복사·이동 금지, 인스턴스 멤버에 상태 보관 |
| 책임 분리 | `ReportService::make` | 검증·선택·조합을 수행하고 제품의 세부 출력이나 카운터 저장을 대신 구현하지 않음 |
| 제출 계약 | 고정 `main`, 고정 `ReportCreator::render` | 제공된 공통 절차를 우회하거나 예상 출력을 하드코딩하지 않음 |

구조 검토는 이 패키지의 기능 점수에 자동 합산하지 않습니다. 별도 점수를 부여한다면 배점과 기준을 학생에게 공개한 뒤 사용합니다. `SAME yes`만으로 Singleton 구조 전체를 충족했다고 판정하지 않습니다.
