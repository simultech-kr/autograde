# 포털 링크와 학생 인증 보안 점검

2026년 10월 29일 기준 로컬 소스와 합성 계정으로 교수자·학생 화면 이동 및 쿠키 인증을 점검했다.
계정 전환 후 이전 학생의 인증이 다시 사용될 수 있는 문제와 공통 로그인 해제의 누락을 수정했다.
변경 사항은 운영 서버에 배포하지 않았다. 외부 운영 서버의 TLS·Nginx 실설정이나 포괄적인 침투 시험을
대신하는 결과는 아니다.

## 링크와 동선

| 대상 | 확인 및 조치 |
| --- | --- |
| 실제 교수자 포털 | 교수자 홈·관리자 홈·두 수업 홈에서 연결된 읽기 경로 46개가 정상 응답. 누락된 화면 내부 앵커 없음 |
| 실제 Next.js 교수자 화면 | 수업 메뉴에 빠져 있던 가입·수강 명단과 실습 환경 바로가기 추가. 허용된 현재 교과목 범위를 유지 |
| 학생 수령 코드 발급 완료 | 공통 로그인 유지 여부를 정확하게 안내. 내 수강 교과목·내 수업·POST 로그아웃 추가 |
| 공통 회원의 기존 계정 연결 | 이미 공통 회원인 학생에게 불필요한 회원 계정 만들기 링크를 표시하지 않음 |
| Next.js 디자인 시안 | 가입 → 수강 선택, 검색·복수 선택·중복 신청 차단은 예시 데이터로 동작. 실제 회원 API와 자료 다운로드는 미연결 |

Next 시안의 역할 전환 메뉴는 화면 검토 도구다. 실제 사용자 권한을 전환하거나 로그인하는 기능이 아니다.
실제 Python 가입 화면은 아직 가입 시 수업을 함께 받는다. 승인한 새 디자인과 연결하려면 회원가입·수강 목록·
신청·로그인·로그아웃 JSON 계약을 추가하고 기존 권한 검사를 재사용해야 한다.

## 수정한 인증 문제

| 문제 | 수정 |
| --- | --- |
| 기존 학생 A의 수업 쿠키가 `/courses/...`에만 전달되어, 학생 B의 공통 로그인에서 폐기되지 않음. B 로그아웃 후 A 인증이 복원될 수 있었음 | 수업 인증 쿠키를 `Path=/`로 발급하고 성공한 계정 전환에서 브라우저가 제시한 이전 서버 세션을 폐기 |
| 로그인 준비용 CSRF 쿠키가 공통 로그인 쿠키와 같은 이름을 사용해, 로그인 화면 방문 시 인증 쿠키를 덮어씀 | 준비 쿠키 `autograde_member_entry`와 인증 쿠키 `autograde_member` 분리 |
| 만료·잘못된 공통 회원 쿠키가 있을 때 과거 수업 쿠키로 인증을 재시도함 | 공통 회원 쿠키가 있으면 그 인증 상태를 우선 검증하고 실패 시 차단. 기존 수업 로그인은 명시적 인증 성공 후 전환 |
| 자료·시험지의 로그아웃이 파생 수업 세션만 제거하여 공통 로그인이 유지됨 | 실제 세션 종류에 따라 공통 로그인도 폐기. 수령 코드 완료 화면에도 유효한 CSRF를 포함한 로그아웃 제공 |
| 여러 쿠키의 설정·삭제를 한 응답에서 안전하게 표현할 수 없었음 | `Set-Cookie`에만 최대 8개 튜플을 허용하고 별도 헤더로 전송. 헤더 개수·합산 크기·개별 값·줄바꿈 검증 유지 |
| 기존 수업 POST에서 Origin 생략이 허용되고, 출처 거절 시 로그인 쿠키를 바꿀 수 있었음 | 정확한 웹 Origin을 요구. 누락·다른 호스트·다른 포트의 요청을 거절하고 인증 쿠키를 변경하지 않음 |

서버 재시작은 메모리 세션을 만료시킨다. 기존 수업 로그인에 성공하면 이전 `/courses/{course}` 범위 쿠키를
만료시키고 새 인증 쿠키를 마지막 헤더로 발급한다. 쿠키를 쉼표로 합쳐 보내지 않는다.

## 확인한 보호 설정

| 항목 | 동작 |
| --- | --- |
| 학생 인증 쿠키 | HTTPS 설정에서 `Secure`, `HttpOnly`, `SameSite=Lax`, `Max-Age=600`. `Domain` 생략 |
| 로그인 준비 쿠키 | 별도 이름, `Path=/student`, 10분. 현재 회원 인증 쿠키를 덮어쓰지 않음 |
| 서버 세션 | 임의 식별자, 서버 측 만료 확인, 비밀번호·수강 상태 재검사, 계정 전환·로그아웃 시 폐기 |
| 변경 요청 | 인증 및 수강 권한, Origin, CSRF 검증. GET 링크로 로그아웃·신청을 실행하지 않음 |
| 응답 저장 | 인증 화면과 개인정보 응답에 `Cache-Control: no-store` 사용 |
| Next.js | production 빌드의 nonce CSP. 시안에는 실제 회원 쿠키·브라우저 저장소·API 변경 요청 없음 |
| 교수자 인증 | Basic 인증은 브라우저가 관리. `autograde_instructor_web`은 로그인 세션이 아닌 CSRF 쿠키 |

HTTP 파일럿 주소에서는 `Secure`를 붙이지 않는다. 외부 운영 설정은 HTTPS여야 한다.
`HttpOnly`는 스크립트의 쿠키 읽기를 제한하지만 요청 자체에 쿠키가 실리지 않게 하지는 않는다.
`Max-Age`가 있으므로 브라우저 종료만으로 즉시 삭제된다고 가정하지 않고 공용 PC에서는 웹 로그아웃을 사용한다.
[MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)

같은 호스트의 20000·20010 포트는 쿠키 격리 경계가 아니다. 제공한 Nginx 예제는 `/app`에서 Cookie·Authorization을
Node에 전달하지 않으며, 실제 데이터 요청은 권한을 검사하는 Python 경로로 보낸다. 서로 신뢰하지 않는 서비스는
같은 호스트의 포트만 나누어 운영하지 않는다.
[RFC 6265 8.5](https://www.rfc-editor.org/rfc/rfc6265#section-8.5)

## 검증 결과

- 쿠키·세션 및 가입·수업·자료·시험지 회귀 테스트: **118개 통과**. 실제 CookieJar를 이용한 계정 전환·로그아웃 15개와 HTTP 쿠키 헤더 검사 13개 포함.
- 마지막 점검에서 직접 수업 로그인 경로의 Origin 거절 응답도 보완했으며, 해당 경로를 포함한 **2개 회귀 테스트를 추가로 재실행해 통과**했다.
- HTTP 처리·교수자 포털·학생 포털·수령 코드 동선·Nginx 예제 등 관련 서버 회귀 테스트: **163개 통과**. 위 묶음과 일부 중복되므로 합산하지 않는다.
- Next.js 웹 테스트 **41개 통과**, production 빌드 성공.
- Chrome에서 합성 학생의 가입 → 교수자 수강 명단 업로드 → 수강 연결 → 과제 코드 발급 → 로그아웃·재로그인 및 기존 학생 계정 연결 **5개 흐름 통과**.
- 실제 Python 학생 화면의 모바일·데스크톱, 밝은·어두운 테마 **24개 배치 검사 통과**, 브라우저 페이지 오류 없음.

브라우저 검증 결과는 `build/student-registration-ui/report.json`에 기록했다. 합성 자료만 사용했으며
시험용 서버는 검증 후 종료했다. 별도의 Next.js 디자인 시안은 실제 인증 흐름 시험 결과에 포함하지 않는다.

## 운영 전 남은 항목

- Next.js 학생 로그인·로그아웃·만료·비밀번호 복구 화면과 실제 API 연결. 디자인 시안만으로 운영 화면을 대체하지 않는다.
- 학번과 교수자 명단의 일치는 수강 자격 확인이다. 다른 사람의 학번으로 먼저 가입하는 것을 막으려면 초대 코드 등 별도 본인 확인 절차가 필요하다.
- 공용 교수자 PC에서는 Basic 인증 캐시를 앱에서 확실하게 지울 수 없다. 명시적인 로그아웃이 필요하면 교수자용 서버 세션 인증으로 전환한다.
- 실제 운영 서버에서 HTTPS 설정, 프록시 헤더, 다른 브라우저·공용 PC의 로그인 전환을 확인한다.

운영 절차는 [학생 회원가입 안내](../operations/student-membership.md), 전환 경계는
[Next.js 전환 계획](../architecture/nextjs-migration-plan.md)을 따른다.
