# 제출 학생 중심 결과 대시보드

2026-09-29 갱신. 기존 학생·점수·수락·제출 파일을 변경하지 않고 교수자 조회 화면을 개선했습니다.
운영 서버 배포·재시작은 별도입니다. 새 설정 항목, 환경변수, DB 마이그레이션, 확장 업데이트는 필요하지 않습니다.

## 사용 방법

교수자 로그인 → 교과목/분반 → **학생별 결과**로 이동합니다.
COME2201의 주소는 `/courses/come2201/instructor/submissions`입니다.

- 기본 정렬은 **제출한 학생 우선 → 최근 제출순**입니다. SQL의 조회 건수 제한을 적용하기 전부터 이 순서를 사용합니다.
- 한 행은 학생 한 명의 과제 한 개입니다. 같은 학생이 여러 과제를 제출하면 여러 행으로 나타납니다.
- 상단에는 제출 학생 수, 채점 대기·진행, 채점 완료, 확인 필요 건수를 표시합니다.
  제출 학생은 중복을 제외한 인원, 나머지는 학생·과제별 최신 제출 건수입니다.
- 결과표는 **학생 / 과제 / 현재 점수 / 상태 / 제출 시각(KST) / 확인**의 6개 열입니다.
  수락·다운로드 횟수와 진단은 `접수·다운로드 정보`를 펼쳐 확인합니다.
- `결과 보기`에서 전체, 제출한 학생, 채점 대기·진행, 확인 필요, 미제출을 선택합니다.
  `과제 선택`과 함께 사용하여 과제별 제출·미제출 명단을 구분합니다.
- 과제 관리 목록·상세의 `제출·미제출 명단`을 누르면 해당 과제가 선택된 화면으로 이동합니다.
- 과제별 요약에서 `제출 N명`, `미제출 N명`을 눌러 해당 명단만 확인합니다.
  과제 선택 후 인원은 현재 활성 수강 학생 기준이며, 상태 필터를 바꿔도 과제별 전체 집계는 유지됩니다.
  여러 과제의 제출·미제출 건수는 학생×과제 단위입니다. 이를 수업 전체의 서로 다른 학생 수로 해석하지 않습니다.
- 수락·다운로드만 한 학생은 미제출입니다. 제출 기록이 있으면 거절·채점 오류·0점도 제출 그룹에 포함하고 상태를 별도로 표시합니다.
  재제출은 같은 과제의 인원을 증가시키지 않습니다. 미제출은 지각이나 0점 판정이 아닙니다.
- 선택 조건은 URL의 `assignment_id`, `result_view`에 유지되므로 새로고침·링크 전달 후 같은 보기를 열 수 있습니다.
  조회 중 선택한 과제가 보관·삭제되면 빈 상태로 유지하며 전체 과제로 자동 전환하지 않습니다.
- 점수는 현재 제출 기준이며, 재제출이 대기/진행 중일 때 이전 점수를 새 점수처럼 표시하지 않습니다.
  과거 결과와 코드 비교는 `코드·제출 이력 확인`에서 확인합니다.

## 자동 갱신

결과 영역만 AJAX로 **5초마다** 조회합니다. 전체 페이지를 이동하거나 새로고침하지 않습니다.
화면 상단의 마지막 확인 시각과 통신 상태를 확인할 수 있습니다.

- 결과 안의 링크에 초점이 있거나 텍스트를 선택해 읽는 중이면 목록 이동을 보류하고 `새 결과 적용`을 표시합니다.
- 과제·상태 필터 선택, ID가 있는 상세 정보의 펼침 상태, 읽던 행의 스크롤 위치를 유지합니다.
  페이지 맨 위에서는 맨 위를 유지하여 새 제출이 위로 올라온 것을 볼 수 있습니다.
- 변경된 행을 잠시 강조합니다. 상태는 색상뿐 아니라 한글 문구로도 구분합니다.
- `자동 확인 일시 중지`로 멈추거나 `결과 새로 고침`으로 수동 조회할 수 있습니다.
- 탭이 가려지거나 오프라인이면 조회를 멈춥니다. 다시 활성화되면 재개하지만 수동 중지는 유지합니다.
- 통신 실패 시 마지막 결과를 유지하고 실패 안내를 표시합니다. 10초 요청 제한, 최대 60초까지
  재시도 간격 증가, 연속 5회 실패 후 일시 중지를 적용합니다.
- 인증 만료·권한 회수·경로 오류(401/403/404)는 자동 재시도를 중단합니다.
  교수자 화면을 다시 열어 인증·대상을 확인해야 합니다. 자동 조회로 로그인 수명을 연장하지 않습니다.
- 브라우저 스크립트가 꺼졌거나 보안 정책에 차단된 경우 정렬된 초기 화면과 수동 새로고침 링크는 동작합니다.
  필터와 자동 갱신 기능만 사용할 수 없습니다.

하단 수강·접속 정보와 과제 수령 링크는 **처음 화면을 연 시점** 기준입니다.
이 영역까지 갱신하려면 하단 `새로 고침`이나 브라우저 새로고침을 사용하세요.

## 과제 집계 기준 수정

검증 중 만들어진 미공개 버전은 학생의 미제출 과제로 세지 않습니다.
기본 결과표에는 공개된 활성 과제와, 숨김 상태여도 해당 학생이 실제 제출한 활성 과제 행을 표시합니다.
숨긴 과제의 미제출 학생 행은 만들지 않습니다. 보관한 과제는 기본 표에서 제외하며 기록을 삭제하지 않습니다.
숨긴 과제의 요약은 `제출 이력 학생`으로 구분하고 미제출 인원을 계산하지 않습니다.
마감된 공개 과제는 결과 조회에 계속 포함됩니다. 같은 제목도 공개본 ID·릴리스로 구분합니다.
조회 한도에 도달하면 전체 인원으로 오해하지 않도록 부분 집계 안내를 표시합니다.

학생은 공개 웹 접속 링크에서 학번·전용 비밀번호로 인증하고
수령 코드를 발급받습니다. 인증·수령 코드·다운로드·제출 방식은 변경하지 않습니다.

전체 교과목/분반 관리 요약은 현재 **활성·공개 과제**만 집계합니다.
따라서 실제 제출 이력을 보존하는 결과표와 숨긴 과제의 포함 범위가 다를 수 있습니다.
명시적인 과제별 역사 조회와 기존 제출·코드 이력은 유지합니다.

결과 화면의 `채점 완료`에는 아직 학생에게 공개하지 않은 `graded` 결과도 포함합니다.
행에는 `채점 완료 · 공개 대기`로 표시합니다. 전체 관리자 요약의 기존 공개 완료 기준은 변경하지 않았습니다.

## 접근 제어와 배포

- 관리 웹 조회: `GET /courses/{course_key}/instructor/submissions/live`.
  관리 웹이 활성화된 경우 교수자 인증과 유효한 서명 쿠키를 모두 확인하고 담당 수업 권한을 매번 재검사합니다.
- 기존 관리 웹 비활성 호환 경로는 기존 Basic 인증 정책을 유지합니다.
  단독 서비스는 `GET /v1/instructor/dashboard/live`를 사용하며 외부 평문 HTTP 모드에서는 접근을 차단합니다.
- 응답은 수업 ID, 생성 시각, 서버에서 이스케이프한 읽기 전용 결과 HTML만 담습니다.
  비밀번호·인증 토큰·제출 코드·내부 저장 경로는 응답에 포함하지 않습니다.
- `no-store`, 동일 출처 조회, 고정 스크립트 해시 기반 CSP를 적용합니다.
  `unsafe-inline` 스크립트 허용은 필요하지 않습니다. 프록시에서 CSP를 별도로 덮어쓰지 마세요.
- 기존 Nginx 일반 경로 프록시를 그대로 사용합니다. 코드 업데이트 후 기존 설정 CSV로 서버를 재시작하고
  교수자 결과 페이지를 다시 여세요. 브라우저에서 최신 버전 HTML을 다시 받아야 합니다.

## 시험

- 합성 학생의 실제 HTTP 제출 → 점수 공개 → 재제출 대기 → 새 점수 공개를 검사합니다.
- 교수자 인증·개인별 수업 권한·서명 쿠키·만료·읽기 전용 응답·XSS·CSP를 확인합니다.
- 제출 우선/동일 시각 정렬, 조회 제한 전 정렬, 검증본 제외, 숨김 과제의 실제 제출 보존을 확인합니다.
- JavaScript의 재시도·취소·응답 순서·필터·펼침·스크롤·초점 보존을 결정적 모의 DOM 시험으로 검사합니다.
- 합성 자료만 사용하는 실제 브라우저에서 새 제출의 위쪽 이동, 점수 변경, 필터를 확인했습니다.
  운영 학생의 점수·제출 자료는 변경하지 않았습니다.

```sh
.venv/bin/python -m pytest -q tests/integration/test_live_results.py \
  tests/integration/test_assignment_participation.py \
  tests/unit/test_dashboard_scope.py tests/unit/test_instructor_results_browser.py
```

실제 운영 적용 후 시험 학생의 제출을 한 번 접수하고 새로고침 없이 위로 이동하는지,
채점 후 점수가 바뀌는지, `확인 필요` 필터와 코드·이력 링크를 확인하세요.
