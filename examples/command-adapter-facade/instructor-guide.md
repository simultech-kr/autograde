# Command Adapter Facade 교수자 운영 안내

이 과제는 다른 API를 가진 장비의 변환, 상태를 가진 명령의 실행·취소, 여러 장비를 묶는 상위 인터페이스를 C++17로 구현하는 실습입니다. 기능 점수와 디자인 패턴의 구조 검토를 분리하여 학생이 점수의 의미를 이해하게 합니다.

## 학습 범위

- Adapter: 객체를 감싸는 방식, 공통 추상 인터페이스, 쓰기·읽기 단위 변환
- Command: 요청 객체, 수신 객체 참조, 실행 시점 상태 저장, 되돌리기, 명령 소유권
- Facade: 입력 검증·장비 선택·장면 조합과 간단한 상위 호출
- 통합: 장면 하나를 한 작업으로 취소, 조회의 읽기 전용 성질, 오류 시 상태 보존
- 선수 지식: 클래스, 상속, 가상 함수, 참조, 생성자 초기화 목록, `std::vector`, `std::unique_ptr`, `std::move`

장비 고장, 멀티스레드, 네트워크, 영속 저장, REDO, 문법이 깨진 입력 파서는 제외합니다. `SceneCommand`의 명령 묶음은 이번 과제의 구현 보조 구조입니다. Composite 패턴의 별도 설계·평가를 요구하지 않습니다.

## 교수자 웹에서 등록

1. [자료 내보내기](README.md#웹-등록용-zip-생성)를 실행해 `starter.zip`과 `grading-private.zip`을 생성합니다.
2. 대상 교과목·분반의 **과제 관리 → 새 과제 등록 → 직접 만들기**를 엽니다. 처음 점검할 때는 별도의 시험 교과목을 사용합니다. 기존 과제의 편집이나 갱신으로 올리지 않습니다.
3. 제목은 `Command · Adapter · Facade — 강의실 장비 제어`로 입력하고 언어를 C++로 선택합니다. 실습 플랫폼은 수업 환경에 맞춥니다. 소스는 표준 C++17만 사용합니다.
4. 문제 설명에 학생용 `README.md` 전체를 입력합니다. 서버에서 배포하는 README는 저장된 설명에서 생성되므로 요약만 입력하지 않습니다. 내보낸 `assignment.json`의 `description`에도 전체 설명이 있습니다.
5. 수령 시작 시각과 제출 마감을 설정합니다. 이 패키지의 `opens_at`, `due_at`은 비어 있으며 자동으로 주차나 마감을 정하지 않습니다.
6. 결과 공개 방식을 **즉시 공개**로 유지하면 학생이 제출 후 힌트를 확인하며 반복 실습할 수 있습니다.
7. 학생 배포 자료에 `starter.zip`, 교수자 채점 자료에 `grading-private.zip`을 각각 업로드합니다. 채점 ZIP에는 정답·오답·테스트가 함께 들어 있습니다.
8. 준비 현황에 **테스트 14개, 총 100점, 오답 기대 점수 0점**이 표시되는지 확인합니다. 평가 요소와 수정 가이드도 저장되어야 합니다.
9. 저장한 버전으로 검증을 시작합니다. 정답 100점, 오답 0점과 검증 성공을 확인합니다.
10. 시험 교과목에 공개한 뒤 시험용 학생으로 수령·다운로드·제출·상세 결과를 확인합니다. 초안 상태에서는 학생이 수령할 수 없습니다. 확인을 마치면 실제 수업 교과목에서 위 등록·검증 절차를 반복하고 학생 공개를 실행합니다.

현재 서버의 `evaluation`과 `hint` 지원을 사용합니다. 확장이나 인증 방식을 새로 만들 필요는 없습니다. `assignment.json`은 입력 참고 자료이며, 파일 전체를 웹에 업로드하는 별도의 기능을 의미하지 않습니다.

## 100점 기능 평가

평가 ID와 배점은 학생 README에 모두 공개되어 있습니다. 한 항목에 여러 명령이 있어도 그 항목의 출력 전체가 맞아야 배점을 받습니다. 컴파일은 점수가 없는 선행 단계이며 실패 시 기능 검사는 미검사로 표시합니다.

| 결과 키 | 평가 ID | 배점 | 확인할 내용 |
| --- | --- | ---: | --- |
| `case_1` | A1 | 10 | 조명 단위 변환 |
| `case_2` | A2 | 10 | 스피커 단위 변환 |
| `case_3` | A3 | 5 | 0과 100 경계 |
| `case_4` | C1 | 10 | 설정 전 값 복원 |
| `case_5` | C2 | 10 | LIFO 취소와 이력 제거 |
| `case_6` | C3 | 5 | 빈 이력 처리 |
| `case_7` | C4 | 5 | 같은 값 설정도 이력 기록 |
| `case_8` | F1 | 10 | 세 장면의 목표 값 |
| `case_9` | F2 | 10 | 장면을 단일 작업으로 취소 |
| `case_10` | F3 | 5 | 개별 설정과 장면 조합 |
| `case_11` | E1 | 5 | 장비 이름과 오류 우선순위 |
| `case_12` | E2 | 5 | 값 검증과 상태 보존 |
| `case_13` | E3 | 5 | 장면 검증과 상태 보존 |
| `case_14` | I1 | 5 | 조회·장면·설정·취소 통합 |

A1, A2, C1, F1은 공개 테스트입니다. 나머지 테스트는 비공개 입력으로 공개 계약을 확인합니다. 비공개라는 이유로 문서에 없는 동작을 요구하지 않습니다. C4의 같은 값 설정, OFF의 취소 가능성, 장면의 이력 개수 등은 학생 문서에 명시되어 있습니다.

## 상세 결과의 수정 힌트

`evaluation`은 통과·실패·미검사에서 해당 항목이 확인하는 내용을 설명합니다. `hint`는 실행되었으나 실패한 항목에 기본 오류 안내와 함께 표시됩니다. 힌트는 점검할 클래스, 상태 변화, 로컬 재현 방법, `HINTS.md`의 ID를 연결합니다.

예를 들어 장면을 두 작업으로 기록했거나 두 장비 중 하나만 복원하면 F2가 실패할 수 있습니다. 학생에게는 다음과 같은 방향으로 안내합니다.

> F2는 장면 하나를 한 작업으로 기록하고 실행 직전 두 장비의 값으로 복원하는지 확인합니다. SceneCommand 하나를 이력에 넣는지, 두 하위 설정이 각자 이전 값을 보관하는지 점검합니다. 임의의 조명·스피커 값을 만든 뒤 장면을 적용하고 한 번 취소해 비교합니다.

이는 수정 방향의 예시이며, 실패 원인을 하나로 확정하는 진단이 아닙니다. 소스 검사 없이 특정 행이 틀렸다고 단정하지 않습니다. 여러 항목이 동시에 실패하면 공통 실행 경로의 미완성 코드가 원인일 수 있습니다.

컴파일 실패에서는 먼저 컴파일 오류 안내를 제공하고 기능 항목은 미검사로 구분합니다. 아직 실행하지 않은 F2 등에 대해 구현이 틀렸다는 힌트를 붙이지 않습니다. 공개 평가 기준은 계속 확인할 수 있습니다.

비공개 테스트의 제목·입력·예상 출력과 정답 소스는 학생에게 전달하지 않습니다. 단, `evaluation`과 `hint`는 비공개 테스트에서도 **학생 공개 문자열**이므로 비밀 데이터나 정답 코드 전체를 넣지 않습니다. 학생은 README 예제로 로컬 실행 결과를 비교할 수 있습니다.

## 패턴 구조 검토

기능 100점은 출력 계약의 통과를 뜻하며 설계 구조 전체의 증명은 아닙니다. 다음 목록을 제출 소스와 함께 확인합니다. 본 패키지는 아래 항목을 기능 100점에 자동 합산하지 않습니다. 구조 점수를 별도로 운영한다면 학생에게 그 배점과 기준을 먼저 공개합니다.

| 검토 대상 | 충족 기준 | 흔한 우회 |
| --- | --- | --- |
| Adapter | 기존 장비 참조를 감싸고 `LevelDevice` 구현, 실제 장비 읽기·쓰기 변환 | 백분율 캐시만 갱신, 기존 API 직접 변경 |
| SetLevelCommand | 대상·목표·이전 값 보유, 실행 직전 읽기, 저장한 값으로 취소 | 무조건 0 복원, 생성 시점 스냅샷 |
| SceneCommand | 하위 명령에 실행·역순 취소 위임, 이력에는 한 객체 | 하위 명령을 이력에 따로 추가 |
| CommandHistory | 구체 장비와 무관한 `Command` 소유·실행·LIFO 취소 | 장비별 분기, 제거한 객체 재사용 |
| Facade | 간단한 상위 API와 입력 검증·조합을 제공 | `main`에 모든 제어 로직 배치 |
| 책임과 수명 | 장비가 Adapter·Command보다 오래 존재, 장비 복사 없음 | 지역 장비 참조 반환, 이력마다 장비 복제 |
| 제출 계약 | 고정 main·기존 장비 유지, 표준 입력으로 계산 | 테스트 출력 하드코딩 |

학생 설명을 추가로 확인한다면 “새 장비를 추가할 때 바뀌는 클래스”, “장면 취소에서 두 스냅샷이 필요한 이유”, “Adapter와 Facade의 차이”를 질문할 수 있습니다. 이 질문은 자동채점 입력에 숨겨 넣지 않습니다.

## 검증 범위와 운영 주의

- 로컬 자동 시험은 합성 학생과 임시 저장소에서 자료 등록·검증·공개·수령·제출·결과 전달을 확인합니다. 실제 수업 계정을 사용하지 않습니다.
- 시작 코드와 검증 오답은 0점, 정답은 100점이 기준입니다. 대표 변형 오답으로 해당 평가 항목이 실패하고 힌트가 연결되는지도 확인합니다.
- 정답을 제출한 뒤 오답을 재제출하여 이번 점수와 이전 최고점이 분리되는 흐름을 확인합니다.
- macOS/Linux 계열 컴파일 시험만으로 Windows Visual Studio 실행을 검증했다고 판단하지 않습니다.
- 과제 공개·마감 설정·운영 서버 반영은 별도의 운영 작업입니다. 이 자료 생성이나 ZIP 내보내기만으로 공개되지 않습니다.
- 교수자 정답·오답·채점 ZIP을 학생 배포 위치나 공개 수업 저장소에 넣지 않습니다.
