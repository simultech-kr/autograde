# 교수자 UI/UX 개선 적용

2026-09-18 · 승인된 시안을 바탕으로 **서버 코드에 1차 화면 개선 및 2차 편집·검증 편의 기능을 구현**했다.
원격 서버 배포·교수자 현장 사용성 검증은 아직 수행하지 않았다.

## 적용된 화면

| 작업 | 변경 내용 |
| --- | --- |
| 전체 수업 | `/instructor`와 `/instructor/admin`을 동일한 교과목·분반 홈으로 통일 |
| 수업 전환 | 교수자 관리 헤더에서 교과목·학기·분반 선택 후 이동. 새 수업 개요로 진입하여 이전 학생/과제 문맥을 가져가지 않음 |
| 수업 개요 | 진행 과제, 공개본별 마감·수락·제출 학생 수, 학생 관리·수업 설정 연결 |
| 수업 설정 | 이름·운영 상태·학생 접속 링크·QR을 `/courses/{course_key}/instructor/settings`로 분리 |
| 과제 목록 | 웹 초안·공개본과 CLI bundle 과제를 통합. 검색·공개 상태 필터·20건 단위 페이지 이동 |
| 반응형 | 목록에서 기존 공통 표/카드 렌더러 재사용. 밝은/어두운 테마와 좁은 화면 지원 |
| 공개본 상세 | 과제 제목에서 운영 정보·마감·검증 결과로 이동. CLI 공개본은 읽기 전용 안내 |
| 검증 안내 | 검증 성공과 공개 상태를 분리. 이미 공개한 과제에 “공개 전”이라고 표시하지 않음 |
| 마감 | KST 기준 표시와 서버 접수 기준 안내. 마감 없는 공개본에 연장 폼을 제공하지 않음 |
| 학생 이력 | 기존 제출·채점 현황, 현재/이전 점수와 이력·코드 비교 화면을 재사용 |

웹 과제의 공개본과 그 작성 초안은 목록에서 한 행으로 표현한다.
검증 중 생성된 내부 bundle을 CLI 과제처럼 추가 표시하지 않는다.
새 버전으로 복제한 초안은 별도 행으로 남는다. 따라서 목록의 “과제·초안 건수”는 최종 성적의 의무 과제 수가 아니다.
이번 통합 목록은 **bundle 방식** 기준이며 과거 Git 저장소 과제 목록 통합은 포함하지 않는다.

수락 수는 중복 인증을 제외한 수강 학생 수, 제출 학생 수는 같은 학생의 재제출을 중복 계산하지 않은 값이다.
“접수 N건”은 재제출을 포함한다. 공개본 전체 이력 기준으로 집계하므로 현재 활성 명단 인원과 다를 수 있다.
실시간 자동 갱신이 아니므로 화면의 기준 시각을 확인하고 필요한 경우 다시 조회한다.

## 입력 오류·충돌 처리

수업 등록/수정, 학생 개별 등록, 과제 작성·테스트 입력·업로드, 공개본 연장/숨김의
일반 입력 오류에서는 원래 폼을 다시 표시한다. 복구할 수 없는 작업은 기존 오류 안내를 유지한다.

- 일반 입력·선택값·체크값을 실패한 폼에만 복원한다.
- 비밀번호, CSRF, 파일 내용은 입력값으로 복원하지 않는다. 파일은 다시 선택해야 한다.
- 초안 생성 요청 키를 유지하여 재시도로 중복 초안을 만들지 않는다.
- 동시 수정 충돌에서는 이전 revision을 유지한다. 다른 탭의 변경을 자동 덮어쓰지 않는다.
  입력을 따로 보관한 뒤 최신 화면을 열어 차이를 확인하고 다시 저장한다.
- 권한 거절, 잠긴 과제, 존재하지 않는 대상에는 편집 폼을 강제로 제공하지 않는다.
- 과제 편집·자료 업로드·마감 연장 폼에 미저장 표시와 화면 이탈 경고를 제공한다.
  자동 저장은 하지 않으며 각 영역의 저장 버튼을 사용한다.

공개 시점에 마감이 이미 지났으면 서버 트랜잭션 안에서 새 공개를 거절한다.
마감이 지난 초안 자체는 삭제하지 않으며 일정 변경 후 재검증하도록 안내한다.
이미 완료한 공개 요청을 재시도하는 것은 새 공개와 구분해 기존 결과를 반환한다.
기존 공개본의 마감 단축, 무기한 과제의 마감 추가, 개인별 유예 정책은 바꾸지 않았다.

## 업데이트·확인 절차

1. 진행 중인 제출·검증 작업을 확인하고 유지보수 시간을 잡는다. 기존 설정·DB·자료를 백업한다.
2. 업데이트된 서버 소스를 적용하고 **기존 서버 실행 명령과 기존 설정 CSV**로 재시작한다.
   이 UI 변경을 위해 포트, 도메인, 학생 명단, 확장 프로그램을 바꿀 필요는 없다.
3. 기존 `instructor_assignment_web_enabled,true`가 켜져 있어야 한다.
   아직 설정하지 않았다면 [교수자 웹 MVP 시작 안내](instructor-web-mvp.md)를 따른다.
4. `/instructor`에서 수업 선택 → 과제 목록 → 공개본 상세 → 검증 결과를 확인한다.
5. 과제 목록에서 검색·상태 필터와 다음 페이지를 확인하고, 다른 분반으로 전환해 범위를 확인한다.
6. 시험용 초안에서 잘못된 마감·배점을 입력해 폼 복구를 확인한다. 실제 공개 과제를 수정해 시험하지 않는다.
7. 기존 학생 인증·다운로드·제출·현재 결과·이전 최고점 조회를 별도로 확인한다.

이번 변경 자체는 DB 스키마·공개 URL·학생 API 계약을 변경하지 않는다.
기존 수업 루트 URL은 이제 개요이고 설정은 `/settings`로 이동했다. 기존 POST 작업 주소는 유지한다.
공유 교수자 인증, CSRF, 정확한 Origin 검사와 no-store를 유지한다.
2차 개선에서는 교수자 HTML에 한해 **고정된 스크립트의 SHA-256 해시**와 동일 출처 상태 조회만 CSP로 허용한다.
임의 인라인 스크립트, 외부 스크립트, 외부 통신은 허용하지 않으며 학생 화면·API의 CSP는 바꾸지 않는다.
프록시가 별도 CSP를 추가하면 두 정책 모두 적용되어 편의 기능이 차단될 수 있다.
그 경우 서버가 반환한 해시 정책을 그대로 전달하도록 운영자가 검토한다.
`script-src 'unsafe-inline'`로 완화하지 않는다. 코드가 바뀌면 해시도 자동 변경되므로 고정 해시를 프록시에 복사해 두지 않는다.

## 2차: 편집·검증 편의 기능

### 미저장 입력 보호

- 문제·일정·테스트 편집, ZIP 선택, 마감 연장에서 변경 여부를 표시한다.
- 다른 단계·수업 이동, 새로고침, 창 닫기는 브라우저의 기본 이탈 확인을 사용한다.
- 한 화면의 다른 영역에 변경이 있으면 저장 버튼을 눌러도 먼저 확인한다.
  예를 들어 테스트를 편집하면서 정답 ZIP만 등록하면 아직 저장하지 않은 테스트는 보존되지 않는다.
- 입력 오류로 복원된 폼은 미저장 상태로 표시한다. 동시 수정 충돌의 버전 검사는 그대로 유지한다.
- 로컬 저장소·쿠키에 입력 내용이나 파일을 저장하지 않는다. 강제 종료·모바일 앱 종료까지 복구하는 기능은 아니다.
  브라우저에 따라 사용자 조작 전에는 이탈 경고가 표시되지 않을 수 있다.

### 테스트 케이스 편집

- 직접 만들기 → 3단계에서 필요한 케이스만 표시하고 추가·복제·삭제할 수 있다.
- 현재 개수, 배점 합계를 표시한다. 삭제 후 저장 전에는 서버 자료를 변경하지 않는다.
- 50개 상한, 서버 배점 검증, 요청 64 KiB 제한은 유지한다. 복제한 케이스의 공개 여부도 복사되므로 확인한다.
- 삭제/추가 후 입력 오류가 나더라도 삭제한 기존 케이스가 다시 나타나지 않도록 복구한다.
- 스크립트를 사용할 수 없으면 기존 50개 입력 칸과 일반 저장 폼으로 동작한다.

### 검증 상태 자동 확인

- 5단계의 대기·실행 작업만 5초마다 조회한다. 완료되면 결과 화면을 다시 불러온다. **자동 공개하지 않는다.**
- 조회는 인증된 `GET /courses/{course_key}/instructor/checks/{job_id}/status`이며
  작업 식별자·상태·검증 버전·현재 초안 버전만 반환한다. 비공개 테스트·정답 코드는 반환하지 않는다.
- 다른 수업 작업 조회를 차단하며, 조회만으로 작업을 새로 실행하거나 세션 만료를 연장하지 않는다.
- 자료 버전이 달라지면 자동 이동을 중단하고 안내한다. 실패한 조회를 검증 완료로 표시하지 않는다.
- 탭이 숨겨져 있거나 오프라인이면 조회를 중지한다. 다시 활성화/연결되면 재개한다.
  수동 일시 중지는 자동 재개하지 않는다. 탭을 닫아도 서버 검증은 계속된다.
- 요청 제한시간은 10초이며, 통신 실패 시 10→20→40→60초로 간격을 늘리고 연속 5회 실패하면 중단한다.
  연결 복구 후 “자동 확인 다시 시작”을 누른다.
- 인증·접근 오류(401/403/404)는 자동 재시도하지 않는다. 교수자 화면을 다시 열어 인증/대상을 확인한다.
- 브라우저 스크립트가 꺼져 있거나 정책에 막히면 기존 “검증 상태 새로고침” 링크를 사용한다.

현장 확인: 시험용 직접 만들기 초안에서 케이스 복제·삭제 → 잘못된 배점 저장 → 입력 보존 확인,
미저장 상태에서 다른 단계 이동 취소, 별도 예제의 서버 검증 자동 완료 표시를 순서대로 확인한다.

## 시험과 남은 단계

회귀 시험: [실제 서비스·HTTP 시나리오](../../tests/integration/test_instructor_ux.py).
화면 검사: [서버 렌더링 검사 도구](../../scripts/check_instructor_ux.cjs).

```sh
python -m pytest tests/integration/test_instructor_ux.py -q --basetemp=PATH_TO_FRESH_TEST_DIR
node scripts/check_instructor_ux.cjs PATH_TO_FRESH_TEST_DIR PLAYWRIGHT_MODULE [CHROME_BINARY]
```

시험 폴더는 새 전용 경로를 사용한다. pytest의 `--basetemp`는 지정 경로를 정리하므로
운영 자료·저장소·홈 디렉터리를 지정하면 안 된다.
Playwright는 별도 개발 환경 도구이며 운영 서버 의존성이 아니다.

현지 검증: 7개 실제 렌더링 화면 × 5개 폭 × 2개 테마, 총 70개 레이아웃 검사와
고대비·키보드 포커스 검사 통과. 실행 오류 복구·수업 경계·권한·검색·접수 집계·마감 공개 차단은 HTTP/서비스 시험으로 확인했다.
이 수치는 시안의 110개 검사와 별개다.

1차 전체 회귀 시험(`python -m pytest -q`): **1040 passed, 19 skipped**, 267.47초.
생략은 Windows/MSVC 2건, 작동하는 JDK가 없는 환경 5건, PATH에 .NET 8 SDK가 없는 환경 12건이다.
새 기능의 HTTP/서비스 시험 14건은 전체 통과했고, 70개 화면 검사는 별도 수행했다.
운영 HTTPS 프록시를 통한 배포 시험이나 Windows 확장 실사용 시험을 완료했다는 의미는 아니다.

2차 HTTP·브라우저 시험:

```sh
python -m pytest tests/integration/test_instructor_browser.py -q --basetemp=PATH_TO_FRESH_TEST_DIR
node scripts/check_instructor_browser.cjs PATH_TO_FRESH_TEST_DIR/test_emit_actual_browser_fixtu0/browser-fixtures.json PLAYWRIGHT_MODULE [CHROME_BINARY]
```

합성 데이터로 실제 HTTP에서 받은 HTML과 CSP를 브라우저에 제공한다.
브라우저 내 상태 응답은 통제된 시험 응답이며 운영 서버 검증 작업을 실행하지 않는다.
실제 HTTP 시험에서 인증·만료·수업 범위·무변경 조회·해시 정책을 별도로 확인한다.

2차 관련 시험 **53개 통과**, 브라우저 동작·보안·좁은 화면 시험 **34개 통과**,
기존 7개 화면의 반응형·테마 검사 **70개 통과** 및 고대비·키보드 검사 통과.
2차 전체 회귀 시험: **1044 passed, 19 skipped**, 270.80초.
생략 사유는 위와 같은 Windows/MSVC·JDK·.NET 8 환경 미충족이다.
전체 시험 실행 중 보완한 배점 누락 안내·합계 표시까지 포함해 관련 53개 및 브라우저 검사를 다시 통과했다.
브라우저 시험에는 실제 이탈 경고 취소, 파일 선택/취소, 케이스 삭제 취소·50개 상한,
배점 누락·오류, 입력 복구, CSP 차단, 오프라인 복구, 인증 오류 중단, 통신 재시도 한도,
버전 불일치, 다른 작업 응답 거절, 완료 시 갱신, 스크립트 없는 폼을 포함한다.

후속 P1: 목록과 등록 폼의 추가 분리, 결과 화면까지 공통 탐색 통일.
P2/P3: 개인별 교수자 권한, 보고서, 보관/복원, SES 설정 화면.
화면에서 버튼을 보여주는 것만으로 이 기능들이 구현되었다고 간주하지 않는다.
