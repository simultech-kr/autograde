# 수업별 학생 전체 초기화·재등록 설계

작성: 2026-09-15. **웹 초기화 API/화면은 설계 단계이며 운영 데이터도 삭제하지 않았다.**
별도 [오프라인 초기화 도구와 실행 절차](../operations/course-student-reset.md)를 추가했다.
이 도구는 서버 중지·백업·DB 상태 확인 후 실행하며, 아래 온라인 작업/선별 복구/격리 보관 UX
전체를 구현한 것은 아니다. 현재 실행 명령은 `python -m autograde.course_reset`이다.

## 1. 이번에 확인된 범위

사용자가 확인한 대상은 **come2201 학생 전체 초기화 후 재등록**이다.
come2201의 과제와 come3105는 보존한다. 다른 수업이나 서버 전체 초기화 권한으로 확대하지 않는다.
운영 서버 연결과 검증된 초기화 기능이 없는 상태에서 임의 SQL이나 데이터 폴더 삭제로 실행하지 않는다.

| 초기화 대상(come2201에 한정) | 보존 대상 |
| --- | --- |
| 수강 등록·수업별 비밀번호/잠금 상태 | 수업 정의·주소·설정 |
| 학생 웹 세션·확장 access/refresh·연결 중 인증·활성화/수령 코드 | 공통 교수자 인증·서버 비밀·최초 명단 초기화 표식 |
| 과제 수락·다운로드 기록·학생별 배정/권한 | 과제 초안/공개본·기간·공개 상태·채점 설정·정답/오답·검증 이력 |
| 제출 요청·접수본·채점 결과·학생 제출 이력·중복 요청 키와 관련 집계 | come3105의 학생·수강·인증·제출·점수·과제 |

전역 Student 식별 행은 유지하고 come2201의 Enrollment와 수업 종속 자료만 초기화한다.
따라서 같은 학번으로 다시 등록하면 기존 학생 식별을 사용하되 새 수강·인증 상태로 시작한다.
come2201만 수강하던 학생의 전역 식별 행도 이번 작업에서 삭제하지 않는다. 이 기능은 개인 정보의
완전 삭제 기능이 아니라 **한 수업의 실습 기록을 초기 상태로 되돌리는 운영 기능**이다.

등록된 과제의 학생 제출 수는 0이 되지만 과제 자체와 공개 기간은 바꾸지 않는다.
이미 마감된 과제는 재등록해도 수령할 수 없으므로 별도 마감 연장이 필요할 수 있다.

## 2. 교수자 UX — 위험 작업 영역의 5단계

진입(신규 예정): 수업 상세 → 학생 관리 → **위험 작업 → 학생·제출 기록 초기화**.
일반 학생 추가/비밀번호 초기화 버튼과 분리한다. 한 번의 클릭이나 GET 요청으로 실행하지 않는다.

1. **범위 확인:** come2201 수업명·코드·학기·분반과 삭제/보존 표를 표시한다.
2. **영향 미리보기:** 수강생·수령 코드·접수본·점수·진행 작업 수와 예상 영향을 서버에서 계산한다.
   “come3105는 변경하지 않습니다”, “과제는 유지됩니다”를 함께 표시한다.
3. **백업 확인:** 최근에 만든 검증된 백업 ID·시각·대상 데이터 저장소를 확인한다.
   단순 ‘백업했습니다’ 체크만으로 실행을 허용하지 않는다.
4. **재인증·명시적 승인:** 교수자 재인증 후 `come2201 초기화`를 직접 입력하고 사유를 작성한다.
   “학생 수강·인증·제출·점수가 제거되며 화면에서 되돌릴 수 없습니다”를 확인한다.
5. **결과·재등록:** 대상별 처리 건수, 보존 확인, 작업 ID를 표시하고 **CSV로 학생 다시 등록**으로 연결한다.

확인 전에는 취소할 수 있다. 실행 요청 후 응답이 끊기면 ‘실패’나 ‘미실행’으로 추정하지 않고
작업 ID로 상태를 조회한다. 작업 진행 중의 ‘취소’가 복원을 의미하는 기능은 만들지 않는다.
초기화 완료 후 CSV 재등록은 별도 확인 작업이며, 초기화와 동시에 오래된 명단을 자동 재적용하지 않는다.

## 3. CLI·웹 공통 계약(신규 제안)

`CourseResetService`에 영향 계산·백업 검증·잠금·초기화·사후 검증을 모은다.
MVC Controller는 교수자 권한·CSRF·정확한 Origin·재인증을 검사하고 View는 상태와 영향만 표시한다.
CLI도 같은 서비스를 호출한다. 현재 제공 중인 student import/password-set에 삭제 기능을 섞지 않는다.

개념상 `student reset-plan`(조회)과 `student reset-apply`(실행), `student reset-status`로 나눈다.
**이 명령들은 계획상의 이름이며 현재 터미널에서 실행할 수 없다.**

- dry-run 계획에는 정확한 course_key, DB 식별, 관련 행/참조 집합의 지문, 예상 건수, 만료를 담는다.
- 적용은 계획 ID, 검증된 백업 ID, 교수자 확인 문구·사유·요청 키를 요구한다.
- 계획은 10분 만료·해당 수업/운영자 세션에 묶고, 데이터 변경이 있으면 폐기 후 다시 미리보기한다.
- 권한이 없는 학생/다른 수업 세션은 계획·결과에 접근할 수 없다. 모든 학생·파일 경로를 응답에 덤프하지 않는다.
- 동일 요청 키의 재시도는 같은 작업 결과를 반환한다. 완료된 작업을 다시 실행해 새로 등록한 학생을 지우면 안 된다.

## 4. 원자성·동시 작업·인증 폐기

1. 대상 수업에 유지보수 잠금을 설정한다. 신규 로그인·코드 발급/교환·다운로드·제출·명단 변경을 막는다.
2. 대기/실행 중 학생 채점과 교수자 검증이 있으면 초기화를 거절한다. 미리보기에서 기다릴 작업을
   알려 주며, MVP에서는 강제 프로세스 종료/작업 삭제 옵션을 제공하지 않는다.
3. 기존 과제 공개/수강/제출 writer도 같은 잠금·수업 generation을 확인하게 한다.
   늦게 도착한 worker 결과나 HTTP 요청이 초기화 이후 이전 기록을 되살리지 못하게 한다.
4. 정확한 계획 지문·백업·스키마를 재확인한 뒤 DB 트랜잭션에서 대상 자격·권한·기록을 제거한다.
   외래키 참조 순서를 코드로 정의하고 FK 검사를 끄지 않는다. 전역 student 단위 삭제/폐기는 사용하지 않는다.
5. 수업 generation을 증가시키고, 메모리의 학생 웹 세션·device 연결 상태도 무효화한다.
   토큰/쿠키/코드는 매 요청의 수업 상태·generation 검사를 통해 재등록 후에도 거절되어야 한다.
6. 학생·제출·점수 0, 과제 해시/상태 유지, 다른 수업 불변, foreign_key_check를 확인한다.
   DB 오류는 전체 롤백한다. 실패 원인을 공개 로그에 비밀번호/소스와 함께 노출하지 않는다.
7. 성공 후 대상 수업은 재등록 대기 상태로 둔다. 기존 학생용 자료는 보존하지만 수령은 막고,
   교수자가 재등록 결과를 확인한 뒤 운영 재개를 승인한다. come3105 운영 상태는 바꾸지 않는다.

## 5. 파일과 백업·복구

- 학생 제출 원본·작업 폴더는 DB 처리 전에 참조 manifest를 만든다. 공유 CAS 파일은 다른 과제,
  다른 수업, 검증 예제와 해시가 같을 수 있으므로 해시 경로를 무조건 지우지 않는다.
- DB 초기화 후 학생 API에서 이전 원본 접근을 차단한다. 미참조 대상 파일은 별도 제한된
  격리 보관 작업으로 이동하고, 실패하면 정리 대기로 표시한다. 공유 파일과 교수자 자료는 유지한다.
- 전체 data_root/DB 삭제나 broad recursive 삭제는 금지한다. 실제 저장소 내 검증된 대상 경로만 취급한다.
- 백업에는 DB와 제출/bundle·교수자 자료·필수 설정을 함께 포함한다. ZIP/SQL 한 파일 복사로
  실행 중 SQLite WAL과 자료의 일관성을 보장한다고 가정하지 않는다.
- 첫 MVP 백업은 서버 정상 종료 후 수행하는 검증된 운영자 절차로 제한한다. 짧은 전체 서버
  점검 시간 동안 come3105도 일시 접속 중단될 수 있지만 데이터는 변경하지 않는다.
  재시작 후 대상 수업 잠금/변경 지문을 확인해 백업 이후 변경이 있으면 다시 백업한다.
- 백업은 접근 제한된 경로에 보관하고 다운로드 링크로 학생/브라우저에 노출하지 않는다.
- 자동 되돌리기는 제공하지 않는다. 복원 시 운영자가 접수를 멈추고 별도 위치에 백업을 복원·검사한 뒤
  come2201 자료만 선별 복구한다. 전체 DB 복원은 다른 수업의 최신 제출을 덮어쓸 수 있어 기본 복구로 금지한다.
- 복원해도 이전 토큰·비밀번호 자격은 자동 활성화하지 않고 새 인증을 발급한다.
  격리 보관·백업의 최종 보존 기간/삭제는 운영자가 별도 결정하며 본 작업으로 영구 파기하지 않는다.

## 6. 재등록과 기존 CSV 초기화 규칙

초기화 성공 → CLI 수업별 import 또는 신규 웹 CSV 등록 → 학생 목록 검증 → 운영 재개 → 새 로그인.
기존 `student_roster.csv` 초기화 완료 표식은 삭제하지 않는다. 서버 재시작으로 이전 명단이
자동 복원되거나 과거 비밀번호가 되살아나면 안 된다.

재등록에는 `student_key,active,password` 형식의 수업별 명단을 사용하고 come2201을 명시한다.
되도록 새 학생별 6자리 비밀번호를 발급한다. 기존 제출/점수는 새 수강으로 재연결하지 않는다.
CSV 형식 오류나 등록 실패가 나면 수강생 없는 재등록 대기 상태를 유지하고 과제는 보존한다.
다른 수업의 비밀번호를 교체하는 옵션은 사용하지 않는다.

## 7. 필수 시험과 완료 판정

- 두 수업을 함께 듣는 합성 학생, come2201 전용 학생, 활성/비활성 학생을 준비한다.
- 초기화 후 come2201 수강/인증/수락/제출/점수는 0, 과제 ID·해시·기간·공개 상태는 동일하다.
- come3105의 수강/비밀번호/세션/코드/제출/점수와 학생 전역 식별은 유지된다.
- 이전 access/refresh·쿠키·수령 코드·활성화·device 교환은 모두 거절되며 같은 학번 재등록 후에도 재사용 불가.
- 실행 중 작업·만료/변경된 계획·잘못된 확인 문구·백업 없음·학생 권한 요청은 실행 전에 거절한다.
- 트랜잭션 중 예외·강제 종료·응답 유실·중복 요청에서 반쪽 초기화나 재등록 학생 재삭제가 없다.
- 서버 재시작 시 잠금/작업 상태가 복구되고 CSV 자동 초기화는 재실행되지 않는다.
- 공유 해시 원본은 다른 수업에서 계속 접근 가능하며 come2201의 과거 원본은 권한상 접근 불가.
- 백업의 별도 복원과 수업별 선별 복구를 시험해 다른 수업의 새 제출을 보존한다.
- 최종 합성 E2E: 초기화 → CSV 재등록 → 새 코드 발급 → 기존 과제 수령 → 새 제출/점수.

위 검증을 마치기 전에는 실제 운영 데이터 초기화 버튼/명령을 활성화하지 않는다.
실행 후에는 삭제된 항목·보존된 항목·복구 가능한 백업·정리 대기 파일 여부를 명시해 보고한다.
