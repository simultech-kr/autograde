# 교수자 성취도 평가 플러그인 설계

2026-09-18 · 설계 단계. [전체 플러그인·SES 설계](platform-plugin-ses.md)의 업무 플러그인이다.
실제 학생 성취도 데이터를 분석한 결과가 아니며, 아래 목표·가중치·임계값은 교수자 검토용 예시다.

확장: [제공 루브릭 평가 모듈](rubric-evaluation-plugin.md)이 항목별 근거/점수를 생성하고 이 모듈이 목표별로 해석한다.
제품군/고객별 조합은 [SPL 설계](software-product-line.md)에 정의한다. 루브릭 평가는 성취도 없이도 독립 사용 가능하다.

## 1. 제공 가치와 하지 않는 일

교수자가 “누가 몇 점인가”뿐 아니라 **어떤 학습목표가 충족되었고, 어떤 증거가 부족하며,
다음 실습에서 무엇을 보완할지** 확인하도록 한다. 수업/분반 비교, 개인별 변화, 과제 품질 검토를 지원한다.

자동 채점 총점은 실행 결과의 근거이지 설계 의도·개념 이해를 완전히 입증하는 값은 아니다.
특히 옵저버/데코레이터는 출력 일치만으로 패턴 적용을 판정하지 않는다.
출석·노력·학습시간·능력/성향을 접속 횟수나 제출 횟수로 추정하지 않는다.
지원 대상 추천은 별도 plugin이며 자동 낙제·순위·불이익·학생 자동 연락으로 연결하지 않는다.

## 2. 교수자 사용 흐름

1. 수업/분반에서 **성취도 사용** → `자동 증거` 또는 `자동+교수자 루브릭` 선택.
2. 학습목표 등록: 식별자, 학생에게 설명할 목표, 관찰할 행동, 판정 기준.
3. 과제 등록 시 테스트/수동 루브릭 항목을 목표에 연결하고 배점·중요도·공개 범위를 설정.
4. 정답/오답 검증 시 “점수→목표별 증거” 미리보기. 목표 미연결·수동 평가 누락을 안내.
5. 과제 공개 시 과제 버전·rubric·목표 매핑·평가 정책을 고정.
6. 학생 제출 후 자동 증거와 교수자 코드 검토를 수집. 최신 제출이 대기 중이면 그대로 표시.
7. 성취도 화면에서 목표별 상태·증거 충족률·점수·변화를 확인. 필요한 학생/목표로 좁혀 근거 열기.
8. 교수자는 원본 코드·평가 항목을 확인하고 판단/사유를 기록. 확정·정정 이력은 덮어쓰지 않음.
9. 필요 시 승인한 피드백만 학생에게 공개하거나 지원 검토 plugin으로 전달.
10. 학기 보고서를 기준 시각·점수 선택·매핑/정책 버전과 함께 생성.

성취도 플러그인 선택만으로 개인별 교수자 인증이나 수동 루브릭을 설치하지 않는다.
의존성이 없으면 “사용 준비 필요”와 선행 작업을 표시하고 활성화 요청을 거절한다.

## 3. 학습목표·루브릭 예시

| 목표 | 관찰할 증거 | 자동/수동 평가 |
| --- | --- | --- |
| LO-OBS-1: 구독자 등록/해제와 상태 변경 통지를 구현한다 | 등록·해제 후 알림 대상과 횟수 테스트 | 자동 실행 증거 |
| LO-OBS-2: 발행자와 구독자를 추상 인터페이스로 분리한다 | 구체 클래스 의존 여부·새 구독자 추가 영향, 해당 코드 위치·설명 | 교수자 코드 루브릭 |
| LO-DEC-1: 래퍼 조합 순서에 따른 기능을 구현한다 | 단일/다중 장식·순서 변경 결과 | 자동 실행 증거 |
| LO-DEC-2: 공통 인터페이스를 유지하며 위임한다 | 상속/위임 구조, 새 장식 추가와 기존 코드 수정 범위 | 교수자 코드 루브릭 |

수동 루브릭 예: 0=근거 미충족, 1=부분 구현, 2=동작하지만 결합 문제 있음, 3=기준 충족.
각 단계에 확인할 코드/조건을 적는다. **미평가(null)와 검토 결과 0점을 구별**한다.
학생 설명은 README/허용 제출 파일의 설명 문항으로 받고, 질문 프롬프트는 교수자의 검토 안내로 사용한다.
성취도 계산기 내부에는 AI 판정을 넣지 않는다. 후속 선택 기능인 루브릭 AI 보조는 제안만 생성하며
교수자가 승인한 항목 증거만 이 모듈이 소비한다. 세부 제한은 루브릭 평가 설계를 따른다.
자동 항목 검사도 자체 정답/오답 사례로 타당성을 검증해야 한다.

교수자가 목표를 만들지 않은 기존 과제는 `unmapped`다. 총점만으로 목표 달성도를 자동 추정하여 채우지 않는다.
C/C++·Linux/WSL2·Windows의 목표를 동일하게 정의할 수 있지만 실행기/과제의 난이도가 같은 것으로 간주하지 않는다.

## 4. 증거 계약과 계산

### 식별 단위

- 학생은 `student_id`, 수강은 `enrollment_id`, 개설/분반은 `course_key`로 구분한다.
- 증거 단위는 논리 과제 × 선택된 submission × grading run/revision × criterion × mapping version.
- 연결 고리: `submitted_at → submission_id → source_digest → grading_run_id → criterion_result → outcome_id`.
- 같은 제출의 네트워크 재시도, 한 과제의 복제 release, 테스트 반복 실행을 서로 다른 성취 증거로 중복 계산하지 않는다.
- 유효하고 superseded되지 않은 채점 run만 후보로 삼는다. 수동 증거도 **선택된 동일 submission/digest**에 연결한다.
  이전 제출의 수동 검토를 새 제출에 자동 이월하지 않는다.

`CriterionEvidence.v1`(제안): course/enrollment, logical_assignment_id, release_id, submission_id,
source_digest, grading_run_id, criterion_id/version, earned, maximum, validity, evaluator_type,
reviewer_id(수동), evaluated_at, supersedes_id, feedback_visibility, restricted_evidence_ref.
자동 결과가 criterion ID 없이 총점만 제공하면 `unmapped`로 두며 어댑터에서 수치를 만들어내지 않는다.

### 분모와 점수 정책

계산 전 기준 시각 `as_of`, 수강/면제/개인 마감 snapshot, 대상 논리 과제, 목표 mapping version을 고정한다.
수업 현재 활성 명단 × 현재 과제 목록을 과거 의무 대상으로 사용하지 않는다.
각 항목의 수업 내 목표별 중요도 `w(j,o)`를 고정하고 유효한 항목만 분모에 남기는 정책과 혼동하지 않는다.
`w`는 양수 유한수이며 복수 목표에 연결할 때 항목별 배분 비율 합은 1로 고정한다.
항목의 기본 중요도 × 목표 배분 비율이 `w`다. 목표별 점수를 다시 합쳐 총 성적으로 사용하지 않는다.

| 값 | 정의 |
| --- | --- |
| E(s,o) | 기준 시각에 평가 대상인 학생 s·목표 o의 항목 집합. 아직 공개/평가 시점이 아닌 미래 항목, 면제 항목 제외 |
| V(s,o) | E 중 선택된 제출과 유효 채점/검토가 있어 점수로 계산 가능한 항목 |
| q(j) | earned / maximum. maximum > 0, 0 ≤ earned ≤ maximum, 유한수일 때만 유효 |
| 관측 성취 점수 | 100 × Σ(V) w(j,o)q(j) / Σ(V) w(j,o). V가 비면 N/A |
| 증거 충족률 | 100 × Σ(V) w(j,o) / Σ(E) w(j,o). E가 비면 N/A |
| 목표 달성 학생 비율 | 확정 가능한 기준 충족 학생 / 확정 가능한 평가 대상 학생. 대상 전체와 자료 부족 인원도 함께 표시 |

관측 점수는 관측된 항목만의 값이다. 증거가 적어도 100점일 수 있으므로 **증거 충족률과 함께** 표시하고
단독으로 달성 판정/성적 환산에 사용하지 않는다. 예정된 미평가 항목을 지워 충족률을 높이지 않는다.
예시 판정 정책은 모든 필수 항목·최소 독립 과제 수를 충족하고 충족률 100%일 때만
80 이상=목표 달성, 60 이상=부분 달성, 그 미만=보완 필요다. 이는 교육적으로 검증된 절대 기준이 아니다.
실제 과목 담당자가 공개 전 기준/최소 증거량을 승인하며 평가 후 임계값 변경은 새 정책 버전과 영향 검토를 요구한다.

선택 정책은 **같은 논리 과제의 제출본 전체**에 적용한다. 항목마다 서로 다른 최고 제출을 골라 가상 답안을 만들지 않는다.

- `latest_received`: 기준 시각까지 마지막 receipt(서버 sequence로 동률 해소). 현재 대기/실패면 과거 점수를 대신 쓰지 않음.
- `best_valid`: 비교 가능한 동일 평가 기준에서 유효한 완료 제출의 전체 점수 최고, 동률은 최근 receipt.
  수동 필수 항목이 미평가이면 hybrid의 완료 제출 후보가 아님. 최신 접수 상태는 별도 표시.
- `instructor_confirmed`: 교수자가 지정한 제출/채점 run. 없으면 미확정이며 latest/best로 자동 대체하지 않음.

재채점은 이전 근거를 superseded로 남기고 새 snapshot을 만든다. 정정된 원장과 고정된 성취도 보고서의
차이를 “변경된 근거 있음”으로 안내한다. 확정 보고서를 몰래 덮어쓰지 않는다.
난이도·배점·rubric이 달라진 버전은 백분율로만 같게 취급하지 않는다. 승인된 호환 매핑이 없으면 비교 불가다.

### 누락·예외 표시

| 상황 | 성취도 처리 |
| --- | --- |
| 실제 평가 0점 | 유효 증거로 0점 포함 |
| 미제출 | missing evidence + 별도 미제출 상태, 개념 이해도 0점으로 단정하지 않음 |
| 채점 대기/실행 중 | pending, 최신 대신 과거 점수 표시 금지 |
| 서버/도구 오류 | infrastructure_error, 학생 오답과 분리 |
| 교수자 미검토 | manual_review_pending, null 유지 |
| 채점 기준상 컴파일 실패=0점 | 해당 기준의 유효 결과가 확인되면 0점. 인프라 실패와 구별 |
| 면제/수강 전 과제 | 대상 제외 사유 기록, 충족률 분모 제외 |
| 최대 점수 0·잘못된 수치·목표 미연결 | invalid 또는 unmapped, 계산 제외와 누락 안내 |
| 비공개 결과 | 교수자 권한 범위에서 분석 가능. 학생 projection은 공개 가능한 근거로만 별도 계산 |

학생에게 비공개 항목을 포함한 합계/충족률을 그대로 제공하면 숨긴 결과를 추론할 수 있다.
학생용은 승인된 공개 기준에서 재계산하거나 “교수자 확인 후 공개”로 전체 보류한다.
미제출 0점 등 최종 성적 정책은 별도 Gradebook 계약이며 성취도 plugin이 성적 원장을 수정하지 않는다.

### 손계산 인수 사례

하나의 목표에 자동 항목 A 중요도 60, 수동 항목 B 중요도 40을 연결하고 둘 다 필수로 설정한다.

- A=8/10, B=3/4 → 60×0.8 + 40×0.75 = **78점**, 충족률 **100%**, 예시 기준에서 부분 달성.
- A=8/10, B=미검토 → 관측 점수 **80점**, 충족률 **60%**, **판정 보류**. B를 0점으로 대체하지 않음.
- A=8/10, B=검토 결과 0/4 → **48점**, 충족률 **100%**, 보완 필요.
- V=0 → 점수 N/A. E>0이면 충족률 0%, E=0이면 충족률도 N/A.
- 직전 제출 90점, 최신 제출 채점 대기 → 최신 pending / 이전 최고 90점으로 분리. latest 기반 목표는 현재 판정 보류.

부동소수점 반올림으로 임계값을 넘기지 않도록 계산은 decimal/rational 정책을 명시하고 판정 후 표시만 반올림한다.
향상 수치는 동일 목표/매핑/정책·비교 가능한 근거에서만 계산한다. 60→80은 **+20%p**이며 인과적 학습 효과로 단정하지 않는다.

## 5. 교수자 화면과 접근성

교수자 공통 shell에 `수업 → 성취도` 탭을 기여한다. 독립 관리자 페이지를 하나 더 중복 생성하지 않는다.

- 상단: 수업명·학년도·학기·분반, 대상 기간, 기준 시각, 점수 선택 정책, 미확정/갱신 상태.
- 요약: 평가 대상 N명 / 판단 가능 N명 / 근거 부족 N명 / 수동 검토 N건. 서로 다른 집계 단위를 명시.
- 목표별 표: 목표명, 관측 점수 분포, 자료 충족, 달성/부분/보완/보류 인원. 분모와 근거 수준 표시.
- 학생별 표: 학생 × 목표 상태, 최신 제출 상태, 이전 최고, 변화, “근거 보기”. 색 외에 텍스트/아이콘을 함께 사용.
- 학생 상세: 목표 설명 → 항목별 점수/누락 → 제출 시각·코드 버전 → 코드/이전 코드 비교 → 교수자 판단·사유.
- 검토함: 수동 미평가, 미연결 목표, 재채점 후 확인 필요, 분석 실패를 구분하고 처리 후 원래 목록으로 복귀.
- 좁은 화면: 한 학생/목표 카드씩 읽도록 전환, 필터 요약 고정, 가로 매트릭스를 유일한 탐색 수단으로 사용하지 않음.
- 위험 작업: 확정 전에 영향과 근거 버전을 보여 주고 재확인. 미저장 루브릭 경고·충돌 감지 적용.

학생에게는 본인의 승인된 목표·현재 근거·다음 보완 항목만 제공한다.
다른 학생 순위·교수자 상담 기록·비공개 정답/테스트는 표시하지 않는다.
VS/VS Code 첫 단계는 기존 결과와 별도 “학습목표” 요약/웹 연결로 시작하며 현재 제출 점수 화면을 대체하지 않는다.

## 6. 저장·계약·확정 이력

| 제안 테이블 | 소유 plugin / 핵심 내용 |
| --- | --- |
| learning_outcome_versions | outcome.catalog / course, outcome ID, 관찰 기준, version |
| rubric_criterion_versions | rubric.mapping / logical assignment, rubric, 항목 ID·기준·배점 |
| outcome_mapping_versions | rubric.mapping / criterion→outcome, 중요도·배분·필수 여부, 유효 구간 |
| criterion_evidence | 증거 adapter / submission/run/criterion/version, 점수·유효 상태·근거 참조 |
| manual_rubric_decisions | manual rubric / reviewer, submission digest, 점수·사유·supersedes, version |
| achievement_snapshots | achievement / as_of·cursor·대상·분모·정책·mapping·plugin/PES hash |
| achievement_cells | achievement / enrollment×outcome, 점수·충족률·상태·근거 refs |
| achievement_confirmations | achievement / snapshot hash·판단자·확정/정정 사유, append-only |

루브릭 평가 모듈 도입 시 rubric criterion·manual decision은 해당 모듈 소유 원장을 참조/projection한다.
성취도 모듈에 같은 평가 원장을 복제하거나 별도 점수를 확정하지 않는다.

로그인 비밀정보·CSV 비밀번호·수령 코드를 복사하지 않는다. 소스 코드는 기존 digest 참조로 연결한다.
SQLite UNIQUE/foreign key와 버전 조건으로 같은 증거·snapshot 중복을 방지한다.
사용 중인 mapping은 수정 불가, 새 버전으로만 변경한다. outcome 삭제 대신 참조가 있으면 retired로 관리한다.
수업 간 공유 목표 template은 복사/version 참조로 관리하며 다른 분반의 rubric을 자동 갱신하지 않는다.

제안 query: `get_course_achievement(scope, snapshot, filters)`, `get_student_evidence(scope, student, outcome)`.
제안 command: `create_outcome_version`, `validate_mapping`, `request_recompute`, `review_criterion`,
`confirm_snapshot`, `correct_confirmation` (모두 검증된 actor/scope·expected_revision·멱등 키).
분석 작업은 accepted/queued/running/ready/failed를 구분한다. 다시 조회는 읽기만 수행한다.

교수자 확정은 자동 계산 근거를 지우거나 바꾸지 않는다. `calculated_state`와 `instructor_decision`을 나란히 보존한다.
개인별 교수자·조교의 수업 권한과 reviewer 신원을 확인해야 확정할 수 있다.
관찰된 제출 자료만으로 학생의 전반적 능력을 확정한 것처럼 표시하지 않는다.

## 7. SES 대안과 검증 기준

- AchievementDisabled: 기존 채점/결과 사용 유지, 새 분석 중단. 과거 결과 보존·허용된 조회/내보내기는 별도 정책.
- CriteriaAchievement: 자동 항목 증거만 평가. 수동 이해도 목표는 자동으로 달성 처리하지 않음.
- HybridAchievement: 자동/수동 근거 결합. 개인별 인증·루브릭 검토 계약·감사 필수.

순수 계산기는 외부 I/O 없이 snapshot+mapping+policy를 받아 같은 결과를 생성한다.
Worker는 snapshot 생성·순수 계산·원자적 결과 등록을 연결하고 report/support/UI는 그 결과를 소비한다.
report exporter가 동일 지표를 다시 계산하여 화면과 다른 값을 만들지 않는다.

인수 시험: 위 손계산, 소수 임계값·분모 0·잘못된 배점·매핑 누락·복수 목표 배분,
동일 과제의 release 중복·재시도·최신 pending·최고 제출 동률·수동 검토 불일치 digest,
재채점/정정/역순 이벤트·등록/면제 유효기간·교과목/분반 분리·비공개 점수 추론 방지,
불완전 자료와 0점 구별·비교 불가 버전·개인 권한·동시 검토 CAS·증거 링크/코드 읽기 권한,
plugin 비활성/재시작·snapshot 재현·분석 실패 시 제출 영향 없음·25명 병행 부하·반응형/키보드/다크 테마.

운영 채택 전 교수자에게 합성 학생 사례를 보여 “수치의 의미·판정 보류 사유·근거 찾기·정정 방법”을
설명 없이 이해하는지 확인한다. 실제 교육 효과나 판정 정확도는 이 설계만으로 보장하지 않는다.
