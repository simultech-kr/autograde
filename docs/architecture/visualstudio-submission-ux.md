# Visual Studio: 제출 접수와 채점 확인 분리 / UI 개선 검토

2026-09-16 · Visual Studio 2022/2026 Community 확장 0.4.0.
VS Code 확장은 이번 변경 대상이 아니다. 서버의 제출/결과 API 계약은 유지한다.

후속 **0.5.0**에서 두 IDE의 결과 요약과 수정 필요 항목을 구현했다.
[현재 결과 UI·교과목/분반 관리 안내](../operations/results-and-course-admin.md)를 참고한다.
아래의 “UI 검토”는 0.4.0 시점의 제안 기록이다.

## 구현한 흐름

1. 학생이 저장된 파일 목록과 제출 대상을 확인하고 업로드한다.
2. 서버에서 접수번호를 받으면 **제출 접수 완료**를 표시하고 작업 버튼을 다시 활성화한다.
3. 별도 **마지막 접수 / 백그라운드 채점 확인** 영역에 과제명·교과목·접수번호·서버 접수 시각을 표시한다.
4. 5초 간격으로 결과를 자동 조회한다. 최대 시간은 클라이언트가 접수 응답을 받은 뒤 2분이다.
5. 이 동안 과제 다운로드, 제출 이력 조회, 재제출, 로그아웃 등을 할 수 있다.
6. 자동 조회 시간이 끝나도 접수는 취소되지 않는다. 해당 과제를 선택하고 **최신 결과 확인** 또는
   **제출 기록 조회 → 선택 기록의 결과 확인**으로 조회한다.

접수 완료는 서버에 소스가 전달되어 접수번호를 받았다는 뜻이다. 검증 통과·채점 성공·점수 공개를
보장하는 표시가 아니다. 업로드 중 연결이 끊겨 접수번호를 받지 못한 경우는 여전히 결과 불명확으로
안내하며, 자동 조회 장애와 구분한다.

| 서버 상태 | 학생 표시 | 자동 조회 |
| --- | --- | --- |
| received | 접수됨 · 서버 검증 대기 | 계속 |
| accepted / queued | 채점 대기 | 계속 |
| running | 채점 중 | 계속 |
| graded | 채점 완료 · 결과 공개 대기 | 종료, 공개 후 직접 조회 |
| published | 결과 공개됨 + 점수·피드백 | 종료 |
| rejected | 제출 검증 거절 | 종료, 교수자 확인 |
| infra_failed / assessment_failed / failed | 채점 환경 오류 또는 채점 작업 실패 | 종료, 교수자 문의 |
| 알 수 없는 상태 | 상태 확인 필요 | 제한 시간 내 계속 |

## 경계와 예외 처리

- 자동 추적 대상은 **이번 로그인에서 마지막으로 접수한 제출 1건**이다. 다른 과제를 선택해도
  접수 영역의 과제명을 유지한다. 전체 수업 제출을 계속 감시하는 기능은 아니다.
- 재제출이 접수되면 이전 자동 조회를 중단하고 새 접수번호를 추적한다. 이전 제출은 서버 이력에
  남으며 채점이 취소되지는 않는다. 재제출 실패 시에는 기존 접수 정보와 조회를 유지한다.
- 로그인 변경, 서버 주소 변경, 로그아웃, 확장 종료 시 기존 추적을 폐기한다. 늦게 도착한 응답이
  다른 학생 또는 새로운 제출에 섞이지 않도록 요청 취소와 객체 동일성 검사를 함께 적용한다.
- 연결 실패·조회 시간 초과·5xx·429에는 접수 유지 문구를 표시하고 제한 시간 내 재조회한다.
  401/403 등 접근 실패는 무한 재시도하지 않는다. **소스를 자동 재제출하지 않는다.**
- 자동 결과는 전용 영역만 갱신한다. 사용자가 직접 조회한 과거 결과나 파일 목록을 덮어쓰지 않는다.
- 학생 작업이 진행 중이면 다음 자동 조회를 미룬다. 이미 시작된 인증 요청은 직렬화되므로
  새 작업이 해당 요청 종료를 잠시 기다릴 수 있다. 버튼 클릭만으로 인증 갱신을 강제로 끊지는 않는다.
- 접수 정보·토큰을 새로 디스크에 저장하지 않는다. IDE 재시작 후에는 로그인과 이력 조회가 필요하다.
- “현재 작업 취소”는 진행 중인 학생 작업에만 적용한다. 서버 채점 취소 버튼이 아니다.

## UI 검토: 아직 남은 개선점

현재 `AssignmentControl`은 단일 세로 패널에 설정·로그인·과제·제출·이력·복원·로그아웃을
동일한 형태의 버튼으로 배치한다. 좁은 도구 창에서는 핵심 동작과 결과를 찾기 위해 스크롤해야 한다.
이번에는 접수/채점 영역과 상태 문구만 개선했으며, 아래 전체 재배치는 **설계 제안**이다.

| 우선순위 | 현재 문제 | 제안 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 주소·코드 설명이 매번 화면 위를 차지함 | 연결되면 설정을 접고 `서버 연결됨 / 로그인됨`을 짧게 표시 | 로그인 후 첫 화면에 선택 과제와 제출 버튼 표시 |
| 1 | 모든 버튼이 같은 비중 | 현재 과제 카드 안에 다운로드·폴더·제출을 묶고 `제출하기`를 주 버튼으로 지정 | 학생이 다음 동작을 별도 설명 없이 찾음 |
| 1 | 여러 확인창과 긴 안내 사이에서 제출 대상 혼동 | 과제명·파일 수·폴더를 한 번의 제출 미리보기에서 확인 | 미저장 안내와 최종 확인 통합, 다른 과제 제출 방지 |
| 1 | 로그인 전에도 사용 불가능한 동작이 활성화됨 | 로그인·과제 선택·폴더 검증 여부에 따른 버튼 활성화와 이유 표시 | 오류를 누르기 전에 필요한 작업을 알 수 있음 |
| 2 | 점수·진단이 긴 텍스트 덩어리 | 점수 요약, 항목별 피드백, 접을 수 있는 상세 로그 | 좁은 창에서도 점수와 다음 수정 사항이 먼저 보임 |
| 2 | 이력 조회·복원 버튼이 일상 작업과 섞임 | `제출 이력` 접기 영역 또는 별도 탭, 선택 기록의 복원 버튼 | 복원은 필요할 때만 노출, 현재 소스 덮어쓰기 금지 유지 |
| 2 | 원시 상태·긴 해시·접수번호가 읽기 어려움 | 한국어 상태, 지역 시간, 접수번호 복사 버튼 | 상태를 색상 없이도 구별하고 문의 정보를 쉽게 복사 |
| 2 | 긴 작업 중 로그아웃도 비활성화됨 | 취소 후 로컬 인증 정리를 수행하는 자리 비우기 동작 설계 | 접수 여부 불명확 안내 및 늦은 응답 차단 함께 검증 |

제안 배치:

```text
Autograde                  연결됨 · 로그인됨
서버 설정 ▸                         로그아웃

현재 과제  [교과목 / 실습 제목]
작업 폴더  …                   폴더 변경
[과제 다운로드]                 [제출하기]

마지막 제출  접수 완료 · 시각 · 접수번호 복사
채점 상태    대기 / 채점 중 / 결과 공개
점수·피드백  …

제출 이력 ▸              문제 해결 도움말 ▸
```

테마 동적 자원은 유지한다. 320~480px 도구 창, 키보드 Tab/Enter, 확대 배율, 밝음·어두움·
고대비를 Windows 실기에서 확인해야 한다. 본 문서는 실제 화면 사용성 시험 결과가 아니라 코드 구조 검토다.

## 검증 결과와 현장 확인

- WPF/VSSDK compile-only: 경고 0, 오류 0.
- Python/C# 연동 및 소스 계약 시험: **18개 통과**.
- C# 자체 점검: **96개 통과**. 위 연동 시험에서 호출되므로 개수를 합산하지 않는다.
- 추가 자동 시험: 정상 상태 전이, 공개 대기·실패 상태 종료, 시간 제한, 네트워크·429·5xx 재조회,
  접근 실패 중단, 취소 후 늦은 응답 차단, 조회 대기 중 취소, 기한 이후 응답 억제.
- WPF 이벤트 결선·버튼 조작은 소스 계약 검사와 컴파일까지만 확인했다. Windows 실기 검증은 별도다.

배포 전 VS2022/VS2026 각각:

1. 0.4.0 VSIX를 Windows에서 빌드·설치하고 정상 로그인한다.
2. 채점 작업자를 잠시 멈춘 **시험 서버**에 제출한다. 접수번호가 나타난 직후 과제/이력/로그아웃
   버튼이 다시 활성화되는지 확인한다. 서버 API 자체는 계속 실행한다.
3. 이력을 열어 둔 상태에서 채점 작업자를 재개한다. 자동 결과만 바뀌고 이력 조회 내용은 유지되는지 확인한다.
4. 제출 A 후 변경된 코드 B를 제출한다. 이전 응답이 새 접수번호·결과를 덮지 않는지 확인한다.
5. 자동 조회 중 로그아웃/주소 변경/다른 학생 로그인. 이전 접수 정보가 사라지고 다시 나타나지 않는지 확인한다.
6. 접수 후 네트워크 차단·복구, 2분 초과 대기, 공개 대기·채점 실패를 시험한다.
   접수 유지 안내와 직접 조회 경로가 나타나는지 확인한다.
7. 창 숨김·복원·IDE 종료와 테마 전환도 시험한다. Windows 설치·화면 조작·Marketplace 게시는 아직 미검증이다.
