# 학생용 상세 채점 결과와 수정 가이드

2026-09-29 구현. 대상은 서버 결과 API, 교수자 웹의 C/C++ 표준 입출력 채점기,
VS Code 및 Visual Studio 결과 화면입니다. 운영 배포나 기존 점수 변경은 포함하지 않습니다.

## 학생이 확인하는 순서

1. 과제·현재 접수번호와 점수를 확인합니다. 이전 최고점은 별도로 표시합니다.
2. 수정이 필요한 항목이 먼저 펼쳐집니다. 통과한 항목은 필요할 때 열어 봅니다.
3. **확인된 현상**에서 교수자가 작성한 **평가 요소**와 컴파일 실패, 실행 오류, 시간/출력량 초과, 출력 불일치를 확인합니다.
4. **수정 가이드**를 보고 코드와 README의 공개 예제를 점검합니다.
5. 확인 가능한 경우 `main.cpp:12:3`처럼 제출 소스 위치를 표시합니다.
   검증되지 않은 원인이나 함수·행 번호는 추측하지 않습니다.
6. 모두 저장하고 재제출한 뒤 **새 접수번호**의 결과를 확인합니다.

컴파일 실패 때문에 실행하지 못한 테스트는 `선행 단계 해결 후 재검사`로 구분합니다.
미검사는 별도의 출력 오답이 아니며, 기존 배점 규칙에 따라 해당 항목의 현재 점수는 0점일 수 있습니다.
점수와 항목 상태가 모순되면 결과 확인이 필요함을 알립니다.

파일 위치가 없는 일반 진단도 결과 화면과 전체 진단에 표시합니다.
VS Code 문제 목록에는 안전한 제출 상대 경로가 있는 진단만 연결합니다.
출력 불일치만으로 Observer·Factory 등 패턴 구조의 잘못을 단정하지 않습니다.
패턴 구조와 설명은 별도 교수자 검토 대상입니다.

## 교수자의 과제별 가이드 작성

과제 초안 → **교수자 채점 자료 → 테스트·배점 직접 편집**에서
각 케이스의 `학생 공개 평가 요소`와 `학생용 수정 가이드`를 작성할 수 있습니다.
각각 선택 입력이며 2048자 이하입니다. 평가 요소에는 무엇을 평가하는지,
수정 가이드에는 실패했을 때 무엇을 점검해야 하는지 적습니다.
또는 교수자 전용 채점 ZIP의 `tests.json`에서 각 테스트에 `evaluation`과 `hint`를 넣습니다.

```json
{
  "negative_score": 0,
  "tests": [{
    "title": "공개 예제",
    "input": "",
    "output": "Hello, World!\n",
    "weight": 10,
    "public": true,
    "evaluation": "요구한 한 줄의 문구와 마지막 줄바꿈을 정확히 출력하는지 평가합니다.",
    "hint": "README의 대소문자, 공백, 마지막 줄바꿈을 점검하세요."
  }]
}
```

작성한 평가 요소는 **통과·실패·미검사 모두**에서 `평가 요소: …`로 표시합니다.
미검사 항목의 평가 요소는 검사 목적을 설명하며 실제로 검사했다는 뜻은 아닙니다.
평가 요소를 작성하지 않은 기존 테스트의 채점 결과는 그대로 유지합니다.
기존 결과의 `feedback` 문장에 포함하므로 새 결과 필드나 확장 기능 변경이 필요하지 않습니다.
기존 피드백 길이 제한이 적용되므로 평가 요소는 핵심 요구사항 위주로 간결하게 작성하세요.

실제로 실행했으나 실패한 케이스에 기본 실패 안내와 작성한 수정 가이드를 제공합니다.
통과했거나 선행 단계 때문에 미검사인 경우 해당 케이스의 사용자 정의 가이드를 붙이지 않습니다.

**`evaluation`과 `hint`는 `public: false`인 비공개 테스트에서도 학생에게 공개됩니다.**
비공개 입력·예상 출력·정답 코드·개인정보를 넣지 마세요. 예를 들어
“구독 해제 후 알림 대상이 갱신되는지 점검하세요”처럼 점검할 개념을 안내합니다.
교수자 웹에서 입력 오류가 나더라도 안내 문구를 복원하고 HTML은 문자로 처리합니다.

## 공개 정책과 보안 경계

- `public: true`인 케이스만 제목·입력·예상 출력을 기존 규칙대로 공개합니다.
  비공개 케이스는 번호, 결과 분류와 작성한 공개 평가 요소·수정 가이드만 제공합니다.
- 학생 프로그램의 stdout/stderr, 컴파일러 원시 로그, 내부 절대 경로는 전달하지 않습니다.
  컴파일 위치는 제출한 주 소스의 오류 위치를 확인할 수 있는 경우에만 추출합니다.
- `score_only`는 총점만 전달합니다. 결과가 공개되기 전에는 항목·진단을 노출하지 않습니다.
- 문자열·항목 수·전체 응답 크기 제한과 토큰 마스킹을 유지합니다.
- 파일 경로는 제출 폴더 기준 POSIX 상대 경로만 사용하고, 행·열은 유효한 양의 정수만 받습니다.
- 기존 `pilot-local` 실행은 보안 샌드박스가 아닙니다. 이번 변경으로 실행 격리가 제공되는 것은 아닙니다.

## 외부 채점기 출력 계약

기존 `rubric` 항목에 아래 필드를 선택적으로 추가할 수 있습니다. 기존 형식도 계속 지원합니다.

```json
{
  "score": 0,
  "max_score": 10,
  "rubric": {
    "output": {
      "title": "출력 형식",
      "score": 0,
      "max_score": 10,
      "status": "failed",
      "feedback": "정상 실행되었지만 출력이 요구사항과 다릅니다.",
      "hint": "출력 순서와 공백·줄바꿈을 공개 예제와 비교하세요.",
      "path": "main.cpp"
    }
  },
  "diagnostics": [{"severity": "info", "message": "공개 예제로 먼저 로컬 실행해 보세요."}]
}
```

`status`는 `passed`, `partial`, `failed`, `blocked`입니다.
`line`, `column`은 위치가 실제로 확인된 경우에만 추가합니다.
배점 없는 단계는 `score`와 `max_score`를 **둘 다 생략**합니다. `max_score: 0`은 허용하지 않습니다.
`hint`와 `feedback`은 학생 공개용 문장입니다. 원시 출력을 복사해 넣지 마세요.

## 적용 시 주의

1. 서버 코드를 업데이트하고 정상 재시작합니다. DB 마이그레이션이나 새 환경변수는 없습니다.
2. 새 화면을 사용하려면 VS Code/Visual Studio 확장을 새 코드로 빌드·설치해야 합니다.
3. 새로 검증하는 웹 과제에는 개선된 채점기가 포함됩니다. 이전에 검증한 미공개 초안은 먼저
   수정·저장한 뒤 새 리비전으로 검증하세요. 같은 리비전의 검증은 이전 성공 결과를 재사용합니다.
4. **이미 공개된 과제의 assessment는 불변 파일**입니다. 서버 재시작만으로 교체되지 않습니다.
   기존 수락·제출이 있는 수업에서는 채점 파일이나 digest를 덮어쓰지 마세요.
   새 버전 초안 복제 → 검증 → 공개는 별도 과제를 만드는 흐름이며, 같은 과제 코드의 기존
   공개본이 활성 상태이면 새 공개가 거부됩니다. 운영 중 과제에 적용할 때는 기존 공개본 처리와
   학생의 수령·마감·점수 이력 전환 계획을 먼저 확인해야 합니다.
5. 과거 점수는 재채점하지 않으며, 과거 결과에 없는 상세 원인은 새 화면에서도 만들어내지 않습니다.

## 검증

합성 자료로 C/C++ 정상 코드, 미완성 코드, 컴파일 오류, 실행 실패, 제한 초과, 미검사를 확인합니다.
서버 테스트는 결과 공개 전/점수 전용 정책, 경로·민감 필드 차단, 평가 요소·안내 문구 저장·복원을 검사합니다.
평가 요소는 통과·실패·미검사 표시와 기존 테스트의 결과 호환성을 함께 확인합니다.
VS Code는 결과 정규화·표시·비공개 상태를 시험합니다.
Visual Studio의 소스 연결 검사는 가능하지만 실제 C#/WPF 시험에는 .NET SDK와 Windows IDE가 필요합니다.
