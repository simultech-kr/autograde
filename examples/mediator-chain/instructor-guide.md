# Mediator + Chain of Responsibility 교수자 안내

실습 문의의 담당자 선택과 전달을 분리하는 C++17 과제입니다. 학생은 TODO 6개를 완성합니다. 파서와 명령별 출력·조회는 제공하며, 자동채점 기능 100점과 패턴 구조 검토는 분리합니다.

## 학습 범위

- 학생 단말이 `ILabMediator`로 전송을 위임하는 구조
- 각 Handler의 수락 조건과 다음 Handler로의 위임
- 첫 일치에서 종료하는 책임 연쇄와 순서 변경의 영향
- 담당자 선택 후 온라인 상태를 확인하는 Mediator의 전달 책임
- 성공할 때만 ID·발신자 통계·수신함을 갱신하는 상태 관리
- `std::optional`의 결과 없음, `std::unique_ptr`의 소유권, 참조의 수명

선수 지식은 클래스, 상속, 가상 함수, 생성자, `std::vector`와 조건문입니다. 네트워크 통신, 스레드, 실제 메시지 큐, 영속 저장은 요구하지 않습니다. 여기서 우선순위·담당 분야·오프라인 처리·ID 중복 정책은 이 실습의 동작 계약입니다. 모든 Mediator나 책임 연쇄가 같은 정책을 따라야 하는 것은 아닙니다.

## 교수자 웹 등록

1. [ZIP 생성 명령](README.md#웹-등록용-zip-생성)을 실행하고 **과제 관리 → 새 과제 등록 → 직접 만들기**를 엽니다. 별도의 새 과제로 등록합니다.
2. 제목을 `Mediator · Chain of Responsibility — 실습실 지원 요청 중계기`로, 언어를 C++로 설정합니다. 수업 환경에 맞게 플랫폼을 선택하고 C++17 사용을 확인합니다.
3. 문제 설명에 학생용 `README.md` 전체를 넣습니다. 저장된 설명이 학생 배포 README에 사용되므로 요약으로 대체하지 않습니다. 내보낸 `assignment.json`의 `description`도 전체 내용을 담습니다.
4. 대상 교과목·분반·수령 시작·제출 마감을 지정합니다. 이 패키지는 기존 과제에 등록하거나 일정을 자동 지정하지 않습니다.
5. 반복 제출과 피드백 실습을 위해 결과 공개를 **즉시 공개**로 설정합니다.
6. 학생 배포 자료에 `starter.zip`, 교수자 채점 자료에 `grading-private.zip`을 올립니다.
7. 준비 현황에서 **테스트 14개, 총 100점, 오답 기대 점수 0점**과 각 평가 요소·수정 힌트를 확인합니다.
8. 저장된 버전으로 검증하여 정답 100점, 오답 0점과 검증 성공을 확인한 뒤 시험 교과목에 공개합니다.
9. 시험 학생으로 수령·다운로드·제출·상세 결과를 확인한 뒤 실제 수업에서 공개합니다.

`assignment.json`은 웹 입력 참고 자료입니다. JSON 전체 업로드 기능을 전제하지 않습니다. 기존 채점 ZIP과 `evaluation`, `hint` 기능을 사용합니다.

## 기능 점수와 피드백

| 결과 키 | 평가 ID | 배점 | 평가 요소 |
| --- | --- | ---: | --- |
| `case_1` | C1 | 10 | 일반 CODE 문의를 TUTOR로 선택 |
| `case_2` | C2 | 10 | 일반 ENV 문의를 TECH로 선택 |
| `case_3` | C3 | 5 | 일반 GRADE 문의를 PROF로 선택 |
| `case_4` | C4 | 10 | PRIORITY 모드의 우선순위 3 문의를 PROF로 선택 |
| `case_5` | C5 | 5 | 방문 trace와 첫 일치 종료 |
| `case_6` | C6 | 10 | DOMAIN과 PRIORITY의 서로 다른 순서 |
| `case_7` | C7 | 5 | OTHER의 처리자 없음 |
| `case_8` | C8 | 5 | EMPTY 연쇄와 모드 복원 |
| `case_9` | M1 | 5 | 학생 단말의 발신자 ID 보존 |
| `case_10` | M2 | 10 | 수신함 분리와 도착 순서·값 보존 |
| `case_11` | M3 | 10 | 선택한 담당자가 오프라인이면 실패, 다음 후보로 전달하지 않음 |
| `case_12` | M4 | 5 | 실패한 ID의 재시도 허용과 성공 시에만 통계 갱신 |
| `case_13` | M5 | 5 | 성공한 ID의 전역 중복 차단과 빈 trace |
| `case_14` | M6 | 5 | 모드 변경 후 수신함·성공 ID·통계·온라인 상태 유지 |
| 합계 | | 100 | 기능 평가 |

C1, C4, C6, M1은 공개 테스트입니다. 나머지 입력과 예상 출력은 비공개이며, 학생에게 공지한 동작만 검사합니다. 한 항목은 전체 출력이 일치해야 배점을 받고 항목 내 부분 점수는 없습니다. 각 테스트는 새 프로세스로 실행합니다. 컴파일은 점수가 없는 선행 단계입니다.

`evaluation`은 통과·실패·미검사 항목의 확인 대상을 설명합니다. 실패 항목의 `hint`는 관련 함수와 상태, 로컬 재현 방향, `HINTS.md`의 평가 ID를 연결합니다. 비공개 항목에서도 이 두 문자열은 학생 공개 정보입니다. 정답 소스나 비공개 입력 전체를 넣지 않습니다.

예를 들어 M3 실패는 온라인 확인을 Handler에 넣었거나, 오프라인 담당자를 건너뛰어 다른 Handler를 찾았을 가능성을 점검하게 합니다. 단일 결과로 특정 소스 행의 오류를 확정하지 않습니다. 시작 코드는 연결이 미완성이므로 `SEND`에 `UNHANDLED`가 나올 수 있습니다. C1~C4와 M1~M2가 함께 실패하면 개별 조건보다 단말→Mediator→연쇄→수신함의 공통 경로를 먼저 확인합니다.

## 별도 패턴 구조 검토

입출력 100점만으로 Mediator와 Chain of Responsibility 구조를 증명할 수 없습니다. 아래 검토는 수동으로 수행하며 기능 100점에 자동 합산하지 않습니다. 별도 구조 점수를 운영하려면 기준과 배점을 먼저 공지합니다.

| 검토 기준 | 확인할 구현 | 피해야 할 구현 |
| --- | --- | --- |
| Mediator 인터페이스 | `StudentTerminal`이 `ILabMediator`를 통해 전송 | 단말이 담당자 객체나 수신함을 직접 변경 |
| 통신 조정 | `LabMediator`가 담당자 조회·온라인 확인·전달·통계를 담당 | Handler가 수신함과 중복 ID까지 관리 |
| 책임 연쇄 | `Handler::handle`이 수락하거나 다음 객체에 위임 | Mediator에 종류별 분기를 복제해 연쇄 우회 |
| 첫 일치 종료 | 선택을 얻은 즉시 반환, 방문한 Handler만 trace에 추가 | 성공 뒤 연쇄를 계속 방문하거나 마지막 결과로 덮어씀 |
| 다형성 | `accepts`를 구체 Handler가 구현 | 클라이언트가 구체 타입을 매번 판별 |
| 소유권 | Mediator가 연쇄 머리, 각 Handler가 다음 객체를 `unique_ptr`로 소유 | 같은 객체 중복 소유, 지역 객체 주소 반환 |
| 참조 수명 | `main`의 Mediator가 자신을 참조하는 학생 단말보다 오래 존재 | 사라진 Mediator를 가리키는 참조 |
| 상태 경계 | 성공할 때 한 수신함·한 발신자 통계·ID 집합만 갱신 | 조회·실패·모드 변경에서 기존 전달 기록 초기화 |

구두 확인은 “CODE 우선순위 3이 모드에 따라 다른 담당자를 얻는 이유”, “PROF가 오프라인이어도 CODE Handler까지 가면 안 되는 이유”, “담당자 없음과 오프라인의 차이”, “단말이 빌린 Mediator 참조를 소유 포인터로 바꾸면 무엇이 달라지는가”로 진행할 수 있습니다.

## 운영 확인

- 정답은 100점, 시작 코드와 대표 오답은 0점이 기준입니다. 컴파일 성공과 기능 완성은 구분합니다.
- 학생 다운로드에 정답·오답·비공개 테스트가 포함되지 않는지 확인합니다.
- 실패 결과에 평가 ID와 수정 힌트가 연결되는지, 컴파일 실패에는 기능 **미검사**와 컴파일 안내가 표시되는지 확인합니다.
- 재제출 결과의 이번 점수와 이전 최고점을 구분해서 안내합니다.
- 자료 생성·내보내기는 운영 서버 공개가 아닙니다. 실제 교과목·마감·공개 여부는 웹에서 확인합니다.
