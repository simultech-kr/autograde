# Iterator 실습 교수자 운영 안내

학생이 C++17 Iterator 인터페이스로 기록을 순회하고, 목록과 순회 상태의 책임을 분리하는 과제입니다. 원본 변경과 객체 수명을 명확하게 다루기 위해 생성 시점의 값 복사 스냅샷을 사용합니다. 기능 100점과 구조 검토는 분리합니다.

## 학습 범위

- Iterator와 Aggregate의 공통 인터페이스, 구체 구현, 클라이언트 위임
- 조건에 맞는 다음 기록 선택과 읽기 전용 조회
- 두 Iterator의 독립적인 위치·필터·수명
- 원본 변경과 스냅샷, 값 복사와 참조의 차이
- 빈 목록·끝 위치·다시 순회·오류 뒤 상태 보존

선수 지식은 클래스, 상속, 가상 함수, 생성자, `std::vector`, 값 복사입니다. `std::optional`과 `std::unique_ptr`는 학생 문제와 힌트에 설명합니다. 입력 검증과 파서는 제공하여 패턴 구현에 집중하도록 합니다. STL Iterator 요구사항 전체, 멀티스레드, 영속 저장은 제외합니다. 스냅샷은 이번 과제 정책이지 Iterator 패턴 자체의 필수 조건은 아닙니다.

## 교수자 웹 등록 절차

1. [ZIP 생성](README.md#웹-등록용-zip-생성)을 실행합니다. 시험 교과목의 **과제 관리 → 새 과제 등록 → 직접 만들기**를 엽니다. 기존 과제의 갱신으로 올리지 않습니다.
2. 제목은 `Iterator — 실습 제출 기록 순회`, 언어는 C++로 설정합니다. 플랫폼은 수업 환경에 맞춥니다. 코드는 표준 C++17이며 기본 메타데이터는 Windows입니다.
3. 문제 설명에 학생용 `README.md` 전체를 넣습니다. 서버가 저장된 설명으로 배포 README를 만들므로 요약만 넣으면 상세 계약이 사라집니다. 내보낸 `assignment.json`의 `description`에도 전체 내용이 있습니다.
4. 수령 시작·제출 마감·대상 교과목과 분반을 설정합니다. 이 패키지는 일정을 자동 지정하지 않습니다.
5. 결과 공개를 **즉시 공개**로 설정하여 피드백을 통한 반복 실습을 허용합니다.
6. 학생 배포 자료에 `starter.zip`, 교수자 채점 자료에 `grading-private.zip`을 업로드합니다. 후자는 정답·오답·테스트를 함께 포함합니다.
7. 준비 현황의 **테스트 12개, 총 100점, 오답 기대 점수 0점**과 각 테스트의 평가 요소·수정 힌트를 확인합니다.
8. 저장된 버전으로 검증합니다. 정답 100점, 오답 0점과 검증 성공을 확인한 뒤 시험 교과목에 공개합니다.
9. 시험 학생으로 수령·다운로드·제출·상세 결과를 확인합니다. 실제 교과목의 공개는 이 점검 이후 별도로 진행합니다.

`assignment.json`은 입력 참고 자료입니다. JSON 전체를 웹에 업로드하는 기능을 전제하지 않습니다. 기존 채점 ZIP 가져오기와 `evaluation`, `hint` 기능을 사용하며 서버나 확장 변경은 필요하지 않습니다.

## 기능 점수와 결과 연결

| 결과 키 | 평가 ID | 배점 | 평가 내용 |
| --- | --- | ---: | --- |
| `case_1` | I1 | 10 | 등록 순서와 기록 값 |
| `case_2` | I2 | 10 | 포함 경계와 연속 불일치 건너뛰기 |
| `case_3` | I3 | 10 | 조회 비소비성 |
| `case_4` | I4 | 10 | 한 건씩 전진과 안정적인 종료 |
| `case_5` | I5 | 10 | 두 슬롯 독립성 |
| `case_6` | I6 | 10 | 추가 전후 스냅샷 구분 |
| `case_7` | I7 | 10 | 삭제 후 순회 유지와 ID 재사용 |
| `case_8` | I8 | 10 | 빈 목록과 일치 결과 없음 |
| `case_9` | I9 | 5 | 같은 스냅샷과 필터의 재순회 |
| `case_10` | I10 | 5 | 선택한 슬롯만 새 Iterator로 교체 |
| `case_11` | I11 | 5 | 점수 0과 100 |
| `case_12` | I12 | 5 | 오류 검증 순서와 상태 보존 |

I1, I2, I3, I9의 테스트 입력은 공개합니다. 나머지도 학생 문제에 있는 요구사항만 검사합니다. 한 항목의 전체 출력이 맞아야 배점 전부를 받으며 항목 내 부분 점수는 없습니다. 컴파일은 점수가 없는 선행 단계입니다.

`evaluation`은 통과·실패·미검사 항목의 확인 대상을 설명합니다. 실행 후 실패한 항목에는 `hint`가 점검할 함수, 상태, 로컬 재현 방향, `HINTS.md`의 ID를 연결합니다. 컴파일 실패는 먼저 컴파일 오류를 안내하고 기능 항목을 미검사로 표시합니다.

예를 들어 I6이 실패한 경우 학생은 원본 벡터 참조를 보관했는지, `next`가 원본을 다시 읽는지, 생성 시 값 복사가 되는지를 점검합니다. 자동채점 결과만으로 특정 행의 오류라고 단정하지 않습니다. I1~I4가 함께 실패하면 공통 TODO의 미완성 가능성을 먼저 확인합니다.

비공개 테스트의 제목·입력·예상 출력과 정답 소스는 학생에게 전달하지 않습니다. 반면 `evaluation`, `hint`는 비공개 테스트에서도 학생 공개 문자열입니다. 여기에 비밀 데이터나 정답 구현 전체를 넣지 않습니다.

## 별도 패턴 구조 검토

기능 100점은 동작 계약을 통과했다는 의미입니다. 다음 구조를 자동으로 증명하지 않습니다. 이 패키지는 아래 기준의 점수를 100점에 합산하지 않습니다. 별도 구조 점수를 운영한다면 배점과 기준을 학생에게 먼저 공지합니다.

| 검토 기준 | 충족 사례 | 확인할 문제 |
| --- | --- | --- |
| 추상 Iterator | `SubmissionIterator`의 가상 함수와 가상 소멸자 사용 | 구체 타입을 매번 판별하는 클라이언트 |
| Aggregate의 캡슐화 | `SubmissionLog`의 private 목록과 생성 인터페이스 | 클라이언트에 벡터·인덱스를 노출 |
| 구체 Iterator 책임 | 위치·필터·일치 검색을 `ScoreIterator`에 보관 | `LogApp` 또는 전역 변수에서 순회 |
| 독립 객체 | A와 B가 서로 다른 객체와 위치를 소유 | static 위치, 같은 객체 공유 |
| 스냅샷 수명 | 생성 때 ID·점수를 값 복사하고 Iterator가 소유 | 원본 참조, 지역 복사본의 주소, ID만 복사 |
| 반환과 종료 | 값 optional 반환, 범위 확인, 끝에서 재접근하지 않음 | 댕글링 참조, 끝 위치 역참조 |
| 클라이언트 위임 | 공통 인터페이스로 조회·반환·초기화 | 테스트별 하드코딩, 직접 순회 우회 |

구두 확인 질문은 “두 Iterator가 같은 목록을 읽어도 위치를 공유하면 안 되는 이유”, “const 참조와 스냅샷 복사의 차이”, “RESET과 OPEN의 차이”, “hasNext가 위치를 바꾸면 발생하는 문제”로 구성할 수 있습니다. 문서에 없는 요구를 비공개 채점 항목으로 추가하지 않습니다.

## 운영상 구분

- 정답은 100점, 시작 코드와 대표 오답은 0점이 기준입니다. 시작 코드는 컴파일 성공과 기능 완성을 구분하기 위한 자료입니다.
- 대표 변형 오답으로 평가 항목이 실패하고 해당 수정 힌트가 제공되는지 확인합니다.
- 합성 계정의 100점 후 0점 재제출로 이번 점수와 이전 최고점 분리를 확인합니다.
- 시험용 원본 코드만 로컬 실행합니다. 로컬 채점은 신뢰할 수 없는 학생 코드의 격리를 보장하지 않습니다.
- 학생에게 배포하는 것은 `starter.zip`입니다. 정답·채점 ZIP은 학생 접근이 가능한 저장소에 두지 않습니다.
- 과제 공개·마감·서버 등록은 별도 작업입니다. 이 자료를 생성하거나 ZIP을 내보낸 것만으로 학생에게 공개되지 않습니다.
