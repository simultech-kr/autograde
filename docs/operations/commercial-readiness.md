# 출시 필수 개선과 운영 비용 관리

2026-10-29 구현 기준. 기관별 전용 설치·SQLite·C/C++ 고정 채점·공용 실습 IDE를 첫 제품 범위로 유지한다. 기능 구현과 실제 기관의 출시 승인을 구분한다. 이 변경으로 운영 서버, 실제 학생 데이터, OS 인증서, 예약 서비스는 자동 변경하지 않는다.

## 적용 순서

1. 현재 서버 코드 버전을 기록하고 기존 서비스를 중지한 상태에서 데이터 루트 전체를 안전한 장소에 보존한다. 새 백업 도구를 최초로 적용하기 전 원본을 유지한다.
2. 새 소스를 반영하고 같은 Python 가상환경에서 `python -m pip install -e .`를 실행한다. 관리자 MFA를 위해 `cryptography` 의존성이 추가됐다. Git 소스만 갱신하고 이전 가상환경을 그대로 두지 않는다.
3. [개인 교수자 인증](instructor-personal-auth.md)에 따라 관리자 계정을 준비하고 `instructor_auth_mode,personal`을 사용한다. 실제 personal 실행의 Basic 로그인은 웹 로그인으로 전환된다. 관리자 첫 로그인에서 MFA와 복구 코드를 준비한다.
4. [격리 채점 운영](isolated-instructor-authoring.md)에 따라 고정 이미지 digest를 준비하고 새 과제를 정답/오답으로 다시 검증한다. 기존 접수증·과거 점수·runner를 직접 수정하지 않는다. 신뢰 자료 전용 pilot-local은 일반 학생 코드 운영 경로로 선택하지 않는다.
5. [기관 운영 안내](institution-operations.md)의 전체 백업→검증→별도 호스트 원래 경로 복원 시험을 수행한다. 관리자 **서버·실습실 운영**에서 상태를 확인한다.
6. [IDE 릴리스 안내](ide-signed-releases.md)에 따라 기관 프로필로 패키지를 빌드하고 승인한다. Mac 고정 채널 아이콘은 담당자가 처음 한 번 배포한다. 이후 승인된 새 버전을 다음 실행에 선택한다. 기존 실행 중 앱을 자동 종료하지 않는다.
7. 소수 좌석부터 배포하여 수령→다운로드→저장/복원→제출/재제출→결과→내보내기→종료/다음 학생 삭제를 확인한 뒤 확대한다.

외부 주소는 기관 HTTPS, 내부 신규 생성 기본 포트는 API `18080` / 웹 `18081` loopback이다. 외부 `20000/20010` Nginx와 같은 포트에서 직접 bind하지 않는다. 기존 설치 CSV는 자동 수정하지 않는다.

## 검증 범위와 남은 출시 증거

자동 시험에는 인증·권한 회수·CSRF·MFA 재사용 차단, 백업 손상/경로 이탈/동시 서비스 거절/원래 경로 복원, 기기 보고 범위·재전송·자격 회수, 서명·변조·업데이트 복귀, 공용 세션 삭제를 포함한다. 실제 Mac Docker Desktop에서 고정 C/C++ 검증·공개·10점 제출·5점 재제출/이전 최고 10점, 점수 위조·숨은 자료 접근·무한루프·과출력을 시험했다. 합성 25명 수령·제출 부하 회귀는 제품의 모든 기능을 동시에 수행하는 기관 현장 용량 인수와 다르다.

추가 실제 OCI 부하 시험(`tests/isolated/test_fixed_stdio_capacity.py`)은 합성 학생 25명의 localhost 동시 접수와 같은 키 재전송을 수행했다. 첫 접수 1.165초, 재전송 1.022초, 첫 접수부터 전체 결과 공개까지 14.026초였고 채점 호출은 정확히 25회였다. worker 4개에서 최대 실행 작업/컨테이너 각각 4개, 학생·영수증·소스·결과 각각 25개, 종료 후 잔류 컨테이너 0개를 확인했다. 환경은 Docker Desktop Linux/aarch64, 20 vCPU·약 7.65 GiB이며 단순 C17 출력 과제이다. 기관 서버·대형 C++ 과제의 처리량/SLA로 사용하지 않는다.

다음은 도구 성공이나 자동 테스트만으로 승인할 수 없다.

- 실제 기관 Linux/Podman 호스트의 공격·장애·동시 부하·daemon 중단 복구와 HTTPS 전체 흐름.
- Apple Developer ID·공증, Windows 서명 인증서, 실제 Windows native/WSL2/Linux 일반 계정 설치·업데이트·삭제 인수. 현재 Mac 앱은 개발용 ad-hoc 후보이며 Windows/Linux 채널은 템플릿·회귀시험 범위다.
- 암호화된 외부 백업 보관소·별도 장비 복원 훈련·운영 알림 수신기 설정. 예약 예제는 기본 활성화하지 않는다.
- 공용 PC의 학생별 OS 계정/격리 정책. 폴더 삭제·확장 제한·자기 보고는 다른 프로그램이나 외부 AI 접속을 차단하는 OS 보안 경계가 아니다. 강제 종료 전 서버에 전송되지 않은 코드는 복원할 수 없다.
- 의존성 취약점·재배포 라이선스 검토, 지원 OS·좌석 수·유지보수/복구 목표에 대한 기관 인수.

고정 격리 채점은 단일 C/C++ 표준입출력 범위이며 임의 채점 스크립트·Windows 전용 API까지 안전하다고 확대 해석하지 않는다. 원격 Python 실습 기능은 공식 고정 C/C++ 채점기와 별도다. 운영 HTTP adapter의 후속 전환과 임의 SES 플러그인 상품군은 기존 아키텍처 계획에 남으며 이번 구현에 포함됐다고 표시하지 않는다. `deployment_ready` 자동 승격은 하지 않는다.
