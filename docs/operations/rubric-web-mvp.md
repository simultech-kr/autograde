# 교수자 웹 루브릭 관리 MVP

**2026-09-20 후속 구현:** 개인 모드에서 [실제 제출물의 교수자 루브릭 평가](rubric-connected-assessment.md)를 사용할 수 있다.
아래 문서는 최초 카탈로그 MVP의 범위와 검증 기록이며, 자동 검사 근거 연결·학생 점수 공개는 여전히 미구현이다.

2026-09-18. 기존 로컬 평가 엔진의 **기준 등록·검토·버전 조회만** 교수자 웹에 연결했다.
학생 점수, 제출 접수, 기존 자동 채점 결과는 변경하지 않는다. 원격 서버 자동 배포는 하지 않는다.

**후속 개인 인증:** [개인 계정·분반 권한](instructor-personal-auth.md)을 선택하면 이 화면도 해당 분반으로 제한되고
루브릭 등록자는 인증된 `ins_…` 계정 ID로 기록한다. 아래 공유 계정 관련 설명은 기본 `shared` 모드 기준이다.
현재 개인 모드의 평가 사용 승인·비공개 판정은 후속 연결 모듈에서 제공한다. 학생 결과 공개는 열리지 않는다.

## 켜는 방법

1. 서버를 정상 종료하고 기존 설정·데이터 폴더를 백업한다.
2. 업데이트한 소스와 기존 Python 환경을 사용한다. 새 의존성은 없다.
3. 현재 사용하는 설정 CSV(`key,value`)에 아래 항목을 추가하거나 기존 값을 수정한다. 키를 중복 추가하지 않는다.

```csv
instructor_assignment_web_enabled,true
instructor_rubric_web_enabled,true
```

이 예시는 **추가할 행**이며 완전한 설정 파일이 아니다. 기존 `data_root`, HTTPS 공개 주소,
웹/API 포트와 학생 초기화 설정은 그대로 유지한다. 웹과 API의 별도 origin이 필요하며,
기존 파일럿과 마찬가지로 역방향 프록시 뒤의 loopback listener를 사용한다.
환경변수·OAuth·Docker 설정을 추가할 필요는 없다.

```sh
python -m autograde.pilot_portal_cli --config pilot/portal.https.local
```

파일 경로는 실제 사용하는 설정 파일로 바꾼다. `instructor_rubric_web_enabled`를 생략하면 기본값은
`false`다. 기능을 끄면 메뉴·경로·새 DB 생성이 비활성화되지만 기존 파일은 삭제하지 않는다.

활성화 시 `<data_root>/rubric-catalog.sqlite3`를 처음 한 번만 만든다. 기존 학생 서비스 DB에
루브릭 테이블을 추가하지 않는다. 기존 파일이 지원하지 않는 형식이거나 손상되면 서버 시작을
거절하며 덮어쓰지 않는다. 파일을 삭제해 우회하지 말고 백업과 저장소 상태를 점검한다.
별도 CLI 시험 DB를 자동으로 가져오지 않는다. 카탈로그 DB도 백업 대상에 포함한다.

## 교수자 사용 순서

1. 기존 교수자 인증으로 `/instructor` 접속 → 교과목·분반 선택.
2. **과제 관리 → 과제 상세 → 루브릭 작성**. 먼저 등록된 과제 공개본이 필요하다.
   CLI로 등록한 bundle 과제도 지원한다. 아직 공개본이 없는 초안은 대상이 아니다.
3. 해당 수업·과제 코드가 채워진 기본 JSON을 수정한다. 기본값은 교수자 코드 검토 항목 100점이며,
   과제의 기존 자동 채점 만점과 연결된 값이 아니다. 실제 요구사항에 맞게 기준·수준·배점을 구체화한다.
4. **배점·수준 미리보기**에서 각 항목의 환산 점수와 설명, 자동 규칙의 검사 ID/통과 개수 매핑을 확인한다.
5. 확인란 선택 → **이 버전 등록**. 등록 시각·내용 해시·미승인 상태가 보인다.
6. **루브릭 관리**에서 버전별 기준을 조회한다. 변경은 원본 JSON을 복사하여 `version`을 올린 뒤
   다시 등록한다. 같은 버전·같은 내용 재전송은 중복 생성하지 않으며, 같은 버전의 다른 내용은 거절한다.

일반 JSON 입력은 `루브릭 관리 → 루브릭 등록`에서도 가능하다.
[옵저버 예제](../../examples/rubric/observer.rubric.json)는 `course_key`와 `assignment_id`를 실제
현재 분반 및 공개본 ID로 바꿔야 한다. 설계용 `design/rubrics/` JSON이나 임의 문서 파일은 받지 않는다.
이번 MVP는 JSON 편집과 읽기 쉬운 미리보기이며, 행 추가 방식의 비개발자용 기준 편집기는 후속 범위다.

## 방어 동작과 제한

- 모든 화면과 POST는 교수자 인증을 먼저 검사한다. 서명된 세션, CSRF, 정확한 Origin 검사를 유지한다.
- 검토 확인 정보는 **내용 해시·수업·현재 브라우저 세션**에 묶이며 15분 후 만료된다.
  내용 변경·세션 변경·만료 시 다시 미리보기를 해야 한다. 등록 페이지를 직접 POST해 검토를 건너뛸 수 없다.
- 수업 범위 밖의 과제를 참조할 수 없다. 보관된 수업은 조회만 가능하다.
- JSON 중복 필드, 잘못된 배점/수준, 잘못된 형식을 거절한다. JSON 32 KiB, HTTP 요청 전체 64 KiB 제한이다.
  URL 인코딩 때문에 전송 크기가 더 커질 수 있다. 제한 초과 문서는 로컬 CLI에서 검토하며 웹 제한을 우회하지 않는다.
- 일반 입력 오류·버전 충돌은 JSON을 화면에 유지한다. 재검토가 필요하며 입력은 브라우저 로컬 저장소에 저장하지 않는다.
  413(요청 크기 초과)이나 503(저장소 오류)이면 원본을 별도 보관하고, 다시 보내기 전에 목록에서 등록 여부를 확인한다.
- 밝음/어두움 테마, 작은 화면의 세로 항목 카드, 입력 이탈 경고를 기존 교수자 UI와 공유한다.
- 감사 등록자는 `shared_instructor_web`이다. 공유 계정이며 **개별 교수자의 신원 증명이나 서명된 평가가 아니다**.

최초 카탈로그 MVP는 `approve`, `evaluate`, 학생 코드/판정 근거 import, 점수 공개, 삭제 API를 제공하지 않았다.
현재 개인 모드의 버전별 평가 사용 승인·서버 원본 기반 판정은 후속 연결 모듈에서 제공하며,
임의 근거 import·점수 공개·삭제는 여전히 제공하지 않는다.
CLI 승인 기록이 있는 경우에도 웹에는 “로컬 CLI 승인 기록 · 운영 승인 아님”으로 표시한다.
자동 기준에 적은 검사 ID가 실제 runner에 존재하는지는 아직 연결하지 않았다.
루브릭 등록만으로 현재 성적이나 Extension 결과가 바뀌지 않는다.

## 모듈 경계와 다음 단계

- `rubric_catalog.py`: 과제 범위 검증, 검토 정보 서명, 등록 서비스. 평가 엔진 호출 없음.
- `instructor_rubric.py`: 독립 화면/라우팅. 기존 교수자 셸의 인증·테마를 사용.
- `rubric_store.py`: 별도 DB, 불변 버전·페이지 목록. 기존 로컬 CLI 계약 유지.
- CSV flag는 이번 호스트의 선택적 연결 설정이다. 전체 SES 제품군을 동적 로딩하는 plugin host가 아니다.
  [SPL 설계](../architecture/software-product-line.md)의 기준 카탈로그 분리 단계에 해당한다.

선택적인 개인 인증/분반 권한은 후속 모듈로 구현했다. 다음 연결 순서는 **서버 제출/검사 원장의 신뢰 가능한 근거 adapter
→ 수동 판정·평가 확정 → 정책에 따른 학생 공개·성취도 분석**이다.
현재 공유 계정과 운영자 입력 근거를 운영 성적 승인에 그대로 재사용하지 않는다.

## 시험

```sh
python -m pytest tests/integration/test_instructor_rubric.py tests/integration/test_instructor_runtime.py tests/unit/test_pilot_config.py -q
```

`test_authoring_preview_register_versions_and_no_grades`가 pytest 임시 폴더에 합성 HTML 5개를 만든다.
Playwright 및 Chrome이 준비된 검증 환경에서는 아래 명령에 실제 경로를 넣는다.

```sh
node scripts/check_instructor_rubric.cjs <pytest임시폴더> <playwright모듈경로> <Chrome실행파일>
```

검사 범위: 실제 HTTP 인증/CSRF/Origin/CSP·전송 제한, 등록/재시도/버전 충돌/입력 복구,
수업 경계/보관/미구현 작업 차단, 페이지 목록, 동시 등록 재시도, 실제 서버 프로세스의 기능 on/off,
합성 HTML의 40개 화면 크기·테마 조합과 확인란/복구 표시. 동시 등록 재시도는 학생 채점 부하 시험이 아니다.

### 이번 변경의 검증 결과

- 전체 회귀 실행: **1,148 통과 / 19 제외** (267.52초). 제외 항목은 Windows/MSVC 2개,
  작동하는 JDK 부재 5개, PATH의 .NET 8 SDK 부재 12개다.
- 전체 실행 시작 후 보강한 5개 사례까지 포함하여 최종 루브릭 웹 테스트 **23개를 별도 재실행, 모두 통과**했다.
  따라서 위 전체 회귀 개수와 이 개수를 더해서 고유 테스트 수로 표현하지 않는다.
- 최종 HTML의 밝음/어두움·화면 크기 **40개 조합**, 복구 상태와 확인란 검사 통과.
- 실제 서버 프로세스의 기능 켜기/끄기와 웹/API 경로 분리는 로컬에서 확인했다.
  원격 도메인 배포, 실제 학생 채점, Windows IDE 설치 시험을 이번 결과로 대신하지 않는다.
