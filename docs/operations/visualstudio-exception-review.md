# Visual Studio 확장 예외 점검 및 수정

## 범위와 결론

2026-09-10, VS2022/VS2026용 확장과 기존 학생 포털/API의 연결을 점검했다.
공용 PC의 인증 분리, 네트워크 오류, 제출 중복, 잘못된 응답, 과제 선택, 파일 취소를 다뤘다.
운영 DB·학생 명단은 수정하지 않았다. 네트워크 오류 시험은 가짜 응답 또는 임시 로컬 서버를 사용했다.

최초 회귀 시험에서 7개 오류 조건이 기존 구현으로 실패했고, 추가 시험으로 잘못된 새 수령 코드가
이전 학생 인증을 유지하는 문제도 재현했다. 해당 경로들을 수정했다. UI 문제는 소스 검토·컴파일과
선택 정책의 공통 모듈 시험으로 확인했으며, 실제 Windows 창 조작을 완료했다고 보지는 않는다.

## 식별한 상황과 처리

| 상황 | 영향 | 수정·검증 |
| --- | --- | --- |
| 웹 로그인 페이지가 `/healthz` 대신 HTTP 200으로 반환 | 잘못된 주소를 정상 연결로 표시 | JSON 응답 형식·`status=ok` 확인. HTML, 비정상 상태, JSON 뒤 추가 데이터 거부 시험 |
| 401 오류 응답의 `error`가 배열이거나 응답이 과대 | 파싱 예외 때문에 인증 만료 처리가 누락 | 오류 본문에 의존하지 않고 HTTP 거부 상태 유지. 인증 실패 시 메모리 세션 제거 시험 |
| 갱신 토큰이 서버에서 회전한 뒤 응답 유실 | 소비된 토큰을 재사용하며 오류 반복 | 갱신 결과가 불명확하면 인증을 지우고 새 수령 코드 요구. 일반 과제 조회의 일시적 단절은 로그인 정보를 즉시 지우지 않음 |
| 확장 종료 뒤 늦은 로그인 응답 도착 | 종료한 인증이 다시 활성화 | 클라이언트 수명 취소와 상태 잠금으로 재활성화 방지. 늦은 응답 재현 시험 |
| 새 코드 오입력 | 이전 학생 인증이 그대로 남음 | 새 로그인 시도에서 기존 메모리 인증을 먼저 폐기. 잘못된 코드 시험 |
| 동시·연속 동일 제출 / 제출 응답 유실 | 동일 풀이가 여러 번 접수 | 제출 직렬화, 원본 바이트 복사, 세션 내 동일 요청 키·접수 기록 재사용. 동시 요청·응답 유실·성공 후 재클릭 시험 |
| 로그아웃/새 로그인 사이에 이전 제출이 대기 | 이전 학생 파일이 새 인증으로 제출될 가능성 | 요청을 시작한 인증 세대에 묶고 전환 뒤 오래된 작업·응답 거부. 대기 제출·진행 중 조회 응답 시험 |
| 주소 입력란을 변경하거나 잘못 입력한 뒤 로그아웃 | 주소 검증 때문에 로그아웃 차단 | 로그아웃은 입력란과 무관하게 기존 연결 대상으로 실행하고 화면·메모리 정리. UI 소스 계약 시험, 실제 창 조작은 별도 필요 |
| 선택한 과제가 새 목록에서 사라짐 | 첫 번째 다른 과제의 결과로 바뀜 | 선택 과제를 유지하고, 사라졌으면 명시적 오류 표시. 공통 선택 정책 시험 |
| 파일 수집·압축 해제 중 취소 | 취소 뒤에도 파일 작업 지속 | 파일 읽기·순회·압축 해제·최종 폴더 이동 전에 취소 확인. 사전 취소 시험 및 루프 검토 |
| 다른 과제의 제출 영수증 또는 다른 제출물의 결과 | 잘못된 접수·점수 정보를 정상 처리 | 원본 SHA-256·과제 ID와 요청한 제출 ID를 검증. 불일치 거부 시험 |

사용자 안내도 상태에 맞게 구분했다. 401은 재인증, 403은 수강·접근 확인, 마감 오류는 교수자 문의,
429는 대기 후 재시도, 413은 제출 크기 확인, 서버 오류는 접수 여부 조회를 안내한다.
서버가 반환한 임의 오류 문구나 토큰을 그대로 화면·로그에 출력하지 않는다.

## 변경된 사용 규칙

- 같은 세션·같은 과제·같은 제출 바이트는 성공 후 다시 눌러도 기존 접수 기록을 사용한다.
  이 동작은 중복 방지이지 재채점 요청이 아니다. 재채점은 교수자 운영 절차로 다룬다.
- 제출 키와 접수 기록은 합계 128개까지 메모리에만 유지한다. IDE 종료·로그아웃 후 복원하지 않는다.
  응답 유실 뒤 재로그인했다면 새 제출 전에 최신 결과부터 조회한다.
- 인증 갱신 실패 시 새 코드가 필요할 수 있다. 복구를 위해 토큰을 파일에 저장하지 않는다.
- 로그아웃은 가능하면 유효한 access token으로 서버 세션도 폐기한다. 오프라인이거나 이미
  인증이 취소된 경우에도 로컬 인증은 지우지만 서버 폐기 완료를 보장하지 않는다.
- 취소는 이미 접수된 서버 제출을 철회하지 않는다. 다운로드 최종 이동 이후 취소가 도착하면
  완성된 폴더는 남을 수 있다. 학생 작업 폴더를 취소 처리로 자동 삭제하지 않는다.

## 재검증 명령

수정 후 공통 점검은 **73개 통과**(신규 예외 회귀 18개 포함), 확장·포털 연동 시험은
**20개 통과**했다. Hello World까지 포함한 별도 실행은 41개 통과·Windows/MSVC 2개 건너뜀이었다.
최종 C# compile-only 빌드는 경고·오류가 모두 0개다. 전체 서버 회귀 집합을 이번 검토에서
다시 실행한 것은 아니며, 변경한 확장과 연결 경로를 중심으로 시험했다.

저장소 루트에서 .NET 8 SDK와 Python 개발 환경을 사용한다.

```text
dotnet run --project extensions/visualstudio/Autograde.Checks/Autograde.Checks.csproj
dotnet build extensions/visualstudio/Autograde.VisualStudio/Autograde.VisualStudio.csproj -p:AutogradeCompileOnly=true
```

```bash
.venv/bin/python -m pytest -q tests/integration/test_visualstudio_extension.py tests/integration/test_course_portal.py tests/integration/test_hello_world_assessment.py
```

`AutogradeCompileOnly=true`는 설치용 VSIX를 만들지 않는다. 실제 패키징은 Windows에서
[build.ps1과 설치 안내](../../extensions/visualstudio/README.md)를 사용한다.

## 아직 남은 현장 시험·제한

- VS2022·VS2026의 설치, 실제 버튼/대화상자 조작, IDE 종료·창 복원은 Windows에서 확인해야 한다.
  특히 주소를 일부만 수정한 채 로그아웃, 제출 대기 중 취소 후 로그아웃을 시험한다.
- 디스크 부족, 백신 파일 잠금, Windows 경로 길이 제한, 권한 변경, junction/hard link를
  다른 프로세스가 동시에 바꾸는 상황은 실제 Windows 장비에서 별도 시험한다.
- 한 번의 파일 읽기/쓰기 또는 압축 호출 자체를 강제 중단하지 않는다. 취소는 확인 지점에서 적용한다.
- Windows 전용 API 원격 채점, 안전한 임의 학생 코드 실행 환경, VSIX 서명·Marketplace 배포는
  이번 수정 범위가 아니다. 기존 `pilot-local`은 신뢰된 코드의 기능 시험에만 사용한다.
