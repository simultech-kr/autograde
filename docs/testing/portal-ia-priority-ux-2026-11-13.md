# 포털 IA와 우선순위 UX 개선 검증

2026-11-13, 로컬 체크아웃과 합성 학생·성적·자료로 검증했다. 운영 서버나 실제 학생 자료는 변경하지 않았다.
메뉴 구조와 화면별 상위 경로는 [Information Architecture Map](../architecture/portal-information-architecture.md)에 정의했다.

## 반영한 흐름

| 영역 | 변경 | 확인한 실패·예외 상황 |
| --- | --- | --- |
| 메뉴·돌아가기 | 서버의 공통 메뉴 정의를 HTML·Next.js에서 사용. 기능 활성 여부와 계정 권한에 따라 표시. 제출 결과·코드 비교에도 공통 메뉴와 상위 경로 적용 | 기능 비활성, 권한 없는 교과목, 선택한 수업 없음, 상세 페이지 직접 접근, 400·403·404 응답, 외부 주소·변경 실행 주소를 메뉴에 주입하는 경우 |
| 성적 공개 | 처음에는 공개 열을 선택하지 않음. 전체 행 검색·페이지 이동, 선택 항목만 미리보기, 기존 공개본 대비 신규·변경·제외 학생 확인 후 명시적 공개 | 검토 전/후 다른 교수자의 공개·비공개 변경, 열 순서 변경, 100명을 넘는 명단, 선택하지 않은 교수자 메모 노출 방지 |
| 과제 저장 복구 | 요청 기록과 저장 버전을 서버에서 확인. 현재 입력·선택 파일을 유지하고 재시도 또는 서버 내용 비교 제공 | 저장 전 실패, 저장 후 응답 유실, 상태 확인 실패, 확인 중 추가 편집, 다른 탭 편집, 검증/공개로 잠긴 초안 |
| 학생별 자료 업로드 | 업로드 진행 표시 → ZIP 검사 → 비공개 매칭 검토 → 명시적 적용. 학생·파일·신규/교체/동일 내역, 용량과 만료 안내 | 413·손상 ZIP·내부 ZIP 누적 용량 초과, 기존 공개본 보호, 명단 변경, 오래된 검토본, 취소·만료, 파일 저장·DB 실패, 1MiB 초과 검토 첨부 다운로드 |

성적표의 검색·페이지 필터는 검토 범위만 바꾼다. 공개는 선택한 항목과 전체 공개 대상에 적용하며 화면에서 안내한다.
과제 편집은 자동 저장으로 바뀐 것이 아니다. 각 영역의 저장 버튼을 사용하고, 저장 결과가 불확실하면 복구 버튼으로 확인한다.
동시 편집 충돌을 자동 병합하거나 덮어쓰지 않는다.

## 실행 결과

- Python 통합 회귀: **507개 통과**. 메뉴·권한·교수자/학생 포털·성적표·과제 저장·자료 업로드·HTTP·수업 삭제 및 개인정보 파기 관련 묶음.
- 추가 확인: 제출 이력·코드 비교·수업 포털·첨부 응답 테스트 **38개 통과**. 성적표 최종 통합 테스트 **16개 통과**. 앞선 묶음과 겹치는 테스트가 있어 합산하지 않는다.
- 성적표 최종 테스트는 100열·120자 헤더·2,000자 셀에서 원본 검토와 선택 미리보기 모두 HTTP 200 및 1MiB 미만임을 확인했다. 셀 요약 후 전체 값 조회, 필터·페이지·공개 선택 복귀, 미선택 항목 차단, 저장 원본 불변도 확인했다. 대용량 사례 자체의 추가 브라우저 렌더링은 수행하지 않았다.
- Next.js 테스트: **94개 통과**, 건너뛴 테스트 없음. TypeScript 검사 및 production 빌드 성공.
- 실제 HTTP 요청으로 CSRF·권한·공개 경합·업로드 검토·다운로드 응답을 검사했다. 서버 메서드 직접 호출만으로 통과를 판단하지 않았다.
- 인앱 브라우저에서 공통 메뉴·돌아가기, 성적표 선택/미리보기, 자료 매칭 검토, 과제 저장 상태 표시를 확인했다.
- 375px 학생별 자료·성적표·과제 작성 화면에서 문서 폭이 뷰포트를 넘지 않음을 확인했다. 넓은 표는 표 영역에서 스크롤한다.
- 화면 검토용 서버는 종료했다. 스크린샷은 로컬 `build/ux-evidence-2026-11-13/`에 있으며 저장소에는 포함하지 않는다.

검증 환경: macOS, Python 3.11, Node.js 26.13.0. 웹 package.json의 지원 범위는 Node 24이므로 이번 Node 26 실행 성공을 별도의 지원 범위 변경으로 간주하지 않는다.

## 적용 범위와 운영 참고

- SQLite 스키마 24에 비공개 자료 업로드 검토 테이블이 추가된다. 검토 ZIP은 1시간 만료, 사용자/자료별 1개, 전체 8개·200MiB 상한을 둔다. 기존 운영 데이터는 초기화하지 않는다.
- 유효하지 않은 ZIP은 일괄 거절한다. 일부 파일만 공개하거나 기존 공개본을 부분 변경하지 않는다. 현재 탭의 파일 선택과 기존 공개본은 유지한다.
- 상위 목록으로 돌아가면 기본 목록을 연다. 이전 검색 필터의 자동 복원은 이번 범위에 포함하지 않는다.
- 자료 유형 저장소 통합, 기관별 메뉴 사용자 정의, 대시보드 전체 재설계는 후속 작업이다.
- 배포 전 DB 백업 후 기존 서버 업데이트 절차와 Next.js 빌드·재시작을 수행하고 운영 URL에서 동선을 다시 확인한다. 이 문서는 운영 서버 반영 완료를 의미하지 않는다.
