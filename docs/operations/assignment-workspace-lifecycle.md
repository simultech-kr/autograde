# 과제 이어하기·전환·재제출

## 세 가지 상태를 구분한다

- **수락 이력**: 현재 인증한 학생이 같은 수업에서 수령 코드를 사용해 수락한 과제 목록이다.
  내려받지 않은 과제도 포함한다. 다른 수업이나 다른 학생의 목록이 아니다.
- **현재 연결 과제**: 이번 수령 코드로 인증한 과제다. 다운로드·제출·점수 조회 권한은 이 과제에 한정한다.
- **작업 폴더**: 학생이 실제 편집·제출할 로컬 폴더다. 서버 주소와 과제 ID가 현재 연결 과제와 일치해야 한다.

폴더를 열었다고 로그인되거나 다른 과제의 제출 권한이 생기지는 않는다.
반대로 다시 로그인했다고 기존 코드를 다시 다운로드할 필요도 없다.
`.autograde/assignment.json`은 서버·과제 연결 정보이며 학생 인증서나 답안 소유권 증명이 아니다.
공용 PC에서는 같은 과제의 폴더라도 본인이 작성한 파일인지 반드시 확인한다.

## 주요 사용 시나리오

| 상황 | 학생이 진행할 순서 | 보존·차단 기준 |
| --- | --- | --- |
| 1. 새 과제로 시작 | 학생 웹에서 과제 선택·새 수령 코드 발급 → 확장에 입력 → 새 폴더 다운로드 → 편집·저장 → 제출 대상과 파일 확인 → 제출 | 기존 과제의 파일을 덮어쓰지 않는다. |
| 2. IDE 재시작 후 이어하기 | 기존 과제 폴더 열기 → 같은 과제의 새 코드로 인증 → 기존 폴더 연결·확인 → 저장 후 제출 | 다시 받은 starter로 수정한 답안을 대체하지 않는다. |
| 3. A를 편집 중 B 다운로드 | A의 편집 내용 확인·저장 → B 수령 코드 입력 → A 내부가 아닌 별도 폴더에 B 다운로드 → B로 작업 전환 | A를 보존하며 IDE의 저장·신뢰 확인창을 우회하지 않는다. |
| 4. B를 하다가 A 재제출 | 수락 이력에서 A의 마감·재연결 가능 여부 확인 → 필요하면 A 새 코드로 재연결 → A 작업 폴더 연결 → 코드·제출 대상 확인 → 제출 | 이전 최고점·B의 코드가 아니라 선택한 A 폴더의 현재 저장 파일을 새로 제출한다. |

같은 과제로 인증 중이라면 기존 폴더 선택만으로 이어갈 수 있다. 다른 과제로 전환하면
해당 과제의 새 코드가 필요하다. 수락 이력은 자동 로그인이나 무인증 전환을 제공하지 않는다.
한 수업에서 새 로그인이 성공하면 이전 세션이 종료되므로 이전 토큰을 캐시해 전환하지 않는다.

### VS Code

수업 상위 폴더에서 과제별 하위 폴더를 사용하는 구성이 적합하다.
과제 루트 자체를 열었더라도 이어하기와 별도 위치 다운로드를 구분한다.
현재 작업 영역 밖의 폴더는 **제출 대상으로 연결하고 소스를 미리보기**할 수 있지만,
이것만으로 탐색기·빌드 작업 영역이 바뀌지는 않는다. 폴더 전체를 탐색기에 표시하려면
**수업 폴더로 전환**을 선택한다. Extension Host가 재시작하면 다시 인증해야 하며 작성한 파일은 남는다.
WSL2 작업은 WSL 창과 Linux 경로를 유지하고 Windows 경로와 섞지 않는다.

### Visual Studio 2022/2026

현재 열린 폴더 또는 솔루션 주변의 과제 연결 정보를 확인하고, 찾지 못하면 기존 과제 폴더를
직접 선택한다. 최종 제출 폴더를 명시적으로 보여 준다. 다른 솔루션이 열려 있다는 이유만으로
그 소스를 현재 인증 과제에 제출하지 않는다. 자동으로 임의의 `.sln`을 선택하거나 생성하지 않는다.
다운로드의 기본 열기 대상은 폴더 작업 영역이며 `.sln`·`.vcxproj`는 현 채점 제출 범위에 포함되지 않는다.

## 서버 목록 계약

`GET /v1/accepted-assignments/catalog`은 현재 인증한 학생·수업의 실제 수락 기록만 중복 제거해 반환한다.
과제별 `accepted_at`은 최근 수락 시각이다. `status`는 `available`, `closed`, `unavailable`이며
`current_session_authorized`, `can_reconnect`, `can_submit`으로 화면 안내를 구분한다.
현재 과제라도 마감됐으면 `can_submit`은 false다. 응답은 조회 시점의 안내이며 제출 시 서버가 다시 검증한다.

이 목록은 점수·파일·정답·수령 코드·학생 식별 정보·서버 경로를 포함하지 않는다.
기존 `/v1/accepted-assignments`와 파일·제출·결과 API의 과제별 권한을 확장하지 않는다.
수락 이력은 로그인 메모리 범위에서 사용하며 디스크에 캐시하지 않는다.

## 배포와 직접 시험

서버와 확장을 함께 업데이트해야 수락 이력 목록을 사용할 수 있다. VS Code와 Visual Studio의
VSIX는 서로 다른 파일이다. 로컬 구현·자동 검사는 원격 서버 배포 또는 Windows 설치 확인을 뜻하지 않는다.

시험용 수업에 A·B·마감된 C를 준비하고 실제 학생 데이터 대신 별도 시험 계정을 사용한다.

1. A를 내려받아 소스에 눈에 띄는 문구를 쓰고 저장한다. 다시 인증·이어하기 후 문구가 유지되는지 확인한다.
2. IDE를 종료·시작하고 A 기존 폴더로 재연결해 제출한다. 새 다운로드 없이 같은 코드가 접수돼야 한다.
3. A 편집 중 B를 수락·다운로드한다. B가 A 안에 생성되지 않고 A 파일이 그대로인지 확인한다.
4. A로 재연결하고 A 폴더를 제출한다. 서버 접수의 과제 ID와 코드가 A여야 한다.
5. B로 인증한 상태에서 A 제출을 시도한다. 대상 불일치가 차단되는지 확인한다.
6. 이력에서 C가 마감으로 보이고 새 연결·제출이 차단되는지 확인한다.
7. 폴더 이동·중복 사본·다운로드 취소·미저장 편집·통신 단절을 각각 시험한다.
8. 로그아웃하거나 다른 시험 학생으로 로그인한다. 이전 학생 이력·점수가 남지 않아야 한다.

각 환경에서 수동 확인한다. C# 정적 검사나 compile-only 빌드는 이 시험을 대체하지 않는다.
