# 학생별 자료 배포 사용 안내

시험지, 개별 피드백, 실습 자료를 학번별 PDF 또는 ZIP으로 배포한다. 교수자는 수업·분반에서 파일을 등록하고 배정 결과를 검토한 뒤 공개한다. 학생은 기존 학번·전용 비밀번호로 로그인하여 본인 파일만 받는다. 과제 수령 코드나 IDE 확장은 필요 없으며 답안 수집·자동 채점은 별도다.

이 문서는 현재 PDF/ZIP 배포 기능의 사용 안내다. [Git 콘텐츠 CMS 설계](../architecture/git-content-cms.md)는
관리자 콘텐츠 버전 관리·학생별 변경 파일 캐시·내보내기를 다룬다. 1차 구현은 아래 별도 절차를
따르며, 기존 개인 자료의 직접 수정·다운로드 절차나 운영 CSV는 그대로 유지한다.

## Git 콘텐츠 변경분 동기화 1차 MVP

기존 `학생별 자료 배포`와 구분되는 **콘텐츠** 메뉴다. 자료 모음별로 같은 파일 트리를 전체
수업 또는 선택한 학생에게 전달한다. 학생마다 서로 다른 PDF/ZIP은 기존 메뉴를 계속 사용한다.
채점·학생 답안과 독립이며 ZIP을 올리면 ZIP 하나로 전달하고 자동으로 압축 해제하지 않는다.

### 서버 준비

1. 운영 데이터 폴더(특히 SQLite·기존 자료)를 백업한 뒤 서버를 중지한다.
2. 이 변경을 적용하고 동일한 Python 가상환경에서 `python -m pip install -e .`로 갱신한다.
3. 서버에 Git 실행 파일이 있어야 한다(`git --version`). GitHub 계정·원격 저장소는 필요 없다.
4. 기존 CSV의 `instructor_assignment_web_enabled,true`로 교수자 관리 기능을 활성화한다.
   새 CMS 환경변수는 없다. 서버 시작 시 additive migration 20을 적용하고 콘텐츠 저장소는
   `data_root/content`를 사용한다. SQLite와 기존 파일을 삭제하거나 다시 초기화하지 않는다.
5. Nginx를 쓰면 [포털 예제](../../config/nginx-autograde-portal.conf.example)의
   `/courses/.../instructor/content/cc_.../upload` 전용 블록(26m)을 추가하고 `nginx -t` 후 반영한다.
   기본 폼 제한은 64k로 유지한다. `data_root/content`를 정적 웹 경로로 공개하지 않는다.
6. 기존 서버 실행 방식으로 재시작한다. 서버는 Linux/macOS 파일럿용이며 Windows 서버는 WSL2를 사용한다.

### 교수자 등록·수정

1. 기존 교수자 웹에서 수업을 선택하고 **콘텐츠**를 누른다.
   예: `https://ai.cbchoi.info:20010/courses/come2201/instructor/content`.
2. 제목·안내로 자료 모음을 만든다. 기본 대상은 전체 수업이며 상세에서 학번으로 대상을 제한할 수 있다.
3. 파일을 하나씩 올린다. `논리 경로`를 `examples/main.cpp`처럼 지정하면 내보낸 폴더 구조가 된다.
   비우면 원본 파일명을 사용한다. 파일당 25 MiB, 모음당 100 MiB/1,000개다.
4. 추가·변경·제외 목록과 대상·배포 종료 시각을 검토하고 **검토한 버전 공개**를 누른다.
   미래 시작 시각의 예약 공개는 아직 지원하지 않는다. 준비 상태 수업은 초안만 저장할 수 있다.
5. 수정할 때는 같은 모음에 파일을 교체하거나 제외하고 새 판을 공개한다. 초안만 바꾸면 학생에게
   보이는 이전 공개본은 유지된다. **배포 중단**은 신규 수령을 막지만 학생 PC의 파일을 지우지 않는다.

### 학생 수신·내보내기

1. VS Code/Autograde IDE 확장을 **0.5.9**로 갱신하고 창을 다시 연다. 이번 기능은 Visual Studio VSIX에는 없다.
2. API 주소(예: `https://ai.cbchoi.info:20000`)와 기존 과제 수령 코드로 해당 수업에 연결한다.
   자료만 사용하는 독립 로그인은 후속 구현이다.
3. 학습 홈의 **강의자료 업데이트**에서 자료 모음을 선택한다.
4. **변경된 파일만 받기**를 선택하면 학생·서버·수업별 캐시에 저장한다. 같은 파일은 해시로
   확인해 재사용한다. 파일명만 바뀐 경우에도 기존 파일 객체를 재사용한다.
5. 필요할 때 다시 들어가 **내 폴더에 저장**을 선택한다. 최신 공개본을 확인하고 고른 위치에
   새 버전 폴더를 만든다. 기존 파일과 답안을 덮어쓰지 않는다. 내보내기에도 서버 연결이 필요하다.

강의자료는 과제 작업 폴더 바깥에 저장해야 한다. 제한 모드에서는 파일 쓰기를 차단하며, 사용자가
본인 학습 폴더를 신뢰한 뒤 진행한다. 로그인 변경·취소·해시 오류·저장 실패 시 새 snapshot을
활성화하지 않는다. 동기화 성공은 열람·출석·학습 완료 또는 성적 증거가 아니다.

### 오류와 운영 경계

- **409 자료 변경:** 교수자가 새 판을 공개했거나 정책이 바뀐 경우다. 목록을 다시 열고 재시도한다.
- **401/403 인증·기간:** 새 수령 코드로 연결하거나 교수자에게 수강/배포 기간을 확인한다.
- **429 전송 중:** 최대 8개의 파일을 동시 전송한다. 잠시 후 재시도하며 과제 접수 API는 별도로 동작한다.
- **503 저장소 오류:** 운영자는 Git 설치·자료 파일·저장 공간을 확인한다. 학생에게 내부 경로를 노출하지 않는다.
- **캐시 한도/잠금:** 자동 자료 삭제는 하지 않는다. 다른 IDE 작업을 마치고 재시도한다. 같은 PC의
  종료된 프로세스 잠금은 복구하지만, 소유자를 확인할 수 없는 잠금은 운영자 확인이 필요하다.
- DB·Git·객체 저장소를 함께 백업한다. 학생 초기화는 콘텐츠 공개 이력과 파일을 삭제하지 않는다.

서버·IDE 교차 검증 재실행(로컬 루프백 서버와 합성 학생만 사용):

```sh
cd extensions/vscode
npm test
cd ../..
python -m pytest -q tests/unit/test_content_store.py \
  tests/integration/test_content_api.py \
  tests/integration/test_instructor_content.py \
  tests/integration/test_instructor_content_http.py
```

Node.js와 확장 컴파일 결과가 있어야 Python→실제 HTTP→IDE 캐시 교차 시험을 실행한다. 이 조건이
없으면 해당 시험은 skip이므로 전체 통과로 계산하지 않는다. 실제 HTTPS/Nginx와 Windows/WSL2,
Linux·macOS의 IDE 화면 검증은 별도 배포 인수 항목이다.

## 파일 준비

파일 이름은 등록된 학번과 정확히 일치해야 한다. 앞자리 0을 생략하지 않는다.

```text
20260001.pdf
20260002.zip
001234.pdf
```

하나의 배포 건에는 학생별 파일 하나를 등록한다. 같은 학생에게 여러 문서를 주려면 해당 학생의 자료를 `학번.zip`으로 묶는다. 별도의 배포 건을 만들어 여러 번 배포할 수도 있다. PDF·ZIP 한 파일은 최대 25 MiB다.

여러 학생에게 일괄 등록하려면 다음과 같이 학생별 파일을 최상위에 담은 ZIP을 만든다.

```text
개별자료.zip
  20260001.pdf
  20260002.zip
  001234.pdf
```

학생별 ZIP 안의 자료를 다른 학생의 파일과 섞지 않는다. 일괄 ZIP은 최대 100 MiB, 최대 200명이다. 일괄 ZIP에서 읽은 학생 파일과 학생용 ZIP 내부 검사에서 읽은 내용의 합계도 100 MiB로 제한한다. 학생용 ZIP에는 최대 1,000개 항목을 넣을 수 있다. 일괄 ZIP에는 하위 폴더를 만들지 않고, 암호화 ZIP, ZIP64·분할 ZIP, 경로 이동·링크 항목을 넣지 않는다. 운영체제가 만든 부가 파일도 제외한다. 없는 학번·비활성 학생·한 학생의 중복 파일이 있으면 해당 일괄 등록 전체를 거절하므로 안내된 파일을 수정한 뒤 다시 등록한다.

## 교수자 등록과 공개

1. `/instructor`에 로그인하고 대상 수업·분반을 선택한다.
2. **학생별 자료 배포**를 연다. 직접 경로는 `/courses/{course_key}/instructor/materials`다.
3. 제목, 학생 안내, 배포 시작·종료 시각을 입력하고 초안을 저장한다. 시각은 한국 표준시다.
4. 단건 등록에서 `학번.pdf` 또는 `학번.zip`을 올리거나 일괄 등록에서 학생별 파일을 묶은 ZIP을 올린다.
5. 배정 목록의 학번·이름·파일명·파일 크기를 확인한다. 개별 등록본을 다운로드하여 내용과 배정 대상을 검토한다. 초안에서는 같은 학생의 파일을 다시 올려 교체하거나 **배정 제외**로 잘못 지정한 학생을 제외할 수 있다. 일괄 재등록은 포함된 학생만 추가·교체하며, ZIP에서 뺀 학생을 자동 제외하지 않는다. 제외 시 비공개 저장 파일은 자동 삭제하지 않는다.
6. 공개 확인란을 선택하고 공개한다. 수업은 운영 상태여야 하며 파일이 없는 초안은 공개할 수 없다. 미배정 학생에게는 이 자료가 표시되지 않는다.
7. 화면에 표시되는 학생용 주소를 수업 공지로 안내한다. 예: `https://ai.cbchoi.info:20010/courses/come2201/materials`. 분반이 별도 수업이면 해당 분반의 `course_key`가 포함된 주소를 사용한다.

학생별 자료 배포는 성적과 무관하므로 공개 후에도 파일·배정 대상·제목·안내·기간을 직접 수정할 수 있다. 과제 제출·자동 채점·점수에는 영향을 주지 않으며, 채점 과제의 공개본 변경 정책은 별도로 유지한다. 이미 내려받은 파일은 회수하거나 자동 교체할 수 없다.

## 공개한 자료 바로 수정

1. **학생별 자료 배포**에서 수정할 공개 자료를 연다.
2. 제목·학생 안내·시작·종료 시각은 해당 입력란에서 수정한 뒤 **안내·기간 수정 즉시 반영**을 누른다.
3. 파일을 변경하려면 같은 학번의 PDF 또는 ZIP을 다시 올린다. 일괄 ZIP도 사용할 수 있으며, 포함된 학생만 추가·교체하고 나머지는 유지한다.
4. 대상에서 빼려면 해당 학생의 **배정 제외**를 사용한다. 새 학생에게 주려면 그 학생의 학번 파일을 추가한다. 모든 배정을 제외하면 학생에게 해당 자료가 표시되지 않는다.
5. 저장 즉시 학생 화면과 이후 다운로드에 적용된다. 기존 자료 주소를 그대로 사용하며, 별도의 수정본 생성·공개 단계는 필요 없다. 기간을 늘려 종료된 배포를 다시 이용 가능하게 할 수도 있다.

새 파일의 검사나 일괄 학번 매칭이 실패하면 기존 파일·배정·요청 기록은 그대로 유지된다. 다른 창에서 먼저 변경했다면 최신 화면을 다시 열어 검토한다. 보관된 자료·교체된 구판과 보관된 수업은 조회만 가능하다.

파일 내용이 바뀌면 해당 학생의 현재 파일 요청 현황은 새로 시작한다. 변경하지 않은 다른 학생의 기록과 동일 파일을 다시 올린 경우의 기록은 유지한다. 교체·제외된 파일과 그때까지의 요청 기록은 교수자 전용 파일 이력에서 확인할 수 있다. 학생에게는 본인의 현재 배정 파일만 제공하고, 교체된 파일을 아직 요청하지 않았다면 다시 다운로드하라는 안내를 표시한다. 요청 기록은 실제 저장 완료·열람을 증명하지 않는다.

이미 **수정본 만들기**로 작성 중인 초안이 있다면 해당 초안에서 작업을 마치거나 그 초안만 보관한 뒤 현재 공개 자료를 직접 수정한다. 서로 다른 변경이 덮어써지는 것을 방지하기 위한 제한이다.

## 여러 변경을 검토한 뒤 한 번에 공개하기 (선택)

즉시 수정이 아니라 기존 배포를 유지하면서 여러 변경을 준비하려는 경우에는 다음의 수정본 절차도 사용할 수 있다. 일반적인 안내 수정·파일 교체에는 필요하지 않다.

1. **학생별 자료 배포**에서 수정할 공개본을 연다.
2. **학생에게 표시할 변경 내용**에 수정 이유와 학생이 다시 확인할 내용을 입력하고, 확인란을 선택해 **수정본 만들기**를 누른다.
3. 기존 제목·안내·배포 기간과 학생별 파일을 복제한 수정 초안이 열린다. 변경할 학생의 `학번.pdf` 또는 `학번.zip`만 다시 올린다. 여러 학생의 수정 파일은 ZIP 일괄 등록으로 교체할 수 있다. 올리지 않은 학생 파일은 유지된다.
4. 필요하면 제목·안내·기간을 수정하고, 배정 제외 또는 추가 등록으로 대상을 조정한다. 파일과 학번을 다시 검토한다.
5. 수정본을 공개하면 새 배포판이 제공되고 이전 배포판은 자동 보관된다. 하나의 공개 작업으로 전환하므로 검증 실패 시 기존 배포는 그대로 유지된다.

수정본 작성 중에는 기존 공개본을 기존 배포 기간 내에서 계속 받을 수 있다. 수정본은 원본과 별도의 비공개 파일로 복제하므로 저장 공간을 추가 사용한다. 진행 중인 수정 초안이 있으면 **작성 중인 수정본 열기**로 이어서 작업한다. 수정을 취소하려면 수정 초안만 보관한다. 기존 공개본은 중단되지 않는다.

수정본 공개는 즉시 전환 방식이다. 수정본의 배포 시작은 현재 시각 이전 또는 같은 시각, 종료는 현재보다 나중으로 설정한다. 미래 시각의 자동 교체 예약은 지원하지 않는다. 기간이 끝난 공개본도 새 기간의 수정본을 만들 수 있지만, 이미 보관하거나 다른 수정본으로 교체한 과거판을 직접 다시 공개할 수는 없다.

별도 공개한 판은 `v1`, `v2`처럼 표시하며 입력 저장 횟수·학생별 파일 버전과 구분한다. 직접 수정은 새 배포판을 만들지 않는다. 취소된 수정 초안도 이력에 남아 번호가 건너뛸 수 있다. 교수자는 **배포 이력**의 각 판에서 해당 판의 파일과 요청 기록을 확인하고, 그 판 안에서 직접 교체했던 파일은 파일 이력으로 확인한다. 새 판의 요청 횟수는 0부터 시작하며 과거 요청을 최신본 수령으로 처리하지 않는다.

학생에게는 현재 배포판만 표시한다. 수정본을 아직 요청하지 않은 학생에게 다시 다운로드하라는 안내와 변경 내용을 제공한다. 예전에 열어 둔 화면에서 구판 다운로드를 누르면 최신 목록으로 돌아가도록 안내하며, 구판 파일을 계속 제공하지 않는다. 배정에서 제외된 학생은 새 판을 받을 수 없다. 학생에게 별도 이메일·푸시 알림은 보내지 않으므로 필요하면 수업 공지로 재수령을 안내한다.

## 학생 수령

1. 교수자가 안내한 자료 주소를 연다.
2. 학번과 해당 수업의 전용 비밀번호로 로그인한다.
3. **내 자료 받기**에서 본인에게 공개된 자료와 배포 기간을 확인한다.
4. 배포 기간 중 다운로드 버튼을 누른다. PDF 또는 ZIP 원본으로 저장된다. ZIP을 학생 컴퓨터에서 열기 전 교수자가 준 신뢰할 수 있는 파일인지 확인한다.
5. 브라우저 다운로드 목록에서 저장 완료를 확인하고 공용 PC에서는 로그아웃한다.

다른 학생의 자료 목록·파일명은 표시하지 않는다. 주소를 변경해도 서버가 로그인 학생의 배정 자료만 제공한다. 로그인은 10분 후 만료되며 비밀번호·수강 상태 변경도 접근에 영향을 준다. 배포 기간 안에서는 다시 다운로드할 수 있다.

## 요청 현황과 문제 해결

교수자 상세 화면에서 현재 배정 파일의 학생별 최초 요청·최근 요청 시각, 요청 횟수, 수강 상태를 확인한다. 직접 교체·제외 전의 기록은 파일 이력에서 확인한다. 별도 수정본 배포 전의 기록은 **배포 이력**에서 해당 판을 열어 확인한다. 요청 기록은 서버가 승인한 요청이며 파일 저장 완료·열람·출석을 증명하지 않는다. 연결이 끊겨도 요청 기록이 남을 수 있다.

- 학번 매칭 실패: 현재 선택한 수업·분반에 등록된 학번인지, 앞자리 0이나 공백·파일명 접미사가 없는지 확인한다.
- ZIP 일괄 등록 실패: 파일을 최상위에 놓고 학번당 PDF 또는 ZIP 하나만 포함한다. 알 수 없는 학번·부가 파일·하위 폴더·중복·용량 제한을 확인한다.
- 학생에게 목록이 없음: 공개 여부, 해당 학생 파일의 배정 여부, 수업·학생·수강의 활성 상태를 확인한다.
- 다운로드 버튼이 없음: 한국 시간 기준 배포 시작·종료를 확인한다.
- 413 오류: Nginx에 아래의 자료 업로드 전용 경로가 반영되었는지 확인한다.
- 파일 무결성 오류: 운영자가 비공개 저장 파일과 데이터베이스를 함께 점검한다. 저장소 파일을 수동 교체하지 않는다.
- 수정본 공개 실패: 시작 시각이 미래이거나 종료 시각이 지났는지, 배정 학생이 수강 취소되었는지, 원본을 다른 창에서 보관했는지 확인한다. 원본이 유지되는지 먼저 확인하고 수정 초안에서 문제를 해결한다.

## 서버 반영

1. 서버를 정상 종료하고 설정 CSV와 데이터 폴더 전체를 백업한다.
2. 기능이 포함된 코드를 반영하고 기존 가상환경에서 `python -m pip install -e '.[dev]'`를 실행한다.
3. 기존 CSV의 `instructor_assignment_web_enabled,true`를 사용한다. 추가 환경변수·비밀번호·포트는 필요 없다.
4. [Nginx 예시](../../config/nginx-autograde-portal.conf.example)의 `/instructor/materials/mat_.../upload` 및 `/upload-batch` 경로를 반영한다. 각각 요청 한도 26 MiB, 101 MiB이며 일반 경로의 한도를 늘리지 않는다. 운영자가 `nginx -t`로 확인한 뒤 설정을 다시 읽힌다.
5. 기존 `python -m autograde.pilot_portal_cli --config 사용중인설정.csv` 명령으로 재시작한다. DB가 v19로 자동 갱신되며 기존 파일·배정·요청 기록은 유지된다. 갱신된 DB에 구버전 프로그램을 실행하지 않는다. 직접 수정과 수정본 기능은 기존 업로드 경로를 사용하므로 앞의 Nginx 설정이 적용되어 있다면 추가 업로드 경로나 용량 변경은 필요 없다.

자료는 `{data_root}/student-materials`에 비공개로 저장한다. Nginx 정적 경로로 노출하지 않는다. SQLite DB와 해당 폴더를 항상 함께 백업한다. 수업 학생 초기화는 배포 원본·요청 이력을 삭제하지 않으며, 같은 학생의 재등록은 기존 배정에 다시 연결될 수 있다.

서버는 학생용 ZIP을 풀거나 실행하지 않는다. 형식·크기·경로 검사는 바이러스 검사가 아니다. 교수자는 신뢰할 수 있는 파일만 배포한다. 기존 `pilot-local` 채점과 같은 서버 계정으로 운영하면 학생 실행 코드로부터 비공개 파일이 격리되지 않으므로, 실제 비밀 시험 자료를 배포하기 전 채점 실행 권한·환경을 분리한다.

기존 전체 수강생 대상 PDF 시험지 배포는 [시험지 배포 안내](exam-paper-distribution.md)를 따른다. 학생별 자료 배포와 별도로 유지된다.

## 검증 기록

2026년 10월 22일 합성 자료를 사용한 로컬 자동 시험 614개가 통과했다. 학생별 자료의 공개 후 직접 수정, 단건·일괄 교체, 배정 추가·제외, 교체 전 파일·요청 이력 보존, 동일 파일 재등록 시 기록 유지, 파일 변경 시 해당 학생만 요청 현황 초기화, 동시 편집·다운로드의 응답 일관성을 확인했다. DB v18→v19 갱신, 학생 초기화·백업, 기존 별도 수정본 배포, 인증·수업 관리·과제 수령·제출·채점·서버 시작의 회귀 시험도 포함한다. 검증·저장·감사 기록 실패 시 직접 수정이나 수정본 전환은 전체 취소되며 기존 자료와 기록을 유지한다.

2026년 10월 22일 교수자·학생 기본 화면 6종, 별도 수정본 화면 6종, 직접 수정 화면 4종에 대해 320·375·768·1440px와 밝음·어두움의 총 128개 조합, 키보드 이동과 고대비 검사를 통과했다. 공개 자료의 편집 입력란, 이전 파일 이력, 학생의 변경 파일 요청 전후 안내도 확인했다. 운영 서버의 HTTPS·Nginx 적용과 실제 학생 파일은 별도로 확인해야 한다. 실제 학생 데이터는 이 시험에 사용하지 않았다.

```sh
  tests/unit/test_student_material_views.py \

```

브라우저 검사는 HTTP 테스트가 내보낸 `materials-browser-fixtures.json`, `material-revisions-browser-fixtures.json`, `material-editing-browser-fixtures.json`을 각각 `scripts/check_student_materials_browser.cjs`에 전달한다. 기본·별도 수정본 화면은 각 48개 조합, 직접 수정 화면은 32개 조합을 검증한다. Playwright 모듈과 Chrome 실행 파일은 개발 환경에서 지정하며 서버 운영 의존성에는 추가하지 않는다.
