# 제출 이후에도 과제 설명 보완하기

2026-09-22 구현. **기존 과제 ID를 유지하면서 설명만 별도 버전으로 저장**합니다.
학생이 이미 수락하거나 제출한 과제에도 적용되며 재수락·재채점하지 않습니다.
운영 서버에 자동 배포하거나 기존 설명을 일괄 변경하는 기능은 아닙니다.

## 무엇이 바뀌고 유지되는가

| 항목 | 처리 |
| --- | --- |
| 학생 안내문·README 설명 | 원문 전체와 변경 사유를 새 설명 버전으로 저장 |
| 과제 ID·수락·제출·기존 점수 | 그대로 유지 |
| 학생 작업 폴더·코드·로컬 README | 덮어쓰지 않음 |
| 최초 배포 ZIP·다운로드 해시 | 변경하지 않음. ZIP의 README는 최초 공개본 |
| 채점 코드·시험 입력·배점·제출 파일 규칙 | 이 화면으로 변경 불가 |
| 마감 | 이 화면으로 변경 불가. 기존 마감 연장 기능 사용 |

설명 버전은 `v0`부터 시작합니다. 최초 공개 설명은 보존하고 변경분을 추가하므로
기존 버전을 덮어쓰거나 삭제하지 않습니다. 이 기능으로 요구사항 자체를 바꾸면
기존 채점 기준과 불일치할 수 있습니다. 교수자는 오탈자, 실행 안내, 예시 해설처럼
**채점 계약을 바꾸지 않는 보완인지 직접 확인**해야 합니다.

## 교수자 사용 순서

1. 교수자 로그인 후 교과목 → **과제 관리** → 기존 공개 과제를 선택합니다.
2. **설명 수정·이력**을 엽니다. 복사·새 과제 공개를 선택하지 않습니다.
3. 개선된 README **전체 내용**을 학생 안내문에 붙여 넣습니다. 최대 20,000자입니다.
4. 학생에게 보여 줄 변경 사유를 입력합니다. 최대 500자이며 공개 정보입니다.
5. 채점 기준을 변경하지 않는 설명 보완임을 확인하고 저장합니다.
6. 저장 전후 비교, 새 버전 번호와 변경 이력을 확인합니다.

교수자 정답, 비공개 시험 입력, 비밀번호는 넣지 마세요. Markdown은 원문으로 표시됩니다.
다른 창에서 먼저 수정한 경우 저장을 거절하고 입력 내용을 보존합니다.
최신 설명을 확인한 뒤 필요한 내용을 병합해 다시 저장하세요.
보관한 수업은 읽기 전용입니다. 웹에서 등록하지 않은 CLI 과제는 이번 편집 기능을 지원하지 않습니다.

현재 화면은 최근 50개 버전의 시각·사유·해시를 보여 줍니다. 전체 기록은 서버에 보존되며
과제당 설명 수정은 200회까지입니다. 과거 버전 본문 탐색·복원 UI는 이번 범위가 아닙니다.
저장 직후 비교는 방금 저장한 버전과 직전 버전 사이의 비교입니다.

## 학생에게 보이는 흐름

- VS Code **0.5.6**, Visual Studio **0.5.7**부터 지원합니다.
- 수락한 과제의 **과제 설명**을 열면 서버의 최신 안내문과 변경 이력을 읽기 전용으로 봅니다.
- 새 버전이 확인되면 설명 업데이트 표시가 나타납니다. 목록 갱신/연결 상태 확인을 통해
  메타데이터를 받아오며, 서버의 실시간 푸시 알림은 아닙니다.
- 다운로드한 프로젝트는 그대로 두고 별도 설명 창을 엽니다. 학생 파일을 덮어쓰거나
  제출 파일에 서버 설명을 자동 삽입하지 않습니다.
- 설명 조회에는 기존 과제 수락 세션을 사용합니다. 설명 수정만으로 다시 수락할 필요는 없습니다.
  로그아웃·IDE 종료 등 기존 세션 만료 정책은 그대로 적용됩니다.
- 읽음 상태는 메모리에서만 유지합니다. 로그아웃이나 과제 전환 시 열어 둔 설명을 정리합니다.
  오래된 서버가 설명 API를 지원하지 않으면 안내만 표시하고 다운로드·제출 기능은 유지합니다.

## 기록과 보안 경계

`GET /v1/assignments/{assignment_id}/document`는 수락한 과제에만 접근할 수 있습니다.
다른 학생/교과목/수령 코드 범위를 벗어난 과제는 조회할 수 없습니다.
본문과 SHA-256을 확인하며 HTML이나 명령으로 실행하지 않고 일반 텍스트로 표시합니다.

새 제출을 접수하는 트랜잭션 안에서 서버의 당시 설명 버전과 해시를 별도로 기록합니다.
같은 제출의 통신 재시도는 처음 접수 때의 기록을 유지합니다.
**이는 서버에 어떤 설명이 있었는지를 기록하는 것이지 학생이 읽었다는 증거는 아닙니다.**
기존 제출에는 당시 설명을 추정해 소급 기록하지 않습니다. 기존 접수증 형식·해시도 바꾸지 않습니다.
이 기록을 교수자 제출 이력 UI에 표시하는 기능과 학생 읽음 확인은 후속 범위입니다.
별도 [학생 전체 초기화](course-student-reset.md)를 명시적으로 실행할 때는 대상 제출에 딸린
설명 버전 참조도 함께 초기화됩니다. 과제 설명 원문·변경 이력과 다른 수업의 기록은 보존합니다.

## 서버 업데이트

1. 서비스를 정상 종료하고 설정 CSV의 `data_root` 전체를 백업합니다.
   SQLite DB뿐 아니라 bundle·인증 파일도 포함하며 백업에는 학생 정보가 있으므로 보호합니다.
2. 새 소스로 기존 가상환경에 프로젝트를 설치한 뒤 기존 CSV로 서버를 시작합니다.
   새로운 환경변수나 설정 항목은 필요하지 않습니다.
3. 첫 실행에서 SQLite 스키마 **13 → 14**로 자동 마이그레이션합니다.
   기존 과제·수락·제출·점수를 보존합니다. 구버전 서버/CLI를 동시에 실행하지 마세요.
4. Nginx를 사용한다면 [웹/API 프록시 예제](../../config/nginx-autograde-portal.conf.example)의
   `/instructor/assignments/{id}/document` 전용 `256k` 블록을 웹 20010 서버에 반영합니다.
   긴 한글 안내문은 폼 인코딩 후 기본 `64k`를 넘을 수 있습니다.
   적용 전 실제 서버에서 `nginx -t`를 통과시키고 다시 읽어 들이세요.
5. 학생 확장을 업데이트하고 교수자/학생 확인 절차를 수행합니다.

DB만 새 상태로 두고 서버 코드만 되돌리는 롤백은 지원하지 않습니다.
필요하면 서비스를 중지하고 업데이트 전 백업·코드를 함께 복원해야 하며,
백업 이후 접수된 제출물이 있다면 먼저 별도 보존·복구 계획을 세워야 합니다.

## 검증 및 현장 확인

자동 시험에서 실제 HTTP 로그인·수락·정답 채점 이후 안내문을 갱신하고,
동일 학생 세션으로 새 설명 조회·재제출·채점하는 흐름을 확인합니다.
기존 점수·접수증·스타터 ZIP·과제 ID·수락 횟수가 변하지 않는지도 비교합니다.
동시 수정, 입력 복구, 타 과목 접근, CSRF, 긴 한글 폼, 스키마 업그레이드도 포함합니다.

VS Code 소스 시험·컴파일·VSIX 패키징은 수행했지만 실제 Extension Host의 화면 조작 시험은 남아 있습니다.
Visual Studio 소스 관련 Python 시험은 수행했으나 이번 환경에는 Windows VSSDK/.NET SDK가 없어
새 C# 검사 실행·WPF 빌드·VSIX 패키징·실제 IDE 시험을 하지 못했습니다.
배포 전에 두 IDE에서 설명 열기 → 교수자 수정 → 새 설명 확인 → 재제출을 직접 확인하세요.
