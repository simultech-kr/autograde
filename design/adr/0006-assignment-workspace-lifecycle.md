# ADR 0006: 수락 이력·인증 과제·로컬 작업 폴더를 분리한다

- 상태: 채택
- 날짜: 2026-09-29
- 관련: [ADR 0005 공용 좌석 인증](0005-shared-seat-ephemeral-auth.md)

## 맥락

재인증 뒤 자동 다운로드가 실행되어 이미 존재하는 과제 폴더와 충돌한다. IDE에서 열어 둔
과제와 인증 대상이 다르면 이전 작업을 잃거나 다른 과제에 제출할 위험이 있다. 단일 수령 코드
세션의 과제만 표시하는 목록으로는 과거에 수락한 과제를 다시 찾기 어렵다.

## 결정

1. 수락 이력은 같은 인증 학생·수업의 수락 기록을 조회하는 별도 읽기 전용 API로 제공한다.
   메타데이터를 안다는 사실이 파일·점수·제출 접근 권한이 되지 않는다.
2. 현재 연결 과제는 기존 수령 코드의 과제별 세션 범위를 유지한다. 다른 과제는 새 수령 코드로
   재연결한다. 최신 로그인 하나만 유지하는 서버 정책과 메모리 전용 토큰을 변경하지 않는다.
3. 로컬 폴더는 서버 주소·과제 ID를 확인해 명시적으로 연결한다. 폴더명·활성 편집기·과제 제목으로
   제출 대상을 추정하지 않는다. 로컬 연결 파일은 학생의 소유권이나 인증을 증명하지 않는다.
4. 기존 작업 이어하기와 새 자료 다운로드를 분리한다. 기존 파일을 덮어쓰거나 기존 과제 안에
   다른 과제를 중첩 생성하지 않는다. 여러 사본은 명시적으로 선택하고 제출 전 경로·파일을 확인한다.
5. 다운로드 성공과 IDE 열기 성공도 분리한다. 자동 열기 실패·취소 시 받은 파일은 남기고 재열기를 제공한다.
6. IDE 재시작·학생 변경·서버 주소 변경 시 인증을 자동 복구하지 않는다. 수락 이력과 학생 화면은
   인증 경계에서 지우며 로컬 소스는 사용자의 파일로 보존한다.

## 결과 및 한계

- 재로그인은 파일 재다운로드 없이 가능하지만 새 코드는 여전히 필요하다.
- 현재 마감 정책상 마감된 과제는 새 코드 발급·제출이 불가하다. 로컬 학습을 계속할 수 있으나
  재제출은 교수자의 마감 연장 뒤 재연결해야 한다.
- 여러 과제의 토큰을 캐시하는 무인증 전환은 제공하지 않는다. 새 로그인은 같은 학생·수업의
  이전 세션을 폐기하므로 클라이언트만 토큰을 보관하는 방식은 동작하지 않는다.
- 다중 과제 무재인증 전환 또는 마감 후 재인증·결과 조회는 별도의 서버 권한 모델 결정 사항이다.
- 상세 시나리오와 인수 기준은 [작업 수명주기 안내](../../docs/operations/assignment-workspace-lifecycle.md)에 둔다.
