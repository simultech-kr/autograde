# Autograde for Visual Studio — C/C++ 실습을 IDE 안에서

과제를 받고, 코드를 작성하고, 제출 결과를 확인하는 학생용 Visual Studio 확장입니다.
교수자의 Autograde 서버와 연결하여 **과제 수령 → 다운로드 → 제출 → 채점 피드백**을
Visual Studio의 도구 창에서 진행할 수 있습니다.

> Windows x64의 Visual Studio 2022/2026 Community를 대상으로 하는 파일럿 MVP입니다.
> 확장만으로 독립적인 채점 서비스가 제공되지는 않습니다. 수업 서버와 수강 등록이 필요합니다.
> 호환 대상 선언과 실제 IDE 검증은 다릅니다. 두 버전의 Windows 설치·화면 조작 시험은 별도로 필요합니다.

[설치와 시작](#설치와-시작) · [제출과 결과 확인](#제출과-결과-확인) · [자주 묻는 질문](#자주-묻는-질문)

## 주요 기능

- **수령 코드 인증:** 학생 웹에서 발급받은 과제 코드를 입력하여 로그인합니다.
- **과제 다운로드·자동 열기:** 새 폴더에 과제를 받고 그 위치를 Visual Studio에서 자동으로 엽니다.
- **제출 파일 미리보기:** 과제·경로·파일 목록을 확인하고 저장된 코드를 제출합니다.
- **접수와 채점 분리:** 접수번호를 먼저 표시하고 채점 상태는 별도 영역에서 확인합니다.
- **결과 카드:** 큰 점수, 총점 달성률, 수정할 항목, 공개 피드백과 다음 할 일을 제공합니다.
- **이전 제출 확인·복원:** 서버 접수본의 결과를 조회하고 코드를 새 폴더로 복원합니다.
- **IDE 테마 연동:** Visual Studio의 색상·스타일 자원을 사용합니다. 실제 사용 테마의 가독성은 배포 전 확인하세요.
- **공용 PC 사용:** 로그인 정보는 실행 중 메모리에만 유지하고 자리 이동 시 로그아웃할 수 있습니다.

## 설치 전 확인

| 항목 | 필요한 환경 |
| --- | --- |
| 운영체제·IDE | Windows x64, Visual Studio 2022 또는 2026 Community |
| C/C++ 실습 도구 | 수업에서 요구하는 C++ 데스크톱 개발 도구·컴파일러 |
| 수업 정보 | 학생 웹 주소, API 주소, 수강 등록된 학번, 학생 전용 비밀번호 |
| 설치 파일 | **Visual Studio용** Autograde VSIX |
| 다른 환경 | Linux/macOS/Windows WSL2는 [VS Code용 확장](../vscode/README.md) 사용 |

Visual Studio Code와 Visual Studio는 다른 제품입니다. VSIX 파일을 서로 바꾸어 설치할 수 없습니다.
학생 PC에는 확장을 빌드하는 SDK나 개발용 .NET 8 도구가 필요하지 않습니다.
ARM64와 다른 에디션은 현재 별도 검증 대상입니다.

**Windows에서 코드를 작성할 수 있다는 것과 Windows 전용 코드를 서버에서 채점할 수 있다는 것은 다릅니다.**
현재 서버 파일럿은 이식 가능한 C/C++ 과제 기준입니다. `windows.h`, Win32 API 등
Windows 전용 과제를 위한 Windows 채점 작업자는 아직 구현되지 않았습니다.

## 설치와 시작

### 1. 확장 설치 후 도구 창 열기

작업을 저장하고 Visual Studio를 종료한 뒤 담당자가 배포한 Visual Studio용 `.vsix`를 실행합니다.
설치할 Visual Studio 인스턴스를 확인하고 설치한 다음 IDE를 다시 시작하세요.
**도구 → Autograde 과제**를 열면 이후 작업을 버튼으로 진행할 수 있습니다.

설치 시 서명·보안 정책 경고가 나오면 학교 담당자에게 확인하세요.
검증 기능을 전역으로 해제하는 방식으로 설치하지 않습니다.
Marketplace 공개 등록·자동 업데이트 채널은 별도 배포 작업이며 이 소개 문서 작성만으로 활성화되지 않습니다.

### 2. 서버 주소 적용

Autograde 도구 창의 API 주소 입력란에 담당자가 안내한 주소를 넣고
**주소 적용 / 연결 확인**을 누릅니다.

| 주소 종류 | 목적 | 파일럿 구성 예시 |
| --- | --- | --- |
| 학생 웹 | 브라우저 인증·과제 코드 발급 | `https://<수업 도메인>:20010` |
| API | 확장에서 다운로드·제출·결과 조회 | `https://<수업 도메인>:20000` |

학교에서 안내한 주소를 우선 사용하세요. 웹 로그인 페이지 전체 경로를 API 주소로 넣지 않습니다.
외부 연결에는 유효한 HTTPS 인증서가 필요하며 인증서 검사를 끄는 기능은 제공하지 않습니다.
`127.0.0.1`은 학생 PC 자신입니다. 교수자 서버에 연결할 주소로 대신 쓰지 마세요.
서버 연결 표시는 최근 접속 가능 여부이며 로그인 성공이나 제출 완료를 보장하지 않습니다.

### 3. 학생 웹에서 수령 코드 발급

수업 링크 또는 QR 코드로 학생 웹에 접속하고 교과목을 선택합니다.
**학번 + 학생 전용 비밀번호**로 인증한 뒤 받을 과제를 선택하고 **과제 수령 코드**를 발급받으세요.
코드 형식은 `AK1-XXXX-XXXX-XXXX`입니다. 이는 형식 설명이며 실제 인증 코드는 아닙니다.

웹에서 사용하는 학생 비밀번호와 확장에서 사용하는 과제 수령 코드는 서로 다른 값입니다.
기본 파일럿 흐름은 학교 SSO나 GitHub OAuth 로그인을 요구하지 않습니다.
코드는 학생·과제별 단기 일회용이므로 다른 사람에게 전달하지 마세요.

### 4. 코드 로그인과 다운로드

확장의 **과제 수령 코드** 입력란에 코드를 넣고 **코드로 로그인**을 누릅니다.
받을 과제를 확인하고 하단 **과제 다운로드 · 열기**에서 저장할 상위 폴더를 지정하세요.
새 고유 폴더를 생성하므로 기존 작업을 덮어쓰지 않습니다.

다운로드가 끝나면 해당 폴더가 Visual Studio의 폴더 작업 영역으로 자동으로 열립니다.
임의의 솔루션 파일을 골라 여는 방식은 아닙니다.
기존 작업의 저장·신뢰 확인창이 나오면 내용을 확인하세요.
IDE 열기 취소·실패에도 받은 파일은 남으며 **과제 폴더 열기**로 재시도할 수 있습니다.
확장은 빌드 명령을 실행하지 않지만 CMake 자동 구성 등 IDE 자체 설정은 별도로 적용될 수 있습니다.

### IDE 열기 실패 안내 (`AG-DL-OPEN-WORKSPACE`)

**다운로드는 완료됐고 Visual Studio에서 폴더를 여는 단계만 실패한 상태입니다.**
수락과 받은 파일은 유지됩니다. 다시 수락하거나 새 폴더에 재다운로드할 필요는 없습니다.

1. 기존 작업을 **모두 저장(Ctrl+Shift+S)**하고 다른 창 뒤에 저장·신뢰 확인창이 있는지 확인합니다.
   확인창을 취소했다면 파일은 그대로 남습니다. 신뢰할 수 있는 수업 자료만 여세요.
2. 확장 하단의 **과제 폴더 열기**로 다시 시도합니다.
3. 계속 실패하면 **파일 → 열기 → 폴더**에서 안내의 **저장 위치**를 직접 선택합니다.
   상위 폴더가 아니라 `main.c`/`main.cpp` 또는 README가 있는 `autograde-…` 과제 폴더입니다.
4. **폴더 관리 · 다시 다운로드 → 제출 폴더**가 직접 연 위치와 같은지 확인합니다.
   IDE에서 다른 폴더를 여는 것만으로 확장의 제출 폴더가 바뀌지는 않습니다.
   필요한 경우 **기존 과제 폴더 선택**으로 이 확장에서 받은 폴더를 지정합니다.
5. 코드를 수정·저장한 뒤 **파일 확인 후 제출**에서 실제 경로와 파일 목록을 확인합니다.

계속 실패하면 **다운로드 상세 · 문의번호**를 펼쳐 문의번호, 오류 코드, VS 버전과 발생 상황을
교수자에게 전달하세요. 비밀번호·수령 코드는 보내지 마세요. 저장 경로는 학생 화면에서만
안내하며 서버 진단에는 전송하지 않습니다. 진단 전달 실패는 다운로드 파일을 취소하지 않습니다.
폴더를 옮기거나 삭제한 경우 자동 열기 실패와 다르므로 파일 위치부터 확인하세요.
IDE 재시작으로 로그인이 해제되면 새 수령 코드로 로그인한 뒤 기존 과제 폴더를 선택합니다.

## 제출과 결과 확인

### 5. 문제 해결과 제출 파일 확인

과제 설명을 읽고 코드를 작성한 뒤 **모두 저장(Ctrl+Shift+S)**합니다.
필요하면 수업에서 안내한 방법으로 로컬 빌드·실행을 먼저 확인하세요.
**파일 확인 후 제출**을 눌러 저장 여부, 과제명, 경로와 제출 파일 목록을 검토하고 승인합니다.
저장하지 않은 편집 내용은 제출되지 않습니다.

현재 제출은 C/C++ 소스·헤더·지원하는 텍스트/빌드 설명 파일 중심입니다.
`.sln`, `.vcxproj`, `.exe`, `.dll`, `.obj`, `.pdb`, CSV 및 임의 바이너리는 제외됩니다.
`build`, `Debug`, `Release`, `.vs` 등의 출력·캐시 폴더도 제외하므로 그 안에 답안 소스를 두지 마세요.
추가 데이터나 프로젝트 파일이 필요한 과제는 교수자가 제출 범위와 맞는지 먼저 확인해야 합니다.
[전체 제출 범위](DEVELOPMENT.md#3-cc-제출-범위와-안전-경계)

### 6. 접수번호 확인

서버가 제출을 접수하면 **접수번호·과제명·접수 시각**을 표시합니다.
접수 후 작업 버튼을 다시 사용할 수 있으며 채점은 서버에서 계속 진행됩니다.
마지막 접수의 채점 상태는 별도 영역에서 최대 2분간 약 5초 간격으로 확인합니다.
자동 확인이 끝나도 서버 채점이 취소되지는 않습니다.
이후에는 **최신 결과 확인**으로 다시 조회하세요.

**접수 완료는 채점 통과나 최종 평가 완료가 아닙니다.**
응답이 끊겼다면 최신 결과·제출 기록부터 확인하고, 접수 여부를 확인하지 않은 채 반복 제출하지 마세요.
현재 작업 취소·창 숨기기·로그아웃은 이미 접수된 제출을 철회하지 않습니다.

### 7. 점수보다 먼저 확인할 것

결과 카드에서 **어떤 제출인지 → 현재 상태 → 점수 → 수정 필요 항목 → 다음 할 일** 순서로 확인하세요.

| 결과 상황 | 학생이 할 일 |
| --- | --- |
| 채점 대기·채점 중 | 기다렸다가 최신 결과를 확인합니다. |
| 결과 공개 대기 | 교수자의 공개를 기다립니다. 공개 전 결과를 0점으로 해석하지 않습니다. |
| 수정 필요 | 공개된 항목별 피드백 확인 → 코드 수정 → 모두 저장 → 재제출합니다. |
| 자동채점 총점 기준 충족 | 자동채점 외 보고서·설계 설명 등 추가 요구사항도 확인합니다. |
| 점수 정보 부족·채점 환경 오류·검증 거절 | 안내를 확인하고 접수번호와 오류 문구를 교수자에게 전달합니다. |

전체 진단은 펼쳐서 읽을 수 있습니다. 공개된 정보만 표시하며 비공개 테스트를 보여 주지 않습니다.
최신 제출과 과거 제출의 결과를 구분하세요. 코드를 수정한 것만으로 기존 제출 결과가 바뀌지는 않습니다.

### 8. 이전 제출과 공용 PC 정리

**제출 기록 조회 → 선택 기록의 결과 확인**으로 이전 제출을 살펴볼 수 있습니다.
**선택 기록을 새 폴더로 복원**은 현재 파일을 덮어쓰지 않고 별도 폴더에 코드를 저장합니다.
복원 후 다시 제출하려면 본인 파일인지 확인하고 명시적으로 제출해야 합니다.
서버에 접수되지 않은 로컬 초안은 복원할 수 없습니다.

자리를 떠날 때는 **로그아웃 / 자리 비우기**를 누르세요.
도구 창을 숨기기만 하면 로그아웃되지 않습니다.
소스 파일은 남으므로 학교의 공용 PC 정리 절차에 따라 처리하세요.

## 개인정보와 인증

- 확장에는 수령 코드를 입력하며 웹 비밀번호를 그대로 넣지 않습니다.
- 서버 주소는 PC에 저장하지만 수령 코드·로그인 토큰은 파일에 저장하지 않습니다.
- IDE를 종료하면 메모리 인증 정보가 사라집니다. 다시 사용할 때 새 수령 코드를 발급받으세요.
- 로그아웃해도 다운로드 파일은 삭제되지 않습니다. 오프라인 로그아웃은 서버 세션 폐기에 실패할 수 있습니다.
- 승인한 과제 파일과 제출 식별 정보는 지정된 Autograde 서버로 전송됩니다.
  제출 폴더에 개인 자료·인증 키를 두지 말고 서버의 보관·삭제 정책은 수업 운영자에게 확인하세요.

## 자주 묻는 질문

| 문제 | 확인 방법 |
| --- | --- |
| Autograde 메뉴가 없습니다. | VS Code용이 아닌 VS용 VSIX인지, 현재 실행한 Visual Studio 인스턴스에 설치했는지 확인합니다. |
| 주소를 확인하라고 합니다. | 학생 웹이 아닌 API 주소인지, 포트·방화벽·HTTPS 인증서가 맞는지 확인합니다. |
| 비밀번호를 입력해도 안 됩니다. | 웹에서 먼저 인증하고 받은 과제 수령 코드를 입력해야 합니다. |
| 수령할 과제가 없습니다. | 교과목·수강 등록·과제 공개 여부를 교수자에게 확인합니다. |
| 다운로드 후 폴더가 안 열립니다. | 파일은 보존됩니다. 재시도 버튼 또는 파일 → 열기 → 폴더로 안내된 경로를 엽니다. |
| IDE를 다시 열었더니 로그인해야 합니다. | 공용 PC용 메모리 인증 방식입니다. 학생 웹에서 새 코드를 발급받으세요. |
| 일부 파일이 제출 목록에 없습니다. | 지원 확장자와 제외 폴더를 확인합니다. 필요한 파일이면 제출 전에 교수자에게 문의하세요. |
| 복원했는데 점수가 바뀌지 않습니다. | 복원은 파일 복구일 뿐 제출이 아닙니다. 저장·제출 후 새 접수번호의 결과를 확인합니다. |

문의 시 IDE/확장 버전, 과제명, 접수번호, 오류 문구를 전달하세요.
비밀번호·수령 코드·로그인 토큰은 보내지 마세요.

## 현재 버전과 운영 안내

**0.5.6:** 아직 제출하지 않은 과제의 결과 조회를 정상 안내로 표시합니다. 자동 조회 중 인증이
만료되면 접수번호를 보존하는 안내와 로그인 화면을 보여줍니다. 과제를 바꾸면 이전 다운로드
상태·문의번호를 초기화하며, 제출 확인창 안에서 전체 파일 목록을 스크롤·복사하고 승인할 수 있습니다.
기존 설치본에 적용하려면 Windows에서 새 VSIX를 빌드하고 0.5.6으로 업데이트해야 합니다.
이번 버전의 Windows VSIX 생성·설치·실제 화면 조작은 아직 검증하지 않았습니다.

**0.5.5:** IDE 열기 실패·취소 시 저장 위치와 단계별 복구 안내를 유지합니다. 폴더 열기 재시도의
성공·실패도 서버에 보고하며 다운로드 성공과 구분합니다. 확장 관리 창의 소개에 시작 방법,
서버 필요 조건, 주요 기능, 자동 열기 복구, 공용 PC 주의사항을 추가했습니다.
설명 변경도 Windows에서 해당 버전 이상의 VSIX로 업데이트한 뒤 확인할 수 있습니다.

**0.5.4:** 명시적인 재제출과 통신 재시도를 구분합니다. 같은 파일도 다시 제출하면 새 접수번호로
추적하고, 현재 제출 점수와 이전 공개 최고점을 별도로 표시합니다. 0.5.3 버튼 정렬 수정도 포함합니다.
[학생별 이력·코드 비교와 업데이트 안내](../../docs/operations/submission-timeline.md)

**0.5.3:** 설정·로그아웃 버튼의 높이·여백을 통일하고 상단 우측에 정렬했습니다.
좁은 창에서는 버튼 묶음이 다음 줄로 이동합니다. 로그인 전에는 로그아웃·과제/폴더 관리가
숨겨지고 결과·기록 탭은 비활성화됩니다. 내용이 없는 하단 메시지 상자도 숨깁니다.
Windows에서 새 VSIX를 빌드·설치해야 적용되며 서버 업데이트만으로 설치된 확장이 바뀌지는 않습니다.
[업데이트 안내](../../docs/operations/visualstudio-updates.md#053-버튼-정렬-수정)를 참고하세요.

**0.5.2:** 과제·결과·기록 탭과 단계별 다운로드 진단·문의번호·서버 상태 보고를 추가했습니다.
[학생·교수자 진단 사용법](../../docs/operations/extension-download-diagnostics.md)을 참고하세요.

**0.5.1:** 다운로드 완료 후 과제 폴더 자동 열기와 재시도 버튼을 추가했습니다.
결과 카드, 접수·채점 상태 분리, 제출 기록·새 폴더 복원 기능을 함께 제공합니다.
Windows 실제 IDE 동작·설치·서명·업데이트는 운영자가 배포 전에 검증해야 합니다.
