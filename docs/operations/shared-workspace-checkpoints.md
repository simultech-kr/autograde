# 공용 실습실 고정 작업 폴더와 서버 작업 저장

공용 실습실에서는 같은 좌석의 작업 폴더 위치를 고정하고, 실행할 때마다 새 로컬 세션
식별자를 발급한다. 학생은 매번 새 수령 코드로 인증한다. 수령 코드·로그인 토큰을 다음
실행에 재사용하거나 이전 학생의 인증으로 남은 파일을 업로드하지 않는다.

## 기본 경로

`<UID>`는 학생 학번이 아닌 현재 운영체제 사용자의 숫자 ID다. 아래는 배포 실행기의
기본값이며, 개발용 실행에서 `--runtime`을 지정했다면 그 경로 아래 `current/workspace`를 쓴다.

| 실행 환경 | 작업 폴더 |
| --- | --- |
| macOS | `/private/tmp/ag-lab-<UID>/current/workspace` |
| Linux | `/tmp/ag-linux-lab-<UID>/current/workspace` |
| Windows의 WSL2 | `/tmp/ag-wsl-lab-<UID>/current/workspace` |
| Windows 네이티브 | `%LOCALAPPDATA%\AutogradeNative\sessions\current\workspace` |

과제는 `workspace` 아래에 내려받고, 강의자료는 형제 폴더 `materials`에 둔다. `current`에는
이번 실행의 코드·자료·IDE 설정과 임시 파일만 보관한다. 학생이 따로 내보낸 폴더·ZIP과
실행기의 `exports` 폴더는 정리 대상이 아니다. 내보내기 위치를 `current` 안으로 지정하지 않는다.

## 작업 저장과 공식 제출

인증한 학생이 과제 폴더를 연결하면 확장이 **30초마다 변경 여부를 확인하고 변경된 작업본을 저장**한다.
해당 과제의 편집 중 문서를 파일에 저장한 뒤 전송하므로 저장 실패나 인증·연결 문제가 있으면
최신 내용이 보관되지 않을 수 있다. 다른 과제 폴더·강의자료·다른 프로그램의 활동은 이
저장 기능으로 보내지 않는다. 공용 실습에서 처음 받은 템플릿은 수정하거나 **지금 작업 서버
저장 · 공식 제출 아님**을 눌렀을 때 보관한다. 전송 단위는 검증한 전체 과제 묶음이며,
서버의 Git 저장소는 파일 객체를 재사용한다. 개별 변경 파일만 네트워크로 전송하는 방식은 아니다.

학습 홈의 **작업 코드 자동 저장 · 공식 제출과 별도**에서 마지막 저장 성공 시각과 현재 상태를
확인한다. 서버 접수 응답이 확인되어야 저장 완료로 표시한다. **지금 작업 서버 저장 · 공식
제출 아님**으로 즉시 저장을 요청할 수 있다. 자동 저장은 채점·점수·공식 제출 이력을 만들지
않으므로 성적을 받으려면 기존 **과제 제출** 절차를 진행한다.

다시 실행한 뒤에는 새 수령 코드로 같은 과제에 연결하고 **서버 작업 저장본 · 새 폴더로 복원**을
선택한다. 저장 시각과 버전을 확인해 선택하면 새 폴더에 복원한다. 현재 작성 중인 파일을
덮어쓰지 않는다. 공식 제출본은 기존 **제출 이력 · 코드 복원**에서 별도로 찾는다.

## 서버 준비와 보관 한도

서버에는 업데이트한 Autograde 코드와 실행 가능한 **Git**이 필요하다. SQLite를 그대로
사용한다. 서버가 작업 저장 API를 제공하지 않거나 Git이 없으면 저장 기능은 오류를 표시한다.
서버 주소·프록시는 기존 `/v1/` API 연결을 사용한다.
작업본은 SQLite 파일 옆의 `<DB 파일명>.learning-checkpoints` 디렉터리에 보관한다.
서버 백업에는 DB뿐 아니라 이 디렉터리도 포함해야 한다.

| 범위 | 상한 |
| --- | --- |
| 학생·과제별 저장본 수 | 최근 20개 |
| 학생·과제별 보관된 원본 크기 합계 | 256 MiB |
| 학생·과제별 보관된 gzip 크기 합계 | 128 MiB |
| 한 번의 전송 | gzip 25 MiB, 압축 해제 후 100 MiB |

개수·용량 한도를 넘으면 오래된 작업 저장본부터 정리하므로 20개보다 적게 남을 수 있다.
기존 서버 업로드 제한이나 프록시 제한이 더 작으면 더 작은 한도가 적용된다. 장기 보관이
필요한 코드는 **내 학습내용 내보내기**로 따로 보관한다. 작업 저장본 보관 정책과 공식 제출본
보관 정책은 별개다.

## 종료와 다음 실행의 정리

IDE가 완전히 종료되고 관련 프로세스가 멈추면 실행기가 `current`를 정리한다. macOS에서는
창만 닫아도 앱이 남을 수 있으므로 **공용 실습 종료** 또는 `Command+Q`를 사용한다.
**공용 실습 종료**는 마지막 저장을 잠시 시도하지만, `Command+Q`나 강제 종료는 이 절차를
거치지 않을 수 있다. 종료 직전 변경까지 항상 저장된다고 가정하지 않는다.
정리가 중단되어 자료가 남았다면 다음 실행에서 이전 관리 폴더의 소유권과 프로세스 종료를
확인한 뒤 삭제하고 같은 위치에 빈 작업 공간을 만든다. 이전 `e-<세션 식별자>` 형식의
관리 폴더도 소유권이 확인되면 정리한다.

이전 실행기가 살아 있거나 소유 표식이 없거나 바뀐 경우, 다른 경로로 연결된 폴더, 잠긴
파일 등은 새 실행을 막는다. 이때는 담당자가 남은 프로세스·권한·오류를 확인한다. 소유 표식을
임의로 고치거나 다른 사용자 폴더를 삭제해서 우회하지 않는다.

**서버 저장을 확인하지 못한 변경도 종료 또는 다음 실행에서 삭제될 수 있다.** 연결이 끊긴
상태나 저장 전 강제 종료의 자료는 복원을 보장하지 않는다. 종료 전에 마지막 저장 시각을
확인하고, 실패하면 먼저 세션 밖으로 내보낸다. 폴더 정리는 같은 OS 계정의 다른 프로그램을
격리하거나 디스크의 삭제 파일 복구까지 막는 보안 기능은 아니다.

## 실습실 확인 절차

실제 성적에 영향을 주지 않는 시험 학생·과제로 확인한다.

1. IDE 아이콘을 실행하고 과제를 수령한다. 폴더 위치가 해당 OS의 `current/workspace` 아래인지 확인한다.
2. 소스를 한 줄 수정한 뒤 30초 이상 기다린다. 학습 홈에 저장 완료와 성공 시각이 표시되는지 확인한다.
3. 다른 내용을 수정하고 **지금 작업 서버 저장 · 공식 제출 아님**을 누른다. 저장 시각이 바뀌고 공식 제출·점수는 추가되지 않는지 확인한다.
4. 코드를 ZIP으로 세션 밖에 내보낸다. **공용 실습 종료** 후 관리 코드·자료가 지워지고 내보낸 ZIP은 남는지 확인한다.
5. 다시 실행한다. 작업 경로는 같지만 이전 학생의 파일과 인증은 없어야 한다. 새 수령 코드로 연결하고 서버 작업 저장본을 새 폴더에 복원해 3단계의 코드를 확인한다.
6. 새 코드를 작성하고 공식 제출한다. 채점 결과가 작업 저장 이력과 별개로 표시되는지 확인한다.
7. 시험 PC에서만 강제 종료를 재현한다. 다음 시작 전에 이전 IDE 프로세스가 모두 멈췄는지 확인하고, 재실행 시 남은 관리 파일이 정리되는지 확인한다. 프로세스가 살아 있다면 시작 차단이 정상이다.
8. 연결을 끊고 코드를 수정해 저장 실패 표시를 확인한다. 이 변경은 먼저 ZIP으로 내보낸다. 재연결 후 **지금 작업 서버 저장**의 성공을 확인하거나, 다음 실행에서 마지막으로 성공한 저장본만 복원되는지 확인한다.

Windows 네이티브의 ACL·Job 종료·잠긴 파일 정리는 실제 Windows PC에서 별도로 확인한다.
다른 OS에서의 빌드나 자동 시험 성공은 이 확인을 대신하지 않는다.

격리된 로컬 HTTP 서버로 확인했으며, 실제 수업 서버와 연결한 새 IDE의 전체 수용 시험은
위 절차에 따라 진행한다. Mac 0.5.15 패키지에는 새 확장이 내장되어 있다.
