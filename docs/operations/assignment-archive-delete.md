# 강의자의 과제 보관·삭제·복원

강의자는 웹에서 등록한 과제와 CLI로 등록한 과제를 모두 보관한 뒤 삭제할 수 있다. 개별 삭제와 일괄 삭제를 마치면 삭제한 과제가 빠진 **과제 관리** 목록으로 돌아간다. 삭제한 과제를 조회하거나 보관 상태로 복원하려면 **과제 관리 → 휴지통**을 직접 연다. 휴지통은 별도 제목으로 표시되며, 기존 `?visibility=deleted` 주소를 사용한다.

기존 강의자 인증 권한으로 실행하며 학생 인증으로는 접근할 수 없다. 확인란·동일 출처·CSRF 검사를 통과해야 처리한다. 이번 기능은 개인별 강의자 계정이나 교과목별 강의자 권한 모델을 새로 만드는 변경은 아니다.

## 강의자 사용 순서

1. 수업의 **과제 관리**에서 대상 과제를 연다.
2. **과제 보관**을 펼쳐 확인란을 선택하고 보관한다. 새 학생 수령과 제출을 중단하고 과제 운영 화면에 머문다.
3. 보관된 과제에서 **과제 삭제**의 안내를 확인하고 확인란을 선택한 뒤 삭제한다. 일반 과제 관리 목록으로 돌아가며 해당 과제는 목록에서 사라진다.
4. 다시 관리하려면 **휴지통**을 직접 열어 과제를 선택하고 **보관 상태로 복원**을 확인해 실행한다.

운영 중인 과제는 먼저 보관해야 삭제할 수 있다. 복원은 과제를 보관 상태로 돌려놓으며 학생에게 자동으로 다시 공개하지 않는다. 복원 후에도 학생 수령과 새 제출은 중단된 상태다. 보관된 수업에서는 과제 삭제·복원 등 변경을 할 수 없으며 조회만 가능하다.

교수자 채점 자료의 서버 검증이 진행 중이면 완료 후 삭제한다. 학생의 제출 채점 대기와는 구분된다. 삭제한 웹 공개본은 관리 한도에서 제외하며, 복원 시 수업별 100개·전체 500개 한도를 다시 확인한다. 한도에 도달했으면 다른 초안을 정리한 뒤 복원한다.

삭제된 과제의 설명, 연결된 웹 작성 자료와 검증 결과는 조회할 수 있다. 삭제 중에는 복제·숨김·마감 연장·설명 변경·재공개를 할 수 없다. 작업 전에 열어 둔 오래된 화면에서 같은 변경을 보내도 차단된다. **휴지통**과 복원은 공개본이 있는 과제에 적용된다. 미공개 초안의 기존 **미공개 초안 삭제** 기능은 별도이며 휴지통에서 복원하지 않는다.

## 보존 범위

여기서 삭제는 복구 가능한 관리용 삭제다. 과제 파일을 압축하거나 디스크에서 제거하는 기능이 아니다. 학생의 수락, 제출 코드, 제출 접수증, 점수, 채점 결과, 설명 변경 이력과 감사 기록은 보존한다. 삭제 이전에 접수되어 이미 대기 중이거나 실행 중인 채점은 계속 완료할 수 있다. 새 수령과 제출은 보관 단계에서 중단하며, 학생이 이미 내려받은 로컬 파일을 지우지는 않는다.

과제의 식별자와 원본 공개본은 유지한다. 웹 과제의 원본 작성 자료를 CLI 과제로 다시 노출하지 않으며, 휴지통에서도 같은 과제를 중복 표시하지 않는다. 삭제·복원 작업에는 과제 식별자가 포함된 감사 기록을 남긴다.

## 배포와 확인

서버 초기화 과정에서 SQLite 스키마 15로 갱신하며 삭제 상태 저장용 `instructor_assignment_deletions` 테이블과 필요한 감사 기록 확장이 자동으로 적용된다. 별도의 수동 데이터 삭제나 과제 파일 이동은 필요 없다. 배포 전 기존 운영 절차에 따라 데이터베이스와 과제·제출 저장소의 일관된 백업을 확보한다. 데이터베이스 파일을 백업할 때는 실행 중인 SQLite의 WAL까지 고려하는 기존 백업 절차를 따른다. 새 DB를 이전 서버 코드로 바로 열지 말고, 롤백 시에는 백업과 코드 버전을 함께 확인한다.

검증에는 임시 데이터베이스와 합성 과제만 사용한다. 운영 과제를 시험 삼아 보관하거나 삭제하지 않는다. 적용 확인은 별도의 시험 수업에서 **보관 → 삭제 → 관리 목록에서 사라짐 확인 → 휴지통 조회 → 보관 상태로 복원**을 수행하고, 복원 후에도 학생에게 공개되지 않는지 확인한다.

회귀 검증은 `tests/integration/test_instructor_assignment_deletion.py`에서 웹·CLI 과제 흐름, 확인란, 강의자 인증, 동일 출처·CSRF 보호, 수업 경계, 검색·복원, 삭제 상태의 읽기 전용 화면을 다룬다.

## 여러 과제 일괄 보관·삭제

**과제 관리** 목록에서 과제 왼쪽의 확인란을 선택한 뒤 **선택 과제 일괄 보관** 또는 **선택 과제 일괄 삭제**를 누른다. 다음 확인 화면에서 선택한 과제와 처리 내용을 검토하고 확인란을 선택한 뒤 실행한다. 확인 화면을 여는 것만으로 과제 상태가 바뀌지는 않는다.

일괄 보관 후에는 변경 건수를 보여 주는 완료 화면에 머문다. 일괄 삭제 후에는 일반 과제 관리 목록으로 돌아가며, 삭제한 과제는 표시하지 않는다. 삭제한 과제는 **휴지통**을 직접 열었을 때 확인할 수 있다.

선택은 현재 페이지에 보이는 과제만 대상으로 하며 한 번에 최대 20개까지 처리한다. **현재 페이지 전체 선택**도 현재 페이지의 선택 가능한 과제에만 적용된다. 검색 조건이나 페이지를 바꾸면 이전 선택은 유지하지 않으므로 새 목록에서 다시 선택한다. 자바스크립트가 꺼져 있어도 각 과제의 확인란과 실행 버튼을 이용할 수 있다.

웹에서 공개한 과제와 CLI로 등록한 과제를 함께 선택할 수 있다. 미공개 초안과 이미 삭제한 과제는 일괄 처리 대상으로 선택할 수 없다. 일괄 삭제는 선택한 과제가 모두 보관된 상태여야 가능하다. 운영 중인 과제가 섞여 있으면 먼저 보관한다. 삭제한 과제의 복원은 기존과 같이 휴지통에서 개별 과제를 열어 수행한다.

선택한 과제 중 하나라도 처리 조건을 충족하지 못하면 전부 미적용한다. 확인 화면을 연 뒤 다른 화면에서 과제 상태가 바뀌었거나 수업이 보관된 경우에도 적용하지 않는다. 학생의 과제 수령 인원이나 제출 건수가 바뀐 경우에도 최신 현황을 확인하도록 기존 확인 화면의 적용을 중단한다. 확인 화면은 10분 동안 유효하다. 오래된 확인 화면이나 다른 로그인 세션의 확인 화면을 재사용하지 말고, 과제 목록을 다시 열어 현재 상태를 확인한 뒤 선택한다.

일괄 삭제에도 위의 보존 범위가 동일하게 적용된다. 학생 제출 코드·점수·채점 결과는 보존하며, 휴지통에서 보관 상태로 복원할 수 있다. 일괄 동작의 선택 범위, 확인 단계, 인증·CSRF·수업 경계와 오래된 확인 화면 차단은 `tests/integration/test_instructor_assignment_bulk.py`에서 합성 과제로 검증한다.
