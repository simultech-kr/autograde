# 학생 관점 사용성 평가

2026년 11월 22일 · 학생 웹 포털과 Autograde IDE의 수령·제출 안내

학생은 수령 코드를 받아 실습을 시작하고, 제출 결과에서 무엇을 고칠지 찾을 수 있었다. 실수하기 쉬운 지점은 **대상을 확정하는 순간**이었다. 어느 분반의 정보 활용에 동의하는지, 방금 누른 과제의 점수를 보고 있는지, 틀린 것이 로그인 비밀번호인지 활성화 코드인지가 화면에서 분명해야 한다.

## 평가 방법

처음 가입하는 학생, 기존 수업 비밀번호를 받은 학생, 여러 번 제출한 학생의 과업을 합성 계정으로 수행했다. 로컬 Next.js 배포용 빌드와 Python 서버, 임시 SQLite를 연결했다. Chrome에서 데스크톱 1440px와 모바일 390×844px를 사용했다. 잘못된 활성화 코드, 동명 두 분반, 미제출, 재제출, 총점만 공개한 과제를 포함했다. 판단 기준은 [공통 UX 지침](../../design/portal-ux-guidelines.md)의 대상 구분·복구·확인된 상태·돌아가기다.

웹은 실제 브라우저와 서버 응답을 확인했다. IDE는 VS Code 확장의 실제 화면 렌더러에 합성 제출 상태를 넣고 호스트 코드와 회귀 시험을 확인했다. 이번 평가에는 운영 서버, 실제 학생 참여 관찰, 실습실 IDE에서의 신규 공식 제출, VoiceOver·NVDA 실기 시험이 포함되지 않았다. 아래 픽셀 수는 특정 화면의 위치 측정값이다. 학생의 성공률이나 소요 시간을 추정한 수치는 없다.

학생 웹 회귀 시험 75개와 확장 수령·저장·결과 관련 회귀 시험 42개가 통과했다. 아래 발견은 이 시험들이 통과한 상태에서 관찰했다.

## 먼저 고칠 세 가지

| 순서 | 학생의 과업과 관찰 | 개선안과 인수 기준 |
| --- | --- | --- |
| 1 | **원하는 분반에만 정보 활용 동의 또는 거절.** 이름이 같은 01·02분반을 수강하면 팝업의 두 선택지가 모두 ‘실습 설계’이고, 저장 안내에도 같은 이름만 나온다. 두 번째 수업만 거절한 결정은 정확히 저장됐다. 별도 설정 화면에 들어가 과목 코드를 비교해야 대상을 구별할 수 있었다. | 팝업 선택지, 확인 문구, 설정 이력에 같은 과목명·학기·분반을 표시한다. 분반 정보가 없는 수업은 코드를 함께 표시한다. 동명 두 분반 중 두 번째를 선택한 학생이 **저장 전후 어느 분반인지 확인**하고 다른 분반의 결정을 독립적으로 바꿀 수 있어야 한다. |
| 2 | **방금 누른 과제의 결과 확인.** 390×844에서 Observer 과제의 ‘평가 결과 보기’를 홈에서 누르면 결과 카드가 화면 위에서 16px에 왔다. 과제 목록에서 같은 버튼을 누르면 수업 제목에 초점이 갔고, 결과 카드는 위에서 1,782px에 있었다. 주소에는 올바른 과제가 지정돼 있었다. 학생은 다른 과제 결과를 먼저 접할 수 있다. | 특정 과제에서 진입하면 해당 카드가 처음부터 보이고 키보드 초점도 그 카드에 있어야 한다. 홈과 과제 목록 양쪽에서 같은 과제로 진입해 검증한다. 일반 ‘내 점수’ 진입에서는 화면 제목으로 이동한다. |
| 3 | **가입 후 활성화 코드 오타 수정.** 잘못된 코드를 제출하면 서버가 ‘코드와 학번을 확인하거나 새 코드를 요청하세요’라고 반환한다. 화면은 입력란 전체를 가리고 ‘로그인 상태를 다시 확인’하라고 한다. ‘다시 확인’ 후 기존 계정으로 돌아오지만 코드 오류 안내는 사라진다. | 코드 오류는 입력란 옆에 원인과 재발급 방법을 표시하고 초점을 돌려준다. 같은 세션에서 올바른 코드를 다시 입력할 수 있어야 한다. 실제 세션 만료에 대한 화면 보호도 별도로 검증한다. |

| 학생이 본 동작 | 개선 후 확인할 동작 |
| --- | --- |
| 총점만 공개한 60/100점 과제에도 ‘평가 항목·수정 힌트 보기’가 있다. 눌러야 ‘항목별 피드백이 공개되지 않았습니다’가 나온다. [누르기 전](assets/student-ux-2026-11-22/score-only-before.png) · [누른 뒤](assets/student-ux-2026-11-22/score-only-after.png) | 처음부터 ‘총점만 공개’로 표시한다. 공개 범위 안에서 실제로 열 수 있는 피드백이 있는 과제에 상세 동작을 제공한다. |
| IDE에서 채점을 마쳤지만 아직 공개하지 않은 제출의 제목은 ‘결과 공개 대기’인데 진행 표시의 현재 단계는 ‘채점 중’이다. | 학습 홈, 상세, 보조기기가 읽는 현재 단계가 모두 ‘채점 완료 · 공개 대기’로 일치하고 추가 제출 필요 여부를 알려준다. |
| ‘시험·출석 성적’에서 새로고침하면 ‘실습 제출 결과’로 돌아온다. 자료 검색어·파일 형식과 홈의 ‘결과 확인’ 필터도 상세에서 뒤로 가면 풀린다. 미제출 학생이 ‘결과 공개’를 선택하면 과제 7개라는 제목 아래 빈칸만 남는다. [결과 0건인 화면](assets/student-ux-2026-11-22/assignment-filter-empty.png) | 같은 학생·수업 안에서 돌아가기와 새로고침으로 보던 탭과 조건을 복원한다. 결과가 없으면 ‘전체 7개 중 0개’와 ‘전체 과제 보기’를 제공한다. 로그아웃 또는 사용자 교체 시 개인 검색·선택은 지운다. |
| 일반 VS Code에서 빈 창으로 시작하면 수령 코드를 입력한 뒤에야 폴더 열기를 요청한다. 호스트가 창을 교체하면 코드를 한 번 더 입력해야 한다. 공용 실행기가 작업 폴더를 미리 연 경우에는 이 경로를 거치지 않는다. | 빈 창의 첫 동작을 ‘수업 폴더 열기’로 두고 폴더가 준비되면 코드 입력란에 초점을 둔다. 최초 수령에서 코드를 한 번만 입력하는지 실습실 PC에서 확인한다. |

## 유지할 동작

- 기존 수업 비밀번호로 로그인한 학생이 별도 가입 없이 과제를 찾아 수령 코드를 발급·복사했다. 아직 IDE에서 수락하지 않았다는 안내도 실제 기록과 일치했다. 선택적 정보 활용 팝업은 미룬 뒤 설정에서 거절할 수 있었다.
- 재제출한 과제에서 이번 **35/100점**과 이전 최고 **95/100점**을 구분했고, 수정할 평가 항목에서 소스 파일과 줄 번호, 힌트를 찾았다. 채점 대기 중인 새 제출은 이전 점수와 구분한다.
- 웹 자료함에서 실제 PDF 바이트를 받았다. 시험·출석 화면은 중간고사 **72**, 기말고사 **미입력**, 출석 **9.5**를 구분했다. 로그아웃 후에는 로그인 화면으로 복귀했다.

## 개선 후 검증

로컬 Next.js 배포용 빌드에 Python API와 임시 SQLite를 연결하고 합성 학생으로 같은 과업을 반복했다.

| 학생이 한 일 | 확인한 결과 |
| --- | --- |
| 팝업에서 동명 수업 중 02분반만 거절하고 나중에 01분반에 동의했다. | 선택지와 저장 확인에 교과목명·학기·분반·과목 코드가 표시됐다. 첫 저장 뒤 01분반은 미응답이었고, 새로고침한 설정에서도 01분반 동의와 02분반 거절이 유지됐다. [분반 선택 확인 화면](assets/student-ux-2026-11-22/consent-confirmation.png) |
| 홈과 과제 목록에서 Observer 과제의 평가 결과를 열었다. | 모바일 Chrome 390×844에서 과제 카드에 초점이 갔고 이번 제출 **35/100점**은 화면 위에서 161~195px에 표시됐다. 이전 최고 **95/100점**은 별도로 표시됐다. 데스크톱 1440×900, 뒤로 가기, 결과 주소를 새로 열 때도 선택한 과제와 점수를 확인했다. [이번 점수와 이전 최고점](assets/student-ux-2026-11-22/selected-assignment-result.png) |
| 가입 후 틀린 활성화 코드를 제출하고 같은 화면에 올바른 코드를 입력했다. | 잘못 입력한 값이 지워지고 입력란에 초점이 돌아왔다. 오류 문구에서 새 코드 요청 방법을 확인했고, 재로그인 없이 활성화와 수강 연결을 마쳤다. 인증이 만료되거나 위조 방지 토큰이 맞지 않는 요청은 거부됐다. [활성화 재입력 화면](assets/student-ux-2026-11-22/activation-retry.png) |

홈 필터, 시험·출석 성적 탭, 자료 검색어와 파일 형식은 같은 학생이 뒤로 가거나 새로고침한 뒤에도 복원됐다. 다른 학생이 로그인하면 이전 검색어와 선택은 나타나지 않았다. 일반 HTTP로 접속해 브라우저 암호화 기능을 사용할 수 없을 때는 새로고침 시 자료 검색어가 비워지고 파일 형식은 유지된다.

총점만 공개한 실습은 결과 카드에서 공개 범위를 바로 안내한다. 과제 필터에 맞는 항목이 없으면 전체 과제 수와 복귀 버튼을 표시한다. IDE에서는 폴더가 없는 첫 실행의 폴더 선택과 수령 코드 입력 순서, 채점 완료 후 공개를 기다리는 상태의 문구와 현재 단계를 회귀 시험으로 확인했다. 실습실에 설치한 VSIX에서 처음 수령하는 과정과 실제 학생의 수행 시간은 후속 현장 검증 항목이다.

최종 실행에서 학생 관련 서버 테스트 146개, 웹 테스트 142개, VS Code 확장 테스트 740개와 Next.js 배포용 빌드가 통과했다. 확장 테스트의 첫 병렬 실행에서 로컬 Git 서비스 준비 대기가 한 번 시간 초과되어 해당 테스트를 단독으로 확인한 뒤, 병렬 실행 수를 2로 제한해 전체를 재검증했다.

## 실제 학생에게 확인할 과업

같은 과업을 로컬 배포용 빌드에서 다시 검사할 수 있다. Next.js를 `127.0.0.1:18082`에 실행한 뒤, 저장소 루트에서 아래 명령을 실행한다. Python 가상환경과 Playwright의 Chromium이 필요하다. 두 번째 포트는 시험이 시작하는 임시 학생 서버에 사용한다.

```sh
node scripts/check_student_priorities.cjs http://127.0.0.1:18082 18186
```

서로 다른 두 분반에 등록한 학생에게 ‘02분반만 거절해 보세요’, 재제출한 학생에게 ‘이번 점수를 말하고 고칠 줄을 찾아보세요’, 처음 가입한 학생에게 ‘틀린 활성화 코드를 고쳐 계속하세요’라고 요청한다. 각각 **정확한 분반 선택**, **정확한 과제·제출본·코드 위치 확인**, **도움 없이 같은 세션에서 복구**를 완료 기준으로 삼는다. 도움 요청과 되돌아간 지점을 기록하되 학번·비밀번호·코드 원문은 기록에서 제외한다.

## 2026년 11월 28일 추가로 재현한 개선 과제

로컬 합성 수업에서 확인했다. 아래 항목은 후속 개선 대상으로 남아 있다.

| 순서 | 학생이 겪는 문제 | 다음 변경의 완료 기준 |
| --- | --- | --- |
| 1 | 마감된 과제 20개 뒤에 아직 열려 있는 과제 1개를 등록했다. 수업 상세 조회에는 21개가 있었지만 홈 조회는 마감된 20개만 반환했다. | 홈의 조회 한도를 적용하기 전에 현재 수령·제출 가능한 과제를 우선한다. 같은 조건에서 새 과제와 마감 시각이 홈에 보이고, 이전 결과도 다시 찾아갈 수 있다. |
| 2 | 현재 볼 수 없는 과제를 가리키는 결과 주소를 열었다. 주소에는 요청한 과제가 남고 화면에는 별도 안내 없이 다른 과제의 결과 카드가 먼저 나왔다. | ‘선택한 과제의 결과를 현재 확인할 수 없습니다’에 초점을 두고 ‘이 수업 전체 점수 보기’를 제공한다. 다른 과제의 점수가 요청한 결과처럼 보이지 않는다. |
| 3 | 좁은 화면에서 ‘내 계정’의 현재 비밀번호를 한 번 틀리자 변경 양식이 사라지고 로그인 상태 확인을 요구했다. 서버에서는 같은 세션으로 계속 로그인된 상태였다. | 현재 비밀번호 오류를 해당 입력란에 표시하고 같은 화면에서 다시 시도할 수 있다. 실제 세션 만료 시에는 재인증을 요구한다. |
| 4 | 수령 코드 발급 요청에 일시적인 서버 오류가 발생했다. 화면 상단의 ‘로그인·수강 상태 다시 확인’을 누르면 안내는 사라지지만 코드는 보이지 않는다. | 해당 과제에 발급 결과를 확인하지 못했다는 안내와 복구 동작을 둔다. 재시도 시 코드가 발급됐는지 확인하고, 중복 발급을 막는다. 보조기기가 읽는 발급 버튼에도 과제명을 넣는다. |
| 5 | 자료 검색은 내려받은 목록에만 적용된다. 자료 201건에 긴 안내문을 넣으면 200건 또는 응답 512KiB 한도로 일부가 빠지고, 제외된 자료는 정확한 파일명을 입력해도 찾을 수 없다. | 학생에게 배정된 전체 자료를 서버에서 검색하고 다음 결과를 열 수 있다. 201번째 자료도 파일명으로 찾아 다운로드할 수 있다. |
