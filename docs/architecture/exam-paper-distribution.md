# 별도 시험지 배포 설계

시험지는 실습용 코드와 채점 자료에 넣지 않고 독립된 PDF로 배포한다. 기존 교과목·분반 명단과 학생 비밀번호를 재사용하되, 시험지를 받는 과정에서 과제 수락·제출·채점 작업을 만들지 않는다. 교수자는 공개 전 PDF와 시간을 검토하고, 학생은 인증된 웹 화면에서 지정된 기간에 파일을 요청한다.

## 사용자 흐름

교수자는 수업의 **시험지 배포** 화면에서 제목, 학생 안내, 배포 시작·종료 시각을 입력한다. 초안을 저장한 뒤 같은 상세 화면에서 학생용 PDF를 업로드하고 등록본을 내려받아 확인한다. 확인란을 선택하고 공개하면 시작 전에는 예약 상태, 기간 중에는 다운로드 가능 상태가 된다. 학생 접속 링크에는 비밀번호나 인증 토큰을 넣지 않는다.

학생은 `/courses/{course_key}/exam-papers`에서 기존 학번·전용 비밀번호로 로그인한다. 공개된 시험지의 제목과 일정을 보고, 기간 중인 시험지의 다운로드 버튼으로 PDF를 받는다. 수령 코드와 IDE 확장은 필요 없다. 답안 작성·제출 방법은 교수자가 학생 안내 또는 PDF에 명시한다.

교수자는 상세 화면에서 학생별 최초 요청 시각, 최근 요청 시각, 횟수를 확인한다. 현재 활성 학생 중 요청이 없는 학생을 함께 표시하고, 이후 수강이 종료된 학생의 과거 요청 기록도 남긴다. 요청 기록은 서버가 파일 요청을 승인했다는 의미이며 전송 완료·열람·출석·응시를 증명하지 않는다.

## 상태와 시간 정책

| 상태 | 교수자 작업 | 학생 접근 |
| --- | --- | --- |
| 초안 | 안내·기간 수정, PDF 교체, 공개, 보관 | 목록·파일 비공개 |
| 공개 | 등록 PDF 조회, 요청 현황 확인, 보관 | 활성 수강생에게 목록 공개, 배포 기간 안에서만 파일 요청 |
| 보관 | 등록 PDF와 기록 조회 | 목록·파일 접근 종료 |

공개 후에는 PDF·제목·안내·기간을 고정한다. 수정하려면 정정 시험지를 새로 만들고 기존 시험지를 보관한다. 보관은 이 MVP에서 되돌리지 않으며 파일과 기록을 삭제하지 않는다. 잘못된 일괄 교체로 학생마다 다른 시험지를 받는 상황을 방지하기 위한 정책이다.

화면 입력·표시는 한국 표준시이고, 저장과 비교는 정규화된 UTC다. 다운로드 허용 범위는 `시작 <= 서버 시각 < 종료`다. 파일 무결성 확인 중 종료 시각이 지나도 거절한다. 별도 예약 작업 없이 요청 때마다 시간을 확인하므로 서버 재시작 이후에도 정책이 유지된다. 서버의 시계 동기화는 운영자가 관리한다.

배포 종료는 파일의 신규 요청을 막을 뿐, 이미 저장한 PDF를 닫거나 회수하지 않는다. 배포 기간은 답안 제출 마감과 별개다. 답안의 자동 채점을 사용하려면 기존 실습 과제의 제출 정책을 별도로 설정한다.

## 모듈 경계

| 구성 | 책임 |
| --- | --- |
| `exam_paper_schema.py` | SQLite v16의 시험지, 요청 기록, 변경 감사 기록과 불변성 제약 |
| `exam_papers.py` | 상태 전이, 기간·수강 상태 확인, 파일 무결성, 요청 기록 |
| `instructor_exam_papers.py` | 교수자 목록·등록·배포·요청 현황 화면 |
| `student_exam_portal.py` | 학생 인증 진입, 목록, 다운로드 요청 |
| `platform_portal.py` | 기존 학생 인증·세션 공유, 시험지 경로 연결 |
| `platform_http.py` | 인증 후 크기가 제한된 업로드 파싱, 첨부 파일 응답 |
| `pilot_portal_cli.py` | 실행 시 서비스 구성과 양쪽 화면에 의존성 주입 |

시험지 서비스는 과제·루브릭·채점 처리기에 의존하지 않는다. `InstructorWeb`과 `CoursePortal`에 서비스를 주입하지 않으면 메뉴와 경로를 제공하지 않는다. 현재 실행 구성에서는 기존 교수자 웹 관리 기능을 켜면 함께 연결한다. SES의 자동 플러그인 로더로 연결한 상태는 아니며, 향후 별도의 `exam_distribution` 선택 지점에 이 서비스를 등록할 수 있다. 외부 Python 코드나 임의 import 경로를 설정 파일에서 실행하지 않는다.

## 접근과 파일 보호

- 교수자 작업은 기존 인증과 담당 수업 권한을 통과해야 한다. 상태 변경·업로드에는 세션·CSRF·정확한 Origin 확인을 적용한다.
- 학생 다운로드는 인증된 세션의 학생 식별자를 사용한다. 클라이언트가 임의 학번을 지정할 수 없다. 매 요청에서 수업 운영 상태와 학생·수강 활성 상태를 다시 확인한다.
- 파일 요청은 CSRF가 포함된 POST다. 목록 조회, 링크 미리 가져오기, 교수자의 등록본 검토는 학생 요청 횟수에 포함하지 않는다.
- PDF는 최대 10 MiB다. 업로드 파일명은 저장 경로로 사용하지 않는다. 서버가 생성한 식별자와 SHA-256으로 비공개 저장소에 저장한다.
- PDF 헤더·끝 표시는 기본 형식 검사일 뿐 완전한 PDF 파싱이나 악성 콘텐츠 제거가 아니다. 신뢰할 수 있는 교수자 원본만 올리고, 공개 전 PDF 프로그램에서 직접 검토한다.
- 다운로드 전 파일 크기·해시·일반 파일 여부를 확인하고 심볼릭 링크·하드 링크를 거부한다. 첨부 다운로드와 `no-store`, `nosniff`를 적용하며 HTML 안에 PDF를 삽입하지 않는다.
- 공개 파일은 덮어쓰지 않는다. 같은 초안의 이전 업로드 파일도 자동 삭제하지 않는다. 보관·백업 정책은 운영 단계에서 별도로 정한다.

이 기능은 웹 접근을 제한하는 배포 모듈이지 시험 감독 도구가 아니다. 파일 재전송, 화면 촬영, 외부 AI 사용을 막지 않는다. 또한 기존 `pilot-local` 채점은 학생 코드를 서버 계정 권한으로 실행하므로 시험지 비밀성을 보장하는 격리가 아니다. 정식 시험에서는 채점 작업과 시험지 저장소를 다른 실행 권한·환경으로 분리해야 한다.

## 검증 범위

단위 시험은 상태 전이, 공개 원본 고정, 시간 경계, 파일 변조·경로 공격, 동시 요청과 재시작, 스키마 갱신을 확인한다. 실제 HTTP 시험은 인증·수업 격리·CSRF·업로드 제한·첨부 응답과 요청 기록을 확인한다. 브라우저 시험은 합성 자료로 교수자·학생 화면의 밝음/어두움 테마, 작은 화면, 키보드 이동을 확인한다.

운영 서버의 TLS·Nginx 설정, 실제 시험지의 PDF 렌더링, 실제 브라우저의 저장 완료 여부는 배포 후 별도 확인 대상이다.

2026년 10월 17일 로컬 검증에서 시험지 전용 시험과 기존 인증·과제·초기화·서버 시작 관련 자동 시험 총 402개가 통과했다. 합성 화면 6종에 대해 320·375·768·1440px, 밝음·어두움의 48개 조합과 키보드·고대비 검사를 통과했다. 별도 저장소 시험에서 동시 요청 20건의 횟수 보존도 확인했다. 운영 서버의 처리 용량이나 시험 감독 기능을 검증한 수치는 아니다.

시험지 전용 재검증 명령은 다음과 같다. 브라우저 검사는 `test_exam_paper_browser.py`가 임시 폴더에 내보낸 `exam-browser-fixtures.json`을 `scripts/check_exam_papers_browser.cjs`에 전달한다.

```sh
python -m pytest -q tests/unit/test_exam_papers.py \
  tests/integration/test_instructor_exam_papers.py \
  tests/integration/test_exam_paper_http.py \
  tests/integration/test_exam_paper_browser.py \
  tests/integration/test_pilot_portal_cli.py \
  tests/integration/test_course_reset.py
```
