## UI/UX 검토 시나리오

교수자 검토에서는 과제 목록에 주차·문제·마감·공개 상태를 식별할 수 있는지, 해당 수업 범위 안에서 과제 상세로 이동하는지 확인합니다. 통합 작성 화면에서는 준비 현황과 영역 바로가기를 이용하여 문제·학생 자료·채점 자료·검증·공개를 이어서 확인합니다. 기본 템플릿 다운로드와 실제 업로드 파일 백업이 다른 동작임을 안내하는지도 확인합니다.

학생 검토에서는 수업 로그인 후 과제 제목과 한국 시간 마감을 보고 수락할 과제를 고를 수 있는지, 확장에는 수락한 과제만 나타나는지, 내려받은 README에 전체 요구사항이 있는지 확인합니다. 정답 제출 후 일부러 미완성 코드로 재제출했을 때 현재 점수와 이전 최고점이 혼동되지 않아야 합니다.

| 상황 | 기대 동작 |
| --- | --- |
| 좁은 화면·밝은/어두운 테마 | 제목·마감·작업 버튼이 겹치거나 가려지지 않음 |
| 긴 설명의 통합 작성 화면 | 준비 현황과 바로가기로 현재 작업 영역을 찾을 수 있음 |
| 영역 하나 저장 | 저장한 영역이 보존되고 다른 미저장 입력의 이탈 경고가 동작 |
| 서버 검증 중 | 접수/실행/완료를 구분하고 검증 성공이 자동 공개로 이어지지 않음 |
| 학생용 ZIP 오선택 방지 | 학생 자료와 교수자 채점 자료의 입력 위치와 용도가 명확 |
| 과거 마감 | 한국 시간 마감과 새 공개 불가 사유를 표시 |
| 학생 재제출 | 새 접수 상태를 표시하고 과거 점수를 새 채점 결과로 표시하지 않음 |

**UI/UX 확인 및 수정:**

- 통합 작성 상단에 마감(KST), 학생 자료, 교수자 자료, 최신 검증 준비 현황을 요약했습니다.
- 문제·학생 자료·채점 자료·검증·공개 5개 영역 바로가기를 제공하고 긴 테스트 편집기는 접었습니다.
- 중복 일정 입력 폼/중복 ID를 제거하고 오류가 난 영역만 입력 복구·자동 펼침되도록 보완했습니다.
- 직접 만들기 검증 중에는 잘못된 “예제 고정” 안내를 표시하지 않으며 과거 검증 화면으로 최신 결과를 오인하지 않게 했습니다.
- 보관된 수업에는 수정·검증 버튼을 노출하지 않습니다.
- 기본 템플릿 다운로드는 업로드 원본 백업이 아님을 설명하고, 입출력 채점만으로 패턴 구조를 판정할 수 없음을 명시했습니다.

관련 Python 시험 63개와 실제 Chrome 검사 35개를 통과했습니다. Chrome은 320/375/768/1440px, 밝은·어두운 테마에서 확인했고 375px 다크 테마 전체 화면도 육안 검토했습니다. 이 UI 수정은 로컬 소스에 적용된 상태이며 원격 서버에 배포 완료되었다는 뜻은 아닙니다.

원격 업로드 장애를 점검하면서 업로드 의존성의 미설치·구버전 생성자 실패를 로컬에서 재현했습니다. 이 경우 인증된 교수자에게만 `503 upload_unavailable`와 서버 환경 확인 안내를 반환하고, 기존 초안·파일을 변경하지 않으며 파일/헤더 제한을 그대로 유지하도록 보완했습니다. 관련 HTTP 시험 **17개 통과**. 이 보완은 원격 원인을 확정한 조치가 아니라 재현 가능한 배포 장애의 진단성 개선입니다.
