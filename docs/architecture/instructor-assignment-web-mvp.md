# 교수자 웹 과제 등록 MVP 계획

작성: 2026-09-15. 갱신: 2026-09-16.
교수자 웹 등록 파일럿을 구현했다. [실제 사용 안내](../operations/instructor-web-mvp.md)와
[시험 기록](../testing/instructor-web-mvp.md)을 현재 구현 기준으로 삼는다.
아래는 목표 설계이며 운영 HTTPS·Windows 실기기 인수, 온라인 전체 학생 초기화 등까지
모두 완료되었다는 뜻은 아니다. 일반 학생 임의 코드 실행의 배포 승인은 별도다.

범위 확장: [수업·학생 등록 웹 MVP 설계](course-student-web-mvp.md)를 필수 선행/통합 범위로 추가한다.
MVC + 공통 서비스 구조와 공통 디자인 규칙을 함께 적용하며, 최종 완료 흐름은
**수업 등록 → 학생 등록 → 과제 등록·검증·공개 → 학생 제출·점수 확인**이다.

교수자 화면은 [과제 자료 제출·검증 UX](instructor-assignment-validation-ux.md)의 6단계를 따른다.
문제 준비 → 학생용 파일 → 채점 자료 → 서버 검증 → 결과·수정 → 공개로 안내한다.
학생 확장 안내는 [제출·검증 UX 설계](submission-validation-ux.md)를 따른다.

학생 재등록 리허설은 [수업별 학생 초기화 설계](course-student-reset-mvp.md)를 따른다.
학생 기록을 초기화해도 과제 정의·공개본·채점 자료를 삭제하지 않는 별도 위험 작업으로 분리한다.

## 1. 목표와 완료 범위

교수자가 서버 터미널이나 파일 경로를 다루지 않고 웹에서 과제를 만들고, 채점을 검증하고,
공개하여 학생이 기존 확장으로 다운로드·제출·점수 확인까지 할 수 있게 한다.
초기 서버 설치·백업·업데이트는 운영자 작업으로 남지만 매주 과제 등록에는 CLI가 필요 없어야 한다.

- 실제 학생 웹/교수자 웹: `https://ai.cbchoi.info:20010`
- 기존 VS Code 및 Visual Studio API: `https://ai.cbchoi.info:20000`
- 교수자 진입: `/courses/come2201/instructor`, `/courses/come3105/instructor`
- Nginx → 내부 HTTP 18081/18080 구성, CSV 설정, SQLite, 학생 인증과 과제 수령 코드 유지.
- 단일 서버·신뢰할 수 있는 교수자 운영자 1명으로 시작한다. 공유 교수자 자격 증명은
  교수자별 권한 분리나 개인별 감사 추적을 제공하지 않는다.
- Docker 도입은 이번 웹 MVP 범위에서 제외한다. `pilot-local`은 사전 검토한 시험 코드 전용이다.
  웹 등록 완료와 일반 학생의 임의 코드 실행을 허용하는 배포 승인은 별개다.

## 2. 현재 코드와 차이

| 현재 구현 | 이번 변경 |

## 3. 교수자 화면과 사용 흐름

### 과제 목록

교수자 로그인 → 교과목 선택 → **과제 관리**. 교과목 코드·실제 접속 주소를 화면 상단에 유지한다.
목록에는 제목, 언어, 시작/마감, 검증 결과, 공개 여부, 수락/제출 수를 표시한다.
초안, 검증 중, 검증 실패, 공개 가능, 공개, 시작 전, 마감, 숨김을 구분한다.
상태는 저장 상태와 시간에 따른 표시 상태를 구분하며, 마감은 서버 시간으로 판정한다.

### 새 과제 마법사

1. **만드는 방법:** `예제에서 만들기` 또는 `직접 만들기`.
2. **기본 정보:** 제목, 문제 설명(일반 텍스트), C17/C++17, 시작·마감(KST 표시), 결과 공개 방식.
   시간 입력에는 시간대를 표시하고 내부는 UTC로 저장한다. 시작이 마감보다 늦으면 저장을 거절한다.
   시험용 마감 없음은 명시적인 선택으로만 허용한다.
3. **학생용 자료:** starter와 문제 설명을 미리 보고 다운로드될 파일 목록을 확인한다.
4. **교수자 전용 자료:** 테스트케이스, 정답, 오답, 오답 기대 점수를 준비한다.
5. **채점 검증:** 실행을 눌러 접수된 작업 상태와 기대/실제 점수, 오류 유형을 확인한다.
6. **공개:** 최신 자료의 검증 성공 후 별도 버튼과 확인 창으로 공개한다.
7. **학생 화면 확인:** 같은 과목의 학생 페이지 링크와 QR을 제공한다. 교수자 미리보기는
   학생 인증·수락 기록을 만들지 않는다.

과제 키·assignment_id·release_id·자료 경로·해시는 서버에서 생성한다.
예제 자료는 템플릿에서 채우고, 내부 식별자를 필수 입력으로 노출하지 않는다.
공개 직후 시작 전이라면 “공개 완료, 학생 수령은 ○월 ○일 ○시부터”로 안내한다.

### 초안 수정과 공개 후 변경

웹 초안은 편집 가능하지만, 검증 시작 시 기존 immutable release 형식으로 자료를 고정한다.
편집하면 초안 revision이 증가하고 이전 검증 성공은 새 revision에 사용할 수 없다.
동일 revision에서 공개 버튼을 반복해도 release가 중복 생성되지 않는다.
검증 중에는 해당 초안 편집을 막고, 실패/완료 후 수정할 수 있게 한다.

공개본의 코드·테스트·배점은 덮어쓰지 않는다. 수정 필요 시 **새 버전 초안으로 복제**한다.
최초 MVP에서 기존 수락·제출이 있는 과제의 교체/숨김은 차단하고 사유를 안내한다.
마감 연장은 기존 감사 기록·결과 공개 제약을 재사용한다. 삭제, 마감 단축, 제출 이관은 제외한다.

## 4. 지원할 과제 종류

### A. 예제에서 만들기 — 첫 번째 수직 구현

- C Hello World / C++ Hello World.
- VS Code Linux/WSL2용 또는 Visual Studio Windows용 starter 선택.
- 기존 검증된 정답·미완성 답안·채점기 사용. 기대 점수 10점/5점과 배점은 고정 표시한다.
- 제목·문제 설명·기간·결과 공개 정책만 편집한다. 템플릿 채점 규칙 변경은 직접 만들기로 처리한다.
- 같은 서버의 POSIX 채점으로 이식 가능한 소스만 평가한다. Windows starter 선택이
  Windows 원격 채점 지원을 의미하지 않음을 표시한다.

### B. 직접 만들기 — 최소한의 주간 실습 운영

- 단일 `main.c` 또는 `main.cpp`의 표준 입력/표준 출력 문제로 한정한다.
- 교수자가 starter ZIP, 정답 ZIP, 오답 ZIP을 각각 올린다. 이름과 역할이 다른 업로드 칸을 사용한다.
- 웹 표에서 입력, 예상 출력, 배점, 학생 공개 여부를 작성한다. 1~50개 케이스를 허용한다.
- 배점 합계가 만점이며 오답 기대 점수는 0 이상·만점 미만이어야 한다.
- 정해진 서버 채점기가 C17/C++17로 컴파일하고 케이스별로 실행한다. CRLF/LF만 동등 취급하며
  추가 공백·추가 출력은 기본적으로 오답이다. 비교 정책과 제한을 등록 화면에서 확인시킨다.
- 초기 실행 예산안: 컴파일 15초, 케이스 2초, 제출 전체 실행 30초, 케이스 출력 64 KiB.
  전체 제한에 걸리면 미실행 케이스와 사유를 명시한다. 실제 호스트 검증 후 상한을 확정한다.
- 컴파일 실패와 도구 부재를 구분한다. 컴파일러/채점 환경 장애를 학생 0점으로 확정하지 않는다.
- `grade.py`, 임의 shell 명령, CMake/프로젝트 빌드 스크립트, 서버 파일 경로, 외부 URL을
  웹에서 지정하거나 실행하게 하지 않는다. 교수자 정답 코드도 신뢰 코드임을 확인하고 검증한다.
- 다중 소스 빌드, Win32 API, 임의 라이브러리, Java, GUI, AI 프롬프트 자동 채점은 후속 범위다.
  옵저버/데코레이터의 설계 구조 자체를 이 입출력 채점으로 평가할 수 있다고 주장하지 않는다.

문제 설명은 README로 합쳐 starter bundle에만 포함한다. 기존 README가 있다면 미리보기에서
대체 여부를 확인한다. 비공개 테스트·정답·오답·채점기는 학생 bundle에 절대 포함하지 않는다.

## 5. 서버 구현 설계

### 공통 운영 서비스

`AssignmentAdminService`(신규 예정)에 등록·검증·공개·숨김·연장 규칙을 모은다.
기존 CLI는 이 서비스를 호출하도록 바꾸되 기존 명령 계약과 데이터는 보존한다.
웹 요청에서 shell로 CLI를 실행하거나 사용자 문자열로 명령을 조합하지 않는다.

교수자 경로는 `/courses/{course}/instructor` 아래에 둔다. 아래는 신규 제안이며 아직 API가 아니다.

| 동작 | 메서드·경로(교수자 경로 기준) |
| --- | --- |
| 목록/새 과제/초안 보기 | GET `/assignments`, `/assignments/new`, `/drafts/{id}` |
| 초안 생성/저장 | POST `/drafts`, `/drafts/{id}` |
| 역할별 ZIP 업로드 | POST `/drafts/{id}/uploads/{role}` |
| 검증 시작/결과 조회 | POST `/drafts/{id}/checks`, GET `/checks/{id}` |
| 검증된 초안 공개 | POST `/drafts/{id}/publish` |
| 공개 과제 조회·복제·숨김·연장 | GET `/assignments/{id}`, POST 하위 `/copy`, `/hide`, `/extend` |

서버 렌더링 HTML/form을 기본으로 하고 검증 상태는 새로고침으로도 확인 가능하게 한다.
JS는 필수가 아니다. 추가 시 CSP를 완화해 inline script를 허용하지 않고 별도 자체 스크립트만 사용한다.

### SQLite와 자료 저장

- 기존 release/check/deadline 테이블은 재사용한다.
- 초안: course, language/template, 설명, 기간, revision, 공개 release 연결, 생성/수정 시각.
- 업로드: opaque ID, course/draft/revision/role, 해시·크기, 비공개 저장 위치, 유효 상태.
- 검증 작업: draft revision, immutable release/check 연결, queued/running/succeeded/failed/interrupted,
  작업 ID, 시작·종료 시각, 제한된 결과 요약.
- 운영 기록: 누가(초기에는 공유 instructor), 어느 교과목·과제에 무슨 작업을 했는지 기록한다.
  비밀번호·토큰·비공개 테스트 원문은 로그에 넣지 않는다.
- 마이그레이션 번호는 구현 시 최신 번호 다음을 사용한다. 기존 DB/제출/점수/자료 해시를 보존한다.
- 업로드·검증 중 긴 파일 작업은 DB 쓰기 트랜잭션 밖에서 수행한다. 최종 상태 전환은 짧은
  트랜잭션으로 revision과 현재 상태를 다시 확인한다. 두 탭의 동시 수정은 409와 재로딩 안내.
- 자료는 전용 비공개 저장소에 두고 학생 bundle 생성은 starter 역할의 허용 목록만 사용한다.
  임시 자료는 등록 성공 후 참조되며 실패한 미참조 자료는 제한된 유예 기간 후 정리한다.

### 비동기 검증과 복구

HTTP 요청은 작업 ID를 반환하고, 교수자 검증 전용 worker 1개가 정답·오답을 실행한다.
학생 worker와 큐를 분리하고 pending 검증은 서버 전체 10개로 제한한다(초기 예산안).
호스트 자원은 여전히 공유하므로 학생 제출 부하와 동시에 시험한다.
중복 검증/공개 요청은 idempotency key와 revision으로 한 작업만 만든다.
서버 재시작 시 queued 작업은 이어서 처리하고, running 작업은 interrupted로 기록한다.
중단된 작업이 자동 성공/공개되면 안 된다. 자식 프로세스 종료 확인 후 교수자가 재검증한다.
검증 실패에는 자료 오류·환경 오류·기대 점수 불일치·시간 제한을 구분해 수정할 입력을 알려준다.

## 6. 인증·업로드·프록시 안전 조건

- 기존 HTTPS 교수자 Basic 인증을 재사용하되 모든 쓰기 요청에 권한을 먼저 검사한다.
  학생 세션/수령 코드/API 토큰으로 교수자 쓰기를 허용하지 않는다.
- 쓰기 폼은 서버 발급 CSRF 토큰과 교수자 전용 Secure/HttpOnly/SameSite 쿠키에 묶는다.
  학생 쿠키와 이름·경로를 분리하며 Origin은 정확한 웹 origin만 허용한다.
  쓰기 요청의 누락/`null`/다른 origin을 허용하지 않는다. 권한 확인 전에 파일을 저장하지 않는다.
- 학생 웹의 `Referrer-Policy: same-origin` 대응을 유지한다. Origin/CSRF 검사를 우회하거나
  Nginx에서 요청 Origin을 강제로 바꾸지 않는다. Basic 인증은 공용 학생 PC에서 사용하지 않는다.
- MVP 업로드: ZIP 1개/요청, 압축 5 MiB 이하, 압축 해제 20 MiB 이하, 파일 1000개 이하,
  초안 전체 해제 용량 50 MiB 이하. 테스트케이스 전체 UTF-8 크기 1 MiB 이하.
  누적 업로드/초안 수에도 상한을 두어 작은 요청 반복으로 저장소를 채우지 못하게 한다.
- 상대 경로만 허용하고 `..`, 절대/드라이브/UNC 경로, 링크·장치 파일, 중복/대소문자 충돌,
  암호화 ZIP, 중첩 압축, 예약 manifest 이름과 압축 폭탄을 거절한다. 추출 전에 목록 검사,
  추출 중 실제 바이트 수 검사를 하고 사용자가 정한 경로로 저장하지 않는다.
- Nginx 웹 기본 64k 제한은 유지한다. **교수자 ZIP 업로드 경로만** 6m 요청 한도를 주고,
  해당 location에도 학생 웹의 proxy/보안 헤더/로그 제한을 빠짐없이 적용한다.
  작은 학생 로그인·교수자 메타데이터 경로의 제한은 별도로 유지한다.
- Python HTTP 계층에도 경로별 본문 제한, multipart 개수·헤더·크기·시간 제한을 구현한다.
  Nginx 제한만 믿거나 deprecated cgi 모듈/수제 문자열 분할로 multipart를 처리하지 않는다.
  유지되는 파서를 선정해 버전을 고정하고 잘못된 본문·중단 업로드 회귀 시험을 추가한다.
- Nginx/Python 413, 디스크 부족, 검증 대기열 초과를 교수자가 이해할 문구로 안내한다.
  외부 클라이언트가 주는 X-Forwarded-*로 인증 origin이나 권한을 결정하지 않는다.

## 7. 구현 순서와 각 단계 통과 조건

선행 단계: 확장 설계의 수업 레지스트리·교수자 공통 진입·수업/학생 등록·인증 폐기를 먼저
구현한다. 아래 과제 단계는 이 공통 MVC/Service 경계와 연결한다. 기존 두 수업으로만 시험한
상태를 신규 수업 등록 완료로 인정하지 않으며, 새 수업의 전체 흐름을 별도로 통과해야 한다.

1. **공통 서비스 추출:** CLI 기존 시험 통과, 불변 release·검증·공개 규칙 보존.
2. **예제 등록 수직 구현:** come2201 교수자 웹에서 Hello World 초안 → 비동기 검증 → 공개 →
   학생 코드 발급 → 기존 확장 다운로드·제출 → 5점/10점까지 실제 연결.
3. **직접 만들기:** 역할별 안전한 ZIP 업로드, 테스트 표, 고정 C/C++ 채점기, 새 문제도 웹만으로 등록.
4. **운영 기능:** 목록의 미노출 사유, 초안 수정/복제, 마감 연장, 제한된 숨김, 충돌/재시작 복구.
5. **staging 검증:** 실제 Nginx·HTTPS·SQLite 사본·합성 학생으로 아래 시험표 통과.
6. **운영 반영:** 백업·점검 시간·마이그레이션·기능 활성화·수동 E2E 검증 후 제한된 파일럿 개시.

1~2단계만 완료한 상태는 **예제 등록 MVP**, 1~6단계 완료가 **직접 과제 등록 MVP**다.
각 단계 결과를 구분해 보고하며 전체 웹 관리 완료로 과장하지 않는다.
확장된 **교수자 웹 관리 MVP**는 여기에 수업·학생 등록 설계의 구현·인수 기준까지 모두 충족해야 한다.

## 8. 필수 인수 시험

| 범위 | 통과 조건 |
| --- | --- |
| 교수자 기본 사용 | CLI 없이 두 교과목 각각 예제·직접 과제를 생성, 검증, 공개 |
| 학생 전체 흐름 | 실제 HTTPS 웹과 VS Code/VS Community에서 코드 수령·다운로드·제출·점수 확인 |
| 공개 규칙 | 초안/검증 실패/검증 중은 학생에게 안 보임; 성공 후에도 공개 버튼 전에는 안 보임 |
| 미노출 안내 | 시작 전·마감·숨김·다른 과목·초안을 교수자가 구분 가능 |
| 버전 무결성 | 검증 후 편집한 revision은 재검증 전 공개 불가; 공개본과 기존 제출 해시 유지 |
| 권한·CSRF | 미인증/학생 token/잘못된 교과목 ID/누락·null·외부 Origin/잘못된 CSRF 쓰기 거절 |
| 비밀 분리 | starter ZIP와 학생 API에서 정답·오답·비공개 입력·채점기·교수자 업로드 ID 접근 불가 |
| 업로드 | 크기 초과·경로 탈출·ZIP bomb·링크·중복 이름·끊김·동시 업로드에 원자적 실패와 정리 |
| 채점 오류 | 정답 만점·오답 기대 점수, 컴파일 오류·무한 반복·출력 과다·도구 부재를 구분 |
| 재시도·복구 | 더블 클릭/응답 유실에도 중복 공개 없음; 재시작 중 작업은 성공으로 오인하지 않음 |
| 기존 호환 | 기존 CLI, 학생 인증/수락 범위, 제출 이력, 두 확장 API 계약 회귀 시험 통과 |
| 실제 부하 | 합성 학생 25명 동시 수령·제출·조회 중 교수자 검증 1개; 유실·중복·DB lock 미처리 오류 0 |
| 백업·복원 | staging 복원 후 기존 학생·과제·제출·점수·비공개 자료 일치 |

부하 시험은 대상 서버 사양과 p50/p95 지연·오류율·대기 시간을 기록한다. 웹 일반 조회/작업 접수
p95 2초 이내를 초기 목표로 하되 장시간 채점 완료 지연과 구분한다. 실패하면 worker/큐 예산을
조정하고 재시험한다. 성능 목표나 보안 격리가 이미 달성되었다고 간주하지 않는다.

## 9. 실제 서버 적용·되돌리기

운영 코드/설정의 현재 버전을 기록하고 서버를 정상 종료한 뒤 데이터 폴더 전체와 비공개 설정을
백업한다. staging에서 같은 스키마 사본으로 먼저 마이그레이션·복원을 검증한다.
운영자가 CSV의 신규 기능 플래그(예정: `instructor_assignment_web_enabled`)를 켜는 방식으로
노출하며 기본값은 꺼짐이다. 환경변수나 별도 서비스 포트는 추가하지 않는다.

Nginx 업로드 경로/본문 제한/Referrer 정책, Python 코드, SQLite 마이그레이션을 함께 반영한다.
HTTPS 양쪽 `/readyz`와 실제 학생 로그인 폼을 확인한다. Windows 확장 설치·UI 동작은 Windows에서
직접 검증하며 macOS 테스트 결과로 대체하지 않는다. 게시/서명/자동 업데이트는 이 계획 범위 밖이다.

장애 시 우선 웹 쓰기 기능을 끄고 기존 조회·학생 서비스를 유지할 수 있는지 확인한다.
스키마가 바뀐 DB에 구버전 코드를 바로 실행하지 않는다. 백업 복원은 새 제출 유실 가능성이 있으므로
접수를 중단하고 변경 후 자료를 보존한 뒤 운영자 승인하에 수행한다. 무조건 DB 삭제는 금지한다.

일반 학생 코드 실행·공식 성적 운영 승인 조건은 별도
[배포 준비 기준](../operations/student-deployment-preparation.md)을 따른다.
