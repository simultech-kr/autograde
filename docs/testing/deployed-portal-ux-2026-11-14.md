## 남은 배포 문제

Next.js 공개 경로 `/app`, `/app/student`, `/app/healthz`는 모두 Python `not_found` JSON으로 404를 반환했다.
운영자가 서버에서 실행한 `curl http://127.0.0.1:18082/app/healthz`도 연결 거절이었다.
제공된 Nginx 조회 결과에는 `listen 20010 ssl;`만 나타났으며 `/app` 및 18082 전달 규칙은 나타나지 않았다.
따라서 Next.js 실행과 외부 프록시 연결을 완료해야 한다. 빌드 성공만으로 화면이 서비스되지는 않는다.

현재 저장소에서 별도 터미널로 시작한다. 기존 서비스 관리 도구가 있다면 그 서비스의 실행 경로·오류를
고친 뒤 시작하며, 같은 포트에 프로세스를 중복 실행하지 않는다.

```sh
npm --prefix "$(git rev-parse --show-toplevel)/web" start
```

다른 터미널에서 확인한다.

```sh
curl --fail --silent --show-error http://127.0.0.1:18082/app/healthz
printf 'include "%s/config/nginx-autograde-next.locations.conf.example";\n' "$(git rev-parse --show-toplevel)"
```

출력된 include를 기존 Nginx의 `listen 20010 ssl;`이 있는 `server {}` 안에 추가한다.
기존 설정·인증서·20000 API 블록은 교체하지 않는다. 예제는 `http {}`의 `portal_web` 요청 제한 zone을
참조한다. 기존 zone이 있으면 중복 선언하지 않으며, 없다면 다음 정의가 필요하다.

```nginx
limit_req_zone $binary_remote_addr zone=portal_web:10m rate=10r/s;
```

```sh
sudo nginx -t && sudo nginx -s reload
curl --fail --silent --show-error https://ai.cbchoi.info:20010/app/healthz
```

내부·외부 모두 `{"ok":true,"service":"autograde-instructor-web","contract_version":"1"}` 응답을 확인한 뒤
인증된 Next.js 메뉴·데이터 화면을 다시 점검한다. [기존 운영 안내](../operations/nextjs-pilot.md)의
CSV 활성화·수업 범위·지속 실행 절차도 적용한다. 서버의 Nginx·서비스 설정은 이 시험에서 변경하지 않았다.
