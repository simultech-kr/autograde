# 원격 C/C++/Python 실습과 종합 포털 운영

2026-10-28 · Autograde IDE 0.5.18. 원격 실습은 선택 기능이며 기존 서버·SQLite와 공식 채점은 유지한다.
교수자 포털에서 실행 관리자 상태를 확인하고 학생 IDE에서 Linux C17/C++17·Python 3 실습을 수행한다.
승인 이미지에는 Python 3.12가 포함된다. Java·디버거·교수자의 환경 패키지 조합/업로드는 아직 제공하지 않는다.
구현과 로컬 합성 계정 검증을 완료한 상태이며 `ai.cbchoi.info` 등 운영 서버에 적용되었다는 뜻은 아니다.
아래 절차로 실행 관리자를 준비하고 서버와 IDE를 각각 갱신해야 한다. DB 이전은 필요하지 않다.

## 제공 범위

- 학생이 수락한 과제의 코드만 서버 작업 저장본으로 만든 뒤 개인 실행공간에 전달한다.
- 컴파일할 C 또는 C++ 소스와 표준입력을 선택하며 컴파일·실행 출력과 종료 코드를 구분한다.
- Python은 실행할 `.py` 파일 1개를 선택한다. 같은 저장본의 프로젝트 모듈과 표준 라이브러리를 불러올 수 있으며,
  별도 컴파일 단계 없이 문법 오류·예외·프로그램 출력을 표시한다. pip 설치·추가 외부 패키지·대화형 터미널은 제공하지 않는다.
- 소스는 읽기 전용이고 실행 중 생성한 파일은 임시 영역에만 기록한다. 이 임시 산출물을 서버 작업본으로 저장하지 않는다.
- 실행·자동 저장은 공식 제출이나 점수를 만들지 않는다. 공식 제출은 기존 제출 버튼을 사용한다.
- 종료는 현재 코드의 서버 저장과 원격 공간 삭제를 확인한다. 코드·인증의 로컬 정리는 공용 IDE 실행기가 담당한다.
- 다른 학생의 공간·저장본 접근을 거절하며, 작업 저장소와 공식 채점 자료는 분리한다.

Mac 학생 PC에는 컴파일러·Python·Docker가 필요하지 않다. 실행 서버에는 Linux Docker와 승인된 이미지가
필요하다. Mac 개발 시험에서는 Docker의 Linux VM을 실행 서버로 사용할 수 있다. Windows 전용 API나
macOS 네이티브 프로그램의 빌드 환경은 이번 Linux 제공자의 지원 범위가 아니다.

## 서버 준비

저장소에서 기존 Python 설치를 갱신하고 실행 이미지를 만든다. Docker 설치는 기관 운영자가 담당한다.
실습 기능을 사용하지 않는 서버에는 Docker를 설치하거나 CSV 키를 추가할 필요가 없다.

```sh
.venv/bin/python -m pip install -e .
docker build -t autograde-learning-cpp:local runtime/learning-cpp
docker image inspect autograde-learning-cpp:local --format '{{.Id}}'
```

마지막 명령의 `sha256:` 값을 기록한다. 실행 관리자는 정확한 로컬 이미지 ID만 허용하며 태그로
이미지를 자동 다운로드하거나 로컬 컴파일러로 대체하지 않는다. 이미지 갱신은 새 이미지 검증 후
실습이 없는 시점에 관리자를 재시작하여 적용한다.
`runtime/learning-cpp` 디렉터리와 위 이미지 태그는 기존 이름을 유지하지만 현재 이미지에는 Python도 포함된다.
0.5.17의 C/C++ 전용 이미지를 사용 중이라면 새 이미지를 빌드하고 그 ID로 worker를 갱신해야 한다.

아래는 같은 운영자 계정으로 기능 시험을 하는 예다. 첫 실행에 전용 디렉터리를 만든다.

```sh
mkdir -m 700 /tmp/autograde-learning-pilot
.venv/bin/python -m autograde.learning_runtime_worker \
  --socket /tmp/autograde-learning-pilot/worker.sock \
  --root /tmp/autograde-learning-pilot/worker \
  --image sha256:빌드한_이미지_ID \
  --lease-seconds 1800
```

`sha256:빌드한_이미지_ID`는 위에서 확인한 실제 전체 값으로 바꾼다. 이 터미널을 유지하고,
현재 사용하는 pilot CSV에 다음 한 행을 넣은 뒤 기존 API·웹 서버를 재시작한다.

```csv
learning_runtime_socket,/tmp/autograde-learning-pilot/worker.sock
```

환경변수는 추가하지 않는다. Unix 소켓 경로는 절대 경로이며 100바이트 이하여야 한다.
원격 실습 API는 기존 `/v1/assignments/.../learning-runtime` 경로를 사용하므로 기존 HTTPS
20000번 API 프록시에 연결된다. 교수자·학생 포털은 기존 20010번 웹 프록시를 사용한다.
worker 소켓이나 Docker 관리 포트를 Nginx 또는 외부 네트워크에 공개하지 않는다.
API의 worker 응답 대기는 요청당 최대 75초이며 worker 소켓은 90초 제한을 사용한다.
Nginx의 해당 API 경로에는 `proxy_read_timeout 120s;` 이상을 권장한다. 소스 전달·실행 후 정리
시간을 포함하기 위한 값이며, 권한 회수 때 별도로 보내는 취소 요청까지 항상 완료된다는 보장은 아니다.
IDE 실행 요청은 90초 제한이므로 응답 시간이 초과되면 결과를 성공이나 삭제 완료로 해석하지 말고
상태를 다시 확인한다.

## 기관 설치의 권한과 수명

같은 계정으로 실행한 시험은 프로세스 분리이며 API와 worker 사이의 OS 계정 권한 분리는 아니다.
기관 설치에서는 API 계정에 Docker 권한을 부여하지 않고 worker만 Docker를 사용하게 구성한다.
공통 IPC 그룹을 만들고 운영자가 짧은 실행 디렉터리를 준비한 뒤 worker에
`--socket-group 그룹명`을 추가한다. 이 옵션은 소켓을 지정 그룹의 `0660`으로 만들며,
부모 디렉터리는 두 계정이 접근할 수 있도록 기관이 소유권·그룹·탐색 권한을 설정해야 한다.
worker 자료 디렉터리는 worker 소유 `0700`으로 유지한다. API에는 원본 실행 폴더 접근권한이 필요하지 않다.

서비스 관리자로 worker를 지속 실행하고 재시작 정책을 설정한다. worker는 종료 시 공간을 정리하고,
재시작 시 자신의 표식이 있는 고아 컨테이너를 제거한 뒤 이전 공간을 만료 처리한다. Docker 연결 또는
정리를 확인하지 못하면 정상 시작·삭제 완료로 표시하지 않는다. 살아 있는 worker가 같은 root를
다시 사용하려 하면 잠금으로 거절한다. 소켓 파일을 임의로 삭제하여 우회하지 않는다.

기본 한도는 동시 실행 4개, 활성 공간 64개, 공간 임대 30분이다. 준비·실행 때 임대가 갱신되며
단순 화면 조회는 갱신하지 않는다. 유휴 공간은 만료 후 정리되고 다음 준비에서 서버 코드로 다시 만든다.
강제 종료·통신 단절 시 즉시 원격 삭제를 보장하지 않으며 임대·재시작 정리로 회수한다.

| 제한 | 현재 값 |
| --- | --- |
| 서버로 전달하는 소스 | 최대 2 MiB, 256개 파일 |
| 한 번에 컴파일하는 소스 | 같은 언어의 1~32개 파일 |
| Python 진입 파일 | `.py` 1개. 저장본 안의 다른 프로젝트 모듈 사용 가능 |
| 표준입력 | UTF-8 64 KiB 이하, NUL 제외 |
| 컴파일 / 프로그램 실행 | 12초 / 5초 |
| 각 단계 출력 | stdout·stderr 합계 원본 64 KiB |
| Linux 실행 | 비특권 UID, 네트워크 없음, 권한 제거, 읽기 전용 시스템·소스 |
| 자원 | CPU 1, 메모리 512 MiB, 프로세스 64개, 임시 공간 128 MiB |

일반 컨테이너의 커널 공유 경계를 가진다. VM 수준의 격리나 학생 PC 전체의 AI 접속 제한을
제공한다고 표시하지 않는다. 커널·장치·권한 상승 실습에는 별도 검증한 제공자가 필요하다.

## 학생과 교수자의 절차

1. 학생은 [회원가입·명단 연결](student-membership.md) 후 본인 교과목에서 과제 수령 코드를 발급하고 IDE에 입력한다.
2. 내려받은 과제 또는 본인의 기존 과제 폴더를 연결하고 학습 홈의 **원격 C/C++/Python 실습**을 연다.
3. **환경 준비 · 현재 코드 저장**을 누른다. 소스 목록과 서버 작업 저장 버전이 나타나야 한다.
4. C/C++은 언어·컴파일할 파일·표준입력을 선택하고 **현재 코드 저장 후 빌드·실행**을 누른다.
   Python은 언어와 진입 파일 1개를 선택하고 **현재 코드 저장 후 실행**을 누른다.
5. C/C++ 컴파일 오류 또는 Python 문법 오류·예외, 프로그램 출력·종료 코드를 확인한다.
   실행 중 수정했으면 이전 코드 결과라는 안내를 확인하고 다시 실행한다.
6. 성적을 받으려면 기존 공식 제출을 진행한다. 종료할 때 **저장 후 원격 공간 종료** 또는 IDE의 **공용 실습 종료**를 사용한다.
7. 다음 실행에는 새 인증으로 서버 작업 저장본을 복원한다. 종료 확인 전 편집·내보내기가 필요한지 확인한다.

저장 제한 때문에 연속 변경 저장이 거절되면 10초 후 재시도한다. 저장 실패·인증 만료·정리 실패에는
성공 표시를 하지 않는다. IDE 종료를 강행하면 로컬 파일은 삭제되며 미전송 편집을 복구할 수 없다.

교수자 포털 `/instructor`에서 수업을 선택한 뒤 **실습 환경**으로 이동한다.
직접 경로는 `/courses/come2201/instructor/environments`다. 미설정·연결 실패·연결됨, 학생별
공간 상태·저장본 식별자·만료 시각을 확인한다. 현재 화면은 조회 기능이며 임의 도구 설치나
학생 프로그램 원격 실행을 제공하지 않는다. 새로고침하여 상태를 확인한다.

학생의 `/courses/come2201/portal`에는 본인의 수락 과제, 원격 공간, 최근 제출·이전 최고점,
배포 자료와 IDE 연결 안내를 표시한다. 역할별 전체 정보구조는 [포털 운영](role-portals.md)에 정리한다.

## 자체 시험

```sh
.venv/bin/python scripts/check_learning_runtime.py \
  --image sha256:빌드한_이미지_ID
```

합성 학생·과제와 임시 SQLite로 실제 HTTP 인증·저장, Linux C/C++ 컴파일·실행과 Python 실행을 시험한다.
운영 DB·학생·성적을 사용하지 않는다. 결과는 `build/learning-runtime-report.json`에 남긴다.
worker가 없으면 host 실행으로 대체하지 않고 실패한다. 같은 스크립트의 `--serve`는 로컬
IDE/브라우저 시험용 API 18180·웹 18181을 열며 만들어진 시험 계정만 사용한다.

소스 변경 후 IDE에는 새 확장 또는 재빌드한 앱을 배포해야 한다. 서버의 `git pull`만으로 이미
설치한 Mac 앱이 바뀌지 않는다. [Mac 앱 제작·정리 안내](autograde-macos-app.md)를 따른다.
검증 범위·검사 결과·재현 명령은 [원격 실습·역할 포털 검증 기록](../testing/remote-learning-runtime.md)에 정리한다.
