# 테마별 가독성과 교수자 제출 코드 확인

작성: 2026-09-16

## 테마 설계와 적용 범위

화면 배경만 밝게 고정하고 입력창/글자를 호스트 기본값에 맡기면 어두운 테마에서
밝은 글자와 밝은 배경이 섞인다. 개별 색 상수 대신 의미별 공통 토큰을 사용한다.
본문/보조 글자, 페이지/카드/입력창, 링크/버튼, 테두리/포커스, 경고/오류를 쌍으로 정의한다.

| 화면 | 정책 | 이번 상태 |
| --- | --- | --- |
| 학생 웹, 교수자 웹, 제출 현황, 코드 확인 | `prefers-color-scheme` 밝음/어두움 자동 전환, `color-scheme`으로 네이티브 컨트롤 일치 | 공통 `web_theme.py` 적용 |
| VS Code 확장 | 기존 네이티브 TreeView/InputBox/ThemeIcon으로 호스트 테마 상속 | 기존 동작 유지, 확장 수정 없음 |
| Visual Studio 2022/2026 확장 | WPF 컨트롤 전체를 Visual Studio 테마 자원에 동적 연결 | 0.3.0 소스 반영·컴파일 확인, Windows 설치/렌더링 인수 대기 |

웹은 운영체제/브라우저의 색상 설정을 따른다. 테마 설정이나 로그인 정보를 새로 저장하지 않는다.
수동 선택기는 후속 단계이며, 도입 시 `자동/밝게/어둡게` 세 값과 전체 화면 공통 설정으로
만들고 인증 쿠키와 분리한다. 브라우저의 강제 반전 확장과의 호환은 별도다.

일반 글자 대비 목표는 4.5:1 이상, 포커스/주요 경계는 3:1 이상이다.
오류/확인 필요는 색뿐 아니라 문구로 표시한다. 비활성 입력도 읽을 수 있어야 한다.
QR은 흰 배경과 여백을 유지한다. 코드 화면은 단색 읽기 전용으로 시작한다.
고대비 강제 색상 모드는 시스템 색상을 존중한다.

### Visual Studio 구현과 인수 명세

`ThemeResources.cs`와 `AssignmentControl.cs`에 반영했다.
[0.3.0 빌드·업데이트 안내](../operations/visualstudio-updates.md)를 따른다.

`AssignmentControl.cs`의 UserControl/ScrollViewer/StackPanel, TextBlock, TextBox,
PasswordBox, ListBox/항목, Button을 한 세트로 처리한다. 도구 창 배경/본문은
Visual Studio SDK 테마 자원, 입력/선택/hover/disabled/focus는 SDK 컨트롤 스타일을
사용한다. 테마 색을 한 번 복사하지 않고 동적 자원 참조로 연결하여 실행 중 변경에 대응한다.
흰색/검정색 강제 지정이나 전체 opacity를 피하고 선택 글자와 선택 배경을 함께 적용한다.

Windows 실기기에서 VS2022/2026 밝음/어두움/파랑/고대비를 바꾸며 주소, 수령 코드,
과제 목록, 선택 항목, 읽기 전용 폴더/결과, 버튼의 모든 상태를 점검한 뒤 VSIX를 배포한다.
이번 웹 시험을 VSIX 검증으로 간주하지 않는다.

## 교수자 코드 확인: 구현된 흐름

1. 교수자 웹에서 수업 → **제출·채점 현황**으로 이동한다.
2. **확인 필요한 제출**에서 최신 제출의 감점·처리 실패를 확인한다.
   미제출·처리 중은 전체 표에서 확인한다. 지연 시간/표절 탐지는 아니다.
3. **코드·제출 이력 확인**을 누른다. 정상 제출도 전체 표에서 열 수 있다.
4. 학번, 과제/릴리스, 제출 ID/접수 시각, 상태/점수/실패 코드와 원본 해시를 확인한다.
5. 파일을 선택하면 줄 번호가 있는 제출 당시 원본 코드가 표시된다.
6. 같은 학생·같은 과제의 최근 100개 제출 이력을 열어 이전 제출로 이동한다.

현황은 활성 학생/과제 기준이다. 비활성화 후에도 기존 제출 상세 링크는 교수자에게 제공된다.
다른 릴리스는 별도 과제다. 감점은 확인을 돕는 표시이지 부정행위 판정이 아니다.
점수 수정·재채점·코드 실행은 하지 않는다.

### 데이터와 보안 경계

- `/courses/{course}/instructor/submissions/{submission_id}`와 `/files/{index}`는
  매 요청 교수자 Basic 인증을 검증한다. 학생 토큰/쿠키로 접근할 수 없다.
- DB에서 교과목과 제출 ID를 함께 검사한다. 다른 교과목은 404.
  공유 교수자 계정은 개인별 담당 수업 권한 분리나 열람자별 감사 기록을 제공하지 않는다.
- 기존 불변 `source_digest`의 **submission** 번들만 사용한다. starter/assessment,
  채점 데이터, 서버 임의 경로를 열지 않는다. 파일 경로 대신 검증된 목록의 숫자 인덱스를 받는다.
- 번들과 선택 파일 해시를 검증한다. 압축을 디스크에 풀거나 실행하지 않는다.
  HTML/스크립트/Markdown은 이스케이프한 텍스트로 표시한다.
  방향 전환·비가시 제어 문자는 `\uXXXX` 형태로 드러낸다.
- 파일별 256 KiB/5,000줄, HTML 변환 후 코드 256 KiB, 목록 페이지 200개, 이력 100개 제한과 초과 안내.
  파일 목록의 긴 이름은 200자에서 줄이며 선택한 파일 제목에서는 전체 경로를 표시한다.
  바이너리/UTF-8이 아닌 파일은 미리보기 제외. 파일 다운로드 기능은 추가하지 않았다.
- 인증 전 파일 저장소를 읽지 않는다. 유실/손상은 안전한 503 안내로 처리하며
  내부 경로나 원시 예외를 노출하지 않는다. HTTP의 no-store/CSP 정책을 유지한다.

## 확인 절차

```sh
.venv/bin/python -m pytest -q tests/unit/test_web_theme.py tests/integration/test_instructor_submission_review.py
```

브라우저에서 밝음/어두움을 전환한 뒤 로그인, 과제 선택, 교수자 입력창/오류 안내,
제출 현황, 코드와 QR을 확인한다. Tab으로 키보드 포커스를 확인한다.
일반 공개 전에는 기존 `pilot-local` 비격리 코드 실행 위험을 별도로 해결해야 한다.

### 이번 검증 결과

- 전체 회귀 시험: 940개 통과, 19개 환경 의존 시험 제외 (247.41초).
- 이후 추가한 이전 버전/파일 목록 이동, 원본 손상, HTML 변환 후 크기 제한과
  최종 호환성 수정을 포함한 관련 시험 재실행: 60개 통과 (24.51초).
  두 집계는 겹치는 시험을 포함하므로 합산하지 않는다.
- 두 웹 팔레트의 본문 대비 4.5:1, 포커스/테두리 3:1 이상 자동 검사 통과.
  로컬 합성 화면에서 밝음/어두움 팔레트를 각각 적용해 입력창·안내·학생 실습 선택을 육안 확인했다.
  운영체제 설정을 실제로 변경하거나 사용자 데이터로 시험하지 않았다.
- 제외된 환경: Windows/MSVC 2개, JDK 5개, .NET SDK 12개.
  원격 HTTPS 배포, Windows 확장 테마 전환 및 VSIX 설치 시험은 수행하지 않았다.
