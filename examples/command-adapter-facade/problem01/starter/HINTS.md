# Command Adapter Facade 평가 항목별 힌트

실패한 항목의 ID를 찾고, 첫 번째 힌트부터 확인합니다. 이 문서는 완성 코드가 아니라 구현 순서와 확인할 상태를 제공합니다. 여러 항목이 동시에 실패하면 가장 앞의 공통 경로인 Adapter → 단일 Command → 이력 → Facade 순서로 점검합니다.

## A1 조명 변환

1. `LampAdapter`는 `LevelDevice`의 백분율을 `LegacyLamp`의 단계로 바꿉니다. 두 값은 같은 단위가 아닙니다.
2. 쓰기에는 10으로 나누기, 읽기에는 10 곱하기가 필요합니다. `level()`이 내부 단계를 그대로 반환하지 않는지 확인합니다.
3. `SET LIGHT 60` 후 `STATUS`의 조명 값은 60이고 `RAW`의 조명 값은 6이어야 합니다. 둘 중 하나만 맞으면 변환의 한 방향이나 실제 장비 갱신을 점검합니다.

## A2 스피커 변환

1. 스피커는 조명과 함수 이름도, 비율도 다릅니다. `changeVolume`과 `volume`을 사용합니다.
2. 백분율을 5로 나누어 저장하고 읽은 값을 5배 합니다. 조명 코드를 복사한 뒤 10을 그대로 두지 않았는지 확인합니다.
3. `SET SOUND 60` 후 외부 값 60, 내부 값 12를 비교합니다. 별도 캐시에 60만 저장해서는 `RAW`가 맞지 않습니다.

## A3 경계값

1. 0과 100은 둘 다 유효합니다. `> 0`, `< 100`처럼 경계를 제외하지 마세요.
2. 조명 100은 내부 10, 스피커 100은 내부 20입니다. 두 Adapter의 상한이 같지 않습니다.
3. 두 장비에 0, 100을 번갈아 설정하고 `STATUS`와 `RAW`를 비교합니다. 이 문제는 정수 연산만으로 충분합니다.

| 백분율 | 조명 내부 단계 | 스피커 내부 단위 |
| --- | ---: | ---: |
| 0 | 0 | 0 |
| 100 | 10 | 20 |

## C1 단일 설정 취소

1. 취소는 0으로 초기화하는 것이 아닙니다. 해당 명령 실행 직전의 값을 복원합니다.
2. `SetLevelCommand::execute`에서 `previous = device.level()`에 해당하는 처리를 **새 값 설정 전**에 수행합니다. 생성자에서 저장하는 것이 아니라 실행 시점에 저장합니다.
3. 조명을 30으로 설정하고 다시 80으로 설정한 뒤 한 번 취소합니다. 0이나 80이 아니라 30이어야 합니다. 다른 장비는 바뀌면 안 됩니다.

## C2 이력과 취소 순서

1. 이력은 스택입니다. 먼저 실행한 명령이 아니라 가장 마지막 명령부터 취소합니다.
2. `back()`의 명령으로 `undo()`를 호출한 다음 `pop_back()`합니다. 먼저 제거하고 나서 그 객체를 사용하면 수명이 끝난 객체를 참조할 수 있습니다.
3. 조명 20 → 스피커 40 → 조명 70을 실행하고 세 번 취소합니다. 각 단계에서 두 값과 이력 개수를 표로 기록합니다. 취소 한 번마다 개수는 정확히 하나 줄어야 합니다.

## C3 빈 이력

1. `back()`이나 `pop_back()` 전에 비어 있는지 확인해야 합니다.
2. `undoLast()`의 반환값은 실제 취소 여부입니다. Facade는 그 결과에 따라 `OK UNDO` 또는 `EMPTY`를 반환합니다.
3. 시작하자마자 취소하거나, 모든 작업을 취소한 뒤 여러 번 더 취소해 봅니다. 값은 유지되고 이력은 계속 0이어야 합니다.

## C4 같은 값으로 설정

1. 이 과제에서 같은 값을 설정하는 명령도 성공한 작업입니다. 최적화 목적으로 생략하지 않습니다.
2. 이미 조명이 0이어도 `SET LIGHT 0`은 이력을 하나 늘립니다. 이를 취소하면 값은 여전히 0이지만 이력은 줄어듭니다.
3. 같은 장면을 두 번 실행한 뒤 한 번 취소해 봅니다. 두 번째 명령의 이전 상태가 첫 장면의 상태였다는 점을 확인합니다.

## F1 장면 구성

1. Facade가 장면 이름을 두 목표 값으로 해석합니다. STUDY는 80·20, MOVIE는 20·60, OFF는 0·0입니다.
2. 두 값의 순서가 조명, 스피커인지 확인합니다. 이 값은 내부 장비 단위가 아니라 공통 인터페이스의 백분율입니다.
3. 장면을 적용한 뒤 `STATUS`뿐 아니라 `RAW`도 확인합니다. Facade가 Adapter를 거치지 않고 기존 장비에 백분율을 직접 쓰면 내부 값이 잘못됩니다.

## F2 장면 전체 취소

1. 장면은 내부적으로 두 번 설정하지만 사용자가 실행한 작업은 하나입니다.
2. 두 `SetLevelCommand`를 가진 `SceneCommand` 하나를 `CommandHistory::run`에 전달합니다. 두 하위 명령을 각각 이력에 추가하지 않습니다.
3. 장면 실행 전 값을 조명 50, 스피커 40처럼 장면 표에 없는 값으로 만듭니다. MOVIE 실행 뒤 취소 한 번으로 두 값이 모두 50·40으로 복원되어야 합니다.
4. 하위 명령의 실행은 조명→스피커, 취소는 스피커→조명 순서로 위임합니다. OFF도 일반 장면 명령이므로 이력을 삭제하지 않습니다.

## F3 장면과 개별 설정 조합

1. 개별 설정과 장면이 같은 이력을 사용해야 합니다. 서로 다른 이력 두 개를 두면 전체 실행 순서를 복원하기 어렵습니다.
2. STUDY → 스피커 90 → MOVIE 순서로 실행하고 취소합니다. 첫 취소는 80·90, 다음 취소는 80·20으로 돌아가야 합니다.
3. 현재 장면 이름만 저장해서는 임의의 개별 설정 값을 복구할 수 없습니다. 각 설정 Command가 자신의 이전 값을 기억해야 합니다.

## E1 장비 검증과 우선순위

1. 지원하는 장비는 정확히 `LIGHT`, `SOUND`입니다. `light`는 지원하지 않습니다.
2. 장비와 값이 모두 잘못된 경우 `ERROR device`가 먼저입니다. 검증 순서를 바꾸지 마세요.
3. 알 수 없는 장비를 조명으로 간주하지 않습니다. 검증 실패 경로에서는 명령 생성·실행·이력 추가를 하지 않도록 확인합니다.

## E2 값 검증과 상태 보존

1. 허용 조건은 범위 안이며 동시에 10의 배수여야 합니다. `0 <= level && level <= 100`과 `level % 10 == 0`을 함께 생각합니다.
2. 스피커에도 동일한 입력 규칙을 적용합니다. 35를 내부 7로 변환할 수 있다는 이유로 허용하지 않습니다.
3. 정상 설정 뒤 -10, 110, 35를 입력하고 `STATUS`, `RAW`, `HISTORY`를 비교합니다. 오류 전후 세 조회가 모두 같아야 합니다.
4. 보정하거나 반올림한 값을 장비에 쓰고 나중에 오류를 출력하는 순서가 아닌지 확인합니다.

## E3 장면 검증과 상태 보존

1. 지원하지 않는 장면을 OFF로 대신 실행하지 않습니다. `ERROR scene`만 반환합니다.
2. 이름 검증을 마친 뒤 장면 명령을 구성합니다. 임시 기본값으로 장비를 바꾼 뒤 오류를 판단하지 마세요.
3. 정상 장면 → 잘못된 장면 → 취소를 실행합니다. 잘못된 장면은 이력에 들어가지 않으므로 취소 대상은 마지막 정상 장면입니다.

## I1 통합 흐름

1. 입력 반복문 밖에 하나의 `RoomFacade`가 존재해야 합니다. 명령마다 새 Facade를 만들면 상태가 초기화됩니다. 제공된 `main`을 유지합니다.
2. STATUS, RAW, HISTORY는 읽기 전용입니다. 조회 과정에서 명령 실행이나 이력 추가를 하지 않습니다.
3. 취소 후 새 작업을 하면 남아 있는 이력 뒤에 새 작업을 추가합니다. 이미 취소한 명령이 다시 나타나면 안 됩니다. REDO는 없습니다.
4. 출력의 공백, 대소문자, 줄 개수도 계약입니다. 로컬 결과를 예제와 줄별로 비교합니다. 로그는 제출 전에 제거합니다.

## 컴파일과 실행 문제 점검

- `std::unique_ptr`를 복사할 수 없다는 오류가 나면 소유권을 넘기는 부분과 `std::move`를 확인합니다. 여러 이력에 같은 명령을 공유하는 구조로 바꾸지 않습니다.
- 추상 클래스 인스턴스를 만들 수 없으면 `execute`, `undo`, `setLevel`, `level`의 선언과 `override`, `const`가 인터페이스와 일치하는지 확인합니다.
- 참조가 초기화되지 않았다는 오류가 나면 생성자의 초기화 목록을 확인합니다. 참조 대상인 장비는 Adapter와 명령보다 오래 살아 있어야 합니다.
- Adapter의 `level()`과 Facade의 조회 함수에서 장비를 바꾸지 않습니다.
- 취소 시 종료되면 빈 이력 접근, 제거한 객체 접근, 지역 객체를 가리키는 참조를 먼저 확인합니다.
- `ERROR incomplete`가 나오면 실행 경로에 남은 TODO 예외를 찾습니다. 채점 힌트에 나온 클래스만이 유일한 원인이라고 가정하지 않습니다.
- 컴파일에 실패한 경우 기능 항목은 미검사입니다. 먼저 로컬 컴파일을 성공시킨 뒤 출력 비교를 시작합니다.

## 구조를 스스로 확인하는 질문

- 새 장비가 추가되어도 `SetLevelCommand`와 이력 코드를 그대로 사용할 수 있는가?
- 장비의 내부 단위가 바뀌었을 때 Adapter 외의 코드를 불필요하게 수정해야 하는가?
- 새로운 장면을 추가할 때 `main`에 장비 제어 순서를 추가해야 하는가?
- 현재 값, 이전 값, 취소 순서를 각각 어떤 객체가 소유하는지 설명할 수 있는가?

이 질문은 구조 검토용입니다. 자동 기능 점수에 별도 가산하지 않습니다.
