# Next.js 0~2단계 검증 기록

검증일: 2026-10-10. 운영 서버나 실제 학생 DB가 아닌 로컬 합성 자료로 시험했습니다. 이 기록은 배포 승인이나 학생 코드 실행 격리 검증을 대신하지 않습니다.

## 구현 범위

- 공개 화면 셸 `/app`, 교수자 인증 진입·bootstrap·담당 수업·결과 조회 API.
- 과제·학생·제출 상태 필터, 서버 페이지 분할, 이번 제출 점수와 이전 공개 최고점 분리.
- 한 DB snapshot의 집계·목록·버전. 데이터가 변경된 다음 페이지·주기 조회는 `409 result_set_changed`로 거절하며 사용자가 최신 목록을 반영합니다.
- CSV의 기능 해제·수업 제외를 다음 API 요청부터 적용. 누락·잘못된 CSV는 신규 API만 닫습니다.
- 기존 등록·수정·삭제·코드·루브릭 화면으로 이동하는 링크. 새 UI의 쓰기 기능, 학생 화면과 IDE 변경은 없습니다.

## 자동 시험

Python API 시험은 공유·개인 인증, 타 수업 접근, 기능 해제, 안전한 복귀 주소, 요청 필터, 현재 0점/이전 최고점, 미확정 점수, 수강 상태·과제 상태, 페이지 버전 충돌을 검사합니다. 별도 실제 프로세스 시험은 실행 중인 포털의 CSV를 수정한 뒤 신규 API 차단, 구 교수자 화면과 학생 API 유지까지 확인합니다.

웹 단위 시험은 응답 계약·숫자 범위·중복 행·링크 범위, 요청 옵션, 조회 조건과 버전, 인증 종료 상태를 검사합니다. 개발 서버가 아닌 production build로 브라우저 검증을 수행합니다.

## 부하 시험 방법

[합성 HTTP 시험](../../scripts/check_nextjs_pilot.py)은 임시 폴더와 loopback 주소만 사용합니다.

1. 학생 25명이 실제 HTTP로 로그인 → 수령 코드 → IDE 토큰 → 다운로드 → 제출 접수 → 해당 제출 상태 조회를 동시에 진행합니다.
2. 교수자 2명이 각각 허용된 수업을 동시에 조회합니다. 학생별 제출 ID가 서로 다르고 정확히 25건 접수되었는지 확인합니다.
3. 그 후 학생 25명 × 과제 20개 × 10회인 5,000개 제출 이력을 합성합니다. 현재 점수는 0점, 이전 공개 최고점은 100점으로 고정합니다.
4. 기존 전체 HTML, 기존 HTML 조각 JSON, 신규 20행 JSON을 각각 한 번 예열한 후 순서를 번갈아 10회 측정합니다. p95는 nearest-rank 방식입니다.

계획의 `4분반 × 25명 × 10과제 × 5회`와 달리 이번 대용량 조회는 **한 수업에 5,000건을 집중**한 조건입니다. 권한 시험에는 별도 수업을 쓰지만, 4분반 부하 목표 전체를 통과한 것으로 간주하지 않습니다.

기존 응답은 500행 전체, 신규 응답은 20행 한 페이지입니다. 응답 바이트 감소에는 페이지 분할 효과가 포함됩니다. 모든 행을 한 번에 내려주는 동일 작업의 순수 직렬화 성능 비교가 아닙니다. 비밀번호 검증을 포함한 전체 학생 요청 통계와 제출·상태 조회 통계를 구분합니다.

**측정하지 않은 항목:** 실제 채점 워커 실행·큐 대기·컴파일 시간, 운영 서버 용량, WAN·실습실 NAT, 기존 버전 대비 접수 지연 변화, 브라우저 초기 표시와 새 결과 알림의 엄밀한 p95.

## 브라우저 시험 방법

[브라우저 검사](../../scripts/check_nextjs_browser.cjs)는 production Next.js와 합성 Python 포털 앞에 일시적인 로컬 GET 전용 프록시를 두어 같은 origin의 인증·결과 조회를 시험합니다. 원격 주소나 실제 학생 자료에는 접근하지 않습니다.

- 실제 API: Python 인증 entry의 303 복귀, bootstrap, 수업별 결과, 20행 페이지, 학생·상태 필터, 수업 전환, 이번 0점과 이전 최고점 100점.
- 화면 동작: 바뀌지 않은 주기 조회의 행·포커스·스크롤 유지, 오프라인 중지·복구, 이전 수업의 늦은 응답 무시, 자동 확인 전환 시 목록 유지.
- 합성 실패 응답: 409 알림과 명시적 갱신, 401·403에서 데이터 제거와 자동 조회 중단. 이 항목은 브라우저에서 응답을 의도적으로 대체하며, 실제 인가 검사는 Python 시험과 구분합니다.
- production의 nonce CSP, 캐시 금지, 공개 HTML의 학생 자료 미포함, 브라우저 영구 저장소 미사용, 좁은 화면·테마를 확인합니다.

자동화에 합성 Basic 자격을 제공한 시험은 브라우저의 실제 비밀번호 입력 대화상자 사용성을 검증하지 않습니다. Edge·Safari 새 프로필과 배포 Nginx/TLS는 별도 인수 대상입니다.

최종 화면은 320·375·768·1024·1440px 각각의 밝은·어두운 테마에서 페이지 가로 넘침이 없었습니다. 고대비 데스크톱과 모바일 점수 카드도 이미지로 확인했습니다. production CSP는 nonce 없는 스크립트를 원문 HTML에 삽입하는 별도 합성 시험에서 실행을 차단하고 브라우저의 거절 메시지를 확인했습니다. 개발 도구가 주입하는 스크립트의 동작을 일반 문서의 CSP 시험으로 혼동하지 않습니다.

시험 중 발견해 수정한 항목은 다음과 같습니다.

- `basePath`의 맨 처음 `/app`에도 CSP를 적용하도록 명시적 root matcher 추가.
- 미인증 Basic 요청이 브라우저에서 대기할 때도 교수자 인증 링크를 즉시 제공하고 15초 후 연결 오류 안내.
- 자동 확인 전환 시 읽던 목록과 409 변경 알림을 유지.
- 입력·선택·버튼 경계를 장식용 구분선과 분리해 밝은·어두운 테마의 식별성 보완.

## 재실행

저장소 루트에서 실행합니다. 테스트는 임시 DB를 사용하며 운영 CSV를 전달하지 않습니다.

```sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/check_nextjs_pilot.py --samples 10 --output .cache/nextjs-pilot-qa/load-report.json
```

Node.js 24 환경에서 웹을 검증합니다.

```sh
cd web
npm ci
npm run typecheck
npm test
npm run build
npm audit --omit=dev
```

브라우저 시험은 세 터미널을 사용합니다. 18081·18082가 다른 서버에 사용 중이면 그 프로세스를 임의 종료하지 말고 별도 시험 포트를 지정합니다.

```sh
# 터미널 1: 저장소 루트. 합성 자료 외의 입력이 없는 임시 포털입니다.
.venv/bin/python scripts/check_nextjs_pilot.py --serve --port 18081

# 터미널 2: web 디렉터리. 먼저 production build가 있어야 합니다.
npm start

# 터미널 3: 저장소 루트. 마지막 두 인자는 설치한 Playwright 모듈과 Chrome 실행 파일 경로입니다.
node scripts/check_nextjs_browser.cjs http://127.0.0.1:18082 http://127.0.0.1:18081 .cache/nextjs-pilot-qa /absolute/path/to/playwright /absolute/path/to/chrome
```

시험이 끝나면 시험용 포털과 Next.js 프로세스를 종료합니다. 보고서와 합성 화면 이미지는 Git에서 제외된 `.cache/nextjs-pilot-qa/`에 생성됩니다. 이 스크립트는 배포 Nginx를 시작하거나 설정을 바꾸지 않습니다.

## 운영 공개 전 남은 조건

1. 실제 Nginx의 설정 검사와 HTTPS 경로·보안 헤더·정적 자산 확인. Node 중단 시 프록시의 구 화면 복귀 안내 확인.
2. Chrome·Edge·Safari 새 프로필의 실제 Basic 입력 → 복귀 → 재인증, 공용 PC 계정 전환 확인.
3. 실제 실습실 NAT·서버 사양에서 목표 부하, 4분반 자료, 접수 지연의 전후 비교와 초기 표시·알림 시간 측정.
4. Windows의 Visual Studio 및 VS Code, WSL2의 기존 수령·다운로드·제출·결과 흐름 확인.
5. 시험 수업만 허용하고 실제 개인정보가 로그나 캐시에 남지 않는지 확인한 뒤 공개 승인.

실행·중단 방법은 [파일럿 운영 안내](../operations/nextjs-pilot.md), 다음 단계 범위는 [전환 계획](../architecture/nextjs-migration-plan.md)을 따릅니다.
