# 항목별 디버깅 힌트

입출력과 패턴 구조의 전체 계약은 [README.md](README.md)에 있습니다. 아래 ID는 자동 채점의 평가 항목 ID와 같습니다. 서버 피드백에는 평가 기준이 항상 표시되고, 힌트는 해당 항목이 실패했을 때만 표시됩니다.

| ID | 확인할 부분 |
| --- | --- |
| F1 | `TextReport`에서 `title=`과 `;value=`의 철자·대소문자·구분자를 확인합니다. 필드 사이에 공백을 넣지 않았는지 점검합니다. |
| F2 | `CsvReport`의 필드 순서는 제목 다음 값입니다. 쉼표는 하나이며 `title=`이나 `value=` 접두어를 붙이지 않습니다. |
| A1 | `PlainTitle`은 이름을 그대로 돌려주고 `PlainValue`는 정수의 10진수 문자열을 만듭니다. 대괄호가 남거나 숫자 대신 문자 코드가 출력되는지 확인합니다. |
| A2 | `BracketTitle`과 `BracketValue`가 각 필드를 한 쌍의 대괄호로 감싸는지 확인합니다. 보고서 전체를 한 번만 감싸면 결과가 다릅니다. |
| A3 | `ReportService::make`에서 형식 선택과 테마 선택을 따로 점검합니다. CSV라고 PLAIN을 고정하거나 한 요청에서 서로 다른 테마의 제목·값 제품을 섞지 않았는지 확인합니다. |
| S1 | `Sequence::instance()`의 두 반환 참조가 같은 객체를 가리키는지 비교합니다. 호출마다 새 객체를 만드는지, 값으로 복사하여 반환하는지, 제공 인터페이스를 바꿨는지 점검합니다. |
| S2 | 각 `PRINT`에서 `ReportService`가 새로 만들어진다는 점을 확인합니다. 서비스의 멤버나 생성자에서 횟수를 초기화하지 않았는지, 정상 요청 한 번에 `next`를 두 번 호출하지 않았는지 점검합니다. |
| E1 | `FORMAT` 검사를 가장 먼저 합니다. 잘못된 형식·테마·값을 함께 넣었을 때 `ERROR format` 하나만 나오는지 확인합니다. `make`는 오류 문자열을 반환해야 하며, `logic_error`를 던지면 고정된 `main`이 `ERROR incomplete`로 처리합니다. |
| E2 | 형식은 유효하게 두고 테마와 값을 함께 잘못 입력합니다. `ERROR theme`가 먼저 나와야 합니다. 오류 문자열의 대소문자도 확인합니다. |
| E3 | 경계값 네 개 `-1`, `0`, `100`, `101`을 각각 실행합니다. `0`과 `100`은 성공하고 나머지는 `ERROR value`여야 합니다. |
| E4 | `COUNT`, 잘못된 `PRINT`, `COUNT`, 정상 `PRINT` 순서로 실행합니다. 두 `COUNT`가 같아야 하며 정상 요청의 일련번호가 건너뛰지 않아야 합니다. 검증 전에 `next`를 호출하는지 확인합니다. |
| I1 | 정상 요청 사이에 `COUNT`, `SAME`, 오류 요청을 섞습니다. 조회가 횟수를 바꾸거나 이전 요청의 형식·테마가 다음 요청에 남는지 확인합니다. 매 명령의 출력 줄 수도 점검합니다. |

`ERROR incomplete`가 보이면 실행된 경로에 미완성 TODO가 남아 있는지 먼저 확인합니다. `SAME no`는 두 인스턴스의 동일성 확인이 실패한 결과입니다.

원인을 좁힐 때는 명령 수를 줄여 재현하되, 입력 첫 줄의 `Q`도 실제 명령 수에 맞춥니다. 디버깅 출력을 사용했다면 제출 전에 제거하고 원래 출력 형식을 다시 확인합니다. 이 문서는 전체 구현 코드를 제공하지 않습니다.
