# 교수자 UI/UX 단계 0: 화면 시안과 검토

2026-09-18 · **시안 제작·자동 검사 완료 — 승인 전 단계의 기록**.
이 시안 제작 단계에서는 실제 서버 UI 변경, API 연결, 데이터 이전, 배포를 하지 않았다.

후속 상태: 사용자 승인 후 [서버 1차 적용](../operations/instructor-ux-update.md)을 진행했다.
아래 시안 기록과 110개 검사는 당시 설계 검증이며 실제 서버 시험과 구분한다.

## 제작 범위

[개선 계획](../architecture/instructor-ui-ux-improvement-plan.md)의 단계 0을 위한
[상호작용 시안](../../design/prototypes/instructor-ux-wireframe.html)이다.
HTML fragment 형식이며 대화 미리보기에서 동작한다. 운영 서버 템플릿으로 바로 배포하는 파일이 아니다.
가상 학생·과제만 사용하며 네트워크 요청, 로그인, 파일 업로드, 실제 저장은 없다.

| 화면 | 확인할 변경 |
| --- | --- |
| 수업 개요 | 교과목·분반 선택 유지, 진행 과제와 다음 할 일, 미접수와 채점 대기 분리 |
| 과제 목록 | 웹·CLI 출처 통합, 검색·상태 필터, 모바일 카드 전환 |
| 과제 상세 | 검증 성공과 학생 공개 분리, 마감과 운영 제약, 연장 영향 미리보기 |
| 과제 준비 | 6단계 진행, 입력 오류와 값 보존, 미저장 이동 방지, 예제 자료·검증·공개 흐름 |
| 제출·결과 | 현재 채점 대기를 이전 최고점으로 대체하지 않음 |
| 학생 이력 | 접수 시각·코드 식별·점수·증감·비교 연결, 1→2차/2→3차 비교 전환 |

같은 화면을 데스크톱·모바일에 맞춰 재배치한다. 미리보기의 디자인 옵션으로
본문 간격과 데스크톱 카드 목록을 비교할 수 있다. 학생 관리·설정은 후속 시안 대상으로 표시했다.
전체 교과목 홈, CSV 등록, 실제 케이스 편집, 실시간 검증 조회, 운영 이력, 보고서·보관은 이번 시안 범위 밖이다.

## 직접 검토할 순서

1. `come2201 · 01분반`에서 **과제 관리**를 선택한다. CLI 과제가 같은 목록에 있는지 확인한다.
2. 검색하거나 공개 상태를 `초안`으로 바꾼다. 검색 결과 없음도 확인한다.
3. 옵저버 과제를 열고 검증·공개·마감이 구분되는지 확인한다.
4. **학생 제출 확인 → 가상 학생 A의 이력·코드 확인**을 선택한다.
   현재 제출은 채점 대기, 이전 최고점은 100점, 현재 증감은 미확정이다.
5. 코드 비교에서 `1차 → 2차`, `2차 → 3차`를 선택한다.
6. **과제 → 새 과제 등록**에서 제목을 비우거나 과거 마감을 입력한다.
   오류 메시지, 입력 보존, 수정 중 수업 전환 차단을 확인한다.
7. 예제 파일 등록 후 6단계를 진행한다. 공개 완료 시연도 실제 서버를 변경하지 않는다.
8. `02분반`으로 전환한다. 이전 분반 과제·학생이 남지 않고 빈 목록이 표시되어야 한다.

예시 기준 시각은 2026-09-18 15:22 KST로 고정했다. 실제 현재 시각에 따라 시안 결과가 달라지지 않는다.
연장 미리보기·검증 결과는 UX 설명용이며 실제 서버 정책·채점 정확성 시험이 아니다.

## 자동 검사

[검사 스크립트](../../scripts/check_instructor_wireframe.cjs)는 인증 프로필을 사용하지 않고
시안만 새 브라우저에 읽어 검사한다. 모든 네트워크 요청을 차단하고 요청이 발생하면 실패한다.

실행 형식(Playwright와 Chromium 또는 Chrome이 설치된 개발 환경):

```sh
node scripts/check_instructor_wireframe.cjs OUTPUT_DIR PLAYWRIGHT_MODULE [CHROME_BINARY]
```

`OUTPUT_DIR`는 미리 만든 시험 전용 폴더, `PLAYWRIGHT_MODULE`은 `playwright` 또는 설치된 모듈의 절대 경로다.
스크린샷에는 가상 데이터만 포함된다. 검사 도구 설치를 운영 서버 의존성에 추가하지 않는다.

2026-09-18 실행 결과:

- 320, 375, 768, 1024, 1440px × 밝은/어두운 테마 × 11개 화면·작성 단계: **110개 레이아웃 검사 통과**.
- 화면 넘침·컨트롤 잘림, 검색·필터, 마감 오류, 일반 입력 보존, 분반 전환,
  6단계 이동, 현재/최고 점수 구분, 코드 비교 전환 검사 통과.
- JavaScript 실행 오류 0건, 네트워크 요청 0건.
- 데스크톱 과제 목록과 모바일 어두운 테마 학생 이력 스크린샷을 시각 검토했다.

이는 합성 시안 검사다. 실제 서버의 인증·권한·CSRF·SQLite 동시성·채점·배포 회귀 시험은
P0/P1 서버 구현 이후 별도로 수행한다. 스크린리더·실제 교수자 사용성 평가는 아직 하지 않았다.

## 다음 단계로 넘길 사항

- 화면 구성 확인 후 P0: 공개 상태 문구, 과제 목록 반응형, 마감 안내, 입력 오류 복구를 실제 서버에 적용한다.
- P1에서 단일 운영 홈과 통합 조회 모델, 저장 상태·검증 갱신을 연결한다.
- 기존 공유 교수자 인증과 실행 권한은 그대로 유지한다. 시안의 제약 안내를 실제 권한 구현으로 오인하지 않는다.
- 삭제·보관·최종 성적 정책은 시안에 맞추어 임의 변경하지 않는다.
