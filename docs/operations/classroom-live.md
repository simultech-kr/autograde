# 교수자 실습 교실 실시간 상태 운영

교수자는 학생 카드에서 IDE 연결, 최근 과제 활동, 선택한 과제의 공식 제출 여부를 확인합니다.
카드를 누르면 최근 활동, 제출 코드 버전, 이번 점수와 이전 최고점을 상세 팝업에서 확인합니다.
학생 상태는 SQLite 원장과 인증된 IDE 보고를 기반으로 갱신하며, 시연용 데이터는 사용하지 않습니다.
팝업의 **IDE 요청**에서는 공지·과제 열기·자료 동기화·환경 점검·저장 제출을 요청합니다.
학생이 IDE에서 확인하기 전에는 작업을 실행하지 않습니다.

## 화면 진입

- 기존 교수자 CMS: **수업 선택 → 실습 교실**.
  COME2201 주소는 `/courses/come2201/instructor/classroom`입니다.
- Next.js: **실습 교실** 또는 `/app/classroom?course_key=come2201`.
  Next.js 빌드·프로세스·프록시가 연결되어 있어야 합니다.
- 공식 제출을 확인할 실습 과제를 선택합니다. 과제 미선택 상태는 미제출로 집계하지 않습니다.
- 학생 이름·학번 검색과 상태 필터를 사용할 수 있습니다. 카드는 학번 순서를 유지하며
  화면 폭에 맞춰 배치됩니다. 상태는 색상 외에도 아이콘과 문구로 표시합니다.
- 팝업은 닫기 버튼 또는 Escape로 닫습니다. **IDE 요청** 탭은 요청 전송과 처리 이력을 제공합니다.

두 화면 모두 교수자 인증, 담당 수업 권한, 서명된 브라우저 세션이 필요합니다.
실습 교실의 `classroom.read` API는 기존 Next.js 결과 화면 활성화 스위치와 독립적입니다.
`instructor_next_results_enabled,false`는 실습 교실을 끄는 설정이 아닙니다.
기존 교수자 웹 자체는 `instructor_assignment_web_enabled,true`가 필요합니다.

## 학생 IDE 동작

VS Code 확장 **0.5.11** 또는 해당 확장을 내장한 Autograde IDE를 사용합니다.
학생이 수령 코드로 인증하고 수락한 과제 폴더를 열어 연결하면 활동 보고를 시작합니다.
Workspace Trust가 허용되지 않은 폴더, 연결되지 않은 임의 폴더에는 보고를 시작하지 않습니다.

활동 보고가 없을 때 IDE는 20초마다 연결 신호를 보냅니다. 과제 열기·파일 저장·제출 시작·제출 요청 완료도 보고합니다.
연속 저장은 5초 단위로 병합하며 네트워크 오류 시 제한된 재시도를 수행합니다.
학생에게 로그인 후 공유 범위를 안내하고 학습 홈에 보고 상태를 표시합니다.
계정·서버 변경과 로그아웃 시 이전 보고 대기열은 폐기합니다.

수집 항목은 과제 ID, 활동 종류, 서버 수신 시각, 운영체제 종류, WSL 등 원격 환경 종류입니다.
활동 보고에는 파일명·전체 경로·소스 코드·키 입력·화면·다른 앱 활동을 넣지 않습니다.
코드 업로드는 기존 공식 제출 흐름을 사용합니다. Visual Studio 2022/2026의 연결 신호 발송·IDE 요청 처리는
이번 구현에 포함하지 않으며, 그 IDE로 접수된 공식 제출·점수는 공통 서버 원장에서 표시합니다.

## 교수자 요청과 학생 확인

1. 실습 교실에서 대상 학생 카드를 열고 **IDE 요청** 탭을 선택합니다.
2. 요청 종류와 안내문을 입력합니다. 공지 외 요청에는 과제 선택이 필요합니다.
3. 전송 후 팝업의 요청 이력에서 수신·학생 확인·처리 결과를 확인합니다.
4. 학생은 IDE 확인창에서 **수락 또는 확인**, **거절** 중 하나를 선택합니다. 창을 닫아도 거절로 처리합니다.
5. 수락이 서버에 기록된 뒤에만 작업을 실행하고, 결과를 서버에 회신합니다.

| 요청 | 수락 후 실행 | 완료 기준 |
| --- | --- | --- |
| 공지 전달 | 안내문 확인 | 학생이 확인 버튼을 누르고 확인 결과를 서버에 전달 |
| 과제 열기 | 현재 인증된 기존 bundle 과제의 탐색기·설명 또는 소스 미리보기 열기 | IDE가 열기 처리를 마치고 결과 보고 |
| 자료 동기화 | 학생이 공개된 Git 콘텐츠와 수신 방식을 선택하고 변경 파일 수신 | 캐시 수신·검증 또는 선택한 내보내기 완료. 목록을 여는 것만으로 완료하지 않음 |
| 환경 점검 | 서버 통신·과제 폴더·운영체제·원격 환경 확인 | 점검 결과 회신. 컴파일러는 미점검으로 표시하며 실행·설치하지 않음 |
| 저장·제출 | 현재 과제의 미저장 파일 확인·저장 후 본인 작업물 제출 확인 | 요청 수락 이후 같은 학생·과제의 실제 서버 접수번호 확인 |

현재 연결·인증된 과제만 처리합니다. 다른 과제를 지정하면 학생이 해당 과제의 새 수령 코드로
연결할 때까지 대기합니다. 서버가 학생의 인증 범위를 바꾸거나 임의 폴더를 열지는 않습니다.
공지 수신을 포함한 모든 요청에 연결된 과제 폴더와 Workspace Trust가 필요합니다. 과제 열기·저장 제출은
현재 bundle 방식에 한정하며 Git 전용 과제는 미지원 결과를 돌려줍니다.
자료 동기화는 Git 콘텐츠 CMS 대상이며 기존 개인 PDF·ZIP의 강제 다운로드 기능은 아닙니다.

| 요청 상태 | 해석 |
| --- | --- |
| 대기 | 서버가 요청을 보관 중. 학생이 봤다는 뜻이 아님 |
| IDE 수신 | IDE가 조회하여 배정받음. 학생 확인 대기 |
| 학생 수락 | 학생이 수락했고 서버가 확인함. 완료 또는 제출 접수와 다름 |
| 완료 | 해당 작업의 완료 결과를 서버가 수신함 |
| 거절 | 학생이 거절하거나 확인창을 닫음. 작업하지 않음 |
| 실패 | 취소·폴더 문제·미지원·통신 문제 등으로 완료하지 못함 |
| 만료 | 생성 후 10분 경과. 수락 이후 만료는 처리 결과 미확인으로 해석 |

학생당 대기·수신·수락 요청은 최대 5개, 새 요청은 시간당 30개로 제한합니다.
IDE는 평상시 약 5초마다 요청을 확인하고 오류 시 간격을 늘립니다. 교수자에게는 기존 SSE로
상태 변경을 전달하며 팝업에는 선택 과제와 무관하게 해당 학생·수업의 최근 20개 요청을 표시합니다.

전송 응답이 유실되면 같은 요청 식별자로 다시 확인하여 중복 요청을 만들지 않습니다.
수락 응답이나 완료 회신이 유실되어도 작업을 자동 재실행하지 않습니다. IDE를 종료하거나
학생·서버·과제·폴더를 바꾸면 기존 요청을 새 연결에서 이어 실행하지 않습니다.
수락 후 만료는 로컬 작업이 취소되었다는 증명이 아닙니다. 제출 접수 여부와 요청 처리 상태를
따로 확인한 뒤 필요할 때만 새 요청을 보내세요.

환경 점검·열기·동기화 결과는 IDE가 보고한 상태이며 변조 방지 증명이 아닙니다.
저장·제출 완료만 서버의 공식 접수 원장과 추가 대조합니다. 교수자의 서버 권한만으로
학생 동의를 생략하거나 임의 명령·경로·URL을 실행할 수는 없습니다.

## 상태 해석

| 표시 | 의미 |
| --- | --- |
| IDE 연결 | 유효한 학생 세션이 있고 최근 연결 신호가 45초 이내 |
| 신호 지연 | 마지막 신호가 45초를 넘고 120초 이내 |
| 연결 끊김 | 마지막 신호가 120초를 넘거나 세션 종료·인증 만료·인증 취소 |
| 연결 기록 없음 | 서버에 수신된 IDE 연결 보고 기록이 아직 없음. 이전 확장 사용 여부도 확인 |
| 공식 제출 | 선택한 과제에 서버가 접수한 제출 기록이 있음 |
| 배정 대상 아님 | 학생별 Git 과제에서 해당 학생에게 배정되지 않은 과제를 선택함 |

IDE 비정상 종료와 인터넷 단절은 즉시 감지할 수 없으므로 신호 만료로 판정합니다.
교수자 브라우저의 실시간 연결이 끊어지면 마지막 확인값과 재연결 안내를 유지합니다.
브라우저 연결 실패를 학생 전원의 연결 끊김으로 바꾸지 않습니다.
연결·저장 횟수는 활동 관측값이며 출석·집중도·성취도 판정 근거를 대신하지 않습니다.

새 제출이 접수되면 이전 점수를 이번 점수로 표시하지 않고 채점 대기 상태로 바꿉니다.
이전 최고점은 최신 제출을 제외한 공개된 과거 채점 결과에서 계산합니다.
과거 공식 제출이 있는 학생의 새 제출 요청이 거절되어도 기존 공식 제출 사실은 유지합니다.
클라이언트의 제출 완료 보고만으로 공식 제출 표시나 점수를 만들지 않습니다.

팝업의 코드 버전은 서버 접수 원장에 기록된 bundle 해시 또는 Git commit SHA입니다.
접수 기록 표시는 저장 파일의 현재 무결성 확인이나 아직 제출하지 않은 코드의 자동 백업을
뜻하지 않습니다. 활동 로그에는 최근 100건, 제출 이력에는 최근 20건을 표시합니다.
이전 최고점은 화면의 20건 제한과 무관하게 전체 공개 이력에서 조회합니다.

## 서버 적용

기존 설치 경로와 운영 CSV를 유지합니다. 학생 명단을 다시 가져오거나 DB를 초기화하지 않습니다.
적용 전 DB와 설정을 백업하고 진행 중인 제출이 없는 시간에 서버를 재시작합니다.
코드가 원격 저장소에 반영된 뒤 운영자가 정상적인 Git 업데이트 절차를 수행합니다.

```sh
.venv/bin/python -m pip install -e '.[dev]'
```

기존 서비스 관리 방식으로 Python 포털·API를 재시작합니다. 직접 실행하는 환경에서는
다음 예제의 CSV 경로를 실제 운영 경로로 바꿉니다. 기존 서비스와 동시에 실행하지 않습니다.

```sh
.venv/bin/autograde-pilot --config pilot/portal.https.local.csv
```

시작 시 SQLite 스키마 22로 확장합니다. 기존 연결·활동 테이블에 더해
`classroom_commands`, `classroom_command_events`에 요청과 상태 전이를 저장합니다.
연결 신호는 클라이언트별 최신 행을 갱신하고, 연결 신호 외 활동은 감사 기록으로 보존합니다.
과목 초기화에는 해당 과목의 활동·연결·IDE 요청 데이터도 포함됩니다. 이번 단계에서는 자동 보관·삭제
정책을 추가하지 않았으므로 운영자는 수업 종료 후 보존 기간과 DB 백업 정책을 정해야 합니다.

Next.js 화면을 사용할 때는 Node.js 24 환경에서 다음과 같이 다시 빌드하고 기존 웹 서비스를
재시작합니다. 상세 프록시·서비스 구성은 [Next.js 운영 안내](nextjs-pilot.md)를 따릅니다.
이번 변경은 Next.js를 16.4.1로 고정합니다. 16.4.0의 보안 수정이 포함된
[공식 패치 릴리스](https://github.com/vercel/next.js/releases/tag/v16.4.1)이며 `npm ci`로 lockfile을 적용합니다.

```sh
cd web
npm ci
npm run build
```

학생 VS Code에는 `extensions/vscode/autograde-vscode-0.5.11.vsix`를 설치합니다.
Code-OSS 개발 설치본은 [IDE 준비 안내](autograde-ide-poc.md)에 따라 새 overlay를 적용합니다.
확장 호스트를 다시 시작하면 기존 메모리 인증은 사라지므로 새 수령 코드로 연결합니다.
학생 확장 버전에 따라 연결·저장 활동과 IDE 요청 지원 범위가 달라집니다.
0.5.10 확장은 연결·활동만 보고하므로 IDE 제어 요청을 받으려면 0.5.11로 갱신해야 합니다.

## 실시간 프록시 연결

브라우저는 webhook 수신 서버를 열지 않습니다. Python 웹 서버가 **SSE**로 상태를 전달합니다.
교실 탭당 스트림 하나를 사용하며 약 2초마다 원장 변경을 확인하고 변경된 전체 상태를 보냅니다.
30초마다 스트림을 종료하고 브라우저가 자동 재연결하여 최신 상태를 다시 확인합니다.
열린 스트림도 수업 권한·교수자 세션을 재검증하며 권한 취소 시 화면의 학생 정보를 비웁니다.

[포털 Nginx 예제](../../config/nginx-autograde-portal.conf.example)의 20010 서버에 있는
`/instructor/api/v1/courses/.../classroom/events` 경로를 실제 설정에 반영합니다.
Next.js include를 사용한다면 [Next.js 경로 예제](../../config/nginx-autograde-next.locations.conf.example)의
`^~ /instructor/api/v1/`에도 아래 옵션이 필요합니다. 해당 prefix가 정규식 경로보다 우선합니다.

```nginx
proxy_http_version 1.1;
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 45s;
```

IDE 요청 생성은 `/instructor/api/v1/courses/{course}/classroom/students/{student}/commands`의
JSON POST입니다. 기존 API 경로를 GET 전용으로 제한한 별도 프록시 규칙이 있다면 이 경로에만
POST를 허용합니다. 서버는 Basic 인증·담당 수업 권한·활성 수업·동일 Origin·CSRF를 모두 검사합니다.
학생의 요청 조회·응답은 기존 20000 API의 `/v1/classroom/commands/...`를 사용하므로 새 외부 포트가 필요하지 않습니다.

기존 HTTPS 인증서·도메인·포트를 유지하고 전체 설정 파일을 예제로 덮어쓰지 않습니다.
설정 검사가 성공했을 때만 적용합니다.

```sh
sudo nginx -t
sudo nginx -s reload
```

## 인수 확인과 장애 대응

1. 교수자가 수업의 실습 교실을 열고 시험 과제를 선택합니다.
2. 전용 테스트 학생이 새 확장으로 인증하고 해당 과제 폴더를 엽니다. 연결 상태와 환경을 확인합니다.
3. 과제 파일을 저장하고 최근 활동이 갱신되는지 확인합니다.
4. 제출하면 공식 접수·채점 대기, 채점 후 이번 점수로 바뀌는지 확인합니다.
5. 수정 후 재제출하여 이번 점수가 대기로 바뀌고 이전 최고점은 남는지 확인합니다.
6. IDE를 종료하고 120초 이후 연결 끊김 표시를 확인합니다.
7. 교수자 화면 새로고침·과제 전환·상세 팝업·좁은 창·어두운 테마를 확인합니다.
8. IDE 요청 5종을 보내고 학생 수락·거절, 동기화 취소, 저장 제출의 실제 접수번호를 확인합니다.
9. 학생 IDE를 닫은 상태에서는 완료로 바뀌지 않는지, 10분 뒤 만료되는지 확인합니다.
