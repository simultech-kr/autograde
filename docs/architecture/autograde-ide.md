# Autograde 전용 IDE 개념연구 설계

## 결정과 범위

2026-10-22 결정: 소규모 수업의 개념연구에서는 기존 Python 서버·CSV 설정·SQLite를 유지한다.
Code-OSS에 기존 Autograde 확장을 내장한 **Autograde IDE**를 만들고, 학생의 연결·과제
이어하기·다운로드·제출·결과 확인을 학습 홈에서 시작할 수 있게 한다. 서버 API와 제출·성적
원장은 변경하지 않는다.

PostgreSQL은 향후 Docker 기반 서비스를 운영할 때 도입을 검토한다. Docker가 PostgreSQL의
기술적 전제라는 뜻은 아니며, 이번 연구의 설치·운영 범위를 늘리지 않기 위한 단계 구분이다.
현재 DB를 이전하거나 PostgreSQL 의존성·접속 설정을 추가하지 않는다.

1단계는 개발용 Code-OSS 구성과 학습 흐름 통합이다. 학생에게 배포 가능한 서명된 설치 파일,
자동 업데이트 서버, AI 사용 강제 차단, OS·네트워크 통제는 완료 범위에 넣지 않는다.
직접 실행은 [개념연구 실행 안내](../operations/autograde-ide-poc.md)를 따른다.

## 구성요소와 경계

```text
Autograde IDE
├─ 고정한 Code-OSS 소스와 작은 제품 설정
├─ 내장 Autograde 확장
│  ├─ 학습 홈과 서버 연결 상태
│  ├─ 기존 과제 수락·다운로드·이어하기
│  └─ 제출·현재 결과·이전 최고점·제출 이력
└─ 운영체제의 개발 도구
   └─ 컴파일러·디버거·언어 도구는 별도 설치 및 검증
          │ 기존 HTTPS 학생 API
          ▼
기존 Autograde 서버
├─ 인증·수업·과제·제출·채점 서비스
├─ SQLite 원장
└─ ZIP·PDF·제출 원본 파일 저장소
```

제품 설정과 빌드 도구는 `ide/code-oss/`, 학습 기능은 `extensions/vscode/`에 둔다.
Code-OSS 원본을 이 저장소에 대량 복사하거나 편집기 핵심에 인증·채점 로직을 다시 구현하지
않는다. 고정한 upstream 소스에 제품 이름·별도 사용자 데이터 경로와 내장 확장을 적용한다.
준비 도구는 대상 소스와 확장의 상태를 검사하며 기존 VS Code 설치·학생 작업 폴더를 바꾸지 않는다.
개발 실행은 별도 사용자·확장·공유 데이터 경로를 사용한다. 처음 생성하는 프로필에만 학습용
기본 설정을 기록하며 기존 사용자 설정을 덮어쓰지 않는다. 초기 설정은 수정 가능한 값이고
서버가 강제하는 시험 정책이 아니다.

인증과 접근 권한의 최종 판정은 계속 서버가 한다. IDE 화면·로컬 과제 연결 파일·제품 이름은
학생 본인이나 과제 제출 권한을 증명하지 않는다. 사용자 데이터 경로를 나누는 것도 보안 격리는
아니며, 공용 좌석의 작업 파일 정리와 OS 계정 관리 절차가 별도로 필요하다.

## 학생의 학습 흐름

학습 홈은 별도 로그인·제출 구현 대신 기존 확장 명령을 호출한다. 기존 VS Code 확장에서도
동일한 홈을 사용할 수 있지만, 전용 IDE 여부와 AI 통제 수준을 혼동시키지 않는다.
`Autograde IDE`의 폴더·작업 영역·열린 탭이 없는 창에서만 홈을 자동 표시한다. 기존 작업 창은
가로채지 않으며 사이드바의 학습 홈 또는 `Autograde: Open Learning Home` 명령으로 다시 연다.
홈은 고정한 8개 동작만 전달하고 웹 화면이 임의 명령·인자·URL을 실행하게 하지 않는다.

| 상황 | 홈에서 수행할 작업 | 유지해야 할 조건 |
| --- | --- | --- |
| 처음 시작 | 서버 주소 확인 → 수업 폴더 선택 → 수령 코드 입력 | 학생 웹의 인증·일회용 코드 흐름을 재사용한다. |
| 새 과제 수령 | 다운로드 → 과제 설명·소스 열기 | 기존 답안을 덮어쓰지 않는다. |
| IDE 재시작 | 기존 작업 폴더 열기 → 새 코드로 재연결 | 파일 보존과 재인증을 구분한다. |
| 다른 과제로 전환 | 수락 이력 확인 → 대상 과제 재연결 → 폴더 확인 | 다른 과제 소스를 현재 과제에 자동 제출하지 않는다. |
| 제출 | 대상 과제·저장 파일 확인 → 접수 → 채점 대기 | 접수 성공을 채점 완료로 표시하지 않는다. |
| 결과 확인 | 현재 제출 결과 → 수정할 항목 → 이전 최고점·이력 | 과거 점수를 새 제출의 채점 결과로 대체하지 않는다. |
| 종료 | 로그아웃 → 공용 PC 작업 자료 정리 | 비밀번호·코드·세션 토큰을 디스크에 저장하지 않는다. |

현재 과제 권한과 로컬 작업 폴더의 차이, 연결 끊김·폴더 이동·미저장 파일 처리 기준은
[과제 이어하기·전환·재제출](../operations/assignment-workspace-lifecycle.md)을 그대로 따른다.
홈은 이 계약을 새로 정의하지 않는다.

## AI 통제와 시험 환경의 분리

1단계의 AI 관련 기본 설정은 불필요한 내장 AI 진입점을 줄이는 용도다. 사용자가 변경할 수 있는
기본값, 확장 갤러리 비설정, 전용 제품 이름을 시험 보안 경계로 취급하지 않는다.
IDE 내부에서 기능이 보이지 않아도 브라우저·터미널·다른 프로그램·다른 기기의 AI 사용은 가능하다.
고정 소스 1.143.0의 시작에 필요한 `defaultChatAgent` 메타데이터는 보존하고, 기본 설정과 실행
플래그로 내장 AI 진입을 비활성화한다. 모든 AI 코드·접속 주소 제거 또는 네트워크 차단은 아니다.

| 단계 | 기능 | 상태와 한계 |
| --- | --- | --- |
| 1단계 | Autograde 내장·학습 홈·독립 개발용 제품 설정 | 이번 구현 범위. AI 미사용 증명을 제공하지 않는다. |
| 2단계 | 수업·과제별 정책, 승인한 확장 목록, IDE 내 제한 상태 표시 | 후속 설계. 정책 계약·변조·재연결·해제 절차를 먼저 정의한다. |
| 별도 시험 환경 | 관리 PC의 실행·OS·네트워크 통제 | 후속 독립 모듈. 학생 고지, 관리자 승인, 장애·종료 시 복구가 필요하다. |

화면 캡처, 비밀 모니터링, 브라우저 기록 수집, hosts 파일 변경, 방화벽 변경은 이번 IDE에
포함하지 않는다. 연결·정책 적용 상태만으로 부정행위 여부를 자동 판정하지 않는다.
서버 측 학생 코드 격리도 별개이며, IDE 내장으로 `pilot-local` 채점이 안전한 샌드박스가 되지 않는다.

## C와 C++ 개발 환경

일반 코드 완성·문법 검사·컴파일 오류 안내와 생성형 AI를 구분한다. 컴파일러나 언어 서버를
일괄 차단하지 않으며, clangd 등 사용 후보의 라이선스·배포 방식·런타임 요구사항을 확인한다.
이번 단계는 C/C++ 도구를 자동 설치하거나 모든 플랫폼에서의 디버깅을 보장하지 않는다.

- Linux/macOS의 로컬 편집·제출 흐름을 우선 검증한다. 실제 컴파일러와 디버거는 따로 검증한다.
- Windows 네이티브 C/C++ 도구 연결, MSVC 및 Windows 시스템 프로그래밍은 별도 인수 대상이다.
- Windows에서 WSL을 원격 작업 영역으로 여는 기능은 별도 인수 대상이다. 기존 Microsoft
  Remote WSL 확장을 fork 제품에 그대로 포함하거나 사용할 수 있다고 가정하지 않는다.
- Visual Studio 2022/2026 확장을 유지한다. Autograde IDE를 도입해도 Visual Studio의 솔루션·
  Windows 개발 도구 지원을 대체했다고 표시하지 않는다.

## 배포와 유지보수

Code-OSS 소스와 Microsoft Visual Studio Code 배포판은 구분한다. upstream 소스의 MIT
라이선스·저작권 표시와 필요한 제3자 고지를 보존한다. Microsoft Marketplace를 fork의 기본
확장 공급처로 연결하지 않고, 추가 확장은 개별 라이선스와 재배포 가능 여부를 검토한다.
[Microsoft의 제품·라이선스 설명](https://code.visualstudio.com/docs/supporting/faq#_licensing)을 기준으로
실제 배포 전에 조건을 다시 확인한다.

릴리스 후보에는 Code-OSS commit, Autograde 확장 버전과 해시, 제품 설정, 빌드 플랫폼을 기록한다.
개발용 실행과 서명·공증·설치·업데이트 검증을 구분한다. Microsoft 배포판의 업데이트 주소나
서명을 재사용하지 않는다. upstream 보안 패치 검토·적용, 확장 API 호환성 검사, 플랫폼별
패키징·코드 서명과 복구 가능한 업데이트 채널은 정식 배포 전 완료해야 한다.

## SES와 제품군 연결

전체 플랫폼의 [플러그인·SES 설계](platform-plugin-ses.md)에 `client.autograde_ide`를
클라이언트 대안으로 추가한다. SQLite와 다른 저장소 선택은 클라이언트 선택과 독립적이다.
IDE 제품 구성 때문에 수업의 저장소·인증·성적 정책을 바꾸지 않는다.

`policy.learning`과 `guard.exam_environment`는 후속 계약 후보다. 현행 SES JSON이나 CSV에
입력해 실행할 수 있는 플러그인이 아니며, `runtime_ready=true`로 선언하지 않는다.
1단계 준비 도구는 고정 제품 구성을 만드는 도구이지 SES pruning·승인·activation Host가 아니다.

## 인수 기준

1. 고정한 upstream 이외의 소스나 손상된 내장 확장을 준비 도구가 거절한다.
2. 기존 VS Code 프로필·설치와 분리하여 시작하며 내장 확장과 학습 홈을 확인할 수 있다.
3. 새 과제 다운로드와 기존 과제 이어하기가 동일한 서버 API·권한 검사를 거친다.
4. 현재 제출의 접수·채점 대기·결과와 이전 최고점을 구분한다.
5. 재시작·인증 만료·통신 오류·과제 전환 시 기존 소스를 보존하고 다음 행동을 안내한다.
6. 홈의 버튼·본문은 밝은 테마·어두운 테마와 좁은 창에서 읽을 수 있다.
7. IDE의 기본 설정을 AI 강제 차단·시험 인증으로 표시하지 않는다.

자동 검사, Code-OSS 전체 빌드, 실제 화면 조작, 플랫폼별 설치·채점 서버 연동은 서로 다른
검증 항목이다. 실행 안내에 각 상태를 기록하고 하나의 통과를 전체 배포 완료로 해석하지 않는다.
