## 문제 상황과 학습 목표

컨설팅 팀은 제목·페이지 수를 정해 보고서를 만들고 기존 보고서를 복제해 고객별 섹션을 추가합니다. 공통 보고서를 복제해 고객 A의 제목을 바꾸거나 고객 B의 섹션을 추가하더라도 원본과 다른 고객의 보고서는 그대로 남아야 합니다. 보고서가 만들어진 뒤에는 페이지 수를 바꾸는 명령이 없으므로 생성 단계에서 유효한 값을 확인해야 합니다.

이 과제에서는 Builder로 **설정 중인 상태와 완성된 객체**를 구분하고, Prototype으로 **기존 상태를 가진 새 객체**를 만드는 과정을 연습합니다. 이름만 다른 두 변수가 같은 보고서를 가리키는 것과, 값은 같지만 독립적인 두 보고서를 만드는 것의 차이를 설명할 수 있어야 합니다.

`main.cpp`의 `Report`, `ReportBuilder` TODO를 완성하세요. Builder의 `withTitle`, `withPages`, `build`와 Prototype의 `clone`을 사용합니다. 제공된 명령 해석과 출력 흐름은 유지하세요. 모든 구현을 **main.cpp 한 파일**에 제출합니다.

## 패턴별 책임과 구현 순서

| 구성 요소 | 맡아야 할 책임 |
|---|---|
| `ReportBuilder` | 제목·페이지 설정을 모으고, `build()`에서 유효성을 확인하여 보고서를 생성 |
| `Report` | 보고서의 제목·페이지·섹션 순서를 보관하고 변경·요약 기능 제공 |
| `Report::clone()` | 현재 상태를 모두 가진 독립 객체를 반환하는 Prototype 진입점 |
| `main`의 보고서 맵 | id의 유일성, 명령의 오류 검사 순서, 보고서 소유권 관리 |

다음 순서로 TODO를 채워 보세요. 아래는 구현 절차이며 완성 코드는 제공하지 않습니다.

1. `withTitle`, `withPages`가 어떤 설정을 남겨야 하는지 정리합니다. 두 메서드를 이어 호출해도 같은 Builder의 설정이 유지되어야 합니다.
2. `build()`의 성공·실패 조건을 정리합니다. 시작 코드의 호출자는 생성 실패를 빈 포인터로 판단하므로 실패 시 불완전한 보고서를 등록하지 않아야 합니다.
3. 제목 변경과 섹션 추가를 구현하고 `summary()`의 필드 순서·구분자를 확인합니다.
4. `clone()`이 제목뿐 아니라 페이지와 현재 섹션 목록까지 복제하는지 확인합니다. 복제 뒤 어느 쪽을 수정해도 다른 쪽에 영향을 주지 않아야 합니다.
5. 생성·수정·복제를 각각 확인한 뒤 오류가 발생한 명령 다음에 `SHOW`를 실행해 이전 상태가 유지되는지 점검합니다.

## 입력과 출력

첫 줄은 명령 수 N(1~100), 다음 N줄은 아래 명령입니다. 식별자와 문자열은 공백 없는 영문·숫자·밑줄 토큰(1~30자)입니다. 문법과 명령어는 정상적으로 제공되며 범위 오류와 없는/중복 식별자는 처리해야 합니다.

| 명령 | 동작 및 출력 |
|---|---|
| BUILD id title pages | 1~500페이지 보고서 생성. 성공 OK, 같은 id는 ERROR duplicate, 범위 밖은 ERROR pages |
| CLONE source target | 제목·페이지·섹션을 독립 복제. 원본 없으면 ERROR missing, 대상 중복은 ERROR duplicate |
| TITLE id title | 제목 변경. 성공 OK, 없으면 ERROR missing |
| ADD id section | 섹션 뒤에 추가. 중복 섹션도 허용. 성공 OK, 없으면 ERROR missing |
| SHOW id | id\|제목\|페이지\|쉼표로 연결한 섹션. 섹션이 없으면 -, id가 없으면 ERROR missing |

BUILD는 중복 id 검사를 페이지 검사보다 먼저 합니다. CLONE은 원본 존재를 먼저 검사합니다. 실패 명령은 상태를 바꾸지 않습니다. 명령당 한 줄을 출력하고 안내 문구는 출력하지 않습니다.

페이지 수의 양 끝인 1과 500은 유효합니다. 섹션이 하나도 없는 보고서도 정상이며 `SHOW`의 마지막 필드만 `-`가 됩니다. 섹션 개수와 페이지 수는 서로 독립적이므로 `ADD`가 페이지 수를 증가시키지 않습니다. 섹션은 입력 순서대로 남고 같은 이름을 두 번 추가하면 두 번 출력합니다. 보고서 id는 등록 이름이므로 `TITLE`로 바뀌지 않습니다.

출력은 대소문자까지 맞추고 `|` 또는 쉼표 앞뒤에 공백을 붙이지 마세요. 마지막 섹션 뒤에는 쉼표를 붙이지 않습니다. 시작 코드의 `ERROR clone`은 `clone()`이 빈 포인터를 반환할 때의 방어 문구입니다. 이 문제의 유효한 복제 요청은 성공해야 하므로 해당 문구가 나오면 TODO 구현을 확인하세요.

## 공개 예제 1 — 복제 후 독립 수정

입력:
```text
8
BUILD r1 Weekly 3
ADD r1 Intro
CLONE r1 r2
TITLE r2 Final
ADD r2 Result
SHOW r1
SHOW r2
SHOW missing
```
출력:
```text
OK
OK
OK
OK
OK
r1|Weekly|3|Intro
r2|Final|3|Intro,Result
ERROR missing
```

`r2`는 복제 당시 `r1`의 `Intro`를 가지고 시작합니다. 이후 제목과 섹션을 바꾼 결과는 `r2`에만 반영됩니다.

## 빌드와 실행

시작 코드는 컴파일되지만 TODO 때문에 아직 정답 동작을 하지 않습니다. 한 번 실행할 때 예제 하나의 입력 전체를 전달하세요. 두 예제를 이어 붙이지 않습니다. 입력 첫 줄의 N과 뒤의 명령 줄 수가 같아야 합니다.

**Visual Studio 2022/2026:** C++ 데스크톱 개발 및 CMake 도구가 설치된 환경에서 **파일 → 열기 → 폴더**로 `main.cpp`와 `CMakeLists.txt`가 함께 있는 폴더를 엽니다. CMake 구성이 끝나면 `lab` 대상을 빌드·실행하고 콘솔에 예제 입력을 붙여 넣습니다. 파일 입력으로 반복 검증하려면 같은 폴더의 **Developer Command Prompt**에서 다음을 사용할 수 있습니다. 아래 `<` 입력 연결은 일반 명령 프롬프트 문법입니다.

```bat
cl /nologo /std:c++17 /EHsc /utf-8 main.cpp /Fe:lab.exe
lab.exe < sample.in
```

**Linux/macOS/WSL2:** C++17 컴파일러가 설치된 터미널에서 다음과 같이 실행합니다.

```sh
c++ -std=c++17 -Wall -Wextra main.cpp -o lab
./lab < sample.in
```

`sample.in`은 예제의 입력 블록만 저장한 로컬 검증 파일입니다. 설명 문장과 출력 블록은 넣지 마세요. 프로그램은 키보드 대기나 `system("pause")` 없이 N개 명령을 처리한 뒤 종료해야 합니다.

기능 자동채점은 표준 입력/출력 계약을 검증하며 총 **100점**입니다. 위 예제 외에도 공개된 명세의 경계와 여러 명령 조합이 평가됩니다. 자동 100점은 출력 계약에 대한 결과이며 **Builder·Prototype 구조를 올바르게 설계했다는 판정과는 다릅니다.** 패턴 책임, 독립성, 소유권 및 설계 설명은 교수자가 별도로 확인합니다. 공개 예제의 문자열만 맞춘 구현으로 일반 입력을 대신하지 마세요.

## 자기점검

- [ ] Builder의 단계적 설정 뒤 build에서 유효성 검사와 객체 생성을 담당한다.
- [ ] 호출자는 clone을 통해 복제하며 내부 필드를 직접 조립하지 않는다.
- [ ] 복제본의 제목과 섹션을 바꿔도 원본/다른 복제본이 바뀌지 않는다.
- [ ] 소유권을 unique_ptr 또는 동등하게 안전한 방식으로 관리한다.
- [ ] Builder와 Prototype의 역할 및 일반 복사 생성자와의 관계를 설명할 수 있다.
- [ ] 오류 후에도 기존 보고서의 제목·페이지·섹션이 유지되고, 출력 줄 수가 N과 같다.

## 자주 묻는 질문

**페이지 수는 섹션 개수와 같아야 하나요?** 아니요. 별개 상태입니다. 이 과제에서는 생성 후 페이지 수를 변경하지 않습니다.

**복제할 때 원본을 새 id로 옮겨도 되나요?** 안 됩니다. 원본과 복제본이 동시에 존재하고 각각 수정될 수 있어야 합니다. 포인터 공유와 독립 복제를 구분하세요.

**`shared_ptr`를 사용하면 자동으로 독립 복제가 되나요?** 아닙니다. 소유권을 공유하는 것과 객체 상태를 복제하는 것은 다른 동작입니다. 수정이 전파되지 않는지 확인하세요.

**컴파일은 되는데 모든 BUILD가 실패합니다.** 시작 코드의 `build()`는 빈 포인터를 반환하는 TODO입니다. 컴파일 성공만으로 기능 구현이 끝난 것은 아닙니다.
