# Autograde — VS Code에서 받는 실습, 제출, 채점 피드백

C/C++ 실습 과제를 내려받고, 작성한 코드를 제출하고, 수정할 부분을 같은 작업 창에서 확인하세요.
Autograde는 학교·수업의 Autograde 서버와 연결하는 **학생용 확장**입니다.
기본 과제 파일 제출 방식에는 GitHub 로그인, commit, push가 필요하지 않습니다.

> 이 확장만 설치하면 사용할 수 있는 공개 채점 서비스는 아닙니다.
> 담당 교수자가 운영하는 서버 주소, 수강 등록, 학생 전용 비밀번호가 필요합니다.
> 현재 파일럿 MVP이며 Marketplace 공개 배포가 완료되었다는 의미는 아닙니다.

[설치와 시작](#설치와-시작) · [제출과 결과 확인](#제출과-결과-확인) · [자주 묻는 질문](#자주-묻는-질문)

## 무엇을 할 수 있나요?

- **수령 코드로 과제 시작:** 학생 웹에서 발급받은 코드를 입력하면 해당 과제를 수락하고 다운로드합니다.
- **내가 수락한 실습만 표시:** 현재 인증으로 수락한 과제를 사이드바에서 확인합니다.
- **다운로드 후 바로 편집:** 현재 창의 탐색기에 과제 폴더를 표시하고 C/C++ 소스 또는 README를 엽니다.
- **IDE에서 제출:** 과제 폴더와 파일 수를 확인한 뒤 서버로 전송합니다.
- **읽기 쉬운 채점 결과:** 점수, 총점 달성률, 수정 필요 항목, 공개된 피드백과 다음 할 일을 보여 줍니다.
- **제출 기록과 복원:** 서버가 접수한 이전 제출의 결과를 확인하고 코드를 새 폴더에 복원합니다.
- **서버 연결 상태 확인:** 하단 상태 표시줄에서 최근 연결 확인 결과를 보고 다시 확인할 수 있습니다.

## 지원 환경

| 사용하는 PC | 과제 작업 환경 |
| --- | --- |
| Windows | VS Code의 WSL2 연결 창 |
| Linux | 일반 VS Code 창 |
| macOS | 일반 VS Code 창 |
| Windows + Visual Studio Community | [별도의 Visual Studio용 확장](../visualstudio/README.md) 사용 |

VS Code **1.92 이상**, 로컬 디스크의 수업 폴더, 신뢰할 수 있는 workspace가 필요합니다.
브라우저 전용 VS Code·가상 파일 시스템과 Windows 네이티브 창의 다운로드/제출은 지원하지 않습니다.
컴파일러는 확장에 포함되지 않습니다. 로컬 실행에 필요한 C/C++ 도구는 수업 안내에 따라 준비하세요.
**로컬 실행 성공과 서버 채점 통과는 다릅니다.** 서버의 컴파일러·입력·채점 기준은 교수자가 설정합니다.

## 설치와 시작

### 1. 담당자가 배포한 확장 설치

VS Code의 **확장** 화면을 열고 상단 **… → VSIX에서 설치(Install from VSIX)**를 선택합니다.
담당자가 제공한 VS Code용 `.vsix` 파일을 선택하고 필요한 경우 창을 다시 시작하세요.
Windows에서는 WSL2 창을 열고 확장이 해당 WSL 환경에서 사용 가능한지 확인합니다.

Visual Studio용 VSIX와 VS Code용 VSIX는 서로 호환되지 않습니다.
서명·학교 보안 정책 오류가 나면 검증 기능을 끄지 말고 담당자에게 설치 로그를 전달하세요.

### 2. 수업 폴더와 서버 주소 준비

빈 수업 폴더를 만들고 **파일 → 폴더 열기**로 여세요. Windows에서는 WSL2 안의 수업 폴더를 사용합니다.
왼쪽 **Autograde → 서버 주소 설정**에서 담당자가 안내한 **API 주소**를 입력합니다.
그다음 **서버 연결 확인**을 눌러 주세요.

| 주소 종류 | 사용하는 곳 | 구성 예시 |
| --- | --- | --- |
| 학생 웹 주소 | 브라우저에서 과제 수령 코드 발급 | `https://<수업 도메인>:20010` |
| API 주소 | 확장의 서버 주소 설정 | `https://<수업 도메인>:20000` |

위 포트는 파일럿 구성 예시입니다. 학교에서 별도 주소를 안내했다면 그 주소를 사용합니다.
`/courses/…/login` 같은 웹 로그인 경로를 API 주소로 입력하지 마세요.
다른 PC의 서버에 연결할 때 `127.0.0.1`은 사용할 수 없습니다. 이는 현재 실행 환경 자신을 가리킵니다.
외부 연결은 유효한 인증서가 있는 HTTPS가 필요합니다.

### 3. 학생 웹에서 수령 코드 발급

담당자가 안내한 링크 또는 QR 코드로 학생 웹에 접속합니다.
교과목을 선택하고 **학번 + 학생 전용 비밀번호**로 인증한 뒤 받을 과제를 선택하세요.
화면에 표시되는 `AK1-XXXX-XXXX-XXXX` 형식의 **과제 수령 코드**를 확인합니다.
이 표기는 형식 예시이며 실제 사용할 수 있는 코드가 아닙니다.

**학생 비밀번호는 웹 인증용이고, 과제 수령 코드는 확장 연결용입니다.**
학교 SSO·GitHub OAuth 로그인은 기본 파일럿 흐름에서 필요하지 않습니다.
수령 코드는 학생·과제별 단기 일회용이므로 공유하지 마세요.

### 4. 코드 입력과 과제 다운로드

**Autograde → 내가 수락한 실습 → 수령 코드 입력 및 다운로드**를 누릅니다.
가려진 입력창에 코드를 입력하면 해당 과제가 목록에 표시되고 다운로드가 시작됩니다.
아직 준비 중이라면 **과제 새로고침** 후 **과제 파일 다운로드**를 선택하세요.
열린 폴더가 없는 창에서는 코드를 입력받기 전에 **수업 폴더 열기**를 안내합니다.
폴더를 연 뒤 **수령 코드 입력 및 다운로드**를 다시 누르세요. 준비 단계에서는 코드를 사용하지 않습니다.

과제는 현재 수업 폴더 아래에 별도 폴더로 생성됩니다. 기존 폴더를 덮어쓰지 않습니다.
다운로드 후 탐색기에 과제를 표시하고 최상위 `main.cpp` → `main.c` → README 순으로
첫 안전한 파일을 엽니다. 해당 파일이 없으면 폴더만 표시합니다.
로그인을 유지하기 위해 새 창을 열거나 현재 수업 workspace를 교체하지 않습니다.
열기에 실패해도 받은 파일은 보존되며 안내된 경로에서 직접 열 수 있습니다.

## 제출과 결과 확인

### 5. 문제 해결 후 모두 저장

문제 설명과 요구된 파일 이름을 확인하고 코드를 작성합니다. 제출 전에 **모두 저장**하세요.
제출 대상은 편집기에서 아직 저장하지 않은 내용이 아니라 **디스크에 저장된 과제 파일**입니다.
0.5.5부터 해당 과제에 저장하지 않은 파일이 있으면 **저장 후 제출** 확인창을 표시합니다.
취소하거나 파일을 저장하지 못하면 제출하지 않습니다. 다른 과제의 파일은 저장하지 않습니다.
다운로드한 폴더의 `.autograde` 식별 파일을 삭제하거나 다른 과제의 것으로 바꾸지 마세요.

### 6. 과제 제출

Autograde에서 해당 과제를 선택해 **과제 제출**을 실행합니다.
확인창의 과제명·폴더·파일 수·크기를 검토하고 **본인 작업물 확인 후 제출**을 누르세요.
선택한 과제 폴더를 제출하며 상위 수업 폴더 전체를 보내지 않습니다.
일반적인 빌드/캐시 폴더와 `.git`, `.autograde`는 제외합니다.

**제출 접수는 채점 완료가 아닙니다.** 접수 즉시 결과 탭을 열고,
이번 접수번호의 상태를 약 3초 간격으로 자동 확인합니다. 기다리는 동안 편집·재제출할 수 있습니다.
이전 공개 최고점은 이번 제출 점수와 별도로 표시합니다.
통신이 끊겼다고 접수가 취소된 것은 아닙니다. 새로 제출하기 전에 최신 결과·제출 기록을 먼저 확인합니다.

### 7. 결과를 읽고 필요한 부분 수정

| 표시되는 상태 | 의미와 다음 행동 |
| --- | --- |
| 접수됨 / 채점 대기 / 채점 중 | 아직 완성 여부를 판단할 수 없습니다. 이번 접수번호로 자동 확인합니다. |
| 채점 완료 · 결과 준비 중 | 공개된 접수의 결과 응답을 준비 중입니다. 같은 접수번호로 자동 재확인합니다. |
| 채점 완료 · 결과 공개 대기 | 교수자의 결과 공개를 기다립니다. 공개 전에는 점수가 표시되지 않습니다. |
| 수정이 필요합니다 | 배점이 부족한 항목과 공개 피드백 확인 → 코드 수정 → 저장 → 다시 제출합니다. |
| 자동채점 총점 기준 충족 | 자동채점 기준을 충족했습니다. 보고서·설계 설명 등 별도 요구사항도 확인합니다. |
| 제출 검증 거절 / 채점 환경·작업 오류 | 안내를 확인하고 접수번호와 함께 교수자에게 문의합니다. 무조건 학생 코드 오류를 뜻하지 않습니다. |

결과 요약에는 과목·과제, 접수번호, 점수, 수정 필요 항목, 다음 할 일이 표시됩니다.
전체 진단은 펼쳐서 확인할 수 있습니다. 숨겨진 채점 자료나 공개하지 않은 피드백은 제공하지 않습니다.
결과 화면은 **조회 시점의 제출본**에 대한 결과입니다. 코드를 고치기만 해서는 기존 점수가 바뀌지 않습니다.
다시 제출한 뒤 최신 접수번호의 결과인지 확인하세요.
결과 탭의 **결과 다시 확인**으로 현재 접수의 조회를 재개할 수 있습니다.
**자동 확인 중지** 또는 탭 닫기는 조회만 중지하며 서버의 제출·채점을 취소하지 않습니다.
10분 대기 또는 연속 연결 오류 후에는 자동 확인을 쉬고 재확인 안내를 표시합니다.
로그아웃·서버 주소 변경·다른 과제 선택·새 제출 후에는 이전 요청의 늦은 결과를 표시하지 않습니다.

### 8. 이전 제출 조회와 자리 정리

과제를 펼쳐 **제출 기록 / 이전 코드 복원**에서 최근 접수본의 결과를 확인하거나
새 폴더로 코드를 복원할 수 있습니다. 현재 파일을 덮어쓰지 않으며 복원만으로 재제출되지 않습니다.
이 기능은 **서버 접수본 기록**이지 로컬 편집 내용의 자동 저장·Git 버전 관리가 아닙니다.

공용 PC를 떠날 때는 **로그아웃**하세요. 다운로드한 소스 파일은 자동 삭제되지 않으므로
학교의 PC 정리 절차를 따라 주세요.

## 인증과 제출 데이터

- 학번·비밀번호는 학생 웹에 입력하고, 확장에는 과제 수령 코드를 입력합니다.
- 수령 코드와 로그인 토큰은 확장의 설정 파일에 저장하지 않습니다. 로그인 토큰은 현재 실행 중인 확장의 메모리에만 유지됩니다.
- 창 종료·재시작·WSL 재연결로 확장이 다시 시작되면 새 수령 코드로 로그인해야 합니다.
- 서버 주소 설정과 다운로드한 파일은 남습니다. **로그아웃은 파일 삭제가 아닙니다.**
- 제출을 승인하면 과제 파일과 제출 식별 정보가 설정한 Autograde 서버로 전송됩니다.
  과제 폴더에 개인 문서·인증 키·비밀번호를 두지 마세요. 서버의 보관·삭제 기준은 수업 운영자에게 확인합니다.

## 자주 묻는 질문

| 문제 | 먼저 확인할 내용 |
| --- | --- |
| 서버 연결은 되는데 과제가 안 보입니다. | 연결 상태는 로그인 상태가 아닙니다. 수령 코드로 인증했는지, 해당 과제가 공개되었는지 확인합니다. |
| 서비스에 연결할 수 없습니다. | API 주소·포트·인증서·네트워크를 확인합니다. WSL 창에서는 WSL 쪽 연결도 필요합니다. |
| 코드가 거절됩니다. | 학생 비밀번호를 넣지 않았는지 확인하고, 만료·사용된 코드라면 학생 웹에서 새로 발급받습니다. |
| 과제를 바꾸고 싶습니다. | 새 과제의 수령 코드를 발급받습니다. 새 코드로 인증하면 현재 인증의 과제 범위가 바뀝니다. |
| 폴더가 이미 존재한다고 나옵니다. | 기존 파일을 삭제하지 말고 본인 과제인지 확인합니다. 새 다운로드는 다른 빈 수업 폴더에서 진행합니다. |
| 제출 버튼이 비활성화됩니다. | 신뢰한 workspace, 지원 환경, 현재 로그인과 과제 선택을 확인합니다. |
| 수정했는데 점수가 같습니다. | 모두 저장 → 재제출 → 최신 제출 결과 조회 순서로 확인합니다. |
| 이전 파일로 돌아가고 싶습니다. | 제출 기록에서 새 폴더로 복원합니다. 서버에 제출하지 않은 초안은 복원할 수 없습니다. |

문의를 보낼 때는 IDE/확장 버전, OS·WSL 여부, 과제명, 접수번호, 오류 문구를 전달하세요.
비밀번호·수령 코드·로그인 토큰은 보내지 마세요.

## 현재 범위와 더 알아보기

0.5.5는 제출 과제의 미저장 파일 확인·저장 실패 차단, 빈 창의 수업 폴더 준비,
접수번호별 비차단 채점 자동 확인과 결과 재확인/중지를 제공합니다. WSL 원격 문서도
해당 작업 영역의 주소 범위에서 저장하며 다른 과제·다른 원격 호스트는 건드리지 않습니다.

0.5.4는 새 제출 접수 시 이전 결과 화면을 현재 접수번호로 전환하고, 최신 결과 조회 시 서버의
최신 제출을 다시 확인합니다. 현재 점수와 이전 공개 최고점을 구분합니다. 서버도 함께 업데이트해야
동일 파일의 의도적인 재제출이 새 기록으로 남습니다.
[학생별 이력·코드 비교와 업데이트 안내](../../docs/operations/submission-timeline.md)

[학생·교수자 진단 사용법](../../docs/operations/extension-download-diagnostics.md)을 참고하세요.
