# 교수자·학생 포털 정보구조와 고도화 계획

기준일: 2026-10-28. 현재 저장소의 Python 웹·Next.js·IDE API를 점검한 계획이다.
운영 서버를 원격으로 변경하는 계획이 아니라, 동일 서버에 적용할 포털 구현과 검증 범위를 정의한다.

## 개선 전 정보구조 진단

| 사용자 업무 | 기존 진입점 | 확인한 문제 |
| --- | --- | --- |
| 서비스 시작 | `/`, `/courses` | 학생 교과목 목록만 보여 교수자 진입점을 찾기 어렵다. |
| 교수자 시작 | `/instructor` | 교과목 관리 화면의 별칭으로, 담당 수업과 다음 업무가 구분되지 않는다. |
| 수업 운영 | `/courses/{course}/instructor` | 과제·학생·평가·자료·IDE 기능이 있지만 한 줄의 긴 메뉴로 나열된다. |
| 제출·교실 현황 | `/app`, `/app/classroom` | Python 관리 화면과 탐색이 다르고 이동할 때 수업 맥락을 잃는다. |
| 학생 시작 | `/courses/{course}` | 수령 코드 발급에 집중되어 학습 현황의 시작 화면이 없다. |
| 학생 자료 | `/courses/{course}/materials`, `/exam-papers` | 배정·기간 검사는 구현되어 있으나 과제 흐름과 탐색이 나뉜다. |
| 학생 제출 결과 | IDE 내부 | 학생 웹에는 본인의 최신 제출·이전 최고점을 확인하는 화면이 없다. |

과제 CRUD·검증·다운로드, 학생 등록·수강 관리, 제출 이력·코드 비교, 루브릭, 개인 자료,
Git 콘텐츠, IDE 연결·교수자 요청·확장 배포는 기존 서비스를 재사용한다.
새 포털에서 동일 업무 규칙이나 성적 저장소를 중복 구현하지 않는다.

## 목표 정보구조

```text
/                         역할별 시작
├─ /student               학생 포털 · 가입/로그인 · 교과목 선택
│  ├─ /student/register   학번 · 본인 비밀번호 · 수업 선택 → 명단 자동 연결
│  ├─ /student/login      공통 회원 로그인
│  ├─ /student/account    내 수업 · 추가 수업 선택 · 명단 연결 상태
│  └─ /courses/{course}/portal       인증된 내 수업
│     ├─ 내가 수락한 실습 · 원격 실행공간 · 최근 제출 요약
│     ├─ /courses/{course}           과제 선택 · 수령 코드
│     ├─ /courses/{course}/results   본인 제출 현황 · 공개 결과
│     ├─ /courses/{course}/materials 본인 배정 자료
│     └─ /courses/{course}/exam-papers 시험지 (활성 기능)
└─ /instructor            교수자 포털 · 담당 수업과 업무 요약
   ├─ /instructor/admin   교과목·분반 관리
   └─ /courses/{course}/instructor   수업 홈
      ├─ 수업 운영: 가입·수강 명단 · 학생 관리 · 실습 교실 · 실습 환경
      ├─ /registrations: 학번 명단 CSV 업로드 · 가입 학생 자동 연결 확인
      ├─ /environments: 원격 Linux 연결 · 학생별 실행공간 조회
      ├─ 평가: 제출·채점 현황 · 루브릭
      ├─ 자료·IDE: 학생별 자료 · 시험지 · Git 콘텐츠 · 확장 배포
      └─ 설정: 수업 정보 · 운영 상태 · 영구 삭제 (관리자)

/app                      Next.js 제출·채점 현황 (기존 주소 유지)
/app/classroom            Next.js 실습 교실 (기존 주소 유지)
```

공개 시작 화면은 역할 선택과 공개 교과목 정보만 제공한다. 역할 링크를 누르는 것으로
교수자 권한을 얻거나 다른 학생의 정보를 조회할 수 없다. 수업 코드는 화면 위치를 지정할 뿐
권한을 대신하지 않는다. 선택 기능은 서버의 활성 서비스와 허용 기능을 확인해서 표시한다.

## 화면별 업무 계약

### 교수자

- 포털 홈에서 담당 수업을 확인하고 수업 홈으로 이동한다. 관리자는 허용된 전체 수업을 본다.
- 수업 홈에서 진행 과제, 학생·제출 상태와 다음 업무를 확인한다.
- 과제 등록 → 학생 수령 → 실습 교실 → 제출·채점 → 코드·평가 검토로 이동한다.
- 교과목·분반 등록과 학생 관리, 자료 배포는 기존 검증된 폼을 사용한다.
- 가입·수강 명단에 비밀번호 없는 학번 CSV를 업로드한다. 해당 수업을 선택한 가입 학생과 자동 연결하며
  명단 업로드 전에 가입한 학생도 일치하면 연결한다. 수동 승인 절차는 두지 않는다.
- Next.js와 Python 화면은 같은 수업 맥락을 표시하고 해당 수업 링크를 유지한다.
- 통계의 기준을 명시한다. 학생 수·접수 수·채점 대기 수·공개 점수를 같은 지표로 섞지 않는다.
- 실습 환경에서 원격 실행 관리자 연결과 해당 수업의 학생별 실행공간·연결된 서버 저장본·종료 상태를 조회한다.
  환경 미설정과 연결 실패, 연결되었지만 학생 공간이 없는 상태를 구분한다.

### 학생

- 학생 포털에서 학번·본인 비밀번호·수업으로 가입하고 공통 회원 계정으로 로그인한다.
  교수자가 올린 학번 명단과 일치하는 활성 수업만 이용한다. 불일치는 명단 확인 대기로 표시한다.
- 기존 6자리 수업 비밀번호도 유지한다. 기존 학생의 공통 계정 연결은 수업 인증 후 별도로 진행하며
  학번만 아는 사람이 기존 계정이나 비밀번호를 바꿀 수 없게 한다.
- 내 수업에서 과제 수령, 제출 현황, 배정 자료로 이동한다.
- IDE가 수령 코드를 사용한 과제만 **내가 수락한 실습**에 표시한다. 코드 발급 자체를 수락·제출로 집계하지 않는다.
- 내 수업에서 본인의 원격 실행공간과 최근 제출을 확인한다. 실행공간의 저장본 식별자는 마지막 연결 버전이며
  아직 전송하지 않은 IDE 편집 내용의 저장을 보증하지 않는다.
- 수령 코드 발급은 수업별 임시 세션을 소비한다. 공통 회원 로그인은 최대 10분 동안 유지되어
  권한을 재검사하고 수업 화면을 다시 열 수 있다. 공통 로그인 없이 기존 수업 비밀번호만 이용했다면
  코드 발급 후 재인증한다. 공용 PC에서는 학생 로그아웃과 브라우저 종료를 별도로 수행한다.
- 최신 접수의 상태·점수와 이전 제출의 공개 최고점을 구분한다. 최신 접수가 채점 대기라면
  이전 점수를 최신 점수 칸에 채우지 않는다. 미공개 결과를 0점으로 표시하지 않는다.
- 공개된 결과만 제공하며 `score_only` 정책에서는 비공개 진단·테스트 정보·루브릭을 표시하지 않는다.
- 과제 작성·코드 제출·작업 복원·Git 콘텐츠 동기화·내보내기는 기존 IDE 흐름을 유지한다.

## 인증·데이터 경계

| 경계 | 유지하는 정책 |
| --- | --- |
| 교수자 | Python이 매 요청 Basic 인증·담당 수업 권한을 검사. 공유 계정과 개인 계정을 구분 |
| 변경 요청 | 기존 Origin·서명 쿠키·CSRF 검사 유지. 조회 포털을 만들기 위해 검사 완화 금지 |
| 학생 웹 | 최대 10분의 공통 회원 세션과 교과목별 임시 세션. 활성 계정·현재 수강·수업 상태를 매 요청 재검사 |
| 수강 연결 | 해당 수업 선택과 교수자 업로드 학번 명단의 일치로 자동 연결. 학번 일치는 학교 SSO나 실명 증명이 아님 |
| 학생 결과 | 세션의 학생·수업으로 범위를 고정. URL 학번이나 교수자 API로 조회하지 않음 |
| 원격 공간 조회 | 교수자는 현재 담당 수업, 학생은 현재 웹 credential의 본인 공간만 조회. 읽기 후 권한 회수를 재확인 |
| 공개 정책 | 비공개·삭제·숨김 자료와 결과는 기존 공개 정책에 따라 제외 |
| Next.js | 공개 HTML에 학생·성적·CSRF 비밀을 넣지 않음. 인증된 bootstrap 이후에 수업 맥락 제공 |
| 저장소 | Python·SQLite 유지. Next.js의 DB 직접 접근·학생 웹의 IDE 토큰 자동 발급 없음 |
| 캐시 | 인증된 응답은 기존 HTTP의 no-store·보안 헤더 유지 |

공통 계정은 이 서버에서 연결된 본인의 수업만 제공한다. 다른 학생의 가입 여부·수강 목록이나
학교 전체 수강 정보는 공개하지 않는다. 수업별 접근 권한은 공통 로그인 후에도 각각 검사한다.
교수자의 Basic 인증 캐시를 지울 수 없는 버튼을 ‘로그아웃’이라고 표시하지 않는다.
웹 세션과 IDE의 공용 실습실 파일 삭제 정책은 별개의 수명이다.

## 종합 수업 포털 확장

포털을 수업의 업무 진입점으로 두고, 교수자 화면은 **수업 운영 → 평가 → 자료·IDE → 설정**으로,
학생 화면은 **수락한 실습 → 실행공간 → 제출 결과 → 배포 자료**로 연결한다. 기존 CRUD·배포·채점
서비스를 호출하며 포털이 별도의 성적 원장이나 IDE 인증 체계를 만들지 않는다.

추가된 `/courses/{course}/instructor/environments`는 조회 전용이다. 웹 방문이나 새로고침으로
학생 공간을 만들거나 삭제하지 않는다. 생성·실행·저장·종료는 현재 수락 과제의 권한을 가진 IDE에서
수행한다. 교수자 화면은 최소한의 학번·과제·공간 상태·저장본 식별자만 표시하고 실행 출력·소스·토큰·
worker 경로를 표시하지 않는다. 상태 조회 중 모든 학생의 로그인 잠금을 유지하지 않는다.

이번 연결은 고정된 C/C++/Python 원격 환경의 상태 조회를 제공한다. 교수자가 임의 이미지·명령을 넣는 기능,
Java·디버거의 활성화, 추가 패키지 설치와 SES 환경 조합 편집은 후속이다. 메뉴가 있다는 이유로 미구현 기능을
사용 가능으로 표시하지 않는다. 실행공간 전체 설계는 [개발도구 모듈 설계](learning-sandbox-modules.md)를 따른다.

## 교과목과 회원 데이터 수명

교과목 이름·코드·운영 상태·분반, 공통 회원과 수강 연결은 SQLite에 저장한다. 설정 CSV는
서버 실행 설정이며 교과목 화면에서 변경한 정보를 매 시작마다 덮어쓰는 원장으로 사용하지 않는다.
관리자는 보관 단계를 거치지 않고 **설정 → 영구 삭제**에서 삭제 대상 수와 파일 보존 범위를 확인하고
수업 코드를 입력하여 삭제할 수 있다. 일반 교수자는 허용된 수업의 운영·수강 관리만 수행한다.

삭제된 수업은 목록·접근·재시작 초기화에서 제외하며 같은 코드를 자동으로 다시 만들지 않는다.
해당 수업의 수강 명단·수강 연결·과제·제출·성적 등 종속 정보를 삭제하되 다른 수업과 공통 회원 계정은
유지한다. 수업 소유 파일 정리나 원격 공간 삭제가 실패하면 삭제 기록에 정리 대기를 남긴다.
공유 파일 저장소(CAS)·공유 입력 캐시·별도 백업은 온라인 삭제로 즉시 지우지 않는다.
자세한 수명과 제한은 [교과목 영구 삭제](../operations/course-permanent-deletion.md),
가입·수강 흐름은 [학생 회원 운영](../operations/student-membership.md)을 따른다.

## 단계별 구현과 완료 기준

아래 0~4단계의 초기 포털은 2026-10-28 구현·로컬 검증을 완료했다. 당시 서버 회귀 621개, 웹 단위 시험 41개,
포털 화면 96개 조합과 production Next.js 브라우저 검증을 통과했다. 이후 회원·수강 명단과 교과목 삭제는
별도 회귀로 확인한다. 운영 서버 배포는 별도다.

| 단계 | 구현 항목 | 완료 기준 |
| --- | --- | --- |
| 0. 구조 점검 | 기존 경로·권한·선택 모듈·다중 화면 분석 | 위 정보구조와 권한 경계 문서화 |
| 1. 포털 진입 | 역할 시작, 학생 교과목 선택, 교수자 담당 수업 홈 | 익명 화면에 개인정보 없음, 비활성 기능 링크 없음 |
| 2. 업무 탐색 | 교수자 그룹 메뉴·수업 홈, Next.js 맥락 유지, 학생 공통 메뉴 | 현재 위치·수업 식별, 주요 업무로 이동 가능, 작은 화면·테마 대응 |
| 3. 학습 현황 | 학생 본인 제출 현황·현재 점수·이전 공개 최고점 | 최신 접수 대기·비공개·다른 학생·다른 수업·권한 취소 시험 통과 |
| 4. 통합 검증 | 기존 CRUD·자료·학생 인증 회귀, Next.js 빌드, 브라우저 확인 | 자동 시험 통과와 로컬 실제 화면 확인 결과 기록 |

단계별 구현 결과·실행 주소·배포 확인은 [포털 운영 안내](../operations/role-portals.md)에 기록한다.
작업 완료는 이 범위의 코드·테스트·문서를 뜻하며 운영 서버 배포 완료를 뜻하지 않는다.

## 유지보수와 확장

학생 결과의 읽기 모델, 교수자 포털 렌더링, Next.js 탐색 모델을 각각 분리하여 변경 범위를 좁힌다.
구현 모듈은 `student_portal_data.py`(학생 결과 조회), `student_portal.py`(학생 홈·이력),
`instructor_portal.py`(교수자 홈·업무 메뉴·실습 환경), `portal_runtime_view.py`(공개 가능한 실행공간 표시 계약),
`web/src/features/navigation.ts`(Next.js 탐색)다.
학생 이력 화면은 최근 100건까지 제공하며 이전 최고점은 이 화면의 표시 제한과 별도로 전체
허용 이력에서 계산한다. 더 오래된 과제별 이력·코드 복원·상세 피드백은 IDE로 안내한다.
기능 표시에는 기존 서버 기능 활성화·capability를 사용한다. 메뉴 구성을 SES 제품 설정의
대체 권한 시스템으로 만들지 않는다. 추후 동적 메뉴 플러그인도 같은 서버 인가 검사를 통과해야 한다.

다기관 운영, 장기 로그인·학교 SSO, 성취도 분석·보고서 자동화,
OS 수준 시험 통제는 별도의 제품 기능이다. 이번 포털 고도화의 완료 조건에 섞지 않고
각각 데이터 범위·보존 정책·권한·검증 기준을 정의한 뒤 확장한다.
