# Mac 실습실용 Autograde IDE 앱

학생은 `Autograde IDE.app` 아이콘을 클릭하여 실습을 시작한다. 앱에는 실행에 필요한 Node.js,
Code-OSS와 Autograde 확장이 포함되므로 학생 PC에 Node.js·npm·Autograde 저장소를 따로
설치하거나 터미널 명령을 입력할 필요가 없다. 로컬에서 빌드·실행할 때는 C/C++ 컴파일러 등
과제별 개발 도구를 별도로 준비한다. **선택형 원격 C/C++/Python 실습**을 사용하면 학생 Mac에
컴파일러·Python·Docker를 설치하지 않아도 Linux C17/C++17 프로그램과 Python 3 코드를 실행할 수 있다.
담당자가 서버에 실행 관리자·승인 이미지를 준비해야 하며 앱 설치만으로 활성화되지 않는다.
[원격 실습 설치·사용 안내](remote-learning-runtime.md)를 따른다. Java·디버거·추가 패키지 설치는 후속이다.
현재 제작·실기기 확인한 패키지는 **Apple Silicon(M1 이상), macOS 13.5 이상**용이다.
포함된 Node.js 24.18.0 실행 파일의 최소 macOS 버전을 앱 메타데이터에 반영한다.

앱은 공용 실습실 모드로 실행된다. 고정된 `current/workspace`를 매번 빈 상태로 만들고, IDE 전체 종료 뒤 코드·자료·
IDE 프로필을 정리한다. 개인 PC에서 기존 폴더를 계속 사용하는 개발용 실행과 구분한다.
채점 서버는 기존 Python·SQLite 구성을 유지하며 이 앱 때문에 서버 실행 방법이 바뀌지 않는다.

## 학생의 시작과 종료

1. 담당자가 제공한 ZIP을 풀고 `Autograde IDE.app`을 **응용 프로그램** 또는 본인의
   **Applications** 폴더에 복사한다. 해당 Mac의 CPU에 맞는 앱을 사용한다.
2. 앱 아이콘을 더블클릭한다. 터미널 없이 새 학습 공간이 열린다.
   제한 모드가 표시되면 **Manage → Workspace Trust**에서 이번 실습 폴더만 신뢰한다.
   홈 디렉터리나 다른 학생의 폴더까지 신뢰 범위를 넓히지 않는다.
3. **서버 연결 확인**으로 기본 주소 `https://ai.cbchoi.info:20000`의 연결을 확인하고
   학생 웹에서 발급한 수령 코드를 입력한다. 다른 서버는 **서버 주소 설정**에서 지정한다.
   수락한 과제는 이번 실습 폴더에 다운로드된다.
   원격 실습이 활성화된 수업은 **원격 C/C++/Python 실습**에서 현재 코드를 서버에 저장하고 실행한다.
   C/C++은 빌드 후 실행하며 Python은 실행할 `.py` 파일 1개를 선택한다.
   성적을 받으려면 별도로 공식 제출을 진행한다.
4. 필요한 내용을 **내 학습내용 내보내기**로 개인 폴더나 USB에 저장한다. 이전 제출본을
   이어서 작업하려면 **제출 이력·코드 복원**을 사용한다.
5. 실습을 마치면 **공용 실습 종료**를 누른다. 보관할 파일과 공식 제출 여부를 확인하고
   종료한다. 원격 공간을 사용했다면 서버 저장·원격 공간 종료 결과도 확인한다. macOS의
   `Command+Q`로 IDE 전체를 종료해도 실행기는 로컬 정리를 수행하지만, 저장 전 강제 종료나
   통신 단절의 원격 공간 회수는 임대 만료에 의존한다.

**미제출·미내보내기 코드도 종료 시 삭제된다.** 단순히 로컬 파일을 저장한 것은 서버 보관이
아니다. 서버 저장이 확인된 작업본·공식 제출본·점수와 세션 밖에 명시적으로 내보낸 ZIP·폴더는 유지된다.
Mac의 빨간 창 닫기 버튼은 앱 프로세스를 남길 수 있으므로 실습 종료 버튼이나 전체 종료를
사용한다. 아이콘을 여러 번 눌러도 다른 학생용 동시 세션을 만들지 않는다.

앱을 다시 실행하면 같은 경로를 사용하되 이전 학생의 파일과 인증은 재사용하지 않는다. 같은 OS 계정에서 실행되는 다른
프로그램의 파일 접근을 차단하는 기능은 아니므로, 접근 자체의 격리가 필요한 실습실은
학생별 OS 계정이나 관리된 가상 환경을 함께 사용한다.

30초 주기 작업 저장, 새 폴더 복원과 다음 실행의 정리 절차는
[고정 작업 폴더·서버 작업 저장](shared-workspace-checkpoints.md)을 참고한다.

## 담당자의 앱 제작

아래 명령은 학생용 안내가 아니라 앱을 만드는 담당자의 개발 Mac에서 실행한다.
먼저 [Code-OSS 소스 준비·빌드](autograde-ide-poc.md)를 완료한다. 소스·Electron·Node 실행
파일의 아키텍처가 같아야 하며, 다른 아키텍처의 빌드 파일을 섞지 않는다.

저장소 루트에서 다음을 실행한다. `--node`에는 앱에 포함할 Node.js 실행 파일을 지정한다.
다음은 준비된 Apple Silicon용 Node.js 24.18.0을 사용하는 예다.

```sh
node ide/code-oss/manage.mjs prepare --source .cache/code-oss
node ide/code-oss/manage.mjs verify --source .cache/code-oss
node ide/code-oss/package-macos.mjs \
  --source .cache/code-oss \
  --node .cache/node-v24.18.0-darwin-arm64/bin/node \
  --output 'dist/Autograde IDE.app'
```

앱에 필요한 편집기 실행 파일과 모듈, 내장 확장, 실행기, 라이선스를 복사한다. 원본 Git
체크아웃이나 학생 작업 공간에 의존하지 않는다. 서버의 DB·CSV·학생 비밀번호·수령 코드·
개인 프로필은 포함하지 않는다. 앱 출력은 Git에 넣지 않는다.

기본 출력은 `Autograde IDE.app`, `Autograde IDE.app.zip`과 ZIP의 SHA-256 확인 파일이다.
완성된 앱의 자체 실행 시험을 마친 뒤 ZIP을 배포한다. 빌드 중 ZIP이 필요 없으면 `--no-zip`을
추가한다. 기존 출력은 덮어쓰지 않으므로 새 버전을 만들 때는 새 출력 경로를 지정한다.
앱을 제작한 원본 저장소에 접근할 수 없는 다른 폴더에서도 실행되는지 확인한다.
일반 소스 갱신만으로 설치된 앱이 자동 변경되지는 않는다.

현재 출력은 파일럿용 로컬 서명을 사용하는 앱이다. Apple Developer ID 서명·공증을 마친
정식 배포본은 아니다. 다운로드한 앱을 macOS가 차단하면 담당자가 출처·배포 방식과 서명
상태를 확인한다. 보안 설정이나 검역 속성을 일괄 해제하여 배포하지 않는다. 배포용 Developer ID
서명·공증과 자동 업데이트는 후속 배포 단계다.

## 실습실 갱신

담당자가 소스를 업데이트하고 위 절차로 새 앱을 만든다. 학생이 실습 중인 앱을 덮어쓰지 말고
먼저 공용 실습을 종료하여 파일 정리가 끝난 뒤 교체한다. 다음 실행은 다시 새 학습 공간에서
시작한다. 학생은 `git pull`, `npm install`, Node.js 설치를 수행하지 않는다.

### 기본 서버 주소와 학생 정보 정리

2026-10-28부터 새로 만드는 관리형 IDE의 기본 API 주소는 `https://ai.cbchoi.info:20000`이다.
Mac·Linux·Windows·WSL2 패키지는 `ide/code-oss/runtime-settings.json`의
`autograde.serviceBaseUrl`을 포함하고, 실행할 때마다 새 임시 프로필에 이 값을 적용한다.
학생 웹 주소의 `20010` 포트는 IDE의 API 주소로 사용하지 않는다.

실습 중 변경한 주소는 해당 세션에만 적용되며 다음 실행은 배포본의 기본 주소를 사용한다.
다른 기관용 앱은 빌드 전에 위 설정 파일의 주소를 변경한다. 주소만 배포 설정에 포함하며
로그인 토큰·비밀번호·수령 코드·학생 프로필은 포함하지 않는다. 전체 종료 후 코드·자료·프로필을
삭제하고, 다음 실행 때 멈춘 이전 세션을 확인하여 정리하는 기존 절차는 유지한다.
일반 VS Code에 별도로 설치하는 확장의 기본값에는 영향을 주지 않는다.

기존 앱은 소스의 설정 변경만으로 갱신되지 않는다. 새 앱 패키지로 교체한 뒤 **서버 연결 확인**을
실행한다. 보관할 코드가 있으면 교체 전에 서버 저장 성공을 확인하거나 내보낸다.

## 정리와 오류 대응

실행기는 해당 OS 사용자의 짧은 임시 경로 `/private/tmp/ag-lab-<UID>/current`에 세션을 만든다.
경로가 짧은 것은 macOS 프로세스 통신 경로의 길이 제한 때문이다. 앱이 설치된 위치나 학생
이름을 임시 폴더 이름으로 사용하지 않는다. 세션 폴더는 소유자만 접근할 수 있도록 생성하며,
정리 전 경로·소유 표식·실행 프로세스를 확인한다.

| 상황 | 처리 |
| --- | --- |
| 이미 실행 중인데 다시 클릭 | 현재 실습을 이어가며 새로운 동시 학생 세션을 만들지 않는다. |
| 앱에 필요한 실행 파일 누락·잘못된 CPU용 앱 | 실행 오류를 표시한다. 담당자가 맞는 앱을 다시 배포한다. |
| IDE가 종료됨 | 실제 프로세스 종료를 확인한 뒤 이번 실습 코드·자료·프로필을 삭제한다. |
| IDE 또는 실행기 강제 종료 | 다음 시작 때 이전 프로세스와 소유 정보를 검사한다. 멈춘 세션임을 확인할 수 있으면 정리한다. |
| 이전 IDE가 살아 있거나 파일 소유 정보가 불일치 | 다음 학생의 새 실습을 열지 않고 오류를 알린다. 담당자가 해당 좌석을 확인한다. |
| 세션 정리 실패 | 다음 학생에게 그대로 넘기지 않는다. 담당자가 프로세스·권한·디스크 상태를 확인한다. |

앱 번들 내부의 실행기나 편집기를 따로 실행하지 않는다. 외부 실행기가 IDE 종료와 정리를
함께 관리해야 한다. 종료 후 자동 정리는 일반 VS Code에 확장만 설치한 경우에는 적용되지 않는다.

## 배포 전 확인할 항목

- Node.js를 설치하지 않은 Mac 또는 시스템 기본 PATH만 사용하는 환경에서 아이콘으로 실행한다.
- 앱을 공백·한글이 있는 다른 폴더로 옮겨 원본 저장소 없이 실행한다.
- 새 코드 파일과 자료를 생성하고, 세션 밖에 ZIP과 폴더로 내보낸다.
- **공용 실습 종료** 후 임시 코드·자료·프로필은 없어지고 내보낸 파일은 유지되는지 확인한다.
- 재실행하여 이전 학생의 코드·인증·프로필이 보이지 않는지 확인한다.
- 아이콘을 연속 클릭하여 두 학생용 세션이 생기지 않는지 확인한다.
- IDE 강제 종료와 실행기 강제 종료를 각각 시험하여 안전한 복구 또는 명시적인 중단을 확인한다.
- 전용 시험 계정으로 과제 수령·다운로드·제출·채점 결과까지 확인한다.

Mac 앱 지원과 별도로 Windows·WSL2의 클릭 실행 패키지는 후속 검증 대상이다.

## 이번 구현에서 확인한 결과

macOS Apple Silicon에서 실제 앱을 Finder로 열어 Autograde 학습 홈이 표시되는 것을 확인했다.
실행 프로세스는 앱 내부의 Node와 편집기를 사용했고, 저장소 밖의 공백·한글 경로로 앱 전체를
옮긴 뒤에도 새 실습을 열었다. `/tmp`와 `/private/tmp` 별칭 및 Unicode 경로 표기 차이를
처리하는 회귀시험을 포함한다.
실행기·공용 세션·패키징 관련 자동 시험 147개가 통과했다.

합성 코드·자료를 만든 뒤 앱에 포함된 내보내기 모듈로 ZIP을 생성했다. **공용 실습 종료** 후
코드·자료·프로필·실행 잠금이 제거되고 ZIP 내용과 압축 무결성이 유지됨을 확인했다. 재실행은
새 빈 작업 공간을 만들었으며, 아이콘 재클릭은 같은 세션을 유지했다. `Command+Q` 종료의
정리도 확인했다. 학생 인증·원격 제출 시험은 이 앱 포장 검증에 포함하지 않았다.

현재 앱은 컴파일된 Code-OSS 파일럿 구성을 담는다. 최적화된 정식 편집기 배포 빌드와
Developer ID 서명·공증, Intel Mac 실기기 검증은 별도 배포 작업이다.

### 0.5.18 원격 실습 추가 검증

2026-10-28 제작한 Apple Silicon 파일럿 산출물은
`dist/remote-learning-0.5.18/Autograde IDE.app.zip`이다. 같은 폴더의 `verification.json`과
ZIP SHA-256 파일에 내장 모듈·기본 서버 주소·서명 검사·압축 무결성 결과를 남긴다.
서명은 **ad-hoc**이며 Developer ID 서명·공증을 받은 배포본은 아니다. 설치된 앱은 자동 교체하지 않았다.

앞선 0.5.17 Mac IDE의 실제 화면에서 합성 계정 수령 인증, 기존 과제 열기, C/C++ 실행, 코드 수정 후
새 서버 저장본 실행, 저장 후 원격 공간 삭제를 확인했다. 원격 실습 시험은 로컬 HTTP 서버와
실제 Linux 실행 관리자를 사용했으며 운영 서버에 적용된 결과가 아니다.
0.5.18은 Python 진입 파일·프로젝트 모듈·입력·오류·제한을 실제 Linux와 컴파일된 IDE 클라이언트의
HTTP 검사로 확인했다. Python 흐름의 실제 Mac 화면 조작은 아직 별도 확인 항목이다.

제작한 앱은 별도의 합성 좌석에서 실제 Electron을 실행해 다음 6개 항목도 통과했다:
앱 실행, 고정 좌석 생성, 종료 후 코드·자료·인증 프로필 제거, 실행 잠금 제거,
세션 밖 내보낸 파일 유지, 번들의 기본 서버 주소 유지. 담당자는 저장소 루트에서 재현할 수 있다.

```sh
node scripts/check_macos_shared_launch.mjs \
  'dist/remote-learning-0.5.18/Autograde IDE.app'
```

이 스크립트는 설치된 사용자 앱이나 평소 실습 좌석을 사용하지 않는다. 시험용 앱 프로세스를
SIGTERM으로 종료하고 실행기의 정리를 확인한다. 이 시험의 종료 코드 1은 의도한 종료 결과이며
정리 완료 사건과 파일 상태를 별도로 검사한다. 결과는 `build/remote-learning-ui/mac-shared-launch-report.json`에
남긴다. 상세 결과와 원격 실습의 별도 인수 범위는
[검증 기록](../testing/remote-learning-runtime.md)을 따른다.
