# 학생 회원가입과 수강 명단 자동 연결

학생은 학번·본인 비밀번호로 먼저 가입하고 운영 중인 수업 목록에서 수강할 수업을 선택한다.
신규 계정은 교수자가 별도로 본인을 확인해 발급한 일회용 활성화 코드를 입력해야 한다.
본인 확인과 해당 수업의 학번 명단 일치가 모두 완료되면 수강 연결된다. 학교 SSO는 사용하지 않는다.
계정·수강 명단·연결 상태는 SQLite에 저장하며, 이 기능 때문에 새 환경변수나 별도 DB 서버를 준비하지 않는다.

## 시작 주소

운영 서버에 갱신된 소스를 적용한 뒤 사용할 주소다. 문서 작성만으로 운영 서버에 적용되지는 않는다.

| 업무 | 주소 예시 |
| --- | --- |
| 학생 시작 | `https://ai.cbchoi.info:20010/student` |
| Next.js 학생 포털 | `https://ai.cbchoi.info:20010/app/student` |
| 새 학생 가입 | `https://ai.cbchoi.info:20010/student/register` |
| 공통 회원 로그인 | `https://ai.cbchoi.info:20010/student/login` |
| 내 수업·추가 수업 선택 | `https://ai.cbchoi.info:20010/student/account` |
| COME2201 내 점수 | `https://ai.cbchoi.info:20010/app/student?course_key=come2201&view=scores` |
| COME2201 내 점수 · Python 화면 | `https://ai.cbchoi.info:20010/courses/come2201/results` |
| 내 비밀번호 변경 | `https://ai.cbchoi.info:20010/student/password` |
| 초기 수업 비밀번호를 개인 비밀번호로 변경 | `https://ai.cbchoi.info:20010/courses/come2201/password` |
| 회원 비밀번호 복구 | `https://ai.cbchoi.info:20010/student/reset` |
| 개인정보 활용 안내 · 로그인 없이 조회 | `https://ai.cbchoi.info:20010/student/privacy` |
| COME2201 개인정보 활용 선택·철회 | `https://ai.cbchoi.info:20010/courses/come2201/privacy` |
| COME2201 수강생 통합 관리 | `https://ai.cbchoi.info:20010/courses/come2201/instructor/students` |
| COME2201 명단 관리 | `https://ai.cbchoi.info:20010/courses/come2201/instructor/registrations` |
| COME2201 명단 양식 | `https://ai.cbchoi.info:20010/courses/come2201/instructor/registrations/template.csv` |

IDE API 주소는 기존 `https://ai.cbchoi.info:20000`을 유지한다. 학생은 웹 회원 비밀번호 대신
수령 코드를 IDE에 입력한다. 웹 주소의 `20010`을 IDE API 설정에 넣지 않는다.

## 교수자: 학생의 현재 상태 확인

수업의 **수강생 관리**에서 학번 또는 이름을 검색한다. 해당 수업의 허용 명단,
가입 후 수강 신청, 기존 수강 기록을 합쳐 한 학생을 한 행으로 표시한다.
다른 수업에만 있는 학생이나 어느 수업도 신청하지 않은 공통 계정은 검색되지 않는다.
검색 결과는 50명씩 표시하며, **확인 필요**, **회원 수령 준비됨**, **본인 확인 대기**,
**허용 명단 없음**, **계정·수강 중지** 등으로 좁힐 수 있다.

| 표시 | 의미와 다음 조치 |
| --- | --- |
| 회원 가입 필요 | 허용 명단만 등록된 상태다. 학생에게 회원 가입과 수업 선택을 안내한다. |
| 본인 확인 필요 | 본인 확인 후 행의 코드 발급 링크를 연다. 학번이 미리 채워지며, 사유·본인 확인을 거쳐 기존 발급 절차를 수행한다. |
| 허용 명단 확인 필요 | 학생이 신청했지만 명단에 없다. 허용 명단 CSV를 검토한다. |
| 수업 선택 필요 | 계정과 명단은 준비되었으나 신청이 없다. 학생 포털에서 해당 수업을 선택하도록 안내한다. |
| 회원 수령 준비됨 | 회원·학생 기록의 연결 및 활성 수강 인증이 준비되었다. 과제의 공개·수령 기간은 별도로 적용된다. |
| 기존 수업 로그인 가능 | 기존 6자리 수업 비밀번호 인증이 유효하다. 공통 회원 미가입·중지 상태와 구분한다. |
| 수강 중지 | 수강 상세에서 사유와 인증 폐기 영향을 확인한 뒤 재활성화한다. 명단 재등록만으로 해제하지 않는다. |
| 학생 이용 중지 / 회원 계정 중지 | 공통 상태를 운영자에게 확인한다. 특정 수업의 수강 상태만 바꾸어 우회하지 않는다. |
| 인증 잠금 / 수업 인증 미설정 | 잠금 해제 시각을 확인하거나 수강 상세의 기존 비밀번호 관리 기능을 사용한다. |

**명단·본인 확인**은 허용 명단 CSV와 일회용 코드 발급을 위한 보조 화면이다.
가입 신청의 ‘연결 처리됨’은 처리 이력이며, 현재 이용 가능 여부는 수강생 통합 화면에서 확인한다.
기존 **학생 추가·CSV 일괄 등록** 기능도 수강생 관리 하단에 유지한다.
이는 수업 전용 비밀번호를 발급하는 방식으로, 회원 가입용 허용 명단 CSV와 형식이 다르다.
명단 제거는 기존 수강 중지를 의미하지 않는다. 실제 중지는 **수강 상세 · 인증 관리**에서 처리한다.

## 교수자: 수강 명단 등록

1. 교수자 포털에서 담당 수업을 연다. 새 수업이라면 수업 설정에서 운영 상태로 전환한다.
2. **수강생 관리 → 수강 허용 명단 CSV 관리** 또는 **명단·본인 확인**에서 **CSV 기본 양식 다운로드**를 누른다.
3. 예시 학번을 지우고 실제 해당 수업 학번을 입력하여 UTF-8 CSV로 저장한다. UTF-8 BOM도 허용한다.
4. 파일과 **명단 추가/허용 명단 교체**를 선택하고 **명단 변경 미리보기**를 누른다.
5. 신규·기존·중복·제외 인원과 본인 확인된 대기 신청 수를 검토한다. 아직 이 단계에서는 변경되지 않는다.
6. 확인란을 선택하고 **검토한 명단 반영**을 누른 뒤 추가·제외·수강 연결 결과를 확인한다.
7. 신규 학생의 본인을 별도로 확인한 뒤 **본인 확인·계정 복구 코드**에서 학번·사유·확인란을 입력하여 활성화 코드를 발급한다. 해당 학생에게 직접 전달한다.

가장 간단한 형식은 한 열이다. 학번의 앞자리 0이 사라지지 않도록 스프레드시트에서는 문자열로 입력한다.

```csv
student_key
20260001
20260002
```

한글 머리글도 허용한다.

```csv
학번
20260001
20260002
```

선택 사항으로 `student_key,name` 또는 `학번,이름`의 두 열을 사용할 수 있다. 이름은 연결 판정에
사용하거나 저장하지 않는다. 이 네 종류의 머리글만 허용하며 **비밀번호 열은 넣지 않는다**.
학번은 숫자 4~20자리, 파일은 최대 1 MiB·10,000명이며 중복 학번은 한 번만 반영한다.

기본 방식은 기존 명단에 **추가**한다. **교체**는 파일에 없는 학번을 허용 명단에서 제외하지만
이미 활성 수강 중인 학생을 중지하지 않는다. 실제 접근 중지는 **수강생 관리 → 수강 상세 · 인증 관리 → 수강 비활성화**에서
별도로 처리한다. 검토 화면은 15분 뒤 만료되며 다른 작업으로 명단이 바뀌면 재검토해야 한다.
명단과 본인 확인이 완료된 학생만 자동 연결된다. 업로드·반영·코드 발급 이력은 SQLite에 기록한다.

## 학생: 가입부터 과제 수령까지

1. 학생 시작 화면에서 **회원가입**을 연다.
2. 학번과 본인이 정한 8~128자 비밀번호로 가입한다. 가입 폼에는 수업을 입력하지 않는다.
3. 운영 중인 수업 목록에서 교과목·학기·분반을 확인하고 수강할 수업을 선택한다.
4. 교수자가 본인 확인 후 제공한 활성화 코드를 입력한다. 코드의 유효기간은 15분이며 한 번만 사용할 수 있다.
5. **내 수업**에서 본인 확인·명단 연결 상태를 확인한다. 명단과 일치한 활성 수업을 열 수 있다.
6. 연결된 수업에서 실습을 선택하고 과제 수령 코드를 발급한다.
7. IDE에 수령 코드를 입력하고 과제를 다운로드한다. 실습 후 공식 제출을 수행하고 결과를 확인한다.
8. 잘못 선택한 수업의 신청이 확인 대기라면 **수강 신청 취소**를 사용한다. 이미 수강 중인 수업은 교수자에게 중지를 요청한다.

명단 확인 대기라면 아직 수업 권한을 얻은 상태가 아니다. 학번·수업 선택을 확인하고 교수자에게
해당 명단 등록 여부를 문의한다. 학번을 바꿔 여러 계정을 만들거나 같은 비밀번호를 교수자에게 보내지 않는다.
명단을 나중에 올려도 자동 연결되므로 학생이 다시 가입할 필요는 없다.

학번 일치는 수강 자격 확인이다. 본인 확인 코드는 실제 학번 소유자를 확인한 후에만 전달한다.
새 코드를 발급하면 이전 미사용 코드는 무효가 된다. 코드 원문은 발급 응답에서만 표시하며 DB에는 해시를 저장한다.
코드를 받았다고 수업이 자동 선택되지는 않는다. 학생이 신청한 수업 중 명단이 일치하는 수업만 연결한다.
기존 파일럿에서 이미 만들어진 회원 계정은 갱신 시 기존 이용 권한을 유지한다. 새 계정부터 활성화 절차를 적용한다.

## 학생: 내 점수 확인

Next.js 학생 포털의 **내 점수**에서 수업을 선택한다. **내 수업**의 수업 카드에서도 해당 수업의
**내 점수**를 바로 열 수 있다. Python 수업 화면에서는 **내 점수** 메뉴를 사용한다.

- 본인에게 공개된 과제별 점수, 공식 제출 버전과 접수 시각을 확인한다. 다른 학생의 결과를 조회하지 않는다.
- **이번 제출 점수**는 현재 제출 결과다. 새 제출이 채점 대기·채점 중·결과 공개 대기이면 미확정으로 표시하며, 이전 점수나 0점을 대신 표시하지 않는다.
- **이전 제출 중 최고점**은 현재 제출을 제외한 공개 결과 중 최고점이다. 점수와 배점을 함께 확인한다.
- **이번 제출 이력 보기**로 같은 제출의 이력과 공개된 평가 내용을 확인한다. 웹의 최근 조회 범위를 넘은 이력은 IDE에서 확인한다.
- 과제별 배점이 다르므로 웹의 과제 점수를 더해 학기 성적이나 평균으로 표시하지 않는다. 학기 성적 산정 기준은 교수자의 안내를 따른다.

## 학생: 연구·수업 개선용 정보 활용 선택

수업의 **개인정보 활용 · 내 선택** 또는 **개인정보 활용** 메뉴에서 목적·항목·보관·철회 범위를
읽고 **동의하고 저장** 또는 **동의하지 않음 · 철회**를 선택한다. 로그인 전에는 `/student/privacy`에서
안내만 읽을 수 있으며, 조회나 로그인 자체로 동의를 기록하지 않는다.

동의는 **수업별 선택 사항**이다. 동의하지 않거나 응답하지 않은 학생도 과제 수령·제출·채점·점수 확인을
계속 이용한다. 광고·판매·외부 AI 학습에는 사용하지 않는다. 연구·수업 개선을 위한 활용에만 적용되며
수업 운영에 필요한 인증·제출·채점과 구분한다.

선택을 저장하면 결정, 안내 버전, 변경 시각과 변경 이력을 기록한다. 수업 보관 전에는 같은 화면에서
선택을 바꾸거나 철회할 수 있다. 다른 탭에서 먼저 선택을 바꾼 경우 오래된 화면이 덮어쓰지 못하므로
현재 상태를 다시 읽고 선택한다. 안내 버전이 바뀌면 기존 동의만으로 새 안내에 동의한 것으로 처리하지 않는다.
통신 오류로 저장 여부가 불명확하면 **동의 상태 새로고침**으로 실제 저장 결과부터 확인한다.

### 수업 보관 시 개인별 기록 처리

교수자의 **수업 보관·개인별 기록 파기**는 되돌릴 수 없는 작업이다. 성적 확정·정정·이의 확인 등
수업 운영 절차를 마친 뒤 대상 수업과 파기 범위를 검토하고 실행한다.

- 해당 수업 접근을 차단하고 학생의 개인별 명단·제출 코드·점수·활동 기록·개별 배포 자료와 연결정보를 제거한다. 동의한 학생도 개인별 원본은 남기지 않는다.
- 당시 현행 안내에 동의한 학생만 연구·수업 개선용 통계 대상이 된다. 미동의·미응답·철회 학생은 제외한다. 최소 5명 이상인 과제별 집계만 남기며, 학번·이름·코드 원문·정확한 활동 시각·개인별 해시는 보관하지 않는다.
- 집계 결과는 인원 구간과 평균 점수 구간이다. 개인과 연결할 수 없게 집계·파기한 후에는 특정 학생의 통계만 찾아 제외하거나 개인 점수·코드를 복원할 수 없다.
- 다른 수업에서 필요한 계정·자료와 교수자가 올린 공용 과제·교재는 해당 범위에서 유지한다.
- 파일·원격 실행공간 정리가 남으면 **파기 확인 필요**로 표시한다. 교수자는 남은 정리를 다시 실행하고 **관리 대상 학생 자료 파기 완료**까지 확인한다. 접근 차단만으로 파일 파기까지 끝났다고 판단하지 않는다.

원본 명단 CSV, 별도 백업·복제본, 교수자·학생이 내보낸 파일은 별도 관리 대상이다. 서버의 수업 보관으로
이 사본까지 자동 회수·삭제하지 않는다. 운영자는 보관 위치와 파기 기한을 확인하고, 백업 복원 시에는
이 수업의 파기 기록을 먼저 적용해 삭제한 개인 기록이 다시 사용되지 않도록 한다.

## 회원 비밀번호 변경·복구

- 로그인한 학생은 **회원 비밀번호 변경**에서 현재 비밀번호, 새 비밀번호와 새 비밀번호 확인을 입력한다. 새 비밀번호는 8~128자이며 현재 비밀번호와 달라야 한다.
- 분실한 학생은 관리자에게 본인 확인을 요청한다. 관리자는 해당 수업의 명단을 확인하고 사유·본인 확인란을 입력하여 **회원 비밀번호 복구 코드**를 발급한다.
- 담당 교수자 권한만 가진 계정은 신규 활성화 코드를 발급할 수 있지만 공통 회원 복구 코드는 발급할 수 없다. 여러 수업이 사용하는 공통 계정에 영향을 주기 때문이다.
- 학생은 로그인 화면의 **회원 비밀번호 찾기**에서 학번·복구 코드·새 비밀번호·확인 입력을 제출한다. 복구 코드는 15분·1회로 제한되며 재사용·다른 학번·만료 코드는 거절한다.
- 다른 사람이 학번으로 먼저 가입한 경우에도 관리자가 실제 소유자를 확인하고 복구 코드를 발급할 수 있다. 미확인 계정의 비밀번호 복구는 계정 활성화를 대신하지 않는다. 새 활성화 코드를 별도로 발급하며 기존 미사용 코드는 무효가 된다.
- 변경·복구 후 기존 공통 웹 세션·수업별 웹 세션·수령 코드·IDE 인증을 폐기한다. 활성 수강 교과목의 인증도 새 비밀번호로 갱신하므로 예전 6자리 비밀번호로 다시 접근할 수 없다. 학생은 새 비밀번호로 로그인하고 새 수령 코드로 IDE를 다시 연결한다. 기존 코드·제출·점수는 삭제하지 않으며 다른 학생이나 중지된 수강을 활성화하지 않는다.

## 기존 6자리 수업 비밀번호를 사용하는 학생

처음에는 교수자가 발급한 수업 비밀번호로 로그인할 수 있다. 이미 비밀번호가 등록된 학번을 새 회원가입에서 입력하여 기존 계정을
덮어쓸 수는 없다. 본인만 아는 개인 비밀번호로 변경하려면 다음 순서를 따른다.

1. 기존 `/courses/{교과목 코드}` 화면에서 학번과 기존 6자리 수업 비밀번호로 로그인한다.
2. **개인 비밀번호 설정·변경**을 선택한다. 해당 경로는 `/courses/{교과목 코드}/password`다.
3. 새 개인 비밀번호 8~128자와 확인 입력을 제출한다. 최초 설정은 로그인한 학생의 현재 수강 인증을 다시 검사한 뒤 계정 생성·비밀번호 갱신을 함께 저장한다.
4. 이후 개인 비밀번호로 본인 수업에 접근한다. 기존 초기 비밀번호·수령 코드·IDE 인증은 만료되므로 IDE에는 새 수령 코드를 입력한다.

이미 개인 회원 계정이 연결된 학생은 초기 수업 비밀번호로 개인 비밀번호를 재설정할 수 없다. **회원 로그인 → 비밀번호 변경**에서 현재 개인 비밀번호를 확인하거나 관리자에게 복구 코드를 요청한다. 과거의 `/activate-account` 연결 경로는 초기 PIN을 유지하는 기존 동작으로 남아 있으므로 새 학생 안내에는 `/password`를 사용한다.

`student_roster.csv`는 초기화 완료 표시가 있는 서버에서 다시 적용하지 않는다. 서버 재시작으로 학생이 변경한 비밀번호가 초기 값으로 돌아가지 않는다. 명시적인 CSV 재등록이나 관리자 비밀번호 초기화는 별도 관리 작업이다.

공통 회원 비밀번호는 직접 수업 로그인에도 사용할 수 있다. 공통 계정 생성·연결은 기존 학생의
과제·제출·성적을 새 학생으로 복제하지 않는다.

## 로그인과 공용 PC 종료

공통 회원 로그인은 최대 **10분** 유지한다. 수업 페이지를 열 때 현재 계정·수강·수업 상태를 다시
검사한다. 수령 코드를 발급하면 수업별 임시 세션은 소비하지만 공통 회원 로그인까지 종료하지는 않는다.
공통 로그인 없이 기존 수업 비밀번호만 사용한 경우에는 코드 발급 후 수업에 다시 로그인한다.

학생은 공용 PC를 떠나기 전에 학생 웹에서 **로그아웃**하고 브라우저를 종료한다. IDE의 공용 실습
종료는 로컬 코드·자료·IDE 인증을 정리하는 별도 절차이며 브라우저 회원 쿠키를 지우는 기능이 아니다.
비밀번호나 수령 코드를 브라우저 자동 저장·공유 문서에 남기지 않는다.

### 인증 쿠키와 계정 전환

Next.js 학생 화면(`/app/student`)에서 수업·과제를 선택하고 수령 코드를 발급한다.
**수령 코드 복사**와 **서버 주소 복사**를 이용해 Autograde IDE에 입력한다.
IDE로 이동했다 돌아오면 같은 학생의 로그인·수강 권한을 확인한 뒤 유효한 코드를 다시 보여준다.
코드는 열린 페이지의 메모리에만 보관하며 브라우저 저장소나 URL에 넣지 않는다.
페이지를 새로 고치거나 닫으면 코드를 다시 발급해야 한다.

- 창 전환만으로 진행 중인 발급 요청을 취소하거나 다시 보내지 않는다.
- 코드가 만료되었거나 IDE가 이미 사용한 코드라고 안내한 경우 명시적으로 새 코드를 발급한다.
- 이전 IDE 수락 시각은 과거 기록이다. 현재 코드 사용 완료·IDE 연결·파일 다운로드 성공을 뜻하지 않는다.
- 연결 확인 실패 시 개인정보를 가리고 다시 확인할 수 있게 한다.
- 만료·계정 변경·수강 권한 회수 시 코드를 지운다. 로그아웃은 응답을 기다리기 전에도 학생 정보를 지우며,
  응답이 끊기면 로그아웃 완료 확인 또는 명시적인 재시도가 끝날 때까지 이전 화면을 복원하지 않는다.

HTTPS 웹 주소로 설정한 경우 학생 인증 쿠키는 `Secure; HttpOnly; SameSite=Lax; Max-Age=600`을
사용하며 `Domain`을 지정하지 않는다. HTTP 파일럿 설정에는 `Secure`가 붙지 않으므로 외부 운영에는
HTTPS 웹 주소를 사용한다. 쿠키에는 비밀번호 대신 임의의 세션 식별자를 넣고, 서버에서도 만료·비밀번호
변경·수강 비활성화를 검사한다.

공통 회원 쿠키와 수업별 인증 쿠키는 `Path=/`다. 계정 전환 시 수업별 인증도 서버에 전달되어 이전 학생의
인증을 폐기한다. 로그인 화면의 CSRF 준비 쿠키는 별도 이름과 `Path=/student`를 사용해 현재 로그인 쿠키를
덮어쓰지 않는다. 여러 쿠키를 변경할 때는 각각의 `Set-Cookie` 응답 헤더로 전송한다.

공통 로그인 상태에서는 과제·자료·시험지의 로그아웃도 공통 로그인을 해제한다. 만료된 공통 로그인에서
과거 학생의 수업 쿠키로 되돌아가지 않는다. 기존 6자리 수업 로그인으로 전환하려면 해당 로그인 화면에서
명시적으로 인증해야 한다.

`Max-Age`가 있는 쿠키는 브라우저 종료만으로 즉시 지워진다고 가정할 수 없다. 공용 PC에서는 반드시
웹의 **로그아웃**을 사용한다. IDE 종료 후 파일 정리는 웹 로그인 해제와 별개다.

같은 호스트의 `20010`과 `20000`은 쿠키가 포트별로 격리되지 않는다. 두 서버는 동일한 신뢰 경계에 두고,
브라우저 웹 요청은 같은 출처의 경로를 사용한다. 제공한 Nginx 설정 예제는 Next.js 셸에 인증 헤더를 전달하지 않는다.
쿠키 동작 기준은 [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)와
[RFC 6265의 포트 격리 제한](https://www.rfc-editor.org/rfc/rfc6265#section-8.5)을 따른다.

### Next.js 시안과 운영 화면의 구분

`/app/preview/portal`은 예시 데이터로 화면을 체험하는 시안이며 실제 계정·수강 신청을 변경하지 않는다.
실제 Next.js 학생 포털은 `/app/student`이며 Python의 `/student/api/*`를 같은 출처로 호출한다.
Next.js 배포와 Nginx 연결을 하지 않은 환경에서도 기존 Python `/student/*` 회원 화면을 사용할 수 있다.
두 화면 모두 계정 생성과 수강 선택이 분리되어 있고 동일한 SQLite 계정·명단·세션 검사를 사용한다.

## 관리 범위와 현재 제한

- 담당 교수자는 자신의 수업 명단만 관리한다. 다른 수업의 명단과 회원 비밀번호는 조회하지 않는다.
- 기존 **학생 관리**에서 수강을 비활성화하면 해당 수업 접근이 차단된다. 명단 재업로드로 비활성 수강을 자동 복구하지 않는다.
- 허용 명단 교체는 수강 중지와 별개다. 교체 후 제외된 학생도 이미 활성 수강 중이라면 접근을 유지한다.
- 교과목 영구 삭제는 해당 수업의 명단·수강 연결을 제거한다. 다른 수업에서 사용하는 공통 회원 계정은 유지한다.
  파일과 데이터 보존 범위는 [교과목 영구 삭제](course-permanent-deletion.md)를 따른다.

교수자·학생 화면의 전체 이동 경로는 [포털 운영 안내](role-portals.md)를 참고한다.
