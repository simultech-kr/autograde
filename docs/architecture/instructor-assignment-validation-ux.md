# 교수자 과제 자료 제출·검증 안내 UX

작성: 2026-09-15. 2026-09-16에 아래 6단계의 서버 렌더링 웹 화면을 구현했다.
[사용 안내](../operations/instructor-web-mvp.md)를 참조한다. 자동 저장·미저장 이탈 확인과
실사용 교수자 참여 사용성 평가는 아직 제공/완료하지 않았다.
학생이 답안을 제출하는 화면이 아니라, 교수자가 문제·학생용 코드·채점 자료를 서버에 등록하고
검증받아 공개하는 화면을 정의한다. 교수자 단계 수와 버튼 명칭은 이 문서를 기준으로 한다.

## 1. 목적과 진입

교수자는 “어떤 파일을 준비해야 하나?”, “서버에 제대로 올라갔나?”, “채점이 되는가?”,
“실패하면 어디를 고쳐야 하나?”, “학생이 지금 받을 수 있나?”를 화면만으로 파악할 수 있어야 한다.

진입: `https://ai.cbchoi.info:20010/instructor` → 수업 선택 → 과제 관리 → **새 과제 등록**.
교수자 웹 진입/등록 기능은 신규 구현 대상이다. 기존 교과목별 교수자 주소는 유지한다.
상단에 수업명·코드·학기·분반을 표시하고 단계 이동 중 임의로 다른 수업으로 바뀌지 않게 한다.
처음에는 “등록 중인 과제는 학생에게 보이지 않습니다. 검증 후 공개해야 합니다.”를 표시한다.

교수자 화면에서는 학생 답안 제출과 구분하기 위해 **자료 등록 / 서버 검증 / 학생에게 공개**라는
용어를 사용한다. 파일 전송 성공을 “과제 공개 완료”라고 표시하지 않는다.

## 2. 6단계 안내

| 단계 | 교수자가 하는 일 | 시스템 안내·검사 | 주 버튼 |
| --- | --- | --- | --- |
| 1. 문제 준비 | 예제/직접 만들기, 제목·설명·언어 입력 | 필요한 자료와 지원 가능한 문제 유형 안내 | 학생용 파일 준비 |
| 2. 학생용 파일 등록 | starter ZIP 업로드, 문제 설명·파일 목록 확인 | 형식·크기·경로 검사, 학생 다운로드 미리보기 | 채점 자료 준비 |
| 3. 채점 자료 등록 | 입력/예상 출력·배점, 정답·오답과 기대 점수 준비 | 비공개 영역 분리, 필수 항목·배점 검사 | 검증 내용 확인 |
| 4. 서버 검증 | 대상 자료 요약 확인 후 검증 시작 | 작업 접수·대기·실행 상태와 진행 시각 표시 | 서버에서 검증 시작 |
| 5. 결과 확인·수정 | 결과와 근거 확인, 필요 시 해당 단계 수정 | 오류 원인·기대/실제 결과·수정할 위치 제시 | 공개 설정으로 / 해당 항목 수정 |
| 6. 공개 설정·완료 | 시작/마감·결과 공개 정책·학생 화면 확인 후 공개 승인 | 최신 검증·현재 상태·기간을 재확인하고 공개 | 학생에게 과제 공개 |

완료한 단계는 체크와 글자로, 현재 단계는 번호와 제목으로, 진행할 수 없는 단계는 이유와 함께
표시한다. 단계 번호만으로 검증 성공이나 공개를 추정하지 않는다. 하단에는 **이전**, **초안 저장 후
나가기**, 단계별 주 버튼을 둔다. 아직 입력하지 않은 항목이 있는 상태도 초안으로 저장할 수 있다.

## 3. 단계별 상세 안내

### 1단계 — 문제 준비

- 첫 문구: “학생이 풀 문제와 사용할 언어를 알려주세요.”
- 예제에서 만들기: C/C++ Hello World가 문제·starter·정답·오답·채점 설정을 자동 채운다.
  교수자는 다음 단계에서 자동으로 준비된 자료를 확인한다. 검증/공개를 자동 수행하지 않는다.
- 직접 만들기: C17/C++17, 단일 main.c/main.cpp의 표준 입력/출력 문제만 첫 MVP로 지원한다.
- 문제 설명 입력 아래에 요구사항·입력·출력·예제·제출 파일을 구분한 작성 틀을 제공한다.
- Windows 전용 API, 다중 파일 빌드, 임의 라이브러리 등이 필요하면 지원 범위 안내를 먼저 한다.
  옵저버/데코레이터 구조를 입출력 일치만으로 검증할 수 있다는 안내는 하지 않는다.
- 내부 과제 ID·서버 경로·release_id는 서버가 관리하고 입력을 요구하지 않는다.

### 2단계 — 학생용 파일 등록

- 첫 문구: “학생에게 내려줄 미완성 코드만 올려주세요. 정답은 다음 단계에 등록합니다.”
- 허용 형식/용량을 파일 선택 전에 표시한다. ZIP 5 MiB, 해제 후 20 MiB·1000개 파일 이하라는
  MVP 업로드 정책을 사용하며 실제 서버가 내려주는 제한과 화면 문구를 일치시킨다.
- 파일 상태는 선택됨 → 업로드 중 → 서버 검사 중 → 등록됨으로 구분한다.
- 정상 응답 후 파일 이름·크기·목록·서버 저장 확인을 표시한다. 링크/경로 탈출/중복 이름은 거절한다.
- 불필요한 최상위 폴더로 main.c가 중첩되면 문제 위치를 설명하고 다시 묶는 방법을 안내한다.
  서버가 자동으로 경로를 바꿔 과제 구조를 추정하지 않는다.
- 학생용 내려받기 미리보기는 실제 생성 예정 starter와 같은 규칙을 사용한다. 문제 설명으로
  README를 만들 때 기존 README 교체 여부를 확인한다.
- 시스템은 업로드 역할을 분리하지만 코드가 정답인지 의미적으로 보장하지 못한다.
  교수자가 “학생용 자료에 정답/비공개 입력을 넣지 않았습니다”를 파일 목록과 함께 확인한다.

### 3단계 — 채점 자료 등록

- 첫 문구: “이 자료는 교수자와 서버만 사용하며 학생에게 배포하지 않습니다.”
- 입력/예상 출력 표: 케이스 제목, 입력, 예상 출력, 배점, 학생 공개 여부. 기본은 비공개.
- 정답 ZIP: “모든 평가 기준을 만족하는 코드입니다. 검증에서 만점을 받아야 합니다.”
- 오답 ZIP: “일부 기준을 만족하지 않는 코드입니다. 예상 점수는 만점보다 낮아야 합니다.”
- 정답의 기대 점수는 만점으로 고정, 오답은 교수자가 지정한다. 예제 모드는 10점/5점으로 채운다.
- 배점 합계·오답 범위·필수 파일·언어를 확인한다. 정답과 오답의 소스 해시가 동일하면
  다른 예제가 필요하다고 안내한다. 의미적으로 다른 오답인지까지 자동 보증하지 않는다.
- 공백/줄바꿈 비교 규칙과 컴파일/실행 제한을 보여 준다. 출력 차이 미리보기에서 줄바꿈·공백을
  구분해 볼 수 있게 하되 학생 공개 결과에는 비공개 테스트 내용이 노출되지 않는다.
- 임의 grade.py나 실행 명령 입력 칸은 만들지 않는다. MVP의 고정 서버 채점기를 사용한다.

### 4단계 — 서버 검증

- 실행 전 요약: 선택 수업·언어, 자료 파일명, 테스트 수·만점, 정답/오답 기대 점수, 초안 저장 시각.
- 확인 문구: “등록한 정답과 오답 코드를 서버에서 실행합니다. 검토한 코드인지 확인해 주세요.”
  pilot-local은 보안 격리가 아님을 표시한다.
- 버튼을 누르면 먼저 초안을 저장·고정하고 작업 ID를 받는다. 이후 같은 검증을 다시 접수하지 않는다.
- 화면은 자료 확인 → 정답 검증 → 오답 검증 → 결과 정리 항목을 보여 주되,
  서버 단계 이벤트가 없으면 세부 항목은 “대기/확인되지 않음”으로 두고 전체 “검증 중”만 표시한다.
- 실제 단계별 이벤트 구현 시 revision/job ID, 단계, 시작/종료 시각, 기대/실제 결과를 서버에서 보낸다.
  타이머로 단계나 80% 같은 진행률을 만들어 내지 않는다.
- 탭을 닫아도 서버 검증이 취소되지 않으며 과제 목록에서 다시 확인할 수 있다고 안내한다.
  재접속 시 교수자 인증 후 저장된 작업 상태를 조회한다. 시간 초과를 자동 실패로 추정하지 않는다.

### 5단계 — 결과 확인·수정

첫 화면은 원시 로그가 아니라 요약과 다음 행동이다. 상세 진단·파일 위치·테스트 비교는 펼쳐서 본다.

| 검사항목 | 기대 | 실제 | 표시 예시 |
| --- | --- | --- | --- |
| 필수 자료·구조 | 제출 규격 준수 | 서버 검사 결과 | 통과 / 수정 필요 |
| 정답 채점 | 10점 | 10점 | 통과 |
| 오답 채점 | 5점 | 10점 | 수정 필요: 예상보다 높은 점수 |
| 검증 대상 | 최신 초안 revision | 작업이 사용한 revision | 일치 / 재검증 필요 |

위 값은 Hello World 설명용 예시이며 실제 결과로 표시하지 않는다.

- 성공 문구: “등록한 정답·오답 예제의 검증을 통과했습니다. 아직 학생에게 공개되지 않았습니다.”
- 실패 문구는 **무엇이 달랐는지 → 가능한 원인 → 수정 버튼** 순서로 쓴다.
  예: “오답이 예상 5점 대신 10점을 받았습니다. 오답 파일·테스트·배점을 확인하세요.”
- 수정 버튼은 2단계 학생용 파일 또는 3단계 채점 설정의 해당 필드로 이동하고 나머지 입력은 보존한다.
- 실패를 통과시키려고 실제 점수를 기대 점수에 자동 대입하지 않는다. 기대값 변경도 명시적 수정이다.
- 자료/언어/테스트/설명을 변경하면 revision을 바꾸고 이전 검증은 참고 이력으로 남긴다.
  최신 자료로 재검증 전에는 공개하지 않는다. 검증 중에는 편집을 잠근다.
- 컴파일러 부재·디스크 부족·작업자 중단은 운영자 조치 대상으로 구분하고 과제 파일 수정만 요구하지 않는다.
- 검증 통과는 특정 예제의 실행 결과일 뿐 전체 정답성·보안·공식 성적 운영을 보증하지 않는다.

### 6단계 — 공개 설정·완료

- 현재 수업·학기·분반, 제목·언어, 학생 다운로드 목록, 시작/마감(시간대), 결과 공개 방식을 확인한다.
- 수업이 준비 상태라면 운영 전환 필요를 알리고, 보관 상태라면 공개를 차단한다.
- 일정/결과 공개 정책을 이 단계에서 변경하면 기존 immutable release에 반영할 수 있도록
  새 revision을 고정하고 재검증을 요구한다. UI가 검사된 버전과 다른 공개본을 만들면 안 된다.
  예제 기본 일정은 1단계의 선택 설정에서도 미리 입력 가능하게 해 반복 검증을 줄인다.
- 마지막 버튼은 “등록 완료”가 아니라 **학생에게 과제 공개**로 한다. 명시적 승인 이후에만 공개한다.
- 성공 시 “공개 완료”와 실제 학생 수령 가능 여부를 구분한다. 시작 전이면 예정 시각을 표시한다.
- 성공 화면의 다음 행동: 학생 페이지 열기, QR 보기, 과제 현황 보기. 실제 학생 인증은 따로 필요하다.
- 공개 후 원본 덮어쓰기는 불가하다. 변경은 새 버전 초안 복제 또는 별도 마감 연장 절차로 안내한다.

## 4. 중단·오류에서 이어가기

| 상황 | 안내와 복구 |
| --- | --- |
| 파일 업로드 실패 | 해당 파일만 다시 선택, 다른 서버 저장 자료는 유지. 브라우저는 파일 선택값 자동 복구 불가 |
| 초안 저장 응답 유실 | 초안 ID/revision으로 저장 상태 확인. 중복 초안 생성 금지 |
| 인증 만료 | 교수자 재인증 → 서버 저장 초안 이어가기. 토큰·비공개 파일을 localStorage에 저장하지 않음 |
| 검증 접수 응답 유실 | 작업 ID/요청 키로 상태 확인. 새 검증을 무조건 시작하지 않음 |
| 서버 재시작 | queued는 재개, running은 interrupted로 표시하는 서버 복구 정책에 맞춰 재검증 안내 |
| 두 탭 동시 수정 | “다른 창에서 변경되었습니다.”, 덮어쓰기 금지·최신 상태 다시 보기 |
| 공개 버튼 반복/응답 유실 | 현재 공개 상태를 조회해 같은 release 재사용, 새 버전 자동 생성 금지 |
| 공개됐지만 학생에게 안 보임 | 수업 상태·교과목·시작/마감·공개 상태를 체크리스트로 표시 |

오류 도움말에는 과제/검증 ID·발생 시각·안전한 오류 분류만 복사한다. 전체 입력/정답/비밀번호/
토큰/내부 서버 경로를 자동 첨부하지 않는다. 개인정보·비공개 자료는 화면 녹화나 사용성 로그에 넣지 않는다.

## 5. 구현 연결과 완료 기준

- MVC View는 6단계 표시·문구·오류 위치를 담당한다. Controller는 인증·CSRF·폼 검증과
  안전한 응답 변환을, AssignmentAdminService는 revision·자료·검증·공개 조건을 담당한다.
- 초안 저장 단계, 완료 조건, 다음 허용 동작, 필드별 오류는 서버가 제공한다.
  파일 업로드 성공·채점 통과·공개를 클라이언트 클릭만으로 확정하지 않는다.
- 공개 가능 여부는 최신 revision 검증과 교과목 상태를 원자적으로 재확인한다.
- 교수자 전용 비공개 업로드, 크기 제한, CSRF/Origin, ZIP 검사, 작업 제한은 기존 MVP 설계를 따른다.
- 안내문은 서버의 실제 제한·지원 언어·정책에서 생성해 문서와 구현 값이 달라지지 않게 한다.

인수 시나리오:

1. 교수자가 새 come2201 과제를 예제에서 만들고 구두 도움/CLI 없이 공개까지 완료한다.
2. 직접 만든 과제의 틀린 오답/예상 출력을 넣어 검증 실패 → 해당 필드 수정 → 재검증 성공.
3. 단계마다 탭 닫기·재인증·업로드/응답 유실 후 저장된 자료를 잃거나 중복 작업을 만들지 않고 복귀.
4. 검증 후 자료/정책 변경으로 이전 성공을 재사용하지 못하고 재검증 안내를 받는다.
5. 정답/테스트 자료가 학생 파일과 API에 포함되지 않으며 공개 전 학생 수령이 불가능하다.
6. 실제 HTTPS 웹과 기존 학생 확장에서 공개 과제 수령·제출·점수 확인까지 연결된다.

교수자 역할 참여자에게 자료 준비 시간, 도움 요청 횟수, 실패 후 복구 여부,
“업로드 완료/검증 통과/학생 공개”의 구분 여부를 확인한다. 테스트 결과는 아직 확보하지 않았다.
