# 교수자 안내: 작성·검사·프롬프트 리뷰

## 수업 흐름 제안

각 실습은 60~90분을 기준으로 조정합니다. C++ 가상 함수와 스마트 포인터를 모르는 학생에게는
사전 설명 시간을 추가하세요. 두 패턴을 한 번에 처음 접하는 수업이면 두 주차로 나누는 편이 좋습니다.

1. 문제 상황을 읽고 기존의 직접 호출/조합 클래스 방식이 왜 불편한지 학생이 설명합니다.
2. 학생이 제공된 `pattern.hpp`의 TODO를 작성합니다.
3. 시연 프로그램과 공개 테스트를 실행합니다. 미완성 starter도 컴파일되지만 검사는 실패해야 합니다.
4. 학생이 코드·실행 로그를 `REVIEW_PROMPT.md`에 넣어 AI 검토를 요청합니다.
5. 지적된 내용을 직접 확인·수정하고 다시 실행합니다.
6. 최종 코드, 실행 결과, 패턴 역할 설명, AI 제안 중 수용/거절한 내용과 이유를 제출합니다.

**배포 단위는 각 실습의 `starter/`뿐입니다.** 상위 `pattern-workshops/` 전체를 학생 bundle로
묶으면 교수자 참고 정답이 함께 나갑니다. `instructor/pattern.hpp`는 교수자 확인용입니다.

## 평가 예시: 각 10점

### Observer

- 3점: 모든 살아 있는 구독자에게 값·순서·횟수를 올바르게 전달.
- 2점: 중복 등록 방지와 해지·재구독.
- 2점: null·소멸된 구독자 처리와 비소유 수명 관리.
- 2점: 추상 Observer 의존, 새 구독자 추가 시 게시판 변경 불필요.
- 1점: 본인 설명과 수정/재검증 근거.

### Decorator

- 3점: 위임을 통한 중첩·반복 옵션 가격 계산.
- 2점: 기본 설명과 장식 순서 누적.
- 3점: 공통 인터페이스·합성 구조, 새 기본 음료에도 옵션 재사용 가능.
- 1점: 제공된 null 검사와 가상 소멸자·단일 소유권 유지.
- 1점: 본인 설명과 수정/재검증 근거.

공개 테스트 개수와 점수를 일대일 대응시키지 않습니다. null 검사 등 일부 코드는 이미
제공되므로 단순 테스트 통과만으로 구현 점수를 전부 부여하지 마세요. AI는 검토 보조이며
최종 점수와 부정행위 판단은 교수자가 근거를 확인하고 결정합니다.

## 교수자 참고 구현 확인

학생 배포 폴더를 별도 임시 작업 폴더로 복사한 뒤, 그 복사본의 `pattern.hpp`만 해당
`instructor/pattern.hpp`로 교체합니다. 기존 학생 작업 폴더를 덮어쓰지 마세요.
각 README의 시연/공개 검사 명령을 실행합니다.

- Observer: 시연 출력 일치, `4/4 checks passed`.
- Decorator: 시연 출력 일치, `5/5 checks passed`.
- Release 빌드에서도 검사가 사라지지 않도록 check는 `assert` 대신 명시적 오류 처리를 사용합니다.

자동 회귀시험은 `tests/integration/test_pattern_workshops.py`입니다. 별도 임시 폴더에서
starter와 참고 구현을 실제 C++ 컴파일·실행하고 일부 잘못된 구현이 거절되는지도 확인합니다.
이 검사는 교수가 검토한 합성 코드만 실행하며 임의 학생 코드용 보안 격리가 아닙니다.

## 현재 자동채점 서비스와의 관계

이번 요청 범위는 **문제·코드 입력 틀·공개 실행 확인·검토 프롬프트**입니다.
서비스에 과제를 등록하거나 학생에게 공개하지 않았습니다. 전용 `grade.py` 어댑터나
AI 채점 API도 추가하지 않았습니다. 서버 자동채점으로 확장할 때는 수정 가능한 학생
`check.cpp`의 출력을 믿지 말고 교수자가 보관한 검사를 사용해야 합니다. 학생 소스 실행과
신뢰 채점 제어는 분리하고 기존 배포 전 보안 기준을 적용합니다.

현재 Windows용 빌드 명령과 CMake 파일은 제공하지만 실제 VS2022/2026 설치·실행은
이 개발 환경에서 검증했다고 간주하지 않습니다.

## macOS 표준 헤더 경로

현재 개발 환경에서는 기본 `c++` 명령이 표준 헤더를 찾지 못했고 SDK의 C++ 헤더 경로를
명시하여 검증했습니다. 학생 코드의 `algorithm`/`memory` include를 지워 해결하지 마세요.
`xcrun --show-sdk-path`가 정상적으로 동작하고 해당 SDK 아래 `usr/include/c++/v1`에
표준 헤더가 있는 환경에서 다음처럼 실행할 수 있습니다.

```bash
c++ -std=c++17 -Wall -Wextra -isystem "$(xcrun --show-sdk-path)/usr/include/c++/v1" main.cpp -o demo
./demo
c++ -std=c++17 -Wall -Wextra -isystem "$(xcrun --show-sdk-path)/usr/include/c++/v1" check.cpp -o check
./check
```

SDK 조회 자체가 실패하면 C++ 개발 도구 환경을 먼저 정비해야 합니다. 컴파일 환경 오류를
학생의 패턴 구현 오류나 0점으로 처리하지 않습니다. Windows의 Developer Command Prompt와
Linux/WSL2의 컴파일러 설치 상태도 수업 전에 확인하세요.
