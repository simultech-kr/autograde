# 학생 학습내용 내보내기와 공용 실습 종료

VS Code 및 Autograde IDE 확장 0.5.12는 작성 중인 코드, 이전 제출본, 강의자료를 골라
독립된 폴더 또는 ZIP으로 저장한다. 내보내기는 공식 제출이 아니며 점수나 제출 대상을 바꾸지 않는다.
공용 실습실에서는 실행기가 만든 일회용 작업 공간을 사용하고, 학생이 가져갈 복사본은 그 밖에 저장한다.

## 내보내기

1. **Autograde 학습 홈 → 내 학습내용 내보내기**를 선택한다. 사이드바의 `…` 메뉴에서도 연다.
2. 필요한 항목을 여러 개 선택한다.

   | 항목 | 포함하는 내용 |
   | --- | --- |
   | 작성 중인 코드 | 현재 연결한 과제 폴더의 코드. 인증이 끝난 공용 세션에서는 이번 작업 공간의 코드를 선택할 수 있다. |
   | 이전 제출본 | 현재 인증된 bundle 과제의 제출 시점별 코드. 여러 버전을 선택할 수 있으며 목록은 최근 100건이다. |
   | 강의자료 | 현재 공개된 Git 콘텐츠 모음. 선택한 공개본을 확인하고 변경 파일을 수신한다. |
   | 개인 배포 자료 | 본인에게 배정된 PDF·ZIP 원본. 배포 기간과 파일 버전을 확인한다. |

3. 미저장 파일이 있으면 **저장하고 내보내기** 또는 **디스크에 저장된 내용만**을 선택한다.
   취소하거나 저장에 실패하면 중단한다. 이름 없는 문서는 먼저 과제 폴더에 저장하거나,
   포함되지 않는다는 안내를 확인한 뒤 명시적으로 제외한다.
4. **폴더** 또는 **ZIP**을 선택하고, 작업 공간 밖의 개인 저장 위치나 USB 폴더를 고른다.
5. 완료 알림의 저장 위치를 확인한다. ZIP은 일반 압축 프로그램에서 열 수 있다.

저장 위치에는 새로운 `autograde-learning-날짜-식별자` 폴더나 ZIP을 만든다. 현재 코드,
제출 버전, 강의자료는 각각 하위 경로로 구분한다. `EXPORT-INFO.json`에는 포함된 파일의
상대 경로·크기·해시가 들어간다. 기존 파일과 이전 내보내기는 덮어쓰지 않는다.

로그인 정보, 숨김 파일·폴더, Git 내부 기록, 알려진 인증 파일, 빌드·의존성 폴더는 코드 내보내기에서
제외한다. 링크·장치 파일은 지원하지 않는다. 전체 작업 환경을 복제하는 백업은 아니므로 필요한
파일이 포함되었는지 완료 목록과 결과물을 확인한다. 최대 파일 5,000개, 전체 100 MiB이며
초과하면 항목을 나누어 내보낸다.

현재 로컬 코드만 내보낼 때는 서버 제출이 필요 없다. 서버의 제출본·강의자료·개인 배포 자료에는
유효한 학생 인증과 연결이 필요하다. 권한 변경·새 공개본·세션 변경·취소가 발생하면 중단한다.
자료가 캐시에 있어도 현재 배포 권한을 확인한다. 내보낸 복사본은 이후 서버의 배포 중단이나
공용 실습 정리로 삭제되지 않는다.

## 실습실 실행 설정

Code-OSS와 내장 확장의 준비·빌드는 [전용 IDE 실행 안내](autograde-ide-poc.md)를 따른다.
저장소 루트에서 다음과 같이 실행한다. runtime 경로는 해당 PC의 운영 계정이 소유한 짧은
절대 경로로 바꾼다. 아래 `seat-01`은 좌석 별칭이며 학생 인증 정보가 아니다.

```sh
node ide/code-oss/manage.mjs run --source .cache/code-oss \
  --runtime /absolute/short/autograde-lab --learner seat-01 \
  --learning-lifetime shared --learning-policy standard
```

`--learner`를 지정하면 기본 수명은 `shared`다. 공용 모드에서는 기존 `--workspace`를 받지 않는다.
매 실행마다 새 `e-<식별자>/workspace`, `materials`, IDE 프로필을 생성한다. 같은 좌석 별칭으로
다시 시작해도 직전 작업 공간을 재사용하지 않는다. 기존 `l-<별칭 해시>` 개인 폴더는 삭제하거나
새 학생에게 자동 연결하지 않으며, 남아 있으면 실행기가 운영자에게 알린다.

일반 VS Code에 확장만 설치한 경우와 `--learner` 없는 개발 실행에는 자동 정리가 적용되지 않는다.
개인 PC에서 기존 파일을 계속 사용할 때만 `--learning-lifetime persistent`를 명시한다.
공용 실습 종료 정리는 macOS·Linux 실행기를 대상으로 하며, Windows 네이티브 실행은 거절한다.
WSL2는 Linux 쪽에서 실행하는 구성이지만 실제 배포 인수 시험은 별도로 수행한다.

### 다른 실습실 PC 갱신

기존 Code-OSS 빌드가 있는 PC는 실행 중인 공용 실습을 종료하고, 저장소 루트에서 다음을 수행한다.
고정 Code-OSS 소스가 요구하는 Node.js 24.18.0을 사용한다.

```sh
git pull --ff-only origin main
npm --prefix extensions/vscode ci
node ide/code-oss/manage.mjs prepare --source .cache/code-oss
node ide/code-oss/manage.mjs verify --source .cache/code-oss
```

이후 위의 `run ... --learning-lifetime shared` 명령으로 실행한다. 새 PC에 `.cache/code-oss`가
없으면 먼저 [소스 준비·운영체제별 빌드](autograde-ide-poc.md)를 완료한다. `git pull`은 소스만
갱신하며 IDE 빌드나 기존 내장 확장을 자동으로 바꾸지 않는다.

일반 VS Code에서 내보내기만 시험하려면 다음과 같이 설치 파일을 만든다. 이 경우 공용 실습의
종료 후 정리는 활성화되지 않는다.

```sh
npm --prefix extensions/vscode ci
npm --prefix extensions/vscode run package:vsix
code --install-extension extensions/vscode/autograde-vscode-0.5.12.vsix
```

## 학생 이용 순서

1. 새 공용 IDE 세션을 시작한다. 기존 학생의 작업 폴더 대신 빈 실습 공간이 열린다.
   제한 모드라면 상단 **Manage**에서 이번 세션의 작업 폴더만 신뢰한 뒤 진행한다.
2. API 주소를 확인하고 학생 웹에서 발급한 새 수령 코드를 입력한다.
3. 수락한 과제의 starter를 이번 실습 공간에 새로 내려받는다. 이전 작업을 계속하려면
   **제출 이력·코드 복원**으로 본인의 서버 접수본을 새 작업 공간에 복원한다.
4. 실습·제출·채점 결과 확인을 진행한다. 보관할 코드와 자료는 **내 학습내용 내보내기**로 저장한다.
5. **공용 실습 종료** 또는 로그아웃을 누른다. **먼저 내보내기**를 선택하면 내보낸 후에도
   IDE가 열려 있으므로 결과물을 확인하고 다시 종료한다.
6. IDE 전체 종료와 실행기의 정리 완료를 확인한 뒤 다음 학생이 시작한다.

공용 모드에서는 한 번 인증한 세션의 학생·과제 인증을 교체하지 않는다. 다른 과제를 받거나
인증 만료·확장 호스트 재시작 후 다시 인증하려면 필요한 로컬 코드를 내보내고 실습을 종료한 뒤
새 세션을 시작한다. 확장 호스트 재시작 자체는 파일을 삭제하지 않는다.

공용 모드의 **내 배포 자료** 다운로드는 이번 세션의 임시 자료 폴더에 저장한다.
**강의자료 업데이트 → 내 폴더에 저장**은 명시적 내보내기이므로 세션 밖의 위치를 선택해야 한다.

**아직 제출하거나 내보내지 않은 코드도 종료 시 삭제된다.** 자동 제출·자동 서버 백업은 아니다.
코드 저장 버튼은 로컬 저장이며 서버 보관을 뜻하지 않는다. 서버에 접수된 제출 이력·성적과
정리 대상 밖에 내보낸 파일은 유지된다.

macOS에서는 빨간 창 닫기 버튼만 눌러도 앱 프로세스가 남을 수 있다. **공용 실습 종료** 또는
`Command+Q`로 앱을 종료한다. 창을 닫은 것만으로 정리가 끝났다고 판단하지 않는다.

## 정리 범위와 실패 처리

실행기는 자신이 만든 세션 표식·경로·소유권·프로세스를 검증한 뒤 해당 세션의 코드, 자료 캐시,
IDE 설정·기록·백업을 정리한다. 개인 폴더나 내보낸 파일은 대상으로 등록하지 않는다.
학생이 임의로 작업 공간 밖에 저장한 파일도 자동 삭제하지 않는다.

IDE 강제 종료는 실제 프로세스 종료 뒤 정리한다. 실행기까지 강제 종료되거나 전원이 끊긴 경우
다음 실행에서 이전 프로세스가 멈췄는지 확인하고 남은 소유 세션을 정리한다. 이전 프로세스가
살아 있거나 표식 손상·권한 오류·불확실한 시작 상태 때문에 정리를 확인할 수 없으면
**새 학생의 세션을 시작하지 않는다.** 임의 경로를 강제로 지우지 말고 운영자가 해당 좌석을
회수하여 이전 프로세스와 소유 경로를 확인한다.

이 기능은 공용 좌석에서 작업 내용이 다음 실행에 남는 것을 줄이는 수명 관리다. 같은 OS 계정의
다른 프로그램이 활성 작업 파일을 읽는 것, 디스크 복구·OS 백업·학생의 외부 저장까지 차단하는
보안 격리는 아니다. 접근 자체를 막아야 하는 실습실은 학생별 OS 계정 또는 관리된 VM을 함께 사용한다.

## 배포 전 확인

- 새 좌석 세션에서 과제 수락 후 빈 작업 공간에 새 starter가 생기는지 확인한다.
- 현재 코드·서버 제출본·강의자료를 선택하여 폴더와 ZIP을 각각 내보낸다.
- 취소·저장 실패·인증 만료·배포 변경 시 완료로 표시하지 않는지 확인한다.
- 종료 후 세션의 코드·캐시·IDE 기록이 없어지고 내보낸 폴더·ZIP은 남는지 확인한다.
- 같은 좌석을 다시 실행했을 때 빈 작업 공간인지 확인한다.
- IDE 강제 종료와 실행기 강제 종료를 별도로 시험하고, 정리 실패 때 다음 학생이 시작할 수 없는지 확인한다.

macOS의 실제 Code-OSS 실행에서는 새 공용 프로필과 학습 홈 표시, **공용 실습 종료**를 통한
앱 종료, 임시 작업 공간·프로필 제거, 외부에 내보낸 ZIP 보존을 합성 코드로 확인했다.
WSL2 실기기 시험과 운영 학생 인증을 사용하는 원격 시험은 별도 인수 항목이다.
