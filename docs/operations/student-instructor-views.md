# 학생·교수자 화면 분리와 수락 과제 목록

2026-09-13 구현, VS Code 0.4.1 기준. 기존 SQLite 및 수령 코드 인증을 유지합니다.

| 화면 | 대상과 내용 | 접근 경로 |
| --- | --- | --- |
| 학생 웹 | 교과목 선택 → 학번·전용 비밀번호 → 수락할 공개 과제 선택 → 수령 코드 발급 | 웹 20010의 `/courses/come3105` 또는 `/courses/come2201` |
| 학생 VS Code 확장 | **현재 수령 코드로 수락한 실습만** 다운로드·제출·결과·이력 조회 | API 20000, 사이드바 `내가 수락한 실습` |
| 교수자 웹 | 교과목 전체 학생·수락·다운로드·제출·점수 조회 | 웹 20010의 `/courses/come3105/instructor` 또는 `/courses/come2201/instructor` |

학생 웹은 좁은 학생용 화면, 교수자는 넓은 표 중심의 별도 관리 화면으로 표시합니다.
학생 페이지에는 교수자 관리 메뉴를 넣지 않습니다. 교수자 경로는 별도 교수자 Basic 인증을
요구하며 학생 브라우저 cookie나 확장의 access token으로 열 수 없습니다. Basic 인증은 실제
배포에서 HTTPS로만 사용하세요. 교수자 계정별 권한 분리는 별도 후속 작업입니다.

## 수락의 의미

### 학생 웹의 실습 선택 화면 (2026-09-16 수정)

학번·비밀번호 인증 후 공개된 실습을 **라디오 버튼으로 하나 선택**하고
**선택한 실습 수령 코드 발급**을 누릅니다. 선택 전에는 브라우저가 발급을 막습니다.
선택은 아직 수락 완료가 아니며 아래와 같이 확장에서 코드를 교환해야 수락됩니다.

수령 가능한 과제가 없으면 선택 입력/발급 버튼과 “선택하세요” 안내를 표시하지 않습니다.
대신 인증은 완료되었음을 알리고, 담당 교수자에게 공개·시작·마감을 확인하도록 안내합니다.
**과제 목록 새로고침**은 같은 웹 세션에서 다시 조회하므로 인증이 유효한 동안 비밀번호를
재입력하지 않아도 새로 공개된 과제를 확인할 수 있습니다. 비공개 과제의 제목은 노출하지 않습니다.

웹 포털 자체도 `Referrer-Policy: same-origin`을 보내도록 수정했습니다. Nginx 예제의 같은
정책은 유지해도 되며 Origin/CSRF 검사는 끄지 않습니다. 확장 API의 `no-referrer` 정책은 유지합니다.

수정한 서버 코드를 운영 서버에 반영하고 `autograde-pilot`을 정상 종료·재시작해야 적용됩니다.
확장 재설치는 필요 없습니다. 기존 로그인 탭을 닫고 학생 페이지를 새로 열어 시험하세요.
검증: 선택·빈 목록·수령 범위·HTTP 관련 자동 시험 47개 통과, 로컬 합성 계정의 실제 브라우저에서
미선택 차단·라디오 선택·코드 발급 확인. 운영 도메인·실제 학생 계정에는 변경/시험하지 않았습니다.

웹에서 수령 코드만 발급한 상태는 **아직 수락 완료가 아닙니다**. 확장에 코드를 입력하고
서버에서 해당 과제와 인증 세션을 결합한 시점이 수락입니다. 한 수령 코드는 한 과제에 묶이며,
이번 변경은 이를 여러 과제에 대한 포괄 권한으로 확대하지 않습니다.

- 수락하지 않은 다른 공개 과제는 학생 웹에서 선택할 수 있지만 확장 목록에는 표시되지 않습니다.
- 다른 학생·다른 교과목의 과제와 제출 결과는 표시하지 않습니다.
- 다른 과제로 전환하려면 학생 웹에서 그 과제의 새 수령 코드를 발급받아 입력합니다.
- 과거 여러 과제의 수락 이력을 현재 한 세션에 모두 모아 보여주는 기능은 이번 범위가 아닙니다.
- 창 종료·로그아웃·서버 주소 변경 때의 메모리 인증/목록 삭제 정책은 유지합니다.
- 마감 후 새 수령 코드 발급, 숨긴 과제의 과거 점수 열람 제한은 이번 변경으로 해결하지 않습니다.

## 서버에서 적용하는 범위

- 새 `GET /v1/accepted-assignments`는 인증을 요구하고 현재 세션의 수락 과제만 반환합니다.
  수락 기록 없는 호환 로그인은 빈 목록, 만료·폐기 토큰은 인증 오류입니다.
- 학생용 CourseAPI는 기존 `/v1/assignments`도 같은 수락 전용 목록으로 처리합니다.
- 수락 기록 없는 호환 토큰으로 학생 API의 직접 다운로드·제출·결과/이력을 호출하면
  `assignment_acceptance_required`로 거절합니다. 로그인 정보 확인·자신의 세션 종료는 계속 가능합니다.
- 수락한 세션에서 다른 과제 ID를 URL에 넣어도 기존 과제 범위 검사를 우회할 수 없습니다.
- 단일 교과목 호환 서비스의 기존 전체 목록 API는 기존 도구를 위해 남습니다. 독립 웹용
  20000 포트는 CourseAPI를 사용하는 `autograde-pilot`으로 실행해야 합니다.

## 업데이트

서버를 먼저 업데이트한 뒤 VS Code 0.4.1 VSIX를 설치합니다. 확장은 이전 서버에서 새 API가
404를 반환해도 전체 과제 목록으로 우회하지 않고 서버 업데이트를 안내합니다.
설치 파일: [autograde-vscode-0.4.1.vsix](../../extensions/vscode/autograde-vscode-0.4.1.vsix).
VS Code의 확장 보기에서 `Install from VSIX...`로 선택한 뒤 창을 다시 로드하고 새 수령 코드를 입력합니다.
패키지는 Marketplace 서명본이 아니며 실제 IDE 설치·UI 시험은 별도입니다.
Visual Studio 확장은 이번에 새로 패키징하지 않았지만, 독립 웹 CourseAPI를 사용하면 기존
목록 요청에도 서버의 수락 전용 정책이 적용됩니다.

이번 변경은 실제 서비스 코드에 반영했습니다. 이전 대화의 관리 시안에 있던 웹 과제 업로드·공개
버튼 및 교수자 접속 관리 조작 전체를 구현한 것은 아닙니다. 과제 관리 변경은 현재 CLI,
교수자 웹은 조회 중심이며 운영 서버 재시작과 확장 설치도 자동으로 수행하지 않습니다.

## 직접 확인

1. 같은 교과목에 서로 다른 공개 과제 A와 B를 준비합니다. 학생 웹에는 둘 다 보여야 합니다.
2. A의 수령 코드를 확장에 입력하면 `내가 수락한 실습`에는 A만 보여야 합니다.
3. A를 다운로드·제출하고 자신의 결과와 제출 이력을 확인합니다. B의 주소를 직접 요청하면 거절되어야 합니다.
4. B 코드로 전환하면 현재 목록이 B로 바뀌어야 합니다. A의 파일은 PC에서 자동 삭제되지 않습니다.
5. 학생 로그인 상태로 교수자 URL을 열어도 교수자 인증이 요구되어야 합니다.
6. 교수자로 로그인하면 학생 화면과 다른 전체 교과목 현황 화면이 보여야 합니다.

이 접근 범위 개선은 일반 학생 배포 승인과 별개입니다. 격리·성적 무결성·복구 검증은
[배포 준비 문서](student-deployment-preparation.md)의 남은 조건을 따릅니다.

## 검증 결과

- 전체 서버 회귀: 780개 통과, 환경 제한 19개 제외(Windows/MSVC 2, JDK 5, .NET SDK PATH 12).
- 관련 HTTP·서비스·교과목 시험: 72개 통과. 위 전체 시험과 중복됩니다.
- VS Code: 132개 통과, TypeScript 컴파일 및 0.4.1 VSIX 생성 성공.
- 설치 파일 안의 버전, 수락 전용 API, 사이드바 이름 확인 및 SHA256SUMS 기록 완료.
- 운영 서버 재시작·실제 IDE 설치는 수행하지 않았습니다. 새 DB 마이그레이션도 추가하지 않았습니다.
