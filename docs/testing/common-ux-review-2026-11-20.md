# 과제·성적·수강 업무의 UX 점검

2026년 11월 20일 · 교수자 포털과 학생 웹 포털 · 로컬 검증

교수자가 학생에게 보여 줄 내용을 판단하는 작업과 학생이 신청할 수업을 확정하는 작업을 먼저 점검했다. 이어서 교수자가 목록을 읽는 도중 서버 응답이 늦거나 일괄 작업을 취소할 때 어디서 이어갈 수 있는지 확인했다. 검토 기준은 [공통 UX 설계·개발 지침](../../design/portal-ux-guidelines.md)이다.

| 적용 순서와 작업 | 재현한 문제 | 변경 후 판단·복구 방법 | 지침 |
| --- | --- | --- | --- |
| 1. 교수자가 성적표의 학생 공개 범위를 검토 | 공개 열을 선택하지 않거나 다른 탭에서 이미 공개한 뒤 미리보기를 다시 열면 교수자용 열과 메모가 표시됐다. 교수자 인증을 거친 미리보기 화면에서 재현했다. | 선택이 비면 공개 항목 선택으로 돌아간다. 초안 상태가 바뀌면 현재 상태를 표시한다. 두 경우 모두 표를 표시하지 않고, 기존 셀 상세 주소에서도 값을 열 수 없다. | EDU-06, UX-02 |
| 2. 교수자가 제출 결과 2페이지에서 다시 조회 | 수동 새로고침이 1페이지로 이동했고 연결 실패 시 읽던 행과 마지막 확인 시각이 사라졌다. | 같은 검색·페이지에 대한 마지막 확인 결과를 유지하고 실패 상태를 표시한다. 결과 목록이 변경되면 교수자가 ‘최신 결과 반영’을 눌러 첫 페이지부터 검토한다. 접근 권한이 회수되면 학생 행을 지운다. | ASYNC-02, FORM-05 |
| 3. 학생이 여러 분반을 검색해 신청 | 검색어를 바꾼 뒤 화면 밖의 선택은 개수만 보였다. 선택한 수업의 신청 상태가 바뀌어도 기존 선택으로 제출할 수 있었다. 바로 수강 가능한 학생에게도 확인 대기 문구를 표시했다. | 선택 영역에 과목명·코드·학기·분반을 표시하고 개별 해제할 수 있다. 신청 불가로 바뀐 수업과 20개 상한을 신청 전에 확인한다. 접수 후에는 이번에 신청한 수업 중 바로 이용할 수 있는 수와 대기 수, 대기 이유를 안내한다. | UX-02, UX-03, UX-04 |
| 4. 교수자가 과제 일괄 보관·삭제를 검토 | 검색 결과 2페이지에서 확인 화면을 열고 돌아가면 원래 검색과 상태 필터가 풀렸다. | 취소, 최종 확인 누락, 완료 후 목록 복귀에 검색어·상태·페이지를 유지한다. 마지막 페이지가 비면 남아 있는 마지막 페이지를 표시한다. 목록으로 돌아오면 실행 대상은 다시 선택한다. | IA-03, FORM-01 |

## 다시 확인할 시나리오

- **성적표** — 점수와 교수자 메모가 있는 파일에서 공개 열을 하나도 고르지 않고 학생 미리보기를 연다. 표 대신 항목 선택 안내가 보여야 한다. 점수만 선택했을 때, 다른 탭에서 공개한 뒤, 셀 상세 주소를 다시 열었을 때도 공개 범위를 확인한다.
- **제출 결과** — 2페이지에서 자동 확인을 끄고 새로고침 중 일시적으로 서버 오류를 반환한다. 행과 마지막 확인 시각이 유지되고, ‘다시 조회’가 같은 페이지를 요청해야 한다. 결과 버전 변경과 권한 회수는 각각 별도 시나리오로 시험한다.
- **수강 신청** — 같은 이름의 두 분반을 선택한 뒤 검색 결과가 0건인 검색어를 입력한다. 선택 목록에서 한 분반만 해제하고 남은 분반을 신청한다. 서버 재조회에서 이미 수강 중으로 바뀐 선택과 20개 상한도 확인한다. 명단 일치·대기가 섞인 경우 신청 완료 안내의 개수를 실제 수강 상태와 대조한다. [모바일 수강 선택 화면](assets/course-selection-mobile-2026-11-20.png)
- **과제 관리** — 필터에 맞는 과제 21개를 준비해 2페이지의 과제를 선택한다. 보관과 삭제 각각에서 확인 화면의 취소, 최종 확인 누락, 성공 후 복귀를 검사한다. 성공 뒤에는 해당 조건에 남은 과제만 보여야 한다.

## 검증 범위

Python 과제 관리·성적표 테스트 156개와 회원·수강 테스트 60개, 웹 테스트 131개, TypeScript 검사와 Next.js 배포용 빌드를 통과했다. 임시 SQLite와 합성 계정을 사용해 로컬 Chrome에서 네 작업을 실행했다. 실제 수강 신청 후 즉시 연결 안내와 변경된 수강 상태를 확인했다. 결과 조회 장애는 해당 요청 한 건에 HTTP 503을 반환해 재현했다. 좁은 화면은 320px와 390px 폭에서 대상 작업을 나누어 점검했다.

다음 검토 대상은 **이름이 같은 과제를 일괄 관리할 때의 구분**이다. 현재 과제 목록의 선택 상자는 과제명만 읽어 준다. 같은 이름의 과제가 함께 표시되는 수업에서 교수자가 마감일이나 차수를 보고 올바른 항목을 선택하는지, 키보드·화면 낭독기로도 검증할 필요가 있다.
