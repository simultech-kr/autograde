# 독립 웹 인증 MVP

- 갱신: 2026-09-09
- 상태: 두 교과목 포털·분리 API·Extension 연결 구현. 실제 학생 명단과 도메인 배포는 운영자 설정 필요.
- 교과목: `come3105`, `come2201`
- 기본 실습 언어: C17·C++17. Java/JDK는 현재 파일럿에 필요하지 않음.
- Windows 클라이언트: [VS2022/VS2026 확장](../../extensions/visualstudio/README.md)이 같은 API를 사용.
  공통 모듈·UI 코드 컴파일 및 서버 프로토콜 시험 완료, Windows VSIX 패키징·설치 검증은 별도 필요.
- [설치·실행 절차](../operations/independent-web-pilot.md)

## 사용자 흐름

교수자는 교과목별 보호된 roster에 `student_key,active,password`를 등록하고, 각 학생에게
자신의 숫자 6자리 Autograde 전용 비밀번호만 전달한다. Starter·채점 코드·입력 데이터와
과제 공개·제출 기간을 등록한다. 학교 비밀번호를 수집하지 않는다.

학생은 20010번 홈페이지에서 교과목을 선택하고 **학번 + 해당 교과목 전용 비밀번호**로
인증한다. 공개·수령 가능한 과제를 선택하면 10분·1회용 `AK1-XXXX-XXXX-XXXX` 수령 코드를
받는다. VS Code 확장 0.3.0 이상에서 서버 주소를 20000번으로 지정하고 수령 코드를 입력하면
과제 수락·다운로드가 진행된다. 풀이 후 같은 확장에서 제출하고 점수·피드백을 조회한다.
비밀번호는 6자리이고 수령 코드는 기존 AK1 형식을 유지한다.

웹 발급은 수락으로 집계하지 않는다. 확장이 코드를 교환한 때 수락을 기록한다. 코드 발급 후
웹 세션은 소비된다. 새 코드를 받으려면 다시 인증한다. 공용 PC에서는 확장 로그아웃 후 떠난다.
확장 창 종료·재시작 시 token은 복원하지 않는다.

## 접속 경계

| 역할 | 공개 주소 예시 | HTTPS proxy 뒤 내부 주소 |
| --- | --- | --- |
| 학생 웹·교수자 조회 | `https://grade.example.edu:20010` | `127.0.0.1:18081` |
| VS Code API | `https://grade.example.edu:20000` | `127.0.0.1:18080` |

도메인은 예시다. 로컬 시험은 proxy 없이 HTTP loopback 20010·20000을 사용한다.
공개 HTTPS 연결은 [Nginx 설정 예제](../../config/nginx-autograde-portal.conf.example)를 사용한다.
실제 도메인·인증서 설정이나 외부 방화벽 변경은 자동으로 수행하지 않는다.

웹 listener는 `/`, `/courses`, `/courses/{course}` 및 그 하위 `login`, `assignments`,
`claims`, `logout`, `instructor`와 `/healthz`만 제공한다. 로그인·발급·로그아웃은 POST다.
교수자 dashboard는 기존 instructor token 기반 Basic 인증으로 교과목별 조회한다.

API listener는 device 생성·코드 교환·token 갱신과 인증된 학생의 과제 다운로드·제출·결과·
세션 관리만 제공한다. 기존 `/activate`, OAuth, Git 연계 UI는 새 listener에서 제공하지 않는다.
웹에서 API로 교차 출처 요청을 하지 않으므로 CORS 개방은 필요 없다. 쿠키는 포트로 분리되지
않는다. 전용 이름·경로를 사용하며 API는 웹 쿠키를 인증에 사용하지 않는다.

## 서버 구조

2026-09-10: 최초 실행 때 설정 파일 옆 `student_roster.csv`를 읽어 두 교과목의 수강 정보를
한 트랜잭션으로 초기화한다. 완료 기록 이후에는 재시작 시 파일을 다시 적용하지 않는다.
기존 비밀번호를 덮어쓰지 않는다. 상세 형식·변경 절차는 실행 안내를 따른다.

`autograde-pilot --config pilot/come3105.csv` 명령 하나가 두 listener와 두 교과목을 실행한다.
`pilot/come3105.csv`, `pilot/come2201.csv`는 공통 `.data-portal` 저장소에 교과목별 학생과 과제를
등록하는 설정이다. 새 registry 형식은 도입하지 않고 허용 교과목 두 개를 코드에서 고정한다.

- 교과목마다 고정된 `StudentPlatformService`와 worker를 둔다. 요청마다 공유 객체의 교과목을 바꾸지 않는다.
- `CoursePortal`은 교과목 선택·인증·과제 목록·코드 발급 화면과 임시 웹 세션을 담당한다.
- `CourseAPI`는 전체 수령 코드·device·access·refresh secret의 digest를 DB에서 조회해 교과목을 선택한다.
  이후 기존 서비스가 만료·폐기·소유권·수강 상태를 검증한다. 클라이언트가 보내는 교과목 값으로 권한을 결정하지 않는다.
- Extension은 pending device 요청에도 수령 코드를 전달한다. 학생이 교과목을 다시 입력할 필요가 없다.
- 채점 worker는 기본 합계 4개(교과목당 2개), 비밀번호 검증 동시 실행 한도는 두 교과목 합계 4개다.
- SQLite 원장·bundle 검증·원자적 코드 교환·비동기 채점과 결과 공개 정책은 기존 구현을 재사용한다.

## 인증·권한

학생 식별은 `student_key`, 수강·비밀번호 범위는 `(course_key, student_key)`이다. 같은 학번이
두 수업에 있어도 전용 비밀번호·과제·제출·결과는 분리한다. 비밀번호는 scrypt hash,
수령 코드는 HMAC digest로 저장한다. 실제 비밀번호가 든 roster는 Git에서 제외하고 파일 권한을 제한한다.

웹 세션은 서버 메모리의 opaque 식별자이며 최대 10분·최대 200개다. HTTPS에서는 `Secure`,
항상 `HttpOnly`, `SameSite=Lax`와 교과목별 경로를 사용한다. CSRF와 Origin 검증을 적용한다.
서버 재시작·로그아웃·성공적인 발급으로 세션을 무효화한다. 비밀번호 변경·수강 비활성화·잠금
상태를 재확인하므로 과거 인증으로 발급을 계속할 수 없다. 실패 5회·5분 잠금을 유지한다.

같은 학생·과제의 코드 재발급 시 기존 미사용 코드를 원자적으로 폐기한다. 이미 연결된 확장은
재발급만으로 끊지 않으며 새 로그인이 성공하면 해당 교과목의 이전 세션을 교체한다.
코드 원문은 URL·로그·파일에 남기지 않는다. 응답은 no-store이며 발급 페이지에 복원 기능을 두지 않는다.

## 파일럿 범위와 후속 계획

LTI·학교 SSO·Google/GitHub OAuth·Docker는 이 실행에 필요 없다. 기존 단일 교과목 서버와
관련 명령은 호환용으로 유지하지만 새 학생 화면에서는 활성화 로그인 등 불필요한 안내를 제거한다.
자동 QR 이미지, 과제 자동 선택 QR, LMS 성적 동기화, 교과목 추가 관리 UI는 후속 항목이다.
현재 LMS/QR에는 공통 입구나 교과목별 공개 링크만 배포하면 된다.

`pilot-local`은 host에서 코드를 실행하므로 **사전 검토한 신뢰 코드의 감독되는 리허설 전용**이다.
학생 임의 코드·비밀 테스트·공식 성적 운영을 위한 강한 격리는 제공하지 않는다.
외부 HTTPS는 전송 보안이며 채점 실행 격리를 대신하지 않는다. 실제 운영 전 격리 환경과 강한
인증을 별도로 검증한다.

## 검증 기준

자동 시험에서 두 listener 경계, 교과목별 비밀번호·과제 접근, 만료·CSRF·Origin,
재발급·재사용, 비밀번호 변경, token 갱신·로그아웃, 25명 혼합 교과목의 인증·수령·다운로드를
검증한다. 제출·채점·결과 회귀 시험도 함께 실행한다. 테스트 결과는 실제 수업의 부하 보장이나
외부 인증서·방화벽 검증을 뜻하지 않는다. 배포 환경에서 VS Code 설치·접속과 신뢰 코드 제출을
별도 리허설한다.
