# 관리자·교수자 결과 화면 반응형 지원

2026-09-17 구현. 서버가 생성하는 HTML/CSS 변경이며 확장 재설치나 DB 변경은 필요하지 않다.

## 적용 화면

- `/courses/<course_key>/instructor/submissions`: 학생별 최신 제출·점수·코드 확인·다운로드 진단.
- `/instructor/admin/subjects/<code>`: 교과목의 학기·분반별 현황.
- `/courses/<course_key>/instructor/submissions/<submission_id>/files/<index>`: 제출 원본 코드.
- 기존 `/courses/<course_key>/instructor` 및 API 서버의 `/instructor` 결과 화면도 지원한다.

브라우저 화면 폭 **1,100px 초과는 표**, **1,100px 이하는 항목명이 붙은 카드**로 표시한다.
태블릿에서는 여유 폭에 맞춰 여러 카드가 나란히 배치되고, 640px 이하에서는 한 열로 표시한다.
같은 데이터를 CSS로 재배치하므로 모바일용 학생 데이터가 별도로 복제되거나 누락되지 않는다.

학생·과제·점수·최신 상태·코드 확인을 먼저 배치했다. 학생별 결과는 학생 관리·접속 링크보다 먼저 나온다.
상단 바로가기로 수업 관리·학생별 결과·수강 및 접속 정보에 이동할 수 있다. 기존 정렬·조회 범위·점수 산정은 바꾸지 않았다.
긴 과제명·학번·문의번호는 줄바꿈하고, 다운로드 상세는 펼쳐서 확인한다.
코드는 줄 번호와 원래 줄을 보존하며 **코드 상자 내부에서만 가로 스크롤**한다.
키보드로 코드 상자에 초점을 옮긴 뒤 방향키로 이동할 수 있다.

밝음·어두움 테마는 기존 시스템 테마 설정을 따른다. 표의 제목·열 제목·학생 행 제목은 유지하며,
카드의 시각적 항목명은 화면 읽기 도구에 중복 낭독되지 않도록 처리했다.
화면 읽기 도구별 실제 사용 검증은 별도 확인이 필요하다.

## 적용 및 직접 확인

1. 수정한 서버 코드를 설치하고 기존 방식으로 서비스를 정상 재시작한다. 포트·인증 설정은 유지한다.
2. 교수자로 로그인해 **학생별 결과·코드 확인**을 연다.
3. 창을 넓혔다 줄이면서 표↔카드 전환, 점수·코드 링크·다운로드 상세를 확인한다.
4. 모바일에서 세로·가로 방향을 바꾸고, 제출 코드를 열어 페이지 전체가 아니라 코드 영역만 가로 이동하는지 확인한다.
5. 다른 수업으로 이동해 수업별 데이터 범위가 유지되는지 확인한다.

이번 개발에서 운영 서버 배포·재시작 및 실제 학생 데이터 변경은 하지 않았다.

## 자동 검증

`tests/integration/test_instructor_responsive.py`는 합성 데이터로 실제 렌더러의 결과·분반·코드·빈 화면을
생성하고, 항목 보존·HTML 이스케이프·접근성 마크업·기존 포털 링크를 검사한다.
기존 인증·수업 범위·코드 열람·다운로드 진단 시험도 함께 실행한다.
관련 Python 회귀 시험은 78개 통과했다.

브라우저 검사는 `scripts/check_instructor_responsive.cjs`로 재실행할 수 있다.
Playwright와 테스트용 Chromium 또는 Chrome이 필요하며 서버의 실행 의존성에는 추가하지 않았다.

```text
.venv/bin/python -m pytest -q tests/integration/test_instructor_responsive.py --basetemp=<새로운 테스트 전용 임시 디렉터리>
node scripts/check_instructor_responsive.cjs <같은 임시 디렉터리> <설치된 playwright 모듈 경로> [Chrome 실행 파일 경로]
```

`--basetemp`는 pytest가 비우는 경로이므로 운영 데이터나 작업 디렉터리를 지정하면 안 된다.
검사는 별도 임시 브라우저를 사용하며 기존 로그인 프로필을 열지 않는다.
320·375·768·1024·1100·1101·1440px × 밝음·어두움 × 6종 화면의 **84개 조합**과 고대비 모드를 확인한다.
긴 문자열·펼친 상세에서도 페이지/셀의 가로 넘침이 없는지, 코드의 키보드 스크롤이 되는지 검사한다.
실제 iOS Safari·Android 기기와 보조기술 사용성 검증은 별도이며 자동 검사의 대체 대상이 아니다.

## 2026-10-23 가독성·일관성 개선

기존 교수자 결과 화면과 Next.js `/app`의 표시 기준을 맞췄다. 평면형 디자인과 공통 색상
토큰은 유지하고, 화면별 임의 색상이나 그림자를 추가하지 않는다.

- 수업 문맥, 제출 현황 요약, 조회 조건, 갱신 상태, 학생별 결과를 구획으로 나눈다.
- 요약은 제출 학생 / 미제출 / 접수·채점 중 / 채점 완료 / 확인 필요 순서로 읽는다.
  학생은 중복을 제외한 **명**, 나머지는 학생 × 과제별 최신 상태의 **건**이다.
  확인 필요와 채점 완료는 중복될 수 있으며 다섯 수치를 더한 값은 전체 인원이 아니다.
- 최신 제출 점수는 큰 숫자로, 이전 최고점은 보조 정보로 표시한다. 대기·오류·미제출은
  0점으로 취급하지 않는다. 채점 완료와 만점도 구분하며 부분점수는 보완 필요를 표시한다.
- Next.js는 같은 행에서 이전 최고점을 제공한다. 기존 화면에는 해당 데이터가 없어
  코드·제출 이력에서 과거 결과를 확인하도록 안내한다. 없는 점수를 추정해 표시하지 않는다.
- 상태는 색뿐 아니라 문구로 구별한다. 대기는 정보색, 보완 필요는 주의색, 처리 오류는
  오류색, 만점은 성공색을 쓴다. 마지막 갱신 시각과 수동·자동 확인 상태를 함께 표시한다.
- 작은 보조 글씨와 줄 간격, 숫자 정렬, 입력 컨트롤의 높이, 모바일 카드의 항목 구분을
  조정했다. 밝음·어두움의 일반 본문·보조 글씨·상태 배지 대비를 자동 검사한다.

같은 AJAX 식별 속성, 로그인·수업 권한, 조회 범위와 제출 순서를 유지한다. 새 DB 스키마나
설정 CSV 변경은 없다. 기존 화면은 서버 재시작, Next.js 화면은 웹 빌드·재시작이 필요하다.
자료 배포·시험 모드 등 다른 작업의 미커밋 변경과 별개인 화면 개선이며 운영 서버에는
자동 반영하지 않는다.

대량 이력 시험에서 확인한 응답 크기 문제는 반복되는 행 설명·마크업을 줄여 대응한다.
응답 크기 제한을 해제하지 않는다. 수업 크기가 커지면 전체 HTML보다 페이지 단위로 조회하는
Next.js 화면을 사용하고, 추가 부하·응답 크기를 별도로 확인한다.

### 개선본 검증 결과

- Python 조회·이력·권한·테마 회귀 시험 120개, 웹 단위 시험 22개 통과. Next.js 배포 빌드 성공.
- 합성 데이터와 로컬 Python/Next.js 서버를 연결한 브라우저 시나리오 19개 통과:
  인증 경계, 수업 전환, 페이지 이동, 필터, 자동 갱신, 통신 중단 복구,
  최신 0점과 이전 최고 100점 구별, 좁은 화면·고대비·긴 문자열 등을 확인했다.
- 기존 화면은 화면 폭·테마 84개 조합과 고대비를 통과했다. 별도로 루트 글꼴을 200%로
  확대해 밝음·어두움 × 10개 화면 폭에서 가로 넘침이 없는지 확인했다.
- 1440×900 화면에서는 스크롤 없이 첫 학생의 최신 점수를 확인할 수 있다.
- 25명 × 20개 과제 × 10회 제출의 합성 이력에서 기존 HTML·AJAX 응답이 기존 1MiB
  한도 안에 있고, 페이지 단위 Next.js 조회도 정상 응답함을 확인했다.

이 검증은 실제 학생 정보나 운영 서버를 사용하지 않는다. 401/403/409 예외는 테스트 응답으로
주입했으며, 로컬 HTTP 검증이 운영 Nginx·TLS 검증을 대신하지 않는다. 글꼴 확대는 브라우저의
네이티브 확대 기능과 다르며, 실제 모바일 기기·Safari·보조기술 검증은 별도로 진행한다.
이력 페이지의 테스트는 CSS 색상 문자열이 제출 번호로 오인되지 않도록 실제 이력 행과
제출 링크를 대상으로 검사한다.
