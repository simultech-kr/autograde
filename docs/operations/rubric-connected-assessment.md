# 실제 제출물에 연결한 교수자 루브릭 평가

2026-09-20. 기존 웹 카탈로그에 **서버에 보관된 제출 원본 → 개인 교수자 판정 → 비공개 평가 이력**을 연결했다.
등록된 루브릭의 `instructor` 항목은 실제 파일·줄 근거와 수준 선택으로 점수를 계산한다.
`deterministic` 항목의 개별 검사 근거 연결과 학생 공개는 아직 구현하지 않았다.
기존 자동채점 점수·Extension 결과·이전 최고점은 수정하지 않는다.

## 활성화

기존 설정 CSV에 아래 기능이 켜져 있어야 한다. 개인 계정 최초 설정은
[교수자 개인 계정 안내](instructor-personal-auth.md)를 따른다. 이미 켜져 있다면 새 설정값은 필요 없다.

```csv
instructor_assignment_web_enabled,true
instructor_rubric_web_enabled,true
instructor_auth_mode,personal
```

서버를 정지하고 DB·제출 bundle을 백업한 뒤 코드를 갱신하고 기존 portal 실행 명령으로 재시작한다.
서버 시작 시 검증된 전용 `rubric-catalog.sqlite3`에 플러그인 소유 테이블 두 개만 추가한다.
기존 학생 DB를 초기화하거나 기존 루브릭을 삭제하지 않는다. 공유 계정 모드는 카탈로그 기능만 제공한다.
계정 DB와 루브릭 DB뿐 아니라 제출 bundle 저장소도 함께 백업해야 근거를 다시 확인할 수 있다.

## 교수자 사용 순서

1. 웹 `/instructor`에서 개인 계정으로 로그인하고 담당 교과목·분반을 선택한다.
2. **과제 관리 → 과제 상세 → 루브릭 작성**에서 기준을 등록한다. 자동 생성되는 기본 양식은
   교수자 검토 항목 1개, 100점이다. 항목·수준·배점을 수업에 맞게 조정하고 미리보기 후 버전을 등록한다.
3. **루브릭 관리 → 버전 상세 → 평가 사용 승인**을 누른다. 선택한 버전의 내용 해시와 승인자를 기록한다.
   로컬 CLI의 오프라인 승인은 이 웹 승인을 대신하지 않는다. 새 루브릭 버전은 별도로 승인해야 한다.
4. **제출물 선택·루브릭 평가**에서 학번·접수 시각·제출 ID를 확인한다. 목록은 50건씩 접수 순으로 표시하며
   같은 학생이 같은 코드를 재제출했더라도 별도 제출이다.
5. 평가 화면의 **제출 코드·줄 번호 확인**을 새 탭으로 열어 원본을 읽는다.
   각 항목에서 평가 수준, 근거 파일 번호, 시작/마지막 줄, 판정 사유를 입력한다.
   파일 번호 목록에는 경로와 줄 수가 표시된다. `미평가`로 남긴 항목은 0점이 아니다.
6. 확인란을 선택하고 **평가 기록 저장**을 누른다. 모두 평가했으면 루브릭 총점, 미평가가 있으면
   부분 점수와 전체 배점을 분리해 표시한다. 결과에는 선택 수준·사유·파일/줄·원본 해시·평가자가 포함된다.
7. **이 제출의 평가 이력**에서 기존 평가와 새 평가를 확인한다. 수정하려면 해당 제출 평가 화면을 새로 열어
   새 기록을 저장한다. 기존 평가를 덮어쓰지 않으며 이전 입력을 자동 복사하지 않는다.

현재 과제나 제출을 일괄 재평가하거나 과제 공개본의 기본 채점 방식을 변경하는 기능은 없다.
다른 루브릭 버전을 적용한 평가는 그 버전의 별도 기록으로 남는다. 보관된 수업은 조회만 가능하다.

## 근거와 신뢰 경계

- `SubmissionEvidenceSource`는 해당 분반의 제출·과제 연결을 검사하고 `BundleStore`가 검증한 학생 bundle만 읽는다.
  압축을 풀어 실행하거나 학생 파일을 수정하지 않는다. 제출 archive 해시와 개별 파일 해시를 확인한다.
- UTF-8 텍스트 파일당 256 KiB, 합산 읽기 4 MiB, 참조 파일 최대 1,000개를 적용한다.
  빈 파일·바이너리·비 UTF-8·한도 초과 파일은 선택에서 제외한다. 근거 파일이 하나도 없으면 저장을 허용하지 않는다.
- 교수자는 파일 번호·줄·수준·사유만 입력한다. 원본/파일 해시와 평가자 ID는 서버에서 결정한다.
  제출에 없는 파일, 범위를 벗어난 줄, 잘못된 수준, 빈 사유는 거절한다.
- 30분짜리 서명된 평가 요청을 계정 ID/revision·화면 세션·분반·제출·루브릭 내용·파일 근거에 묶는다.
  CSRF/Origin 검증과 매 요청 개인 인증·분반 인가도 기존 웹과 동일하게 적용한다.
- 동일 저장 요청의 재전송은 같은 평가 ID를 반환한다. 같은 요청으로 내용을 바꾸면 409를 반환한다.
  입력 오류는 필드를 보존하여 다시 표시한다. 만료/충돌은 입력을 따로 보관한 뒤 화면을 새로 열어야 한다.
- 학생의 새 제출은 이전 평가를 상속하지 않는다. 기존 제출 평가 중 새 제출이 생겨도 평가 대상이 바뀌지 않는다.
- 원본 검증 실패는 민감한 서버 경로를 노출하지 않는 503이다. 권한 없는 다른 분반은 조회/저장을 거절한다.
- 기존 자동채점 원장에는 총점·항목별 점수가 있지만 개별 검사 통과/실패 원장이 없다.
  총점으로 통과 검사 수를 추정하지 않는다. 자동 항목은 `pending`, 최종 총점은 `null`로 보존한다.
  레거시 evidence 계약의 `grading_run_id`는 여기서는 `source_…` 원본 snapshot ID이며 실제 검사 실행을 주장하지 않는다.
- 기록의 `evidence_provenance=server_verified_source_and_authenticated_instructor`는 서버 원본과 인증된 판정을 의미한다.
  학생 코드의 안전한 실행 환경이나 부정행위 검증을 보증하지 않는다. `pilot-local`은 여전히 신뢰 코드 전용이다.

## 모듈·저장 구조

| 구성 요소 | 책임 |
| --- | --- |
| `rubric_catalog` | 변경 불가 루브릭 버전 등록·조회 |
| `SubmissionEvidenceSource` | 분반별 실제 제출 식별 및 원본 파일 근거 생성 |
| `ConnectedRubricAssessment` | 개인 인가, 웹 평가 사용 승인, 요청 검증, 계산, 감사·평가 이력 저장 |
| `rubric_engine` | 고정 평가자 registry의 수준별 점수 계산과 미평가 처리 |
| `instructor_rubric_assessment` | 제출 선택·입력·결과·이력 화면 |

전용 DB의 `rubric_web_approvals`와 `rubric_web_assessments`를 사용하며 후자는 검증된 evidence와 결과를 함께 보존한다.
승인/평가와 `rubric_audit` 기록은 같은 SQLite 트랜잭션으로 저장한다. 오프라인 가져오기용
`rubric_assessments`와 분리하여 수동 입력된 오프라인 자료를 검증된 서버 근거로 승격하지 않는다.
개인 모드에서 이 모듈이 연결되면 웹 `/readyz`가 두 테이블도 점검한다. 학생 API readiness는 분리되어 있다.

이는 고정된 연결 어댑터이며 전체 SES/SPL 동적 플러그인 Host를 구현한 것은 아니다.
후속은 **검사별 근거 원장 → 자동 항목 연결 → 평가 확정·학생 공개 정책 → 성취도 분석** 순서다.
현재 모든 기록은 `publication_allowed=false`, `gradebook_updated=false`를 유지한다.

## 검증 방법

```sh
python -m pytest tests/integration/test_connected_rubric_assessment.py tests/integration/test_instructor_rubric.py tests/integration/test_instructor_personal_auth.py tests/integration/test_instructor_runtime.py tests/integration/test_rubric_local_workflow.py tests/unit/test_rubric_engine.py -q
```

합성 계정·제출 파일·DB로 실제 HTTP 평가, 항목별 계산, 중복 클릭, 새 제출 분리, 범위/만료/권한,
원본 손상, 입력 복원, 미평가와 0점 구분, 기존 학생 점수 불변을 확인한다.
화면 검사는 테스트가 만든 `connected-rubric-*.html`에 대해 실행한다.

```sh
node scripts/check_connected_rubric.cjs <pytest임시폴더> <playwright모듈경로> <Chrome실행파일>
```

검사는 외부 네트워크를 차단하고 320/375/768/1440px × 밝음/어두움 테마의 4개 화면을 확인한다.

### 2026-09-20 검증 결과

- 최종 전체 회귀: **1,204 통과 / 19 제외**, 321.55초.
  제외 항목은 Windows/MSVC 2개, 동작하는 JDK 부재 5개, PATH의 .NET 8 SDK 부재 12개다.
- 연결 평가 전용 최종 테스트: **13 통과**. 위 전체 회귀에 포함되므로 합산하지 않는다.
- 실제 브라우저의 화면 크기/테마 조합: **32개 통과**. 입력 화면의 최종 밝음/어두움 이미지를 확인했다.
- 원격 서버 배포나 실제 학생 평가/점수 변경은 수행하지 않았다.
