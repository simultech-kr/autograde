# 수업·학생 등록 웹 MVP 설계

작성: 2026-09-15. **설계 단계이며 화면/API가 구현되었다는 뜻이 아니다.**
[교수자 웹 과제 등록 계획](instructor-assignment-web-mvp.md)의 필수 범위를 확장한다.

등록 이후의 학생 제출과 교수자 검증 안내는 [단계별 UX 설계](submission-validation-ux.md)를 따른다.

위험 작업으로 [수업별 학생 전체 초기화·재등록](course-student-reset-mvp.md)을 추가한다.
이번 승인 범위는 come2201의 수강·인증·제출·점수 초기화이며 과제와 come3105는 보존한다.

## 1. 전체 사용자 흐름

교수자 로그인 → 수업 등록 → 학생 등록 → 과제 등록·검증·공개 → 학생 수령·제출 → 현황 확인.

- 교수자 공통 시작 화면(신규 예정): `https://ai.cbchoi.info:20010/instructor`.
- 기존 `/courses/come3105/instructor`, `/courses/come2201/instructor` 주소는 유지한다.
- 학생 웹 20010, 두 확장 API 20000, SQLite, CSV 기반 서버 설정을 유지한다.
- 교수자는 웹으로 생성·수정하고 DB를 기준으로 운영한다. CSV를 매번 고치거나 서버를
  재시작할 필요가 없어야 한다. 초기 서버 설치·백업은 운영자 업무로 남는다.
- 단일 신뢰 교수자 운영자 계정을 전제로 한다. 교수자별 계정·수업 소유권·조교 RBAC는
  후속 범위이며 공유 Basic 자격 증명으로 개인별 권한을 제공한다고 주장하지 않는다.

## 2. 수업 등록과 관리

### 입력 및 데이터

| 항목 | 규칙 |
| --- | --- |
| 교과목 코드 | 예: come3105, come2201. 소문자 영문·숫자·하이픈·밑줄, 1~32자 |
| 수업명 | 필수, 최대 100자. 교수자가 실제 이름을 입력하며 코드에서 추정하지 않음 |
| 학년도·학기 | 신규 수업에 필수. 학기는 1학기/2학기/여름/겨울 중 선택 |
| 분반 | 필수, 최대 16자. 기본 제안 01을 교수자가 확인 |
| 설명 | 선택, 일반 텍스트 최대 2000자 |
| 상태 | 준비/운영/보관. 생성 직후 준비 상태 |
| 내부 course_key | 서버 생성·변경 금지. 기존 course_key와 학생·과제·URL 연결은 보존 |

교과목 코드와 한 학기의 개설 수업은 다르다. 새 수업은 (교과목 코드, 학년도, 학기, 분반)의
조합 중복을 거절하고 각 개설 수업에 고유 course_key를 만든다. 다음 학기는 새 수업이며
이전 제출·수강생·비밀번호를 자동 이관하지 않는다.
기존 come3105/come2201은 원래 course_key를 유지하는 레거시 개설 수업으로 옮긴다.
확인되지 않은 수업명·학기는 임의로 채우지 않고 “정보 확인 필요”로 표시한다.
교수자가 정보를 보완할 때 중복을 재검사하고, 수업을 자동 병합하지 않는다.

### 화면 동작

1. **수업 관리 → 새 수업**에서 기본 정보를 입력한다.
2. 저장하면 준비 상태의 수업 상세 화면과 **학생 등록**, **과제 등록** 안내를 제공한다.
3. 교수자가 **운영 시작**을 누르면 학생 웹 목록·로그인에서 사용 가능해진다.
4. 학생 URL·QR은 서버의 확정된 공개 주소와 course_key로 생성한다. 임의 URL 입력은 받지 않는다.
5. 수업명·설명은 수정할 수 있다. 운영 시작 이후 학기·분반·교과목 코드는 잠그고
   변경 필요 시 새 개설 수업을 만들도록 안내한다.

보관은 삭제가 아니다. 처리 중 검증·대기/실행 중 제출이 있으면 보관을 거절한다.
가능한 경우 확인 창에 영향 범위와 수강생·과제·제출 수를 보여 준다. 보관 시 신규 로그인·코드
발급·교환·다운로드·제출을 막고 해당 수업의 기존 인증 세션과 미사용 코드를 폐기한다.
기존 점수·원본은 보존하고 교수자 조회는 계속 허용한다. 학생의 보관 수업 성적 열람은
첫 MVP 범위 밖임을 경고한다. 재운영 시 폐기된 인증은 복원하지 않고 새 로그인부터 시작한다.
수업 자체의 물리적 삭제·여러 수업의 일괄 보관은 MVP에서 제공하지 않는다.
학생 기록 초기화는 보관과 다른 별도 위험 작업이며 백업·미리보기·재확인을 요구한다.

## 3. 학생 등록과 수강 관리

### 학생과 수강 정보 분리

- Student: 기존 내부 student_id와 문자열 학번(student_key)을 유지. 이름은 선택 표시 정보.
- Enrollment: student_id + course_key의 고유 조합, 수강 활성/비활성 상태.
- Credential: 기존 수업별 학생 비밀번호 자격 정보를 재사용. 다른 수업과 독립적으로 관리.
- 과제 수락·제출·점수는 기존 학생/수강/수업 연결을 보존한다.
- 동일 학번의 다른 수업 수강은 같은 학생에 새 수강 정보를 추가한다. 이름이 다르면
  다른 사람이라고 자동 추정하거나 기존 학생 이름을 덮어쓰지 않고 충돌을 표시한다.
- 학번은 앞자리 0을 포함한 문자열이다. 등록 후 학번 변경·학생 병합·전역 학생 삭제는 제외한다.

### 개별 등록

수업 상세 → **학생 추가** → 학번, 이름(선택), 수강 상태, 비밀번호 발급 방법 → 등록.
수업은 현재 화면에서 고정하며 학생 입력으로 다른 수업을 선택할 수 없다.
기존 수강생이면 새 계정을 만들지 않고 기존 상세 화면으로 안내한다. 비활성 계정을 재등록할
때도 확인 없이 자동 활성화하지 않는다.

활성 학생의 비밀번호는 기존 호환을 위해 ASCII 숫자 6자리로 한다. 기본은 서버의
암호학적 난수 생성, 필요하면 교수자 직접 입력. 같은 수업 내 중복 금지와 로그인 시도 제한을
유지한다. 이름·학번·연속 숫자로 기본 비밀번호를 만들지 않는다.
DB에는 해시만 저장한다. 발급/초기화 직후 응답에서 본인에게 전달할 값만 일회 표시하고,
일반 목록·새로고침·감사 로그·학생 다운로드에는 원문을 남기지 않는다.
응답이 유실되면 기존 비밀번호를 조회하는 대신 새 비밀번호로 명시적 초기화한다.

6자리 인증은 기존 파일럿 호환을 위한 결정이지 공식 성적 운영의 충분한 인증 수준이 아니다.
학생 자가 가입·학교 SSO·학생 비밀번호 변경 화면은 이번 범위에서 제외한다.

### CSV 일괄 등록

웹에서 선택한 수업에만 적용되는 등록 파일은 기존 수업별 CLI 형식을 따른다.
필수 열 `student_key,active,password`, 선택 열 `name`. 템플릿 다운로드를 제공한다.
이 기능은 CSV 설계이며 실제 학생 명단이나 비밀번호 파일은 문서/저장소에 생성하지 않는다.

**파일 선택 → 검증/미리보기 → 적용 확인 → 결과**의 네 단계로 처리한다.

- UTF-8/BOM, 정확한 열 수, 학번 문자열, 활성 상태, 6자리 숫자, 중복 학번·비밀번호를 확인한다.
- 웹 CSV는 1 MiB·최대 1000행으로 제한한다. 본문 제한은 이 교수자 전용 경로에만 적용한다.
- 신규 활성 학생의 빈 password는 “자동 발급” 선택 시에만 허용한다. 비활성 학생은 빈 값만 허용한다.
- 기존 활성 학생의 빈 password는 변경 없음이다. 같은 값은 유지하고 다른 값은 충돌로 처리한다.
  일괄 등록으로 기존 비밀번호를 바꾸지 않고 학생 상세의 명시적 초기화로 안내한다.
- 미리보기는 신규/동일/상태 변경/오류를 구분하고 행 번호·오류 필드만 표시한다.
  비밀번호는 원문 대신 “유지/신규 발급/직접 지정/충돌”로 표시한다.
- 한 행이라도 오류가 있으면 전체 미적용. 유효한 일부 행만 조용히 적용하지 않는다.
- 파일에 없는 기존 학생을 삭제·비활성화하지 않는다. 상태 변경은 별도 강조·확인한다.
- 미리보기 ID는 교수자 세션·수업·정규화한 입력 해시·만료 10분에 묶는다.
  비밀번호는 미리보기 단계에서 해시로 변환하며 업로드 원본은 처리 후 지운다.
  자동 생성 비밀번호는 최종 적용 시 생성한다. 저장 직전에 기존 DB 상태를 다시 검증하고
  미리보기 이후 변경이 있으면 재검토를 요구한다. 적용은 짧은 단일 트랜잭션이다.
- 중복 클릭·네트워크 재시도로 수강 정보를 중복 생성하지 않는다. 성공 여부 조회에는 원문
  비밀번호를 반환하지 않는다. 자동 발급 값은 적용 성공 응답의 개별 전달용 화면에서만 확인한다.
  첫 MVP에서는 전체 비밀번호 CSV 내보내기를 제공하지 않는다.

이 웹 규칙은 최초 `student_roster.csv`나 기존 CLI의 빈 password 의미를 조용히 변경하지 않는다.
공통 Service 입력으로 정규화하는 어댑터에서 각 경로의 계약을 명확히 구분한다.

### 학생 상세 관리

- 해당 수업의 수락 과제·제출·점수 조회.
- 이름 수정은 다른 수업에도 쓰이는 학생 정보임을 명시하고 충돌 확인 후 처리.
- **비밀번호 초기화:** 재확인 후 새 비밀번호 발급. 해당 수업의 웹/확장 access·refresh 세션,
  미사용 수령 코드·연결 중 인증을 모두 무효화한다. 다른 수업의 자격 정보는 유지한다.
- **수강 비활성화:** 같은 인증 폐기 규칙과 신규 접근 차단. 이미 접수된 제출은 보존하며
  접수 후 처리·결과 보존 정책에 따라 완료하고 신규 제출만 막는다.
- **수강 재활성화:** 새로운 비밀번호 발급과 새 로그인 필요. 이전 세션·코드는 되살리지 않는다.
- 비밀번호 재설정/수강 변경 이력에는 공유 instructor, 대상, 시각, 사유만 남긴다.

## 4. MVC와 공통 서비스 경계

| 계층 | 구성(신규 예정) | 책임 |
| --- | --- | --- |
| Controller | CourseAdminController, StudentAdminController, AssignmentAdminController | 인증·CSRF·입력·응답 변환 |
| Model | CourseOffering, Student, Enrollment, AssignmentDraft/Release | 수업·수강·공개 상태와 불변 조건 |
| Service | CourseAdminService, EnrollmentAdminService, AssignmentAdminService | 중복 확인·원자적 적용·인증 폐기·공개 규칙 |
| Repository | 기존 PlatformStateStore의 점진적 어댑터 | SQLite 조회·트랜잭션·마이그레이션 |
| View | 공통 레이아웃, 수업/학생/과제 목록·폼·상세 | 표시와 입력. SQL·권한 판단·채점 실행 금지 |
| Worker | 검증 worker와 학생 채점 worker | 비동기 실행. DB 쓰기 잠금을 잡고 컴파일하지 않음 |

CLI와 웹은 같은 Service를 호출한다. Controller에 SQL이나 subprocess를 넣지 않는다.
기존 학생 API 계약은 유지하며 MVC 도입을 위해 전체 서버를 교체하지 않는다.

교수자 공통 `/instructor`의 수업 목록/등록, `/courses/{course_key}/instructor/students`의
목록/개별 추가/CSV 미리보기·적용, 학생 상세의 비밀번호 초기화·수강 변경을 신규 경로로 설계한다.
GET은 조회만 하고 모든 변경은 POST + CSRF + 교수자 인증 + course scope 검사를 적용한다.
학생 정보·교수자 목록은 인증 전에 읽거나 반환하지 않는다.

## 5. 디자인 시스템 반영

왼쪽 메뉴는 **수업 관리 / 학생 관리 / 과제 관리 / 제출·채점 현황**으로 통일한다.
수업 선택 전에는 수업 관리와 시작 안내만 보여 준다. 수업 선택 후 상단에 수업명·코드·학기·분반을
항상 표시하고, 이동 시 저장하지 않은 입력이 있으면 확인한다.

- 공통 색상: 주 버튼 #2563EB, 배경 #F8FAFC, 카드 #FFFFFF, 본문 #0F172A.
- 본문 16px, 버튼/입력 최소 높이 44px, 간격 4/8/16/24/32px. 실제 대비와 키보드 접근성을 시험한다.
- 수업 카드, 학생 표, 상태 배지, 필드 오류, 확인 창, 빈 화면 안내를 공통 컴포넌트로 만든다.
- 빈 수업 목록: “첫 수업을 등록하세요” + 새 수업. 빈 학생 목록: 학생 추가/CSV 등록.
- 상태는 색상만 쓰지 않고 준비/운영/보관, 수강 중/비활성 등 문구와 함께 표시한다.
- CSV 미리보기 오류는 행 번호·필드·수정 방법을 제공하고 비밀번호는 숨긴다.
- 비밀번호 초기화·수강 취소·보관은 영향 설명과 확인이 필요하다. 저장/등록 주 버튼은 하나로 유지한다.
- 학생 모바일 화면에는 교수자 메뉴를 노출하지 않는다. 확장은 현재 수락 과제만 보여 주는 정책 유지.

## 6. 현재 고정 수업 구조를 바꾸는 작업

현재 `platform_portal.COURSES`, URL 정규식, `pilot_roster.py` 허용 목록,
`pilot_portal_cli.py`의 시작 시 서비스/worker 생성이 두 수업을 전제로 한다.
이를 수정하지 않은 수업 CRUD 화면은 완료로 인정하지 않는다.

1. DB 수업 레지스트리를 기준으로 안전한 course_key 경로를 해석한다. 경로 형식만 맞는
   미등록 수업은 404이며, 학생 선택 페이지에는 운영 중 수업만 표시한다.
2. 공통 인증 토큰은 course service가 없어도 교수자 최초 수업 등록에 사용할 수 있도록 분리한다.
3. 새 수업 생성/운영 전환을 서비스 레지스트리에 원자적으로 반영한다. 실패한 수업은 준비
   상태로 남기고 학생에게 공개하지 않는다. 재시작 없이 신규 수업 로그인·수령이 가능해야 한다.
4. 수업 수만큼 worker를 무제한 생성하지 않는다. 기존 전체 학생 worker 예산(초기 4개)을
   지키는 공유 스케줄러/공정한 수업별 큐 처리로 바꾸고, 교수자 검증 worker는 별도로 제한한다.
   DB에 등록된 수업과 활성 서비스·worker 상태를 readiness에서 확인한다.
5. archived/비활성 상태를 모든 로그인·코드 교환·토큰 갱신·다운로드·제출 경로에서 재확인한다.
   사후 UI 숨김만으로 접근을 막았다고 간주하지 않는다.

## 7. 기존 CSV와 초기화 호환

- 기존 come3105/come2201의 학생 ID·수강·비밀번호 해시·과제·제출·점수·URL은 그대로 보존한다.
- 최초 `student_roster.csv` 자동 등록 완료 표식은 유지한다. 웹 수정 후 서버 재시작 시
  CSV가 웹 변경을 덮어쓰거나 비활성 계정을 되살리면 안 된다.
- 기존 CSV 초기화 모드는 파일 누락/형식 오류에 대한 실패 규칙을 유지한다. 잘못된 CSV를
  무시하고 자동으로 빈 상태를 만드는 방식은 금지한다.
- 새 설치에서만 명시적 CSV 설정 `roster_bootstrap_mode=web`(신규 예정)을 선택하면
  학생 없는 관리 초기화 상태로 시작할 수 있다. 교수자 인증 후 수업·학생을 등록한다.
  기본값은 기존 CSV 모드다. web 모드는 학생 인증 우회나 임의 수업 자동 생성을 허용하지 않는다.
- 신규 수업은 DB 등록이 필요하다. 레거시 명단의 두 기본 수업만 호환 마이그레이션에서 보존하며,
  이후 명단 오타로 새 수업이 생기지 않도록 미등록 course_key를 거절한다.
- SQLite 마이그레이션은 과제 관리 변경과 함께 순서를 조정하고 데이터 사본으로 먼저 검증한다.

## 8. 구현 순서와 인수 기준

1. MVC 경계·공통 운영 인증·DB 수업 레지스트리와 기존 두 수업 마이그레이션.
2. 수업 생성·수정·운영 전환 및 동적 서비스/worker 연결.
3. 개별 학생 등록·수강 변경·비밀번호 초기화 및 모든 관련 인증 폐기.
4. CSV 업로드·미리보기·원자적 적용·오류/유실 대응.
5. 과제 예제/직접 등록·검증·공개를 연결하고 공통 디자인 적용.
6. staging에서 실제 HTTPS와 두 확장, 합성 학생 25명 부하·백업 복원 검증 후 운영 반영.

추가 위험 작업 단계: 수업별 초기화 계획/적용/상태 조회와 재등록 대기 흐름을 구현하고,
두 수업 간 보존·토큰 폐기·백업 선별 복구 시험을 통과한 경우에만 별도로 활성화한다.

필수 통과 기준:

- 웹에서 **새 수업 → 신규 학생 → 새 과제 → 학생 수령·제출·점수**를 서버 재시작/CLI 없이 완료.
- 같은 교과목의 다른 학기·분반 간 과제·학생 자격·결과 접근 차단, 중복 개설 거절.
- 학번 선행 0 보존, 중복 학번의 수강 중복 방지, 이름 충돌 시 기존 데이터 보존.
- CSV 일부 오류는 전체 미적용, 누락 학생 유지, 재적용 멱등성, 동시 수정 충돌 감지.
- 비밀번호 초기화·수강 취소 후 기존 웹/확장 토큰·refresh·미사용 코드 모두 거절;
  같은 학생의 다른 수업 로그인에는 영향 없음.
- 수업 보관은 대기 작업 존재 시 거절, 보관 후 접근 차단과 기존 기록 보존.
- 새 웹 등록 후 서버 재시작해도 CSV가 변경을 덮어쓰지 않음. 빈 web 초기화와 기존 CSV 오류를 구분.
- 학생 권한의 교수자 경로 접근, CSRF, 파일 업로드 공격, 이름/수업명의 XSS 시도 차단.
- 25명 합성 제출 중 수업/학생 등록에도 worker 수 상한 유지, 인증/제출 유실·중복 없음.
- 교수자 공유 계정 한계, 일반 학생 코드 격리 미완료, Windows 전용 채점 미지원은 화면·안내에서 유지.

이번 설계 반영은 운영 수업 생성·실제 학생 등록·비밀번호 변경을 수행하지 않는다.
