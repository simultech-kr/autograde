# Autograde 전용 IDE 개념연구 설계

## 결정과 범위

2026-10-22 결정: 소규모 수업의 개념연구에서는 기존 Python 서버·CSV 설정·SQLite를 유지한다.
Code-OSS에 기존 Autograde 확장을 내장한 **Autograde IDE**를 만들고, 학생의 연결·과제
이어하기·다운로드·제출·결과 확인을 학습 홈에서 시작할 수 있게 한다. 제출·성적 원장은
그대로 사용한다. 2026-10-23 확장에서는 기존 자료 배포 서비스에 학생용 IDE API를 추가하고,
로컬 학습자별 프로필·작업 폴더와 선택적인 IDE AI 제한 시작 설정을 제공한다.

2026-10-24의 **폴더 분리 MVP + OS 격리 설계** 결정에 따라 학생 PC의 작업·자료·프로필을
분리한다. 학생 PC의 OS 계정·VM 생성과 네트워크 통제는 후속 설계다. 이 로컬 폴더 분리는
외부 AI 접속 차단이나 동일 OS 계정 안의 학생 간 보안 격리를 제공하지 않는다.

2026-10-28 별도 구현 요청에 따라 **선택형 원격 Linux C/C++/Python 실습**을 추가했다. Mac IDE 0.5.18에서
현재 코드를 서버 작업본으로 저장하고 C17/C++17 컴파일·실행 또는 Python 3 실행, 저장 확인 후 공간 종료까지 연결한다.
교수자·학생 포털에는 허용된 학생 공간의 상태를 표시한다. Linux Docker 실행 관리자와 승인 이미지를
별도로 준비한 서버에서 활성화하며, 설정이 없는 기존 파일럿은 기존 흐름을 유지한다.
로컬 합성 계정으로 검증했으며 운영 서버에 적용되었다는 뜻은 아니다.
[설치·사용·검증 안내](../operations/remote-learning-runtime.md)를 따른다.

[학생별 실행공간과 개발도구 모듈](learning-sandbox-modules.md)의 Java·디버거,
교수자의 환경 조합·공개와 전체 SES Host는 후속 설계다. 원격 실행을 추가해도 학생 PC의
프로그램·브라우저·외부 AI 접속을 통제하지 않는다.

같은 날의 [Git 기반 콘텐츠 CMS 확장](git-content-cms.md)은 서버 자료 버전 관리,
학생별 변경 파일 캐시, 검증된 snapshot과 명시적 내보내기의 1차 구현을 추가했다. VS Code/
Autograde IDE 0.5.9에서 수동 수신을 제공하며 기존 개인 PDF/ZIP 다운로드와 구분한다.
예약·자동 수신·오프라인 내보내기·Next.js 콘텐츠 관리는 후속이다.

2026-10-25 확장 0.5.12는 작성 중인 코드·이전 제출본·강의자료의 폴더/ZIP 내보내기와
공용 실습의 일회용 세션을 추가한다. 실행기가 만든 작업·자료·IDE 프로필은 앱 종료 뒤 정리하며,
내보낸 복사본과 서버 제출본은 보존한다. 기존 개인 폴더를 채택하거나 삭제하지 않는다.
[학생 내보내기와 공용 실습 운영](../operations/student-learning-export.md)을 따른다.

PostgreSQL은 향후 Docker 기반 서비스를 운영할 때 도입을 검토한다. Docker가 PostgreSQL의
기술적 전제라는 뜻은 아니며, 이번 연구의 설치·운영 범위를 늘리지 않기 위한 단계 구분이다.
현재 DB를 이전하거나 PostgreSQL 의존성·접속 설정을 추가하지 않는다.

1단계는 개발용 Code-OSS 구성과 학습 흐름 통합이다. 학생에게 배포 가능한 서명된 설치 파일,
자동 업데이트 서버, AI 사용 강제 차단, OS·네트워크 통제는 완료 범위에 넣지 않는다.
직접 실행은 [개념연구 실행 안내](../operations/autograde-ide-poc.md)를 따른다.

## 구성요소와 경계

```text
Autograde IDE
├─ 고정한 Code-OSS 소스와 작은 제품 설정
├─ 내장 Autograde 확장
│  ├─ 학습 홈과 서버 연결 상태
│  ├─ 기존 과제 수락·다운로드·이어하기
│  ├─ 제출·현재 결과·이전 최고점·제출 이력
│  ├─ 본인 배포 자료 목록·PDF/ZIP 저장
│  └─ 선택형 원격 C/C++/Python: 서버 저장·실행·공간 종료
├─ 로컬 학습자별 프로필·workspace·materials
│  └─ standard / restricted 시작 설정 (OS 격리 아님)
└─ 선택한 실습 방식
   ├─ 로컬 실행: 컴파일러·디버거·언어 도구 별도 준비
   └─ 원격 C/C++/Python: 학생 PC의 컴파일러·Python·Docker 설치 불필요
          │ 기존 HTTPS 학생 API
          ▼
기존 Autograde 서버
├─ 인증·수업·과제·제출·채점 서비스
├─ SQLite 원장
├─ ZIP·PDF·제출 원본 파일과 Git 작업 저장본
└─ 선택형 Linux 실행 관리자 (별도 프로세스·승인 이미지)
   └─ 학생별 임시 공간·실행 제한·삭제 확인
```

제품 설정과 빌드 도구는 `ide/code-oss/`, 학습 기능은 `extensions/vscode/`에 둔다.
Code-OSS 원본을 이 저장소에 대량 복사하거나 편집기 핵심에 인증·채점 로직을 다시 구현하지
않는다. 고정한 upstream 소스에 제품 이름·별도 사용자 데이터 경로와 내장 확장을 적용한다.
준비 도구는 대상 소스와 확장의 상태를 검사하며 기존 VS Code 설치·학생 작업 폴더를 바꾸지 않는다.
개발 실행은 별도 사용자·확장·공유 데이터 경로를 사용한다. 처음 생성하는 프로필에만 학습용
기본 설정을 기록하며 기존 사용자 설정을 덮어쓰지 않는다. 초기 설정은 수정 가능한 값이고
서버가 강제하는 시험 정책이 아니다.

인증과 접근 권한의 최종 판정은 계속 서버가 한다. IDE 화면·로컬 과제 연결 파일·제품 이름은
학생 본인이나 과제 제출 권한을 증명하지 않는다. 사용자 데이터 경로를 나누는 것도 보안 격리는
아니며, 공용 좌석의 작업 파일 정리와 OS 계정 관리 절차가 별도로 필요하다.

## 학생의 학습 흐름

학습 홈은 별도 로그인·제출 구현 대신 기존 확장 명령을 호출한다. 기존 VS Code 확장에서도
동일한 홈을 사용할 수 있지만, 전용 IDE 여부와 AI 통제 수준을 혼동시키지 않는다.
`Autograde IDE`의 폴더·작업 영역·열린 탭이 없는 창에서만 홈을 자동 표시한다. 기존 작업 창은
가로채지 않으며 사이드바의 학습 홈 또는 `Autograde: Open Learning Home` 명령으로 다시 연다.
홈은 허용 목록의 고정 동작만 전달하고 웹 화면이 임의 명령·인자·URL을 실행하게 하지 않는다.

| 상황 | 홈에서 수행할 작업 | 유지해야 할 조건 |
| --- | --- | --- |
| 처음 시작 | 서버 주소 확인 → 수업 폴더 선택 → 수령 코드 입력 | 학생 웹의 인증·일회용 코드 흐름을 재사용한다. |
| 새 과제 수령 | 다운로드 → 과제 설명·소스 열기 | 기존 답안을 덮어쓰지 않는다. |
| IDE 재시작 | 공용: 새 과제 다운로드 또는 서버 작업 저장본·제출본 복원. 개인: 기존 폴더 열기 | 공용 모드에서는 이전 로컬 작업을 보존하지 않는다. |
| 다른 과제로 전환 | 수락 이력 확인 → 대상 과제 재연결 → 폴더 확인 | 다른 과제 소스를 현재 과제에 자동 제출하지 않는다. |
| 제출 | 대상 과제·저장 파일 확인 → 접수 → 채점 대기 | 접수 성공을 채점 완료로 표시하지 않는다. |
| 결과 확인 | 현재 제출 결과 → 수정할 항목 → 이전 최고점·이력 | 과거 점수를 새 제출의 채점 결과로 대체하지 않는다. |
| 원격 C/C++/Python 실습 | 환경 준비 → 현재 코드 저장 후 실행 → 저장 후 공간 종료 | C/C++은 빌드 후 실행. Python은 진입 파일 1개 실행. 공식 제출·점수와 구분한다. |
| 개인 자료 수령 | 내 배포 자료 → PDF/ZIP 선택 → 별도 자료 폴더 저장 | 본인 자료만 조회하고 과제 소스와 섞거나 ZIP을 자동 실행·해제하지 않는다. |
| 내보내기 | 현재 코드·이전 제출본·자료 선택 → 폴더/ZIP 저장 | 제출 대상을 바꾸지 않고 세션 밖에 독립 복사한다. |
| 종료 | 공용 실습 종료 → 실행기 정리 확인 | 서버 제출본과 내보낸 파일은 유지하고 소유 세션만 정리한다. |

현재 과제 권한과 로컬 작업 폴더의 차이, 연결 끊김·폴더 이동·미저장 파일 처리 기준은
[과제 이어하기·전환·재제출](../operations/assignment-workspace-lifecycle.md)을 그대로 따른다.
홈은 이 계약을 새로 정의하지 않는다.

## 개인 자료 배포 API

기존 교수자 자료 등록·수정·기간 관리와 학생별 파일 배정 기능을 재사용한다. 자료는 성적과
무관하며 과제 파일을 변경하거나 새 제출을 만들지 않는다. IDE는 기존 수령 코드로 연결된
학생 세션을 사용하므로 자료만 받는 학생도 현재는 수령 코드 로그인이 필요하다.

- `GET /v1/materials`: 토큰이 속한 교과목의 본인 배정 자료만 반환한다. 학번·교과목 선택
  파라미터를 받지 않고 서버가 인증·활성 수강 상태를 판정한다. 한 번에 30개와 `next_cursor`
  (마지막은 null)를 반환하고 이후 `?cursor=...`로 조회한다. 커서는 학생·수업·목록 버전에
  연결하며 중간에 변경되면 409로 처음부터 재조회한다. 클라이언트는 중복/반복 커서를 거절하고
  1,000개를 초과하면 일부를 전부인 것처럼 표시하지 않고 자료 정리를 요청한다.
- `GET /v1/materials/{id}/download`: 목록의 SHA-256을 `X-Autograde-Expected-SHA256`에
  보내며 파일 교체 시 409로 중단하고 목록 갱신을 안내한다. 배포 전·종료 후 다운로드는 거절한다.
- PDF/ZIP 최대 25MiB. 서버 스냅샷·권한 검사와 클라이언트 크기·형식·해시 검증을 모두 거친다.
  인증/서버 변경 시 진행 중 요청을 취소하고 지연 응답을 폐기한다.
- IDE는 기존 파일을 덮어쓰지 않는다. 현재 작업 영역·연결한 과제 폴더 안의 저장을 거절하고
  별도 폴더를 사용한다. 파일은 자동으로 열거나 압축 해제하지 않는다.
- 서버의 기존 다운로드 요청 기록을 재사용한다. 이 기록은 실제 저장 완료나 학생 열람을
  증명하지 않으며 성적·학습 완료 지표로 자동 전환하지 않는다.

서버의 자료 배포 서비스가 활성화되지 않았거나 구버전이면 학생 웹 이용·서버 갱신을 안내한다.
기존 CSV·SQLite와 자료 저장소를 유지하며 별도 DB나 저장소 이전은 없다.

## 학생별 학습공간: 논리 분리 MVP

`run --learner <로컬별칭>`은 기본적으로 `shared` 수명으로 매번 새 세션의 `workspace`,
`materials`, `user-data/extensions/shared-data`를 만든다. 앱 종료 뒤 소유 세션을 정리하고,
비정상 종료 잔여물은 다음 실행 전에 검증·정리한다. 정리를 확인할 수 없으면 다음 세션을 막는다.
한 세션의 최초 인증 후 다른 학생·과제 인증으로 교체할 수 없다. 재인증이 필요하면 코드를
내보낸 뒤 새 세션을 시작한다. `persistent`를 명시한 개인 모드는 기존 코드를 보존한다.
별칭과 표식은 로컬 폴더 수명 구분이며 서버 학생 신원이나 OS 격리를 증명하지 않는다.

학습 홈의 프로필·정책 표시는 실행기가 전달한 힌트다. 편집 가능한 환경 값이므로 서버에
정책 준수 증거로 보내지 않는다. 자료 폴더 힌트도 사용자가 선택할 기본 위치일 뿐 자동 저장
권한이 아니다. 일반 VS Code에서는 이 힌트를 사용하지 않는다.

**동일 OS 계정으로 접근 가능한 파일·프로세스는 서로 차단되지 않는다.** 별칭만 바꾸면 다른
학습공간을 열 수 있으므로 공용 좌석에서 학생 간 기밀성이 필요하면 OS 계정 또는 별도 VM이
필요하다. WSL2 배포판 하나를 여러 학생이 공유하는 것만으로도 이 요구를 충족하지 않는다.
학생 PC에는 OS·컨테이너·VM을 자동 생성하지 않으며 기존 개인 파일을 삭제하지 않는다.
로컬 자동 정리 대상은 실행기가 소유한 공용 세션뿐이며 macOS 창 닫기만으로는 앱 종료가 보장되지 않는다.
선택형 원격 실습의 서버 컨테이너는 별도 실행 관리자가 생성·회수한다. 서버 작업본·공식
제출본은 남기며, 강제 종료나 통신 단절 때의 원격 회수는 임대 만료·재시작 정리에 의존한다.

학생 PC 전체를 격리하는 OS/VM 후속 모듈과 추가 실행 제공자는 다음 계약으로 검증한다.

1. 서버 인증 학생과 관리된 OS 계정/VM을 연결하고 학생별 전용 볼륨·최소 권한을 제공한다.
2. 검증된 언어 도구 이미지, CPU·메모리·디스크 제한, 네트워크 허용 목록을 관리한다.
3. 개인 홈·호스트 소켓·관리자 권한을 공유하지 않고 반출 파일만 명시적으로 교환한다.
4. 종료·오프라인·관리 서버 장애 시 작업 보존·정책 해제·보존 기간·삭제 승인을 기록한다.
5. Linux 컨테이너/VM, Windows 관리 VM 또는 학생별 OS 계정, macOS VM을 각각 인수한다.
   선택형 원격 Linux 이외 제공자는 후속 설계이며 실행 가능한 제공자로 표시하지 않는다.

## AI 통제와 시험 환경의 분리

1단계의 AI 관련 기본 설정은 불필요한 내장 AI 진입점을 줄이는 용도다. 사용자가 변경할 수 있는
기본값, 확장 갤러리 비설정, 전용 제품 이름을 시험 보안 경계로 취급하지 않는다.
IDE 내부에서 기능이 보이지 않아도 브라우저·터미널·다른 프로그램·다른 기기의 AI 사용은 가능하다.
고정 소스 1.143.0의 시작에 필요한 `defaultChatAgent` 메타데이터는 보존하고, 기본 설정과 실행
플래그로 내장 AI 진입을 비활성화한다. 모든 AI 코드·접속 주소 제거 또는 네트워크 차단은 아니다.

| 단계 | 기능 | 상태와 한계 |
| --- | --- | --- |
| 1단계 | Autograde 내장·학습 홈·독립 개발용 제품 설정 | 이번 구현 범위. AI 미사용 증명을 제공하지 않는다. |
| 2단계 MVP | 개인 자료 배포·학습자별 프로필·IDE 제한 시작 설정 | 구현. 시작 검사와 로컬 환경 안내이며 정책 강제·준수 증명은 아니다. |
| 정책 연계 | 서버의 수업·과제별 정책, 서명된 승인 확장 목록 | 후속 설계. 정책 계약·변조·재연결·해제 절차를 먼저 정의한다. |
| 별도 시험 환경 | 관리 PC의 실행·OS·네트워크 통제 | 후속 독립 모듈. 학생 고지, 관리자 승인, 장애·종료 시 복구가 필요하다. |

화면 캡처, 비밀 모니터링, 브라우저 기록 수집, hosts 파일 변경, 방화벽 변경은 이번 IDE에
포함하지 않는다. 연결·정책 적용 상태만으로 부정행위 여부를 자동 판정하지 않는다.
서버 측 학생 코드 격리도 별개이며, IDE 내장으로 `pilot-local` 채점이 안전한 샌드박스가 되지 않는다.

`--learning-policy restricted`는 학습자 프로필에서 채팅·Agent·Copilot CLI 진입을 비활성화하고,
확장 허용 설정을 deny-all로 시작한다. 승인하지 않은 사용자 확장·추가 내장 확장·대체 프로필·
충돌 설정은 실행 전에 거절하며 파일을 지우거나 개인 VS Code 설정을 바꾸지 않는다.
고정 소스에서 사용하는 설정/플래그를 검사하지만 시작 후 변경, 터미널에서 실행한 AI CLI,
외부 프로그램 및 네트워크를 막는 OS 통제는 아니다. 시험용 AI 금지 보장으로 사용하지 않는다.
임의 사용자 확장을 허용하지 않으므로 clangd 같은 비생성형 도구도 별도 검토·승인 빌드가 필요하다.

## C·C++·Python 개발 환경

일반 코드 완성·문법 검사·컴파일 오류 안내와 생성형 AI를 구분한다. 컴파일러나 언어 서버를
일괄 차단하지 않으며, clangd 등 사용 후보의 라이선스·배포 방식·런타임 요구사항을 확인한다.
이번 단계는 C/C++ 도구를 자동 설치하거나 모든 플랫폼에서의 디버깅을 보장하지 않는다.

- 선택형 원격 실습은 승인된 Linux 이미지의 C17/C++17 컴파일·실행을 제공한다. Mac IDE에는
  로컬 컴파일러가 필요하지 않다. 실행 시 생성된 임시 파일은 서버 작업본으로 자동 저장하지 않는다.
- Python 3 실행은 진입 파일 1개, 같은 저장본의 모듈·표준 라이브러리, 표준입출력과 오류 표시를 제공한다.
  학생 PC에 Python을 설치하지 않는다. pip·추가 패키지 설치·대화형 터미널은 지원하지 않는다.
- Java·원격 디버거·환경 패키지 조합은 후속이며 현재 화면에 실행 가능 도구로 표시하지 않는다.
- Linux/macOS의 로컬 편집·제출 흐름을 우선 검증한다. 실제 컴파일러와 디버거는 따로 검증한다.
- Windows 네이티브 C/C++ 도구 연결, MSVC 및 Windows 시스템 프로그래밍은 별도 인수 대상이다.
- Windows에서 WSL을 원격 작업 영역으로 여는 기능은 별도 인수 대상이다. 기존 Microsoft
  Remote WSL 확장을 fork 제품에 그대로 포함하거나 사용할 수 있다고 가정하지 않는다.
- Visual Studio 2022/2026 확장을 유지한다. Autograde IDE를 도입해도 Visual Studio의 솔루션·
  Windows 개발 도구 지원을 대체했다고 표시하지 않는다.

## 배포와 유지보수

Code-OSS 소스와 Microsoft Visual Studio Code 배포판은 구분한다. upstream 소스의 MIT
라이선스·저작권 표시와 필요한 제3자 고지를 보존한다. Microsoft Marketplace를 fork의 기본
확장 공급처로 연결하지 않고, 추가 확장은 개별 라이선스와 재배포 가능 여부를 검토한다.
[Microsoft의 제품·라이선스 설명](https://code.visualstudio.com/docs/supporting/faq#_licensing)을 기준으로
실제 배포 전에 조건을 다시 확인한다.

릴리스 후보에는 Code-OSS commit, Autograde 확장 버전과 해시, 제품 설정, 빌드 플랫폼을 기록한다.
개발용 실행과 서명·공증·설치·업데이트 검증을 구분한다. Microsoft 배포판의 업데이트 주소나
서명을 재사용하지 않는다. upstream 보안 패치 검토·적용, 확장 API 호환성 검사, 플랫폼별
패키징·코드 서명과 복구 가능한 업데이트 채널은 정식 배포 전 완료해야 한다.

## SES와 제품군 연결

전체 플랫폼의 [플러그인·SES 설계](platform-plugin-ses.md)에 `client.autograde_ide`를
클라이언트 대안으로 추가한다. SQLite와 다른 저장소 선택은 클라이언트 선택과 독립적이다.
IDE 제품 구성 때문에 수업의 저장소·인증·성적 정책을 바꾸지 않는다.

`policy.learning`과 `guard.exam_environment`는 후속 계약 후보다. 현행 SES JSON이나 CSV에
입력해 실행할 수 있는 플러그인이 아니며, `runtime_ready=true`로 선언하지 않는다.
1단계 준비 도구는 고정 제품 구성을 만드는 도구이지 SES pruning·승인·activation Host가 아니다.

이번 모듈 경계는 서버 `student_material_api`(기존 자료 서비스 어댑터), 확장
`studentMaterials`/`studentMaterialsView`(조회·검증·수령), 실행기 `learning-profile`
(로컬 공간·시작 정책), 확장 `learningEnvironment`(정보 표시)로 나눈다. 자료 배포는 기존
수업 서비스 활성화에 따라 주입하며 격리 수준과 별개다. SES의 향후 선택 축은
`workspace.directory_profile | workspace.os_account | workspace.vm` 및
`ai_policy.launch_defaults | ai_policy.managed_environment`로 설계하되, 뒤의 OS/VM 선택은
실행 구현이 없는 설계 후보임을 유지한다.

## 인수 기준

1. 고정한 upstream 이외의 소스나 손상된 내장 확장을 준비 도구가 거절한다.
2. 기존 VS Code 프로필·설치와 분리하여 시작하며 내장 확장과 학습 홈을 확인할 수 있다.
3. 새 과제 다운로드와 기존 과제 이어하기가 동일한 서버 API·권한 검사를 거친다.
4. 현재 제출의 접수·채점 대기·결과와 이전 최고점을 구분한다.
5. 재시작·인증 만료·통신 오류·과제 전환 시 기존 소스를 보존하고 다음 행동을 안내한다.
6. 홈의 버튼·본문은 밝은 테마·어두운 테마와 좁은 창에서 읽을 수 있다.
7. IDE의 기본 설정을 AI 강제 차단·시험 인증으로 표시하지 않는다.
8. 다른 학생·교과목 자료, 배포 기간 위반·자료 교체·인증 만료를 거절하고 다운로드 실패 시 기존 파일을 보존한다.
9. 공용 모드는 종료·재실행 때 소유 작업과 인증을 정리하고, 명시한 개인 모드만 로컬 작업을 보존한다.
   링크·소유 표식·정책 충돌을 거절하며 공용 작업 복원에는 본인 서버 저장본을 사용한다.
10. 원격 실습이 활성화된 경우 학생·수업·과제 권한과 현재 서버 저장본을 확인하고 실행한다.
    저장·실행·삭제 실패를 성공으로 표시하지 않으며 다른 학생 공간은 조회·사용할 수 없다.

자동 검사, Code-OSS 전체 빌드, 실제 화면 조작, 플랫폼별 설치·채점 서버 연동은 서로 다른
검증 항목이다. 실행 안내에 각 상태를 기록하고 하나의 통과를 전체 배포 완료로 해석하지 않는다.


## 공용 작업 상태의 지속성과 초기화

공용 실행기의 작업 경로는 OS 계정별 `current/workspace`로 고정하되 세션 식별자와 인증은
실행마다 새로 만든다. 30초 간격으로 연결된 과제의 변경 여부를 검사하고 작업본을 서버의
비공개 Git 저장소에 보관한다. 공식 제출·채점 데이터와 분리하며 SQLite 구성은 유지한다.
저장 성공을 응답받은 작업본만 보관된 것으로 표시하고, 복원은 기존 파일을 덮어쓰지 않는
새 폴더에서 수행한다. 종료 뒤 정리가 중단되면 다음 시작에서 소유권·프로세스를 확인하고
남은 관리 파일을 지운다. 서버 미전송 작업을 다음 학생 인증으로 업로드하지 않는다.
경로, 저장 한도, 실패 처리와 시험 절차는 [운영 안내](../operations/shared-workspace-checkpoints.md)에 정의한다.
