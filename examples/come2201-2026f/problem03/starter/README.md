# Week06 · Problem03: 레거시 센서 통합 보고서

- 교과목: COME2201
- 마감: **2026-10-07 13:50 (Asia/Seoul, KST)**
- 언어: C++17 / 채점 대상: main.cpp
- 설계 패턴: Adapter(Adaptor), Template Method

## 문제 상황과 학습 목표

실습실의 온도 센서가 두 종류입니다. 기존 섭씨 센서는 0.1도 단위 정수를,
기존 화씨 센서는 1도 단위 정수를 제공합니다. 이미 다른 프로그램에서도 사용하는 레거시 API라서
메서드 이름·시그니처·단위를 변경할 수 없습니다. 보고서마다 센서 종류를 검사하고 환산하면
중복과 오류가 늘어납니다.

두 센서를 공통 섭씨 데이터 소스로 연결하고, 전체 관측값 보고서와 영하를 제외하는 보고서를 만드세요.
실제 장치나 파일을 읽는 것이 아니라 입력한 원시값을 센서 객체가 가지고 있는 콘솔 프로그램입니다.

- Adapter가 서로 다른 API와 단위를 공통 TemperatureSource로 변환합니다.
- Template Method가 읽기 → 필터링 → 집계 → 출력의 공통 순서를 고정합니다.
- 파생 보고서는 필터 조건만 바꾸며 집계 코드를 중복하지 않습니다.
- 필터링 시점, 실수 연산, 빈 데이터 처리를 정확하게 구분합니다.

## 입력·출력 계약

첫 줄은 `sensor policy N`, 이어서 N개의 원시 정수가 공백 또는 줄바꿈으로 구분되어 주어집니다.
N은 0..100, 각 원시값은 -1000..1000입니다. 정수 형식과 토큰 수는 올바릅니다.
N=0이면 읽을 원시값이 없습니다. 식별자는 대소문자를 구분합니다.

| 항목 | 허용 값 | 의미 |
| --- | --- | --- |
| sensor | C | 원시값이 섭씨의 10배인 정수 |
| sensor | F | 원시값이 화씨 정수 |
| policy | ALL | 변환한 값을 모두 유지 |
| policy | NONNEGATIVE | 변환 후 섭씨가 0 이상인 값만 유지 |

환산은 C의 경우 `원시값 / 10.0`, F의 경우 `(원시값 - 32) × 5.0 / 9.0`입니다.
정수 나눗셈으로 계산하지 마세요. NONNEGATIVE의 기준은 **원시값이 아니라 변환한 섭씨 값**이며,
섭씨 0도는 포함합니다. 집계가 끝나기 전에 표시용 한 자리 소수로 값을 잘라 계산하지 않습니다.

### 정상 출력

유지된 값이 있으면 아래 순서로 정확히 네 줄을 출력합니다.

| 줄 | 형식 | 계산 대상 |
| --- | --- | --- |
| 1 | `COUNT 개수` | 필터 후 유지된 값의 수 |
| 2 | `MIN 최솟값` | 유지된 값 중 최솟값 |
| 3 | `MAX 최댓값` | 유지된 값 중 최댓값 |
| 4 | `MEAN 산술평균` | 유지된 값의 합 ÷ 유지된 개수 |

개수는 정수이고 온도는 `std::fixed << std::setprecision(1)`에 해당하는 **소수점 아래 정확히 한 자리**입니다.
0은 0.0으로 출력합니다. 단위 기호·쉼표·설명은 붙이지 않습니다. 채점 입력은 표시 결과가 플랫폼별
반올림 경계에 걸리지 않도록 구성됩니다.

입력이 없거나 필터 후 아무 값도 남지 않으면 **COUNT 0, NO_DATA 두 줄만** 출력합니다.
이때 MIN/MAX/MEAN을 출력하거나 빈 범위에서 최솟값을 찾거나 0으로 나누지 않습니다.

### 오류 출력

sensor가 C/F가 아니면 `ERROR sensor` 한 줄을 출력하고 종료합니다.
sensor가 유효하지만 policy가 ALL/NONNEGATIVE가 아니면 `ERROR policy` 한 줄을 출력하고 종료합니다.
둘 다 잘못되면 sensor 오류가 우선입니다. 오류 시 COUNT나 통계값을 추가로 출력하지 않습니다.

## 구현 단계

1. CelsiusSensor::readTenths(), FahrenheitSensor::readWholeDegrees()의 기존 계약을 읽습니다.
   이 레거시 클래스의 이름·시그니처·원시 단위를 바꾸지 않습니다.
2. CelsiusAdapter와 FahrenheitAdapter가 TemperatureSource::readCelsius()를 구현하도록 설계합니다.
   보고서는 어떤 레거시 센서가 연결되었는지 몰라도 동작해야 합니다.
3. Report::run()에서 공통 순서를 구현합니다. 읽은 값에 keep()을 적용하고 남은 값만 집계합니다.
4. AllReport와 NonnegativeReport가 keep()의 조건만 다르게 제공하게 합니다.
5. main은 식별자를 검증하고 Adapter와 Report를 선택한 뒤 공통 진입점을 호출하게 합니다.
6. 원시값·섭씨 환산값·필터 후 값·평균을 종이에 나란히 적어 출력과 비교합니다.

출력까지 한꺼번에 작성하기보다 센서 환산, 필터, 빈 결과, 통계 순으로 확인하세요.
같은 집계 코드를 보고서별로 복사하면 Template Method의 목적을 달성하지 못합니다.

## 공개 실행 예제

각 예제는 별도 프로그램 실행입니다.

### 예제 1 — 화씨 데이터를 공통 섭씨로 읽기

입력
```text
F ALL 3
32 68 104
```

출력
```text
COUNT 3
MIN 0.0
MAX 40.0
MEAN 20.0
```

환산값은 0, 20, 40도이므로 평균은 (0+20+40)/3=20도입니다.

### 예제 2 — 원시값이 양수여도 섭씨 영하는 제외

입력
```text
F NONNEGATIVE 5
5 23 32 41 59
```

출력
```text
COUNT 3
MIN 0.0
MAX 15.0
MEAN 6.7
```

원시값은 모두 양수지만 환산값은 -15, -5, 0, 5, 15도입니다. 0, 5, 15만 남으므로
COUNT는 3이며 평균 20/3을 한 자리 소수로 표시하면 6.7입니다.

## 자기 점검과 FAQ

- [ ] C/F와 ALL/NONNEGATIVE의 네 조합을 확인했습니다.
- [ ] C의 원시값 0과 F의 원시값 32가 필터를 통과합니다.
- [ ] N=0, 모두 제외, 값 하나만 남는 상황을 확인했습니다.
- [ ] 잘못된 식별자와 오류 우선순위를 확인했습니다.

**NONNEGATIVE는 입력 정수가 0 이상이면 되나요?** 아닙니다. 섭씨로 환산한 다음 판단합니다.

**평균을 원래 N으로 나눠도 되나요?** 안 됩니다. 유지된 값의 개수로 나눕니다.

**섭씨 센서도 Adapter가 필요한가요?** 필요합니다. 레거시 단위는 0.1도 정수이고 공통 인터페이스는 섭씨 실수입니다.
