# 수업 운영 개선과 SES 기반 모듈 구성

2026-09-17 · Canvas/LTI 연동은 이번 로드맵에서 제외한다.

## 1. 범위와 현재 상태

목표는 수업 종료까지의 운영 부담을 줄이고, 학생 지원에 필요한 근거를 제공하며,
수업마다 필요한 기능만 조합하는 것이다. 분석 결과로 성적·수강 자격을 자동 변경하지 않는다.

**이번에 구현한 것:** 제한된 SES 모델 검증, 수업별 specialization 선택,
multi-aspect 인스턴스화, PES 구성 미리보기, 파라미터·의존성 검사, 결정적 구성 해시, 읽기 전용 CLI.
**아직 구현하지 않은 것:** 아래 보관 작업자·보고서 생성기·학생 분석·알림·설정 웹 UI와 운영 서버 연결.
Model Base는 인터페이스 계약 목록이며 실행 모듈이 아니다. 출력의 runtime_ready=false를 유지한다.
기존 서버 설정·DB·학생 자료·이전 확장 변경은 건드리지 않는다.

## 3. 과제 수명주기: claim 종료 ≠ 압축 시점

| 필드(설계) | 의미 |
| --- | --- |
| claim_code_expires_at | 발급한 1회용 코드의 유효기간. 과제 운영 기간이 아님 |
| claim_opens_at / claim_closes_at | 학생이 과제를 **처음 수락**할 수 있는 기간 |
| submission_due_at | 기본 제출 마감 |
| effective_due_at(student) | 해당 학생의 승인된 연장/대체 일정까지 반영한 실제 마감 |
| appeal_until | 결과 정정·이의신청·재채점 처리 기간 |
| archive_not_before | 보관 가능한 가장 빠른 시각 |
| retain_until | 보관본 검토 시점. 삭제 명령이 아님 |

신규 수락을 닫아도 이미 수락한 학생의 재로그인 코드는 따로 발급할 수 있어야 한다.
마감 전이면 제출 권한, 마감 후이면 본인 결과 조회 권한을 적용한다.
코드 발급 권한, starter 재다운로드, 제출 권한, 결과 열람은 각각 검사한다.
현행 단일 과제 세션 검사를 이 모델로 바꾸는 것은 **후속 구현**이다.

    과제 준비 → 공개 → 신규 수락 종료 → 제출 종료 → 결과 확정·이의신청 종료
                                                              ↓
                                             보관 후보 → 검증된 보관본 → 복원 가능

이는 기본 경로다. 개인별 연장·늦은 제출 허용·재채점·보관 금지가 있으면 자동 진행을 보류한다.
마감 없는 과제는 자동 보관하지 않는다. 신규 수락 마감은 제출 마감 이후가 될 수 없도록 검증한다.
일정 저장은 UTC, 화면과 주간 집계는 수업 시간대(기본 Asia/Seoul) 기준이다.
경계는 now >= deadline이면 종료로 통일한다.

보관 후보 시각은 **학생별 effective_due_at 최댓값, 이의신청 종료, 결과 확정 시각 중
가장 늦은 시각 + 보관 지연 기간**으로 계산한다.
마지막 채점/재채점/업로드/교수자 검증 작업이 종료되었는지 다시 확인한다.
이벤트가 누락되어도 정기 스캔으로 재평가하며 같은 작업을 두 번 만들지 않는다.

## 4. 보관·압축·복원 모듈

### 보관 대상

- 공개 과제 버전·문제 설명·starter digest·채점 기준 버전·제출별 digest와 접수 시각.
- 점수·공개 상태·항목별 결과, 승인된 마감 연장/면제, 당시 정책 버전.
- 파일별 크기·SHA-256·파일 수·schema_version·과제/수업 scope를 담은 manifest.
- 정답·비공개 테스트는 **교수자 전용 별도 영역**. 학생용 묶음에 넣지 않는다.
- 원장 전체 DB, 비밀번호 원문/해시, 로그인 토큰, 코드, roster 원본은 과제 보관본에 넣지 않는다.
  전체 서비스 백업은 별도 접근제어·복구 정책으로 관리한다.

원본 bundle은 이미 tar.gz다. 기본 LocalTarArchive는 검증된 bundle을 중복 없이 모은
보관 컨테이너와 manifest를 만들고, 기존 압축 파일에 중첩 gzip을 강제하지 않는다.
저장소 어댑터는 파일 형식과 보관 정책을 분리한다.

### 안전한 작업 순서

1. **미리보기:** 대상·예상 용량·진행 작업·연장·보관 금지·다른 과제의 공유 참조 표시.
2. **예약:** assignment_id + snapshot revision + 정책 해시로 식별. 짧은 DB 트랜잭션으로 lease 획득.
3. **스냅샷:** SQLite 일관 읽기 기준점과 불변 blob 목록 확보. 압축 동안 쓰기 잠금을 유지하지 않음.
4. **생성:** 접근 제한된 임시 위치에 복사/포장. 작업 중 새 자료를 스냅샷과 섞지 않음.
5. **검증:** 해시·파일 수·크기·참조 검사, 별도 임시 경로에 시험 복원. 파일 존재만으로 성공 처리하지 않음.
6. **등록:** fsync·원자적 rename 후 DB에 verified 보관본 등록. 그동안 마감·revision이 바뀌면 전환 보류.
7. **논리 보관:** 과제 목록에서 ‘보관’으로 이동. 수업 전체 archived 상태를 대신 사용하지 않음.
8. **공간 회수:** 이번 MVP에서는 비활성. 별도 승인·참조 검사·백업 확인 후 GC로 설계.

파일 작업과 DB 갱신은 하나의 원자적 작업이 아니므로 단계별 저널과 재시작 조정 작업을 둔다.
실패하면 원본을 유지하고 archive_failed를 표시한다. 임시 파일도 소유권·lease 확인 후 정리한다.
이미 만들어진 보관본은 검증해 재사용하되 이전 기록을 덮어쓰지 않는다.

복원은 새 경로에 검증 후 새 참조를 등록한다. 기존 제출·점수를 덮어쓰지 않는다.
복원만으로 신규 수락·제출을 다시 열지 않으며 ‘재개’는 별도 승인이다.
학생 소스 보존 기간이 지나도 본인 결과·메타데이터 열람은 별도 보존 정책을 따른다.
**보관은 백업이 아니다.** 같은 디스크의 보관본만으로 장애 복구가 가능하다고 표시하지 않는다.
보관 180일 등은 학교가 검토할 예시 설정값이지 의무 기간이 아니다.
보존 만료는 검토 알림만 발생시킨다. 이의신청·감사·보관 금지를 자동 삭제로 무시할 수 없다.

## 5. 보고서 모듈

| 보고서 | 내용 | 주기/대상 |
| --- | --- | --- |
| 주간 수업 운영 | 의무 대상·수락/미수락·제출/미제출·처리 지연·지원 검토 | 교수자 주간 |
| 과제 품질 | 항목별 실패·컴파일/실행 오류·재제출·이의신청·서버 오류 | 과제 종료 후 |
| 학생 실습 이력 | 개인 마감·접수 시각·선택 점수·공개 피드백·개선 추이·예외 | 본인/권한 있는 교수자 |
| 학기 성적 검토 | 채점 기준 버전·최신/최고/확정 점수 정책·누락·미확정·예외 | 교수자 확정 전 |
| 보관·복원 증빙 | 대상·용량·digest·검증/복원 시각·보존 기간·실행자 | 운영자 |
| 서비스 상태 | 접수→채점 대기시간·오류율·큐 적체·디스크·백업 복구 점검 | 운영자 |

1차 형식은 HTML·CSV. PDF/XLSX는 별도 exporter로 후속 제공한다.
CSV에는 수식으로 해석될 셀의 안전한 이스케이프와 UTF-8·열 정의를 적용한다.
HTML은 학생 이름·진단 등 비신뢰 텍스트를 이스케이프한다.
비밀번호·코드·토큰·비공개 테스트는 어떤 보고서에도 넣지 않는다.
다운로드는 인증·수업 권한 검사·짧은 만료 링크·감사 기록을 거친다.
큰 보고서는 비동기로 생성하고 생성 대기/완료/실패와 데이터 기준 시각을 표시한다.

### 지표 정의

분석 단위는 **수업 개설(course_key) × 학생 수강 × 논리 과제**다.
새 release를 같은 실습의 추가 의무로 중복 계산하지 않도록 논리 과제 ID를 분리한다.

- 의무 대상: 과제 대상 기간에 수강 자격이 있고 공개 과제를 수행해야 하며 면제되지 않은 셀.
  현재 활성 명단만 곱하지 말고 등록/취소 유효시각·대상자 스냅샷을 사용한다.
- 수락률: 기준 시각까지 최초 수락한 의무 대상 / 전체 의무 대상. 코드 발급만으로 수락 처리하지 않음.
- 기한 내 접수율: 개인 마감 이전 receipt가 있는 대상 / 마감이 지난 의무 대상.
  유효성 거절은 별도 열로 표시해 접수와 유효 제출을 구분한다.
- 미제출률: 마감이 지난 의무 대상 중 receipt가 없는 수 / 마감이 지난 의무 대상.
  분모 0은 N/A, 마감 전 과제는 제외.
- 점수 달성률: 공개된 유효 score / max_score. 0점 배점·누락·잘못된 점수는 N/A.
- 재제출: 서로 다른 접수본 수. 같은 요청 재시도는 별도 시도나 학습 실패로 세지 않음.
- 지원 필요 추이: 동일 정의의 주차별 근거 변화. 서버 장애·미공개·면제를 성적 0으로 대체하지 않음.

보고서에 as_of·시간대·대상 범위·분자/분모·점수 기준·rubric 버전·PES 해시·누락 건수를 담는다.
latest는 가장 최근 접수본의 상태까지 표시한다. 최근 제출이 채점 중이면 예전 점수를 최신으로 대체하지 않는다.
best는 유효·공개 평가끼리 비교하고 배점·rubric이 비교 불가능하면 판정하지 않는다.
instructor_confirmed는 확정 레코드가 없으면 미확정이며 자동 대체하지 않는다.
보고서 선택 정책은 실제 성적 원장을 변경하지 않는다.

## 6. 학습 지원 분석과 후속 조치

기능 이름은 ‘낙오/위험 학생 판정’ 대신 **학습 지원 확인 대상**으로 한다.
규칙과 근거를 공개하고 학생을 평가·제재하는 자동 의사결정으로 쓰지 않는다.

| 확인 신호 예시 | 필요한 근거 | 제외/주의 |
| --- | --- | --- |
| 마감이 지난 의무 실습 2회 연속 미제출 | 과제·개인 마감·수강·면제·receipt | 연장·면제·서버 장애 기간 제외 |
| 유효 평가 3개 이상, 최근 3개 모두 60% 미만 | 공개 점수·배점·rubric·접수본 | 기준값은 예시. 비교 불가 과제·미공개 제외 |
| 서로 다른 제출 3회에서 같은 컴파일 오류 범주 | 제한된 오류 분류·서로 다른 source digest | 통신 재시도·서버 환경 오류 제외 |
| 교수자 설명 후에도 같은 항목 미충족 | 항목별 결과·조치 기록 | 항목 매핑이 없으면 생성하지 않음 |

이번 SES의 규칙 파라미터는 최소 평가 수·연속 미제출 횟수·낮은 점수 기준이다.
반복 컴파일/항목 분석은 추가 모듈 계약으로 후속 확장한다.
학습 시간·출석·노력·성향·장애 여부를 로그인/다운로드 횟수만으로 추정하지 않는다.
온라인 활동이 없어도 오프라인으로 학습할 수 있다. 신규 수강이나 평가 부족은 ‘자료 부족’.
반 평균보다 낮다는 이유만으로 지원 대상으로 지정하지 않으며 공개 순위·낙인 점수를 만들지 않는다.

각 후보 카드에는 수업·학생, ‘확인 제안’ 상태, 규칙 버전·기준 시각,
근거 과제/제출, 제외 조건·자료 부족·서버 오류, 교수자 판단, 후속 조치·재확인 날짜를 담는다.
근거는 “개인 마감이 지난 실습 2건의 제출 기록 없음”처럼 사실 문장으로 쓴다.

후보 생성 → 교수자 확인 → 필요 시 연락 승인 → 지원 조치 → 재확인 → 해결/보류.
학생 자동 연락·성적/마감/등록 자동 변경은 하지 않는다.
같은 원인 알림은 학생·과제·규칙 버전별로 묶고 새 근거가 생길 때 다시 알린다.
학생의 사실 정정 요청을 받아 재계산하며 조치 후 변화는 관찰값이지 인과관계로 단정하지 않는다.
상담 자유기술은 최소화하고 건강·가정사 등 불필요한 민감 내용 입력을 유도하지 않는다.
개인별 교수자·조교 권한이 없는 현재 공유 인증 모드에서는 상담 기록을 운영 활성화하지 않는다.

## 7. SES 구조와 모듈 계약

단순한 enable 플래그 묶음이 아니라 구성 공간(SES)과 선택 결과(PES)를 구분한다.
Entity는 구성요소, Aspect는 구성 분해, Specialization은 대안 선택,
MultiAspect는 같은 템플릿의 수업별 반복을 표현한다.
구성·선택 개념은 [Wismar SES Toolbox](https://www.cea-wismar.de/tbx/SES_Tbx/examplesDoc/ses_tbx_index.html),
형식적 구조는 [Jafer 외 SES 논문](https://articles.jsime.org/1/2/)을 참고했다.
이 저장소 JSON은 해당 도구의 파일 형식과 호환된다고 주장하지 않는 제한된 자체 dialect다.

    ManagementSystem [Entity]
    └─ SystemComposition [Aspect]
       ├─ MandatoryCore [Entity] — 권한·수업 경계·감사·원장 보호
       └─ CourseFleet [Entity]
          └─ CourseReplication [MultiAspect: courses]
             └─ CourseManagement [Entity]
                └─ ManagementModules [Aspect]
                   ├─ Lifecycle [E] → [S] ManualLifecycle | DeadlineWindows
                   ├─ Archive [E] → [S] ArchiveDisabled | LocalTarArchive
                   ├─ Reports [E] → [S] ReportsDisabled | CsvReports | HtmlCsvReports
                   ├─ LearningSupport [E] → [S] SupportDisabled | ExplainableRules
                   ├─ Notifications [E] → [S] NotificationsDisabled | InstructorInbox
                   └─ Scheduler [E] → [S] ManualScheduler | PyJevSimScheduler

각 S의 자식은 Entity이며 그 잎은 Model Base의 고정 module_id에 연결된다.
임의 파이썬 코드·경로·표현식을 설정에서 실행하지 않는다.
보존 일수 등은 선택된 Entity의 검증된 attribute로 결합된다.
PES에서는 specialization을 선택된 Entity에 병합하고 multi-aspect를 수업별 분해로 확장한다.
수업별 이름 공간으로 서로 다른 구성의 노드 이름이 충돌하지 않게 한다.

현재 dialect는 entity/relation 교대, 유일 template label, 한 entity당 하나의 분해,
하나의 수업 반복, specialization 단일 선택을 지원한다.
전역 고유 template label로 strict hierarchy·valid brothers를 보장하고 uniformity의 모호성을 피한다.
일반 SES의 다중 Aspect 대안·동적 함수·범용 상속·일반 coupling 수식은 지원하지 않는다.
완전한 SES 검증기나 실행 가능한 DEVS 모델 생성기라고 부르지 않는다.

### Model Base / 서비스 경계 (실행 구현 예정)

| 모듈 | 입력 계약 | 출력 계약 | 직접 하면 안 되는 일 |
| --- | --- | --- | --- |
| LifecyclePolicy | 일정·수강/연장·현재시각·revision | 신규 수락 종료/보관 후보 결정 | 바로 파일 삭제 |
| ArchiveService | 승인된 snapshot·blob refs·manifest | 검증된 archive index·복원 작업 | 인증 DB 통째로 묶기 |
| ReportService | 일관 읽기 snapshot·점수 선택 정책 | ReportSnapshot + exporter 결과 | 원장 점수 변경 |
| SupportAnalyzer | ReportSnapshot·규칙 버전·예외 | 근거 있는 SupportSignal | 자동 낙제·학생 자동 통보 |
| InstructorInbox | 승인 범위·SupportSignal | 중복 제거 교수자 알림 | 외부 발송·임의 수업 조회 |
| SchedulerAdapter | 만료 일정·tick | 중복 방지 작업 예약 요청 | 이벤트 루프 안에서 압축/채점 |
| MandatoryCore | 주체·수업 scope·요청·버전 | 권한 검사·감사·불변 기록 | 정책 선택으로 권한 검사 끄기 |

Coupling은 Scheduler → Lifecycle → Archive,
읽기 projection → Report → Support → InstructorInbox다.
모듈 오류로 제출 API를 실패시키지 않으며 분석/보관은 별도 bounded worker에서 실행한다.
Model Base 등록 시 input/output 계약 버전·필요 capability·scope·부작용·복구 방식·테스트를 선언한다.
runtime loader는 배포 시 허용한 구현만 선택하고 contract_only 모듈 활성화를 거절해야 한다.

### 선택 제약

- DeadlineWindows는 PyJevSimScheduler 필요.
- LocalTarArchive는 DeadlineWindows 필요. 실제 작업은 보관 가드·승인 이후에만 실행.
- ExplainableRules는 CsvReports 또는 HtmlCsvReports의 snapshot capability 필요.
- InstructorInbox는 ExplainableRules 필요. 현재 계약은 학습 지원 알림만 포함.
- 자동 삭제·학생 자동 연락은 예시 설정으로 켤 수 없다. core는 선택 해제할 수 없다.
- 수업 key 중복, 알 수 없는 variant/module/parameter, bool을 정수로 넣기,
  코드 표현식, 잘못된 범위, 중복 JSON 키는 거절한다.

관리 설정은 중첩 구조이므로 JSON으로 표현한다. 기존 서버/roster CSV를 대체하지 않고 환경변수도 추가하지 않는다.
현재 CLI는 미리보기만 한다. pilot CSV에 아직 지원하지 않는 설정 키를 넣지 않는다.
각 profile은 **완전한 유효 설정**이며 암묵적 상속·과제 override는 없다.
후속 기본 → 교과목 개설 → 과제 override 도입 시 병합 출처를 표시하고,
기관 최소 보존·권한·개인정보 제한은 더 느슨하게 덮어쓸 수 없도록 한다.

## 8. SQLite와 작업 처리 설계

기존 SQLite를 유지한다. 아래는 신규 테이블 제안이며 이번 작업에서 migration은 실행하지 않는다.

| 테이블(제안) | 주요 키 / 역할 |
| --- | --- |
| management_policy_versions | scope, version, SES/PES hash, effective_at, actor, 승인 상태 |
| assignment_lifecycle | assignment, schedule_revision, claim/submission/appeal/archive 경계 |
| assignment_student_exceptions | enrollment, assignment, 면제·개인 마감·사유·승인자·유효기간 |
| management_jobs | 종류, scope, snapshot_revision, policy_hash, 유일 idempotency_key, lease, 재시도 |
| artifact_archives / archive_objects | 보관 index, 검증 상태, digest 참조, 보존 기한, 보관 금지 |
| report_snapshots | 기준시각, 대상·분모·정의·생성 버전, 권한 범위, 만료 |
| support_signals / support_actions | 근거·규칙 버전·교수자 검토·조치·정정 기록 |
| management_outbox / audit_events | 트랜잭션 이벤트·전달 상태, 행위자·수업·변경 사유 |

이벤트는 event_id, course_key, 필요한 객체 참조, occurred_at, schema_version, policy_hash를 사용한다.
비밀번호·코드·원시 소스는 이벤트에 넣지 않는다. at-least-once 전달을 전제로 event_id를 중복 제거한다.
순서가 뒤바뀌면 revision으로 거절한다. 상태 변경과 outbox 생성은 동일 트랜잭션,
실제 디스크 작업은 lease와 저널로 분리한다.

PyJevSim은 일정 tick과 모의 시간 시험에 사용한다. 실제 마감은 저장된 UTC 시각과 서버 시계를 비교한다.
재시작·일시중지 후 overdue 스캔으로 누락을 복구하고 OS supervisor가 프로세스를 관리한다.
worker는 수업별 quota, 최대 작업 수, 디스크 여유 검사, backoff·재시도 상한을 둔다.
이 설계만으로 20명 동시 제출을 보장하지 않는다. 보관·리포트 병행 부하 시험이 필요하다.

## 9. 관리자 UX

- **운영 홈:** 마감 예정, 미확정 결과, 실패한 보관/보고서, 지원 검토 대기, 디스크·큐 상태.
- **과제 상세 → 일정:** 코드 TTL이 아닌 신규 수락·제출·개인 연장·이의신청·보관 시각.
- **보관함:** 후보/진행/검증 완료/실패, 용량, 보호 사유, 미리보기·보관·복원. 삭제는 별도 승인.
- **보고서:** 범위·기준일·점수 기준 → 분모/누락 미리보기 → 생성 → 다운로드.
- **학생 지원:** 근거 확인 → 판단 → 지원 조치 → 재확인. 자동 낙인·순위 없음.
- **수업 설정 → 운영 구성:** SES 템플릿·variant → 파라미터 → 의존성 설명 →
  PES 미리보기·이전 버전 차이 → 검증 → 담당자 승인 → 적용 시점 예약.

설정 변경은 기존 제출·확정 보고서에 소급하지 않는다. 새 작업은 새 버전, 실행 중 작업은 원래 버전을 고정한다.
설정 되돌리기는 새로운 정책 버전이며 삭제한 파일을 복구하는 기능이 아니다.
분석 off는 이후 후보 생성을 중단하지만 기록을 몰래 삭제하지 않는다. 정리는 별도 정책/승인이다.

## 10. 단계별 구현·검증

0. **이번 완료:** SES·수업 profile 예시, 읽기 전용 PES 미리보기와 구성 단위 시험.
1. **일정/권한/운영 기반:** 독립 claim 기간·개인 마감, 코스 이름 전달, 개인별 권한, jobs/outbox.
2. **보관 MVP:** 후보 미리보기·원본 유지 포장·검증·복원. 삭제는 계속 끈다.
3. **보고서 MVP:** 기준 시각·분모·점수 기준을 명시한 HTML/CSV, 수업별 접근제어.
4. **지원 MVP:** 검증된 snapshot 기반 규칙·근거·교수자 판단, 내부 알림함.
5. **설정 UI/운영화:** SES 선택 UI·승인·diff·배포 프로필. 공간 회수는 복원 훈련 뒤 별도 승인.

### 인수 시험

- 수령 종료 후 신규 수락은 거절, 기존 학생 재로그인·허용된 제출/결과 열람 유지.
- 마감 1초 전/정각/후, UTC↔KST, 개인 연장·면제·늦은 수강·마감 없는 과제.
- 보관과 업로드·재채점·마감 연장 경합 시 revision 재검사로 보류.
- 압축 중 종료, 디스크 부족, DB busy, rename 후 DB 실패, 깨진 digest, 재시작·중복 실행.
- 공유 blob을 한 과제에서 보관/복원해도 다른 과제에 영향 없음.
- 미공개 점수·0점 배점·release 중복·최근 제출 채점 중·빈 분모·서버 장애 구분.
- 합성 수강/제출/예외 fixture로 손계산 보고서와 비교. CSV 수식 삽입·HTML escape 검사.
- 지원 후보 오탐·제외 조건·최소 표본·정정 후 재계산·권한 밖 열람 차단.
- 잘못된 SES 조합·자료형·범위·중복 이름·임의 코드·미구현 module activation 거절.
- 25명 합성 제출 + 보관 1건 + 보고서 1건 병행: 접수 누락/자료 손실 0, 지연·DB busy 측정.
- 보존 작업은 합성 데이터/임시 디렉터리·모의 시간으로 시험. 실제 학생 자료로 삭제 시험 금지.

SES 선택 검사 통과는 위 인수 시험이나 운영 기능 구현 완료를 의미하지 않는다.
