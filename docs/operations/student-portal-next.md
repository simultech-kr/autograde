# 학생 포털과 IDE 사용성

학생 웹은 `/app/student`, 교수자 교실은 `/app/classroom`에서 사용한다. 인증·수강 자격·과제 수령·성적은
Python 서버와 SQLite가 관리하고, Next.js는 화면을 제공한다. `/app/preview/portal`은 별도의 예시 화면이다.

## 학생의 이용 순서

1. 학번과 회원 비밀번호로 가입한다. 가입할 때 수업을 선택하지 않는다.
2. 운영 중인 교과목 목록에서 과목명·학기·분반을 확인하고 수강할 수업을 선택한다.
3. 교수자가 실제 학생 본인을 확인하고 발급한 활성화 코드를 내 계정에 입력한다. 활성화 코드와 과제 수령 코드는 별개다.
4. 활성화된 계정의 학번이 교수자 허용 명단과 일치하면 수업을 이용한다. 일치하지 않으면 대기 사유와 문의 방향을 확인한다.
5. 수업 홈에서 과제와 자료를 확인하고 과제 수령 코드를 발급한다. IDE의 **Autograde → 학습 홈**에서 **과제 수령 코드**를 입력하고 **코드로 연결**을 누른 뒤 다운로드하거나 기존 작업 폴더를 연다.
6. IDE에서 작성·실행·서버 작업 저장을 하고, 준비가 되면 공식 제출한다. 서버 작업 저장은 제출 접수가 아니다.
7. 웹 **내 점수**에서 수업을 선택하거나 IDE 결과 화면에서 현재 제출의 접수번호·시각·채점 상태·이번 점수를 확인한다. 이전 제출 중 최고점은 별도 항목이다.
8. 공용 PC를 떠날 때 학생 웹에서 로그아웃하고 IDE를 종료한다. 웹 로그아웃과 IDE 공용 작업 폴더 정리는 별도 절차다.

기존 초기 수업 비밀번호로 등록된 학생은 수업 화면의 **개인 비밀번호 설정·변경**에서 본인 비밀번호와
확인 입력을 제출한다. 이후 변경은 **내 계정 → 회원 비밀번호 변경**에서 현재·새 비밀번호·확인 입력으로 진행한다.
변경 전부터 존재하는 파일럿 회원은 마이그레이션으로 기존 접근을 유지한다. 신규 회원은 명단 일치만으로 활성화되지 않는다.

## 학생 화면의 메뉴와 작업 카드

상단 메뉴는 **내 수업 · 학습 자료 · 내 점수 · 정보 활용 설정 · 수강 선택 · 내 계정**의 여섯 영역이다.
**내 수업**에는 수업별 상태와 다음 작업을 보여 주는 카드를 배치한다. 학생은 문장 속 링크를 찾는 대신
과제 수령, 자료 확인, 점수 확인 버튼에서 바로 작업을 시작한다. 수강 대기·본인 확인 필요 상태도
카드 안에서 안내하여 지금 할 수 있는 일을 구분한다.

**학습 자료**와 **내 점수**는 수업을 선택한 뒤 해당 수업의 내용만 표시한다. **정보 활용 설정**은
학습 화면에서 분리하여 수업별 선택을 관리한다. **수강 선택**은 새 수업 신청, **내 계정**은 계정 상태와
비밀번호 변경을 담당한다. 메뉴는 좁은 화면에서도 줄바꿈되어 같은 기능을 이용할 수 있다.

## 웹에서 내 점수 확인

**내 점수** 메뉴에서 수업을 선택한다. **내 수업** 카드의 **내 점수** 버튼과 수업 화면의 같은 이름 탭도
해당 수업의 점수 화면을 연다. 예를 들어 `/app/student?course_key=come2201&view=scores`다.
Next.js가 없는 환경에서는 `/courses/come2201/results`를 이용한다.

각 과제는 현재 제출 상태, 이번 점수·배점, 이전 제출 중 최고점·배점, 공식 제출 버전과 접수 시각을 표시한다.
이전 최고점에는 이번 제출이 포함되지 않는다. 새 제출이 대기 중이면 이번 점수는 미확정이며 이전 점수로
대체하지 않는다. 미제출·대기·오류를 0점으로 취급하지 않고, 배점이 다른 과제들의 총점·평균도 계산하지 않는다.
본인에게 공개된 결과만 확인할 수 있다.

화면이 활성화되어 있는 동안 15초마다 수업 상태를 갱신한다. 조회 실패 시 마지막 확인 자료라는 안내와
다시 조회 버튼을 표시한다. **이번 제출 이력 보기**는 화면에 조회된 이력으로 연결하며, 웹 조회 범위를
넘은 과거 제출은 IDE에서 확인하도록 안내한다.

## 선택적 개인정보 활용과 수업 종료

미응답 수업이 있으면 로그인 후 팝업에서 연구·수업 개선 목적과 활용 사례를 설명한다. 과제에서
어려웠던 부분을 파악하고 설명·힌트를 보완하는 데 어떤 정보를 쓰는지 먼저 안내한다.
**동의합니다**(opt-in), **동의하지 않습니다**(opt-out), **나중에 선택** 중 직접 선택한다.
이미 동의한 수업은 설정에서 **동의 철회**로 참여를 중단할 수 있다.
나중에 선택하거나 Esc로 닫아도 수업을 계속 이용하며, 동의나 거부로 기록되지 않는다.
미응답 안내는 같은 로그인에서 반복하지 않고 다음 로그인 때 다시 확인한다.

상단 **정보 활용 설정** 탭은 과제·점수와 분리된 화면이다. 수업별 현재 선택과 최근 변경 이력을
확인하고 언제든 참여·미참여를 바꾼다. 기존 Python 포털도 **정보 활용 설정** 탭과 미응답 팝업을 제공한다.
별도 화면은 `/courses/{교과목 코드}/privacy`, 로그인 없이 읽는 공통 안내는 `/student/privacy`다.
화면 조회만으로 동의가 기록되지 않으며, 기존 동의·거부·철회자는 같은 안내의 팝업을 다시 받지 않는다.

- 연구·수업 개선 목적에 한해 수업별로 선택한다. 미응답·거부·철회해도 과제 수령·제출·채점·점수 확인에 불이익이 없다.
- 안내 버전과 선택·변경 시각을 저장하고 최근 20건의 변경 이력을 보여준다. 수업 보관 전까지 변경·철회할 수 있다.
- 다른 탭에서 선택이 바뀌었거나 저장 응답을 확인하지 못한 경우 현재 상태를 다시 읽는다. 오래된 선택을 자동 재전송하지 않는다. 안내 버전이 바뀌면 다시 선택하기 전까지 연구 활용에서 제외한다.
- 교수자가 수업을 보관하면 해당 수업의 개인별 원본과 연결정보를 제거한다. 당시 동의한 학생 중 과제별 최소 5명 기준을 충족하는 인원·점수 구간 통계만 남긴다. 동의 학생도 개인 코드·점수를 남기지 않으며, 미동의·미응답 학생은 통계에서도 제외한다.
- 수업 보관은 복원할 수 없다. 다른 수업에서 필요한 계정·자료와 교수자 공용 교재는 유지한다. 파일·원격 공간 정리가 남으면 완료로 표시하지 않으며, 교수자는 남은 정리를 재시도한다.

서버가 관리하는 자료와 별도로 원본 CSV·백업·복제본·내보낸 사본은 보관 위치에서 파기해야 한다.
백업 복원 시 파기 기록을 먼저 적용한다. 개인과 연결할 수 없는 집계가 만들어진 뒤에는 특정 학생의
집계만 찾아 철회하거나 원래 기록으로 복원할 수 없다.

`GET /student/api/privacy`는 현재 회원이 수강 중인 수업의 선택·이력과 로그인 중 안내를 닫았는지
(`prompt_dismissed`)를 읽는다. 수업별 저장은 기존 `POST /student/api/course/{course_key}/privacy`를
사용하며 현재 안내 버전과 수정 번호를 검증한다. Next.js의 **나중에 선택**은
`POST /student/api/privacy/dismiss`로 현재 이용 가능한 수업들의 안내를 로그인 세션 메모리에서 숨긴다.
Python 팝업은 `POST /courses/{course_key}/privacy/dismiss`로 그 수업의 안내를 숨긴다. 같은 세션 객체를
사용하므로 새로고침과 Next.js↔Python 화면 이동에서도 안내가 반복되지 않는다. 새 로그인 또는
안내 버전 변경 시 다시 안내하며, 동의 DB·감사 기록·브라우저 저장소에는 선택을 남기지 않는다.

## IDE 학습 홈에서 연결과 제출

VS Code용 확장 0.5.20과 이를 내장한 Autograde IDE에서는 명령 팔레트 없이 학습 홈에서 입력한다.
Visual Studio 2022용 확장은 별도 화면과 절차를 유지한다.

1. 왼쪽 **Autograde** 아이콘에서 **학습 홈**(집 아이콘)을 연다.
2. 접힌 **서버 주소 설정**을 펼친다. **채점 서버 주소**에는 `https://ai.cbchoi.info:20000`을 입력하고
   **채점 서버 적용**을 누른다. **학생 포털 주소**에는 `https://ai.cbchoi.info:20010`을 입력하고
   **학생 포털 적용**을 누른다. 기관이 다른 주소를 제공하면 해당 주소를 사용한다.
3. **학생 포털 · 내 수업**에서 발급한 과제 수령 코드를 학습 홈의 **과제 수령 코드** 입력란에 넣는다.
   **코드로 연결** 또는 Enter로 진행한다. 회원 비밀번호·계정 활성화 코드·비밀번호 재설정 코드는 IDE에 넣지 않는다.
4. **서버 과제·자료 다운로드** 또는 **기존 과제 이어서 열기**로 실습할 폴더를 연결한다.
5. 코드 작성 후 **현재 과제 공식 제출**, 접수 후 **이번 제출 결과 확인**을 누른다.
   접힌 **과제·자료·제출 도구**에서도 같은 버튼을 사용할 수 있다.

수령 코드는 가려서 입력하며 전송·학습 홈 숨김·닫기 시 입력란을 비운다. 설정 파일에 저장하지 않는다.
서버 주소나 로그인 상태가 바뀐 경우에는 코드를 자동 재전송하지 않고 다시 입력하도록 안내한다.
폴더 선택, 작업 영역 신뢰, 본인 작업물 제출 확인 대화상자는 유지한다.

공용 실습실 모드에서는 **공용 실습 종료 · 임시 파일 정리**로 종료한다. 이번 실행의 코드·자료와
IDE 임시 기록은 종료 후 정리하고, 정리가 남아 있으면 다음 실행 때 다시 정리한다. 서버 저장본·공식 제출본·
별도로 내보낸 ZIP은 유지한다. 일반 VS Code의 로그아웃은 로컬 과제 파일을 삭제하지 않는다.
공용 PC에서 **내 학습내용 내보내기**를 사용할 때는 저장한 코드·자료에 본인 정보가 포함될 수 있다는
안내를 확인한다. 내보낸 폴더·ZIP은 공용 실습 종료로 지워지지 않으므로 본인 저장 장치로 옮기고 공유
저장 위치의 사본을 직접 정리한다. 내보내기 확인은 연구 활용 동의와 별개다.

## 교수자 명단과 계정 지원

- 수업의 **가입·수강 명단**에서 CSV를 선택하고 **추가** 또는 **교체**를 고른다.
- 추가·기존·중복·제외·연결 대상 인원을 검토한 뒤 반영한다. 다른 담당자가 명단을 바꾸면 다시 검토해야 한다.
- 허용 명단에서 제외하는 것과 이미 수강 중인 학생의 이용을 중지하는 것은 별개다. 이용 중지는 기존 학생 관리에서 수행한다.
- 활성화 코드는 해당 수업의 허용 명단 또는 수강 학생에게 본인 확인 후 발급한다. 발급 사유가 기록되며, 코드는 15분 동안 한 번만 사용할 수 있다.
- 공통 회원 비밀번호 복구 코드는 관리자만 발급한다. 학생이 직접 정한 회원 비밀번호를 복구하며, 기존 6자리 수업 비밀번호 초기화와 구분한다.
- 학생은 내 계정에서 현재 비밀번호, 새 비밀번호와 확인 입력을 제출한다. 변경하면 기존 웹·수령 코드·IDE 인증은 만료된다. 새 비밀번호로 로그인하고 새 수령 코드로 IDE를 다시 연결한다. 초기 CSV 비밀번호를 사용하는 학생은 수업 화면의 **개인 비밀번호 설정·변경**에서 처음 설정할 수 있다.

활성화·복구 원문 코드는 서버에 해시로 보관한다. 발급 화면을 캡처해 공개 자료로 배포하지 않는다.
교수자 인증은 기존 Basic 방식을 유지하므로 학생용 세션 로그아웃과 동일하지 않다.

## 같은 상태를 보여주는 웹과 IDE

| 상태 | 학생 안내 |
| --- | --- |
| 공식 제출 전 | 작성·실행 후 공식 제출 |
| 제출 접수 | 현재 접수번호와 접수 시각 확인 |
| 채점 대기 | 점수 미확정, 결과 조회 |
| 채점 중 | 점수 미확정, 결과 조회 |
| 결과 공개 대기 | 처리 중인 결과를 확정 점수로 표시하지 않음 |
| 결과 공개 | 이번 점수와 이전 제출 중 최고점 분리 |
| 처리 확인 필요 | 접수번호를 기준으로 교수자에게 문의. 자동으로 다시 제출하지 않음 |

IDE 학습 홈은 현재 수업·과제를 표시하고 상황에 맞는 다음 행동을 우선 배치한다. 보조 도구와 설명은 접어서 표시한다.
학생 웹 주소는 학습 홈의 **서버 주소 설정 → 학생 포털 주소**에서 별도 설정한다(`autograde.studentPortalBaseUrl`). API 포트에서 웹 포트를 추정하지 않는다.
기관 기본값은 API `https://ai.cbchoi.info:20000`, 웹 `https://ai.cbchoi.info:20010`이다.
웹을 열 때 토큰·비밀번호·수령 코드를 URL에 넣지 않는다. 웹에서는 별도로 로그인한다.

교수자 교실의 **조치 필요** 필터는 연결 지연·연결 끊김, 제출·채점 오류, 접수 후 10분 이상 대기,
IDE 요청 실패·만료를 분리한다. 학번순을 유지하며 실제 실패 원인은 학생 상세에서 확인한다.
최근 요청 범위에서 같은 작업·과제의 새 요청이 성공하면 이전 실패는 해소된다. 연결 기록이 없다는 이유만으로 오류나 결석으로 판정하지 않는다.

## 서버 연결과 배포

기존 Next.js 서버가 있다면 소스를 갱신한 뒤 웹 프로젝트를 다시 빌드하고 Python·Next.js를 재시작한다.
Node.js 24 환경에서 저장소의 `web` 폴더로 이동하여 `npm ci`, `npm run build`, `npm start`를 순서대로 실행한다.
운영 환경에서는 기존 서비스 관리 도구로 프로세스를 유지한다.

`config/nginx-autograde-next.locations.conf.example`을 웹 20010 서버 블록에서 포함한다.

- `/app`과 `/app/` → Next.js `127.0.0.1:18082`. Cookie·Authorization을 제거한다.
- `/student/api/` → Python 웹 `127.0.0.1:18081`. 원래 Cookie·Origin을 유지하고 JSON 오류를 통과시킨다.
- `/courses/` → 기존 Python 웹 목록·다운로드.
- IDE `/v1/` API는 기존 20000 경로를 유지한다.

실제 주소는 `https://ai.cbchoi.info:20010/app/student`이다. Nginx 설정 검사 후 반영하고,
외부 HTTPS에서 신규 가입·수강·활성화·수령 코드·로그아웃을 확인한다. 설정 예제만 수정했다고 운영 서버가 변경되지는 않는다.

## 로컬 확인

실제 학생 자료 없이 확인할 때는 먼저 Next.js를 18185 포트에서 실행하고 다음을 실행한다.

```sh
.venv/bin/python scripts/check_student_portal_fixture.py
```

`http://127.0.0.1:18186/app/student`은 임시 SQLite와 로컬 프록시를 사용하는 실제 화면이다.
예시 학번은 `20260001`, 비밀번호는 `synthetic portal password`다. 이 계정은 로컬 검증 전용이며 서버에 배포하지 않는다.
이전 최고 95점과 최신 채점 대기 상태를 확인할 수 있다. 시험 프로세스를 종료하면 임시 자료가 삭제된다.
