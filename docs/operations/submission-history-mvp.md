# 제출 기록·코드 복원 MVP

2026-09-10 · VS Code 0.4.0 / Visual Studio 0.2.0 소스 기준.

## 이번 개선

학생이 제출하면 서버가 접수한 소스 bundle과 접수 정보를 변경 불가능한 원본으로 보관합니다.
확장에서 그 기록을 조회하고 특정 제출의 점수를 확인하거나 코드를 **새 폴더로 복원**합니다.
Git 설치·commit·GitHub 계정은 필요하지 않습니다. 로그인 토큰이나 비밀번호를 이력 파일로
저장하지 않으며, 다른 실습 PC에서도 같은 학생·같은 과제의 새 수령 코드로 로그인하면
서버 기록에 접근할 수 있습니다.

독립 웹 20010번 / 확장 API 20000번, CSV 설정·학생 초기화, C/C++ 채점 흐름은 유지합니다.
새 환경변수나 Docker는 추가하지 않았습니다.

## 학생 사용법

VS Code용 설치 파일은 [autograde-vscode-0.4.0.vsix](../../extensions/vscode/autograde-vscode-0.4.0.vsix)입니다.
VS Code의 확장 화면 → `…` → **VSIX에서 설치**로 업데이트합니다. Marketplace 게시·서명은 하지 않았으며
기관의 확장 설치 정책을 따라야 합니다. 서버도 새 코드로 업데이트·재시작해야 새 API를 사용할 수 있습니다.
이 파일은 Visual Studio용 VSIX가 아닙니다.

### VS Code (Linux / macOS / Windows WSL2)

1. 개선된 서버와 VS Code 확장 0.4.0을 사용합니다. 학생 웹에서 해당 과제 수령 코드를 발급받아 로그인합니다.
2. 과제를 풀고 파일을 저장한 뒤 제출합니다. 편집기의 미저장 내용은 서버 원본에 포함되지 않습니다.
3. 왼쪽 Autograde 과제를 펼쳐 **제출 기록 / 이전 코드 복원**을 누릅니다.
4. 접수 시각·상태·SHA-256 앞부분으로 제출 기록을 선택합니다. 선택 항목의 전체 제출 ID도 표시됩니다.
5. **이 제출의 채점 결과**로 공개된 점수와 피드백을 확인합니다. 미공개 결과는 우회하지 않습니다.
6. **새 폴더로 코드 복원**에서 상위 폴더를 선택합니다. `autograde-restore-<고유 ID>`에 복원됩니다.
7. 표시된 폴더를 IDE에서 열어 확인합니다. 복원은 빌드·실행·제출을 자동으로 하지 않습니다.
   수정 후 다시 제출하려면 기존과 같이 파일을 저장하고 제출을 승인합니다.

Command Palette의 `Autograde: Submission History and Restore`에서도 같은 기능에 접근할 수 있습니다.
기록이 없다면 새로 제출한 뒤 다시 조회하세요. 구버전 서버가 404를 반환하면 서버를 먼저 업데이트합니다.

### Visual Studio 2022 / 2026

1. [Visual Studio 확장 안내](../../extensions/visualstudio/README.md)에 따라 Windows에서 0.2.0을 빌드·설치합니다.
2. **도구 → Autograde 과제**에서 로그인하고 과제를 선택합니다.
3. **제출 기록 조회** → 기록 선택 → **선택 기록의 결과 확인** 또는 **선택 기록을 새 폴더로 복원**을 누릅니다.
4. 복원 폴더는 창에 표시되고 제출 폴더로 선택됩니다. VS의 **파일 → 열기 → 폴더**로 여세요.

두 IDE 모두 설치 후 현장 동작 시험이 필요합니다. macOS에서의 C# 컴파일·통신 시험은
Windows VSIX 패키징·설치·실제 UI 시험을 대신하지 않습니다.

## 무엇을 버전으로 취급하나

- 버전의 식별자는 서버의 불변 `submission_id`와 `source_sha256`입니다. 임의로 바뀔 수 있는 `v1/v2` 순번을 붙이지 않습니다.
- 서버가 **접수한 제출**만 기록합니다. 업로드 전 초안, 오프라인 변경, 거절·전송 실패 건의 로컬 백업은 이번 범위가 아닙니다.
- 응답이 끊겨 접수 여부를 모를 때는 먼저 기록을 조회합니다. 재시도·동일 제출의 병합 정책에 따라 새 기록이 생기지 않을 수 있습니다.
- 접수 원본·접수 시각은 고정이지만 채점 상태는 진행되면서 바뀝니다. 결과는 기존 공개 정책을 따릅니다.
- 최신 100건을 표시하며 더 있으면 제한 안내가 나옵니다. 과거 자료를 삭제하는 기능이 아니며 100건 이전의 탐색 UI는 후속입니다.
- 복원 시 압축 파일 크기와 SHA-256을 기록과 비교하고, manifest의 `submission` 종류와 파일별 해시를 검사합니다.
  starter와 submission은 서로 바꿔서 해제할 수 없습니다. 경로 탈출·링크·충돌은 기존 archive 검증으로 차단합니다.
- 과제 매핑만 복원 폴더에 생성합니다. 인증 정보는 생성하지 않습니다. 기존 Git 저장소에는 commit·reset을 하지 않습니다.

## 서버 계약과 운영 주의

- `GET /v1/assignments/{assignment_id}/history`: 본인의 최신 접수본 최대 100개와 `has_more`, `limit`.
- `GET /v1/submissions/{submission_id}/source`: 본인의 접수 원본 gzip. 실패 시 404/503, 익명 접근 불가.
- 두 API는 현재 수강 상태, 학생 소유권, 교과목과 과제별 수령 코드의 세션 범위를 검사합니다.
  기록 목록에는 채점 rubric·비공개 데이터·학생 식별 내부 ID를 넣지 않습니다.
- 기록 목록은 현재 제공 중인 과제만 조회 가능합니다. 서버에 보관된 소스가 없어지면 복원할 수 없습니다.
- SQLite 상태와 bundle 저장소를 함께 백업하세요. 이번 기능은 별도 DB 마이그레이션을 요구하지 않습니다.
- 로그아웃하면 메모리 인증과 기록 UI를 지웁니다. **이미 다운로드·복원한 소스 파일은 PC에 남습니다.**
  공용 PC에서는 개인 OS 계정 또는 수업 후 폴더 정리 절차를 사용하세요. 로컬 파일은 서버 권한 검사로 보호되지 않습니다.
- 접속·학생·과제·접수본 권한만 강화했으며, `pilot-local`은 여전히 임의 코드를 격리하지 않습니다.
  사전 검토한 신뢰 코드 파일럿에 한정하고 Windows 전용 API 원격 채점은 후속 구현입니다.

## 직접 시험하기

1. 합성 학생 A로 C/C++ Hello World를 제출하고 제출 ID를 적습니다.
2. 코드를 다른 내용으로 저장하되 제출하지 않습니다. 기록에서 이전 제출을 새 폴더로 복원합니다.
3. 현재 폴더의 변경 내용은 그대로이고 복원 폴더에는 제출 당시 코드가 있는지 확인합니다.
4. 같은 접수본을 다시 복원하면 별도 폴더가 만들어지는지 확인합니다. 점수가 기존 제출과 일치하는지도 확인합니다.
5. 로그아웃·IDE 재시작 후 A의 같은 과제 새 코드로 로그인해 기록을 다시 조회합니다.
6. 학생 B로 바꾸면 A 기록이 보이지 않는지, 다른 교과목·과제 코드로 A 원본 URL에 접근할 수 없는지 확인합니다.
7. 네트워크를 끊었을 때 성공으로 표시하지 않는지 확인합니다. 복구 후 기록을 조회해 접수 여부부터 확인합니다.

자동 시험은 `tests/integration/test_submission_history.py`,
`tests/unit/test_bundle_platform_state.py`, VS Code `submissionHistory.test.ts`,
Visual Studio `Autograde.Checks`와 `test_visualstudio_extension.py`에 있습니다.
서버→C# 다운로드→C17 제출→실제 채점→기록 조회→원본 복원까지 실제 로컬 HTTP 통신으로 시험합니다.

2026-09-10 개발 환경(macOS) 검증 결과:

- Python 전체 회귀: **754 통과 / 7 제외**. 제외 항목은 Windows/MSVC 2건과 동작하는 JDK가 없는 Java 5건입니다.
- 이후 추가한 동일 학생·다른 과제 권한 시험을 포함한 새 이력 HTTP 시험: **4 통과**. 위 전체 집계와 중복되므로 합산하지 않습니다.
- VS Code: **131 통과**, TypeScript 컴파일과 0.4.0 VSIX 생성 성공. 실제 IDE 설치·UI 조작 시험은 별도입니다.
- C# 공통 검사: **75 통과**. Visual Studio 통합 시험 **14 통과**, 확장 코드 컴파일 경고·오류 0건.
- C#이 만든 제출 archive를 VS Code 추출기로 복원해 C 소스가 같은지도 확인했습니다.
- VSIX 내용에 새 `submissionHistory.js`와 0.4.0 manifest가 포함됨을 확인했습니다. 라이선스 파일 누락 경고가 있으며 Marketplace 배포 준비는 이번 범위가 아닙니다.

## 후속 범위

파일별 변경 비교, 100건 이전 페이지 탐색, 로컬 미제출 초안 백업, 학기별 보관·삭제 정책,
교수자 기록 비교 UI는 아직 구현하지 않았습니다. 서버 실행 중인 프로세스와 설치된 확장은
자동 교체하지 않으므로 유지보수 시간에 업데이트·재시작하고 위 절차로 시험하세요.
