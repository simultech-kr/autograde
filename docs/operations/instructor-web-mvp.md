# 교수자 웹 관리 MVP 사용 안내

**선택 인증:** [교수자 개인 계정·분반 권한](instructor-personal-auth.md)을 켜면 교수자마다 담당 수업만 관리한다.
기본 공유 운영자 인증과 학생 인증은 그대로 유지한다.

**선택 기능:** [교수자 웹 루브릭 관리](rubric-web-mvp.md)를 켜면 기준 입력·배점 검토·버전 등록을 사용할 수 있다.
기존 학생 점수와 자동 채점은 변경하지 않는다.

**2026-09-18 UI 개선:** `/instructor`와 `/instructor/admin`이 동일한 운영 홈으로 연결된다.
수업 루트는 개요이며 이름·운영 상태·QR은 **수업 설정·QR**로 이동했다.
과제 목록은 웹·CLI bundle을 통합한다. [변경 사항·업데이트 안내](instructor-ux-update.md).

**교과목·분반 관리자 추가:** `/instructor/admin`에서 교과목을 선택하고 학기·분반별 학생·과제·
최신 제출 현황을 관리한다. [학생 결과 UI와 분반 관리 안내](results-and-course-admin.md).

추가 기능: **수업 → 제출·채점 현황 → 코드·제출 이력 확인 → 파일 선택**으로
학생의 제출 원본을 읽기 전용 열람한다. 감점·처리 실패는 '확인 필요한 제출'에 모인다.
웹은 밝음/어두움 자동 전환을 지원한다.
[테마 설계·열람 제한 안내](../architecture/theme-and-submission-review.md)를 참고한다.

2026-09-16 구현. 원격 서버에 자동 배포하지 않으며, 아래 설정은 운영자가 검토한 뒤 적용한다.
이번 변경은 **교수자 웹 등록 파일럿**이다. `pilot-local`은 학생 코드를 서버 계정으로 실행하므로
보안 격리나 일반 학생의 임의 코드 실행에 대한 배포 승인을 제공하지 않는다.

## 1. 업데이트 및 시작

서버를 정상 종료하고 기존 데이터 폴더 전체, 설정 CSV와 필수 자격 파일을 접근 제한된 별도
위치에 백업한다. 이번 버전은 SQLite 스키마를 10에서 11로 자동 갱신한다.
업데이트 후 DB에 구버전 서버를 실행하지 않는다. 실제 학생 명단이나 DB를 지울 필요는 없다.

저장소의 `autograde` 폴더에서 기존 가상환경을 활성화한 다음 실행한다.

```sh
python -m pip install -e '.[dev]'
python -m autograde.pilot_portal_cli --config pilot/portal.https.local
```

사용 중인 **설정 CSV의 기존 `key,value` 표에** 다음 한 행을 추가한다. 같은 키를 중복 추가하지 않는다.

```csv
instructor_assignment_web_enabled,true
```

기존 설치는 `roster_bootstrap_mode`를 추가하지 않아도 된다. 기본값은 `csv`이며 기존
초기화 완료 표식을 유지하므로 웹에서 바꾼 학생 정보를 재시작 시 덮어쓰지 않는다.

**학생이 없는 새 설치에서 웹으로만 시작할 때에 한해** 다음 행을 함께 추가할 수 있다.
명단 파일이 잘못됐을 때 우회하는 옵션이 아니다. 기존 수강 데이터가 있고 초기화 표식만 없는
저장소에서는 이 모드의 최초 초기화를 거절한다.

```csv
roster_bootstrap_mode,web
```

설정에서 `grading_runtime,pilot-local`을 유지한다. 이번 교수자 웹 작성 기능은 `--isolated`와
동시에 켜지 못하도록 차단했다. 웹 작성 기능을 끄더라도 등록된 수업·학생·과제는 삭제되지 않는다.

## 2. 접속 및 인증

- 교수자: `https://ai.cbchoi.info:20010/instructor`
- 학생: `https://ai.cbchoi.info:20010/courses/{course_key}/login`
- VS Code / Visual Studio 확장 주소: `https://ai.cbchoi.info:20000`
- Nginx 내부 연결: 웹 `127.0.0.1:18081`, 확장 API `127.0.0.1:18080`

교수자 로그인 창의 사용자 이름은 `instructor`, 비밀번호는 기존 데이터 폴더의
`platform-instructor-token` 파일에 보관된 값이다. 학생의 6자리 비밀번호와 다르다.
공유 교수자 계정이므로 교수자별 수업 소유권·권한 분리를 제공하지 않으며 공용 학생 PC에서
교수자 로그인이나 토큰 보관을 하지 않는다.

Nginx에는 [예시 설정](../../config/nginx-autograde-portal.conf.example)의 교수자 ZIP/CSV 업로드
전용 `location` 두 개도 반영한다. 역할별 ZIP과 통합 채점 템플릿 경로만 6 MiB,
CSV 경로만 1100 KiB를 허용한다. 실제 애플리케이션의 파일 한도는 각각 5 MiB/1 MiB다.
`Referrer-Policy: same-origin`을 유지하되 요청의 `Origin`을 강제로 바꾸지 않는다.
인증·쿠키·CSRF·정확한 Origin 검사 후에만 업로드를 처리한다.

## 3. 수업 및 학생 등록

1. **전체 수업 → 교과목·첫 분반 등록**에서 코드, 수업명, 학년도, 학기, 분반을 입력한다.
2. 서버가 고유 수업 주소를 생성한다. 같은 코드·학년도·학기·분반은 중복 등록할 수 없다.
3. **학생 관리**에서 개별 등록 또는 CSV 파일 검증·미리보기를 선택한다.
4. 미리보기에서 오류가 없을 때 별도로 적용한다. 오류가 있는 명단은 일부만 적용하지 않는다.
5. 수업 준비가 끝나면 **수업 설정·QR → 운영 상태 → 운영**으로 전환한다. 서버 재시작은 필요 없다.

수업 설정의 **학생 접속 QR 코드**를 펼쳐 학생에게 안내한다. QR에는 공개 로그인 주소만
포함하며 학생 비밀번호나 수령 코드는 포함하지 않는다.

기존 `come3105`, `come2201` 주소는 유지한다. 이전에 기록하지 않았던 수업명·학기 정보는
“정보 확인 필요”로 표시하며 실제 정보를 입력한다. 새 학기는 새 수업으로 등록한다.

웹 CSV는 UTF-8/BOM, 최대 1 MiB·1000행이며 필수 열은 `student_key,active,password`, 선택 열은
`name`이다. 화면에서 빈 서식 파일을 받을 수 있다. **최초 부팅용 `student_roster.csv`는
`course_key`까지 포함하는 별도 형식**이므로 두 파일을 혼용하지 않는다.

- 학번은 문자열로 보존한다. 새 학생의 빈 비밀번호는 ‘자동 발급’ 선택 시에만 허용한다.
- 비밀번호는 수업 내에서 중복되지 않는 숫자 6자리다. DB에는 원문을 저장하지 않는다.
- 기존 활성 학생의 CSV 빈 비밀번호는 변경 없음이다. 다른 비밀번호를 넣어 교체하려 하면 거절한다.
- 비밀번호 변경은 학생 상세의 **비밀번호 초기화**에서 별도로 수행한다.
- 자동 발급/초기화한 비밀번호는 성공 화면에서 한 번만 확인한다. 목록이나 재시도 응답에서 재조회하지 못한다.
- 비활성화·비밀번호 초기화는 해당 수업의 인증을 폐기한다. 다른 수업의 비밀번호·세션은 유지한다.
- 이름은 공통 학생 정보이므로 수정하면 다른 수업에도 반영된다. 화면에서 이 영향을 확인한다.

수업 보관 시 점수·제출은 보존하지만 학생 접근과 이전 인증은 차단한다. 진행 중 제출이나
과제 검증이 있으면 보관하지 못한다. 재운영해도 폐기한 인증은 복원하지 않는다.

## 4. 교수자 과제·채점 통합 작성

새 과제의 기본 정보를 입력하면 하나의 초안 화면으로 이동한다. 이 화면에서 문제·일정,
학생용 starter, 교수자 채점 자료와 테스트·배점, 서버 검증 결과, 학생 공개를 위에서 아래 순서로
처리한다. 별도의 단계별 작성 URL은 제공하지 않는다. 각 영역을 저장하면 같은 초안 URL로 돌아오며
저장 버전이 증가한다.

첫 시험은 **예제에서 만들기 → C/C++ Hello World**를 권장한다. 정답 10점·미완성 답안 5점이
기대값이다. Visual Studio 환경은 이식 가능한 코드와 CMake 폴더를 제공하며 Windows 전용 API
원격 채점을 뜻하지 않는다.

직접 만들기는 ZIP 최상위의 단일 `main.c` 또는 `main.cpp`를 고정 서버 채점기로 평가한다.
임의 Python 채점기·실행 명령·외부 URL·서버 경로 입력은 지원하지 않는다.
비공개 정답·오답·테스트는 학생 starter에 포함하지 않는다. README는 입력한 문제 설명으로 생성된다.
새 과제 화면에서는 초안을 만들기 전에도 C/C++와 Linux/macOS/WSL2 또는 Visual Studio용
기본 starter ZIP을 받을 수 있다. 초안 화면에서 받는 파일에는 현재 문제 설명이
`README.md`로 반영된다. **기본 템플릿을 서버에 저장**은 직접 만들기 초안의 실제 학생용
파일로 보존하며, 이미 등록한 starter가 있으면 명시적 확인 후 교체한다. 예제 모드는 언어·환경·
문제 설명 설정 자체가 재현 가능한 서버 템플릿이므로 별도 파일 업로드 없이 저장된다.
채점 자료도 교수자 전용 ZIP 템플릿으로 받을 수 있다. ZIP은 `solution/main.c(pp)`,
`negative/main.c(pp)`, `tests.json`, 안내 README로 구성한다. 정답·오답 소스와 테스트를 수정한 뒤
통합 작성 화면의 **채점 템플릿 한 번에 저장**에 올리면 정답 ZIP·오답 ZIP·테스트·오답 기대 점수를
하나의 저장 버전으로 교체한다. 예상하지 않은 파일, 링크, 잘못된 JSON 또는 언어가 다른 파일은
전체를 거부하며 기존 채점 자료는 유지한다. 이 ZIP은 학생에게 배포하지 않는다.
테스트 1~50개, CRLF/LF만 동등 취급하며 추가 공백·추가 출력은 오답이다.
웹 폼 전체는 64 KiB로 제한되므로 큰 테스트 원문은 이번 웹 파일럿 범위에서 줄여서 사용한다.

검증은 학생 채점과 별도의 작업자 1개로 수행하며 대기열은 10개다. 화면은 새로고침으로 실제
상태를 확인하고 임의 진행률을 표시하지 않는다. 공개 버튼을 누르기 전에는 학생에게 보이지 않는다.
검증 중 편집은 차단되며, 검증 후 일정·배점·자료를 수정하면 다시 검증해야 한다.

공개본은 덮어쓰지 않는다. 변경은 새 초안 복제 또는 감사 기록을 남기는 마감 연장으로 처리한다.
이미 수락·제출한 학생이 있으면 숨김과 대체 공개를 차단한다. 기존 CLI bundle 과제는 통합 목록에서
확인할 수 있지만 웹 초안 복제는 웹에서 작성한 과제에 한정한다.

### ZIP 업로드 장애 진단

ZIP 업로드에만 `internal_error`(이전 서버) 또는 `503 upload_unavailable`가 발생하면
서버 실행에 쓰는 **동일한 Python 가상환경**의 업로드 의존성을 확인한다. 현재 프로젝트는
`python-multipart==0.0.31`을 요구한다. 모듈 미설치 또는 헤더 제한 인자를 지원하지 않는
구버전은 교수자 파일 업로드만 실패시킬 수 있으며 `/readyz` 성공만으로 업로드까지 검증되지는 않는다.

```sh
python -m pip show python-multipart
python -m pip check
```

의존성이 다르다면 배포된 프로젝트 루트에서 같은 Python으로 `python -m pip install -e .`를
실행하고 서비스를 재시작한다. 소스 업데이트·DB 마이그레이션 전에는 서버를 정지하고 기존
설정 CSV와 data_root를 백업한다. 이후 작은 starter ZIP을 초안에 올려 실제 저장 여부를 확인한다.
파일 크기·헤더 제한을 제거하거나 인증을 우회해서 해결하지 않는다. 최신 처리에서는
`instructor_upload_unavailable` 운영 이벤트에 예외 종류만 기록하고 학생 소스·토큰을 기록하지 않는다.
다른 원인의 업로드 오류는 서버 로그를 확인해야 하며, 모든 `internal_error`를 의존성 문제로 단정하지 않는다.

### 과제 CRUD 운영

| 작업 | 교수자 화면 동작 | 데이터 처리 |
| --- | --- | --- |
| 생성 | **새 과제 등록**에서 초안 생성 | 학생에게 비공개인 revision 1 생성 |
| 조회 | 과제 목록 → 제목 선택 | 초안·웹 공개본·CLI 공개본을 교과목 범위에서 조회 |
| 수정 | 미공개 초안의 각 영역 저장 | revision을 증가시키고 다른 창의 오래된 저장을 거절 |
| 삭제 | 미공개 초안의 **초안 삭제** | 목록·직접 URL에서 제외하되 검증·감사 기록은 보존 |
| 공개본 변경 | **새 버전 초안으로 복제**, 마감 연장 | 이미 제출한 자료가 참조하는 공개본은 덮어쓰지 않음 |
| 공개본 삭제 처리 | **과제 보관** | 학생 수령을 중단하고 제출·점수·코드·감사 기록은 보존 |

검증 대기·실행 중인 초안은 삭제할 수 없다. 삭제와 보관에는 확인 체크가 필요하며 오래된 화면의
revision으로 요청하면 거절한다. `instructor_assignment_drafts.deleted_at` 열은 서버 시작 시 자동으로
추가된다. 공개 과제를 데이터베이스에서 물리 삭제하는 기능은 성적·제출 증거를 손상시키므로 제공하지 않는다.

## 5. 학생 전체 흐름

1. 교수자가 제공한 수업 웹 주소에서 학번·학생 전용 비밀번호로 인증한다.
2. **수락할 실습의 선택 칸**에서 하나를 고른 뒤 수령 코드를 발급받는다.
3. 확장에 API 주소와 수령 코드를 입력한다. 현재 수락한 실습만 표시된다.
4. 과제를 다운로드하고 문제를 해결한 뒤 기존 제출 기능으로 제출한다.
5. 서버의 접수·채점 상태와 공개된 점수를 확장에서 확인한다.

이번 서버/웹 변경에는 확장 재설치가 필요하지 않다. 두 확장 바이너리 자체는 변경하지 않았다.
Windows Visual Studio의 실제 설치·다운로드·제출은 Windows 장비에서 별도로 최종 확인한다.

## 6. 초기화 및 알려진 경계

학생 관리의 **초기화 안내**는 위험 범위와 오프라인 절차를 보여 준다. 실행 중인 웹에서
전체 학생 기록을 삭제하는 버튼은 제공하지 않는다. 실제 초기화는
[서버 중지·백업·미리보기·확인 절차](course-student-reset.md)를 사용한다.
스키마 10/11을 지원하고 새 등록 수업도 명시적으로 선택할 수 있다. 과제와 다른 수업은 보존한다.

- 초안은 각 영역의 저장 버튼을 눌러야 보존된다. 자동 저장이나 브라우저 종료 확인은 없다.
- 자료 선택값은 브라우저가 복구하지 않으므로 실패한 파일만 다시 선택한다.
- 다중 소스·Win32·Java·GUI·AI 기반 설계 패턴 구조 평가는 이번 작성기에서 제외한다.
- 실제 원격 HTTPS/Nginx 적용, 실사용 교수자 사용성 평가, Windows 확장 수동 시험은 운영자가 수행한다.
- 공식 성적 처리·공개 인터넷의 임의 학생 코드 실행 승인은 별도 보안 격리 시험이 필요하다.

구현·시험 기록은 [교수자 웹 관리 검증 기록](../testing/instructor-web-mvp.md)을 참조한다.
