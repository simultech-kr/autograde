# 교수자 관리도구의 IDE 확장 설치·업데이트

교수자는 수업별 **IDE 확장 배포**에서 VS Code용 `.vsix` 파일을 등록하고, 검토한 버전을
인증한 학생 IDE에 배포한다. Mac·Windows WSL2 Autograde IDE에서 같은 수업 서버를 통해
설치 안내를 받으며, 학생 확인 후 해당 IDE의 확장 설치 기능으로 설치한다. Microsoft Marketplace
계정이나 학생의 Node.js 설치는 필요하지 않다.

이 기능은 **추가 확장**의 신규 설치·업데이트를 관리한다. Autograde 핵심 확장을 포함한 내장
확장과 Code-OSS 본체·Node·실행기는 앱 전체 업데이트로 교체한다. Visual Studio 2022·2026의
VSIX는 다른 형식이므로 이 화면에서 배포하지 않는다. 먼저 이 기능을 지원하는 Autograde IDE
앱을 좌석에 설치해야 한다. 최초 배포는 **Autograde 확장 0.5.13 이상**을 내장한 앱을 사용한다.
이전 클라이언트에 이 기능 자체를 자동 추가하지 않는다.

## 교수자 절차

1. 교수자 관리도구에서 운영 중인 교과목·분반을 선택한다.
2. **IDE 확장 배포**를 연다. 실습 교실의 Next.js 화면에서도 같은 메뉴로 이동할 수 있다.
3. **VS Code 확장 파일 (.vsix)**을 선택하고 **파일 검증 후 초안 등록**을 누른다.
4. 등록된 확장 ID(`publisher.name`), 버전, 지원 플랫폼, IDE 호환 범위, 크기·파일 해시를 확인한다.
5. 별도 시험 좌석에서 해당 파일이 정상 동작하는지 확인한 뒤 확인란을 선택하고
   **이 버전 설치·업데이트 배포**를 누른다.
6. **학생별 처리 결과 → 처리 상태 새로고침**으로 수신·설치·설치 버전 확인 결과를 확인한다.

예시 경로는 `/courses/come2201/instructor/extensions`다. 교수자는 본인에게 허용된 수업에서만
접근할 수 있고, 등록·배포·중단에는 교수자 인증과 CSRF 확인이 적용된다. 준비·보관 상태의 수업은
조회만 가능하다. 초안 파일은 학생에게 내려가지 않는다.

파일당 최대 크기는 **64 MiB**다. 확장 ID·버전·플랫폼은 ZIP 내부의 확장 선언을 검증해 읽으며
교수자가 임의로 입력하지 않는다. VSIX는 수정하지 않은 원본으로 등록한다. 같은 ID·버전·대상
플랫폼에 내용이 다른 파일을 덮어쓰지 않는다. 수정본은 버전을 올려 새 파일로 등록한다.
의존 확장이나 확장 팩을 통해 외부에서 다른 확장을 자동으로 받는 구성은 지원하지 않는다.

Linux/WSL2 좌석에는 Linux용, Mac 좌석에는 해당 Mac 프로세서용, 모든 지원 환경에서 실행할 수
있는 확장은 공통 플랫폼 패키지를 선택한다. Windows WSL2의 IDE는 Linux 프로세스이므로
Windows용 VSIX를 선택하지 않는다. 플랫폼이 맞더라도 네이티브 라이브러리·컴파일러 등 확장의
운영 조건은 시험 좌석에서 별도로 확인한다.

## 새 버전 공개와 배포 중단

같은 확장 ID·대상 플랫폼의 새 버전을 공개하면 해당 플랫폼의 이전 공개본을 대체한다.
이미 진행 중인 작업의 결과는 뒤늦게 보고될 수 있으므로 학생 표의 배포 버전과 마지막 보고 시각을
함께 확인한다. 교수자의 공개는 즉시 모든 PC에서 활성화되었다는 뜻이 아니다.

**배포 중단**은 이후 신규 수신을 중단한다. 이미 설치한 확장을 제거하거나 학생의 작업을 중단하지
않으며, 자동으로 이전 버전으로 되돌리지 않는다. 확장은 학생 작업 파일에 접근할 수 있는
프로그램이므로 신뢰하는 제작자의 파일만 배포한다.

## 학생 IDE에서 일어나는 일

학생이 수업 서버에 연결하면 현재 수업의 공개 확장을 확인한다. 설치 안내에서 확장·버전을
확인하고 설치를 선택한다. 내려받은 파일의 크기와 SHA-256을 확인한 뒤 로컬 VSIX를 설치한다.
학생·서버·수업 연결이 바뀌거나 패키지·플랫폼 검증이 실패하면 해당 설치를 중단한다.

설치 뒤 현재 IDE에서 확인한 확장 버전이 공개 버전과 일치할 때 **설치 버전 확인됨**으로
보고한다. 확장의 활성화·정상 동작까지 검증했다는 뜻은 아니다. 현재 실습에서 이전 버전이
계속 실행 중이면 **설치됨 · 적용 대기**로 구분한다. 학생 코드를 저장·제출하거나 IDE를 자동으로
종료·다시 로드하지 않는다. 먼저 제출·내보내기를 마치고 공용 실습을 종료한다. 새 세션에서
새 수령 코드로 인증하면 현재 공개 버전의 설치를 다시 시도한다. 모든 확장이 이 방식으로 즉시
적용되는 것은 아니다. 새 세션에서도 계속 적용 대기라면 담당자가 해당 확장을 앱에 미리 포함한
새 배포본을 준비해야 한다.

제한 정책의 학습공간은 임의 확장 설치를 허용하지 않는다. 학생이 설치 안내를 보류하거나 작업
폴더가 신뢰되지 않은 경우에도 설치 완료로 보고하지 않는다. 실패 시 교수자 화면에서 상태와
원인을 확인하고 해당 좌석의 IDE 안내를 함께 확인한다.

## 공용 실습실에서 유지되는 것

- 설치한 추가 확장은 이번 공용 세션의 확장 폴더에 저장한다.
- **공용 실습 종료** 후 코드·자료·프로필과 함께 이번 세션의 추가 확장도 정리한다.
- 서버의 공개 파일·배포 설정·설치 보고는 남는다. 다음 학생이 인증하면 현재 공개본을 다시 안내한다.
- 학생이 명시적으로 세션 밖에 내보낸 ZIP·파일은 삭제하지 않는다.

설치 기록은 IDE가 보고한 세션별 상태다. 서버가 PC의 디스크를 독립적으로 검사한 결과가 아니며,
미접속·구버전·미보고 학생은 표에 없을 수 있다. 이 표를 전체 좌석 설치율이나 출석 판단에 그대로
사용하지 않는다. 다른 수업 또는 다른 학생의 인증 토큰으로 배포 파일을 받을 수 없다.

## 시험 절차

1. 시험 수업과 전용 학생으로 기능이 포함된 Mac 또는 WSL2 앱을 실행한다.
2. 의존 확장이 없는 간단한 추가 확장 VSIX를 초안으로 등록한다. 학생에게 안내되지 않아야 한다.
3. 해당 버전을 공개하고 학생 IDE에서 수락한다. 교수자 표에서 학생 확인 대기 → 설치 중 →
   설치 버전 확인됨 또는 설치됨 · 적용 대기를 구분하는지 확인한다.
4. 같은 확장의 버전을 높인 VSIX를 등록·공개하고 업데이트되는지 확인한다.
5. 다른 플랫폼·내장 확장·변조 파일·신뢰하지 않은 폴더·제한 정책에서 설치 실패가 완료로
   표시되지 않는지 확인한다.
6. 배포 중단 후 새 학생 세션에는 설치를 안내하지 않는지 확인한다. 기존 설치를 자동 제거하면 안 된다.
7. 공용 실습을 종료한 뒤 세션의 확장 폴더가 삭제되는지 확인한다. 새 세션에서는 로그인 후
   현재 공개본을 다시 안내해야 한다.

웹 서버 앞에 Nginx가 있으면 이 화면의 VSIX 업로드 경로에도 업로드 크기 제한을 적용한다.
multipart 오버헤드를 포함해 `client_max_body_size 70m;` 이상을 사용하되, 다른 과제 업로드
경로에 이미 필요한 큰 제한을 더 작은 값으로 덮어쓰지 않는다. 실제 VSIX의 64 MiB 제한은
Autograde 서버에서도 검사한다.

## 이번 구현의 검증 범위

확장 클라이언트 전체 시험 524개, Mac·WSL 실행기 시험 200개, 배포 저장소·교수자 화면·실제
HTTP·학생 초기화·Nginx 예제 관련 시험은 범위별 실행을 합해 106개가 통과했다(초기 묶음 98개,
이후 버전 숫자 경계 8개 추가를 포함한 단위 시험 50개 재검증). Next.js TypeScript 검사도 통과했다.
VSIX 크기·SHA-256, 다른 수업·세션 접근, 공개 취소, 정책·플랫폼·버전 불일치, 중복 설치,
응답 유실 후 상태 보고 재시도를 포함한다.

Mac의 실제 Code-OSS에서 합성 확장 1.0.0을 로컬 VSIX URI로 설치하고 실행했다. 실행 중
1.1.0 설치 후에는 호스트가 1.0.0을 계속 사용하는 것을 확인했다. 새 빈 프로필에 1.1.0을
설치하면 1.1.0이 실행됐다. 따라서 파일 설치와 현재 버전 적용을 별도로 보고한다.
이 시험은 운영 학생·원격 배포 서버를 사용하지 않았다. Windows WSL2의 실제 설치·GUI 시험과
배포 서버의 `nginx -t`는 대상 환경에서 별도로 확인해야 한다.

저장소의 `config/nginx-autograde-portal.conf.example`과
`config/nginx-autograde-pilot.conf.example`에는
`location ~ ^/courses/[a-z0-9_-]+/instructor/extensions$` 전용 70 MiB 설정이 들어 있다.
기존 배포 서버는 이 블록을 실제 설정에 반영하고 `nginx -t`로 검사한 뒤 Nginx를 다시 로드한다.
Git 갱신만으로 이미 설치된 Nginx 설정이 자동 변경되지는 않는다. Next.js include의 `/app/`·
`/instructor/api/v1/` 경로는 이 교수자 업로드 경로를 가로채지 않으며 별도 수정이 필요하지 않다.
