# IDE 시험 모드와 별도 Agent 연결

VS Code·Autograde IDE의 시험 모드는 **별도 Exam Control 관리 서버를 통한 좌석 상태 조회** 기능이다.
현재 배포 대상은 VS Code 확장 0.5.12이며, Visual Studio용 시험 모드는 별도 후속 배포로 다룬다.
과제 제출·채점은 기존 Autograde 서버가 담당하며, 네트워크 제한은 별도 Agent가 담당한다.
확장을 설치했다고 Agent가 자동 설치되거나 통신이 제한되지 않는다.

## 학생 사용 순서

1. 기존 Autograde 수령 코드로 로그인하고 시험 과제를 선택한다.
2. VS Code·Autograde IDE에서 **학습 홈 → 시험 모드**를 연다.
3. 표시된 채점 서버 주소와 현재 과제 ID를 감독자에게 전달한다.
4. 감독자가 실제 좌석의 Agent를 확인하고 발급한 **8자리 시험 연결 코드**와 **시험 관리 서버 주소**를 입력한다.
5. 좌석·Agent 상태를 확인하고 기존 버튼으로 과제를 제출하고 결과를 확인한다.

시험 연결 코드는 과제 수령 코드와 다르며 5분간 한 번만 사용할 수 있다.
관리 서버는 외부 접속 시 HTTPS가 필요하다. 같은 PC의 개발 시험만 loopback HTTP를 허용한다.
VS Code 관리 주소는 `autograde.examControlBaseUrl`의 사용자 설정만 사용하고 작업 영역 설정은 무시한다.

로그아웃, 과제·계정·채점 서버 변경, IDE 종료 시 시험 조회 연결을 지운다.
**연결 종료나 제출 완료는 통신 제한 해제가 아니다.** 감독자가 별도 해제와 Agent 응답을 확인한다.
코드·토큰은 저장하지 않고 Autograde 로그인 토큰을 시험 관리 서버에 전달하지 않는다.

## 감독자 준비

별도 관리 서버와 좌석에 등록된 온라인 Agent가 필요하다. 해당 좌석의 **Agent → IDE 시험 연결 코드 발급**에서
학생 패널의 채점 서버 주소와 과제 ID를 입력하고 실제 좌석을 확인한 뒤 코드를 발급한다.
코드 재발급, 서버·Agent 재시작, 장치 등록 폐기 시 기존 IDE 연결은 무효화된다.
이 방식은 감독자 확인 기반이며 학생 신원과 PC 소유를 자동 증명하지 않는다.

처음에는 simulation 모드로 연결 → 모의 제한 → IDE 상태 조회 → 기존 과제 제출 → 모의 해제를 시험한다.
`제한 설치 보고`는 실제 트래픽 차단 검증이 아니며 오류·오프라인은 확인 불가로 취급한다.
Agent 설치·실행, 실제 Windows WFP/WSL2 제한, Windows IDE 설치 검증은 별도 절차다.

- [VS Code 설치와 상세 사용법](../../extensions/vscode/README.md)
- [Visual Studio 설치와 상세 사용법](../../extensions/visualstudio/README.md)
- [Exam Control 통합 운영 절차](../../../exam-control/docs/ide-exam-mode.md) — 두 저장소를 같은 상위 폴더에 배치한 경우.

이번 버전은 자동 학생 인증 연계, 자동 최종 제출·제한 해제, Agent 자동 설치·업데이트,
IDE 내 화면 공유를 제공하지 않는다. WSL에서도 서버를 통해 조회하며 Windows 서비스에 직접 연결하지 않는다.
