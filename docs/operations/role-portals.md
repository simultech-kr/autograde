# 교수자·학생 포털 운영 안내

정보구조와 권한 기준은 [포털 고도화 설계](../architecture/role-portals.md)를 참고한다.
웹은 기존 `20010`, IDE API는 기존 `20000`을 사용한다. SQLite와 CSV 설정을 유지한다.

## 교수자 사용 순서

1. `/instructor`에 접속하여 기존 교수자 계정으로 인증한다.
2. 담당 수업 카드에서 수업 홈을 연다. 개인 교수자는 담당 수업만 표시된다.
3. **과제 관리**에서 문제·정답·오답·채점 자료를 등록하고 검증·공개한다.
4. **가입·수강 명단**에서 학번 CSV를 업로드한다. 가입 시 해당 수업을 선택한 학생과 자동 연결한다.
   **학생 관리**에서 현재 수강 상태를 확인하고 학생에게 `/student`를 안내한다.
5. **실습 교실**에서 IDE 연결·활동·교수자 요청을 확인하고 **제출·채점 현황**에서 결과를 확인한다.
6. 자료 배포와 콘텐츠·IDE 확장 메뉴는 해당 기능이 활성화된 수업에서 사용한다.
7. **실습 환경**에서 원격 실행 관리자 연결과 학생별 공간 상태를 확인한다. 상태는 페이지를 연 시점의 조회이며
   **상태 새로고침**으로 갱신한다. 이 페이지는 학생 공간 생성·삭제를 수행하지 않는다.

교과목·분반 생성은 관리자 권한이 필요하다. 교과목 정보는 SQLite에 저장한다. 관리자는
**설정 → 영구 삭제**에서 삭제 범위를 확인하고 수업 코드를 입력하여 바로 삭제할 수 있으며,
보관이 필수 선행 단계는 아니다. 자세한 대상·보존·정리 대기는 [교과목 영구 삭제](course-permanent-deletion.md)를 따른다.
학생 포털 링크는 학생 화면의 시작점이며
교수자를 학생으로 로그인시키거나 학생 비밀번호를 대신 발급하는 기능이 아니다.
공용 교수자 PC에서는 브라우저의 Basic 인증 캐시가 남을 수 있으므로 별도 브라우저 프로필과
브라우저 종료 등 기존 운영 정책을 따른다.

## 학생 사용 순서

1. `/student`의 회원가입에서 학번·본인 비밀번호·수업을 입력한다. 이미 가입했다면 로그인한다.
2. 교수자가 올린 해당 수업의 학번 명단과 일치하면 자동 연결된다. 명단 확인 대기는 담당 교수자에게 확인한다.
3. **내 수업**에서 연결된 수업을 열고 **과제 받기**, **제출 현황**, **내 자료**로 이동한다.
4. 과제를 선택해 수령 코드를 발급하고 IDE에 입력한다. 코드를 받는 것과 공식 제출은 별개다.
5. IDE에서 작성·제출한 뒤 웹에서 본인 제출 현황을 확인한다. 공통 회원 로그인은 최대 10분 유지되며
   만료되면 다시 로그인한다. 코드 발급으로 공통 회원 로그인까지 종료되지는 않는다.
6. **최신 제출**과 **이전 최고점**을 구분해서 확인한다. 대기·비공개 점수는 이전 점수로 대체하지 않는다.
7. 학생 홈의 **내가 수락한 실습**은 IDE에서 실제 코드 수령을 완료한 과제를 표시한다. 새 PC에서는 수령 코드를
   다시 발급하고 IDE에서 기존 작업을 이어간다. **내 원격 실습 공간**에서 본인 공간의 상태를 확인할 수 있다.

기존 학생은 6자리 수업 전용 비밀번호로도 수업에 로그인할 수 있다. 이 방식만 사용하면 수령 코드 발급 후
해당 수업의 웹 재인증이 필요하다. 기존 학생의 공통 계정 연결과 CSV 양식은
[학생 회원가입·수강 명단 안내](student-membership.md)를 따른다. 공용 PC에서는 웹 로그아웃과
브라우저 종료를 수행한다. IDE 종료의 파일 삭제와 브라우저 로그인은 별개다.

학생 웹에는 다른 학생의 명단·성적·소스와 교수자용 비공개 채점 자료가 표시되지 않는다.
새로 제출한 내역이 아직 없다면 미제출 안내를 제공한다. 자료가 없다는 안내는 자료 배정·공개 기간도
교수자가 확인해야 한다는 뜻이며 로그인 실패와 구분한다.

## 원격 실습 상태 읽기

| 표시 | 의미와 다음 행동 |
| --- | --- |
| 원격 실습 환경 미설정 | 서버의 실행 관리자 연결 설정이 없음. 운영자에게 준비 요청. 기존 과제 수령·제출과 별개 |
| 원격 실습 연결 확인 필요 | 설정은 있으나 worker 상태를 확인하지 못함. 빈 공간이나 삭제 완료로 해석하지 않음 |
| 원격 실행 관리자 연결됨 | 상태 조회 성공. 개별 학생의 컴파일 성공을 뜻하지 않음 |
| 사용 가능 / 실행 중 | 해당 학생의 원격 공간 상태. IDE에서 현재 코드를 저장하고 실행 |
| 종료됨 / 사용 시간 만료 | 해당 공간의 실행 상태. 서버 작업본·공식 제출·성적 삭제를 뜻하지 않음 |
| 공간 정리 확인 필요 | 운영자 확인 필요. 정리 성공으로 안내하지 않음 |

원격 실행에는 별도의 Linux 실행 관리자와 승인된 C/C++/Python 도구 이미지가 필요하다. 포털 코드를 갱신하는
것만으로 실행 환경이 준비되지 않는다. 학생 공간을 확인하기 위해 브라우저에서 IDE 토큰을 발급하거나
보관하지 않는다. 학생 웹의 원격 상태 조회가 실패해도 결과·자료 페이지는 계속 사용할 수 있다.
아직 지원하지 않는 Java·디버거는 활성 도구로 표시하지 않는다. Python은 진입 파일 1개와 프로젝트
모듈·표준 라이브러리를 실행하며 임의 패키지 설치는 지원하지 않는다.

## 서버 적용

1. 운영 DB·업로드 파일과 CSV는 기존 백업 정책에 따라 보관한다.
2. 갱신된 소스를 서버에 반영하고 기존 Python 가상환경에서 의존성을 설치한 뒤 웹 서비스를 재시작한다.
3. Next.js를 사용한다면 `web/`에서 기존 빌드 절차로 다시 빌드한 뒤 Next 프로세스도 재시작한다.
4. Nginx의 `/app` → Next.js, 그 외 웹 경로 → Python 연결을 유지한다. 새 외부 포트나 DB 이전은 없다.
5. 아래 배포 확인을 수행한다. 업로드·다운로드·IDE API를 Next.js로 우회시키지 않는다.

## 배포 확인

- 익명으로 `/`와 `/student`를 열어 역할 선택·교과목 목록만 보이는지 확인한다.
- 교수자로 로그인하여 담당하지 않은 수업·학생 데이터에 접근할 수 없는지 확인한다.
- 학생 시험 계정으로 가입 → 명단 자동 연결 → 내 수업 → 과제 목록 → 수령 코드 → 제출 현황을 확인한다.
- 명단이 없는 학생이 대기 상태로 표시되고, 명단을 나중에 추가하면 연결되는지 확인한다.
- 기존 6자리 수업 로그인과 본인 인증 후 공통 계정 연결이 유지되는지 확인한다.
- 최신 제출이 대기인 학생은 대기 상태와 이전 공개 최고점이 각각 표시되는지 확인한다.
- 비공개 점수와 다른 학생의 자료·제출 내역이 보이지 않는지 확인한다.
- 자료·시험지 기능이 비활성화된 구성에서도 잘못된 메뉴가 나오지 않는지 확인한다.
- 실습 환경에서 미설정·연결 실패를 구분하고, 교수자의 다른 수업 공간과 학생의 다른 학생 공간이 표시되지 않는지 확인한다.
- 수령 코드 발급만 한 과제와 IDE에서 수락한 과제가 다르게 표시되는지 확인한다.
- Next.js 화면에서 수업을 변경하고 Python 수업 홈으로 돌아와 선택한 수업이 유지되는지 확인한다.
- 휴대전화 크기와 어두운 테마에서 메뉴·표·폼이 잘리지 않는지 확인한다.

## 로컬 검증 기록

2026-10-28, macOS·Chrome·로컬 합성 계정 기준. 아래는 공통 회원 흐름 추가 전 초기 포털 기록이다.

- 새 포털 진입·교수자 담당 수업·학생 본인 제출·공개 정책과 기존 과제 CRUD·자료·학생 인증을
  포함한 서버 회귀 시험 **621개**를 통과했다.
- 웹 단위 시험 41개, TypeScript 검사, Next.js production 빌드를 통과했다.
- 역할 시작 → 학생 인증 → 내 수업 → 제출 현황 → 수령 코드 발급 → 재인증 요구를 실제 브라우저로 확인했다.
- 교수자 담당 수업만 표시되고 다른 수업은 404로 거절되는지 실제 HTTP로 확인했다.
- 포털 8종 × 화면 폭 4개(320/375/768/1440) × 테마 3종(밝음/어두움/고대비)의 96개 조합에서
  가로 잘림·잘못된 활성 메뉴·브라우저 실행 오류가 없었다.
- Next.js의 실제 인증 진입, 수업 전환·조회·페이지 분할, 현재 점수와 이전 최고점,
  권한 취소 시 화면 초기화와 보안 정책을 브라우저로 확인했다. 추가 메뉴를 적용한 뒤에도
  1440×900 화면에서 첫 최신 점수가 스크롤 없이 보이도록 간격을 보정했다.
- 합성 학생 25명·교수자 2명의 동시 HTTP 흐름과 5,000개 이력 데이터를 사용하는 기존 검증 도구를 통과했다.
  이력 대부분은 미리 생성했으며 채점기 실행 성능이나 운영 서버의 처리 용량을 측정한 결과는 아니다.
- `9.999999 / 10`이 만점으로 반올림되지 않는 회귀 시험을 추가했다.

같은 날의 원격 실습 포털 연결에서는 교수자·학생 포털, 기존 교수자 CRUD·학생 인증·교과목 흐름,
테마 관련 회귀 **119개**를 통과했다. 새 검사는 미설정/연결 오류/정상 상태의 구분, 다른 수업 거절,
조회 중 권한 회수, 다른 과제 공간 숨김, 발급과 실제 수락의 구분, 최신 대기 결과·이전 최고점,
느린 실행 관리자 조회가 전체 학생 로그인 잠금을 점유하지 않는 동작을 확인한다.
이 포털 시험은 원격 Linux에서 실제 컴파일·실행·삭제를 검증한 결과와 구분한다.

원격 실행 관리자가 연결된 로컬 합성 서버에서 실제 Chrome으로 역할 진입, 교수자 홈·수업·실습 환경,
학생 로그인·홈·제출 현황의 7개 화면을 추가 확인했다. 화면 폭 4개(320/375/768/1440)와
밝음·어두움 테마의 **56개 조합**, 포털 내부 링크 **15개**가 통과했다. 실제 HTTP 검색·상태 필터,
담당하지 않은 수업 404, 익명 응답의 학생 정보 비노출, 학생 본인 상태만 표시하는 동작도 확인했다.
교수자 화면에는 다른 합성 학생의 원격 공간이 표시되고 해당 학생이 아닌 학생 홈에는 숨겨졌다.
이 검사는 수령 코드를 발급하거나 학생 공간을 변경하지 않는다.

재현 도구는 `scripts/check_nextjs_pilot.py`, `scripts/check_nextjs_browser.cjs`,
`scripts/check_role_portals.cjs`, `scripts/check_learning_portal.cjs`다.
원격 실습 포털 검증은 `scripts/check_learning_runtime.py --serve`가 제공하는 로컬 합성 서버에서 실행하며,
보고서와 화면은 `build/learning-portal/`에 저장한다. 화면 검증에는 로컬 시험 서버만 사용할 수 있도록 제한한다.
사진·점수·인증 정보 등 실제 학생 데이터는 사용하지 않았다.
운영 HTTPS·Nginx 배포, 실제 학생 계정, Safari·Edge의 새 프로필 인증은 별도 현장 확인이 필요하다.

같은 날 추가한 공통 회원 흐름은 별도 회귀 **68개**와 Chrome 기능 흐름 **5개**, 화면 조합 **24개**로
